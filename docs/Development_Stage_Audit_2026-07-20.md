# LongEdit 开发阶段审计与后续执行顺序

审计日期：2026-07-21

审计基线：`main`（W7-2 智能集合收尾）

当前版本：`v0.7.0`

## 1. 审计结论

项目与最初的“本地优先专业知识工作台”设计总体对齐，已经越过原型阶段，进入“补齐专业工作面深度与统一扩展能力”的阶段。

当前最准确的阶段判断是：

- 安全、可靠写入、统一质量门禁和 Rust 模块拆分已经形成可持续开发基线。
- 图谱、Canvas、PDF、Open Table、图表和 Mermaid 已具备各自可用闭环，不再只是展示原型。
- 完整 Excel 等价编辑器处于 **FR-DATA-009 部分完成 / S6-15 已完成**；渐进式 XLSX 编辑已经可用，但完整等价仍须继续按公开兼容矩阵推进。
- 新文件格式扩展框架与首个新增格式 OPML 已验收完成；主题预设也已在 T7-1 收敛为统一契约，并建立专业预设、共享消费者和持续结构门禁。

因此，后续不能只连续追加工作簿功能，也不能放弃 Excel 主线去做零散新页面。建议采用三条明确工作流交错交付：工作簿等价、格式扩展、主题系统。

## 2. 当前完成度

### 2.1 工程与数据安全

已完成：

- `WorkspaceGuard`、外部文件授权、路径和扩展名校验。
- 同目录临时文件、备份恢复、冲突签名和可靠原子替换。
- 前端构建、Rust 测试、PDF 大文件基准和生产依赖审计的统一质量门禁。
- `lib.rs` 单体拆分及按业务划分的 commands/formats/services 边界。

当前证据：127 项 Rust 功能与性能回归纳入统一门禁；本地功能、契约、静态分析和桌面构建通过，机器相关性能预算以 GitHub Quality Gate 为发布裁决。

### 2.2 专业知识工作面

已形成闭环：

- 全局/局部图谱、关系证据、筛选、治理、布局和导出。
- JSON Canvas、思维导图生成、专业选择/对齐/连线编辑和互操作保存。
- PDF 渐进读取、文本层、搜索、批注、Markdown 引用、索引、图谱和离线 OCR。
- CSV/TSV、Open Table、表格/看板/图表/仪表盘和 Markdown/Canvas 引用。
- Mermaid 源码工作室、常用流程图结构编辑、导出和 Canvas 嵌入。

专业主页、保存搜索和动态集合已形成统一日常入口；仍需继续完整知识库健康治理。统一 KnowledgeObject/Relation、本地索引和索引化跨格式搜索已完成。

### 2.3 完整 Excel 等价编辑器

S6-2 至 S6-15 已完成以下能力：

- 多 Sheet、分页虚拟预览、基础类型、公式文本和缓存结果读取。
- 受签名保护的文本、数字、布尔、清空、公式和空白单元格可靠写回。
- 连续/多区域、整行整列、TSV 剪贴板、撤销重做和填充柄。
- 字体、字号、粗斜体、下划线、RGB 颜色、填充、基础边框、对齐、换行和常用数字格式。
- 公式相对/绝对引用迁移、同 Sheet/跨 Sheet 依赖求值、按需重算和循环引用诊断。
- 行高列宽、合并区域、冻结窗格、命名样式、主题/索引色、分边框、自定义数字格式和条件格式保真。
- 命名区域、日期/错误值、Excel Table、基础数据验证、图表/绘图对象、透视表、切片器、外部链接、打印与保护结构的分级读取或保护性写回。
- 未编辑 OOXML 部件保留、ZIP 解压预算、请求上限和真实 fixture 回归。

尚不能称为 Excel 等价编辑器，关键缺口包括：

- 图表/绘图对象、数据透视表、切片器、外部数据、打印布局和保护设置的等价编辑，而不只是安全读取与保真。
- Table 结构编辑、持久化排序筛选、公式/自定义验证、条件格式规则编辑和命名区域增删改。
- 动态数组、易失函数、更多 Excel 函数、计算缓存写回以及完整 XLSX 往返。
- 更广泛的真实复杂工作簿语料、发布级性能矩阵和人工差异验收。

### 2.4 新文件格式编辑器

已完成：`shared/file-formats.json` 已成为前后端共享契约，集中声明扩展名、路由、大小预算、创建/读取/索引适配器和能力等级；创建、打开、外部授权与索引入口均消费该注册表。`.txt` 证明适配器和 OPML 专业编辑器已验证新增格式无需继续向根级白名单或命令分支堆叠逻辑。

### 2.5 更多主题预设

已有基础：当前具有多种颜色主题、深色模式、样式变量和设备端持久化，主要工作面已消费一部分统一 token。

T7-1 已完成：主题身份、模式、核心 UI/编辑器/图表 token 和预设组合已收敛到唯一注册表；设置页、命令面板、Naive UI、Vditor、Graph、Canvas 和 Table Chart 均消费公共契约。专业浅色、专业深色、高对比预设及结构门禁已交付，真实 Tauri WebView 视觉矩阵已固化为发布验收要求。因此 FR-THEME-001 升级为“已完成”。

## 3. 与最初设计的对齐情况

| 最初目标 | 当前判断 | 说明 |
|---|---|---|
| 本地文件是事实源 | 对齐 | Markdown、Canvas、Table、XLSX、PDF sidecar 均保持文件事实源 |
| 图谱成为日常工作工具 | 基本对齐 | 局部图谱、关系证据、治理和 Canvas 闭环已完成 |
| 真正可编辑的思维导图 | 对齐 | 使用开放 JSON Canvas，支持生成后继续编辑 |
| 完整 Excel 等价编辑器 | 部分对齐 | 已进入原生工作簿编辑阶段，但高级兼容矩阵尚未完成 |
| 新文件格式编辑器 | 对齐 | 共享扩展契约、证明适配器和首个 OPML 专业编辑器均已验收 |
| 更多主题预设 | 对齐 | 唯一预设模型、专业深浅/高对比主题、共享编辑器/图表消费者和桌面视觉矩阵已交付 |
| 专业管理系统 | 部分对齐 | 专业工作面较完整，统一索引、主页、集合和健康度仍待开发 |

需要修正的主要偏差不是代码方向，而是文档和排期：早期文档仍保留“XLSX 只读/完整引擎不进入默认构建”的旧结论；同时“新格式编辑器、主题预设并行排期”没有拆成有退出条件的开发批次。本次审计统一以 PRD 的完整 Excel 长期目标和渐进兼容矩阵为准。

## 4. 后续开发顺序

### 阶段 A：S6-8 工作表结构编辑（已完成）

范围：

1. 稀疏读取并原位写回默认/自定义行高和列宽。
2. 合并区域读取、选择、合并与取消合并；拒绝重叠和静默丢弃非锚点内容。
3. 前端可变行列尺寸虚拟滚动、合并区域渲染、撤销重做和未保存保护。
4. 真实 fixture 覆盖 `<cols>` 区间拆分、`customHeight`、`mergeCells` 顺序和未编辑部件保真。

退出条件：能力矩阵中的 `rowDimensions`、`columnDimensions`、`mergedCells` 为 `supported`；桌面端构建和往返测试通过。

### 阶段 B：T7-1 主题预设契约（已完成）

范围：

1. 抽取唯一 `ThemePreset` 注册表，统一颜色、表面、边框、阴影、密度、编辑器和图表 token。
2. 清除 `App.vue`、设置页和命令面板中的重复主题清单。
3. 在现有预设上增加专业浅色、专业深色和高对比预设，不以单一色相铺满界面。
4. 为 Library、Markdown、Canvas、PDF、Table、Workbook、Mermaid 建立桌面/移动宽度截图矩阵。

退出条件：新增预设只需注册一次；全部工作面无文本重叠和不可读组合；FR-THEME-001 升级为“已完成”。

### 阶段 C：F7-1 格式扩展契约收口（已完成）

范围：

1. 建立前后端一致的格式描述：扩展名、MIME、读取/编辑/创建/索引能力、路由、大小限制和外部授权策略。
2. 让创建、打开、导入、重命名和索引入口消费注册表，移除残留格式分支。
3. 为新格式提供模板模块、fixture 和能力降级约定。
4. 通过需求、开放性、往返保真和维护成本评分，确定第一种新增格式；未完成该决策前不直接堆新页面。

退出条件：用一个小型文本格式适配器证明无需修改根页面或根 Rust 命令；FR-FORMAT-001 的扩展框架验收完成。

### 阶段 D：S6-9 命名样式与高级样式（已完成）

范围：`cellStyleXfs/cellStyles`、命名样式应用与保留、主题色/索引色读取、分边框、自定义数字格式和条件格式只读保真。高级对象必须按能力矩阵区分“可编辑”和“仅保留”。

### 阶段 E：F7-2 第一种新增格式编辑器（已完成）

使用阶段 C 的注册、权限、可靠写入、索引和按需路由模板交付第一种新格式。立项文档必须先明确磁盘格式、编辑等级和往返验收，不以“能打开文件”作为完成。

### 阶段 F：Excel 等价兼容矩阵连续批次

按以下顺序继续：

1. S6-10：公式/命名区域/日期与错误 fixture 扩展。（已完成）
2. S6-11：冻结窗格、排序筛选、Excel Table、数据验证。（已完成）
3. S6-12：图表和绘图对象分级读取、编辑与保真。（已完成结构读取、受限显示和保真；对象编辑仍按公开矩阵为计划）
4. S6-13：数据透视表、切片器和外部链接边界。（已完成脱敏结构识别、安全提示与保真；刷新和交互仍为计划）
5. S6-14：打印区域、页面布局、页眉页脚和保护。（已完成安全只读摘要、受保护写入拒绝和保真；打印预览、布局编辑及解锁仍为计划）
6. S6-15：真实复杂工作簿差异门禁、性能预算和完整兼容声明。（已完成全包差异白名单、10,000×12 Debug CI 预算和受限发布口径）

## 5. 排期规则

工作簿保持主线，但最多连续执行两个工作簿批次，随后必须交付至少一个主题、格式平台或知识图谱核心工作流批次。当前起始顺序为：

1. S6-8 工作表结构。
2. T7-1 主题预设契约。
3. F7-1 格式扩展契约。
4. S6-9 命名样式。
5. F7-2 第一种新增格式编辑器。
6. S6-10、S6-11 后插入 G7-2 图谱关系创作闭环。（已完成；依据用户核心优先级替代纯主题批次）

这保证完整 Excel 仍是主线，同时让“知识图谱工作流”“新文件格式编辑器”和“更多主题预设”拥有明确交付，不再无限期写成并行事项。

## 6. 每阶段统一门禁

- 更新 PRD 状态、能力矩阵、兼容边界和交接文档。
- 新增真实 fixture、失败路径和往返测试；写入功能必须验证未编辑部件保真。
- 执行 `npm run ci:check`、`cargo fmt --check`、严格 Clippy；涉及 Rust IPC/桌面注册时执行 Tauri Debug 构建。
- 执行 RustSec 审计；高危漏洞不得以“传递依赖”理由直接放行。
- 推送 `main` 后等待 GitHub Quality Gate 成功并核对本地/远端 SHA。
