# UI-4B 主要格式编辑器视觉审计

日期：2026-08-03
当前状态：已完成，真实桌面矩阵与人工复核均已接收

## 需求对齐

UI-4B 对齐最初的“完整 Excel 等价编辑器、新文件格式编辑器、更多主题预设”需求，但当前阶段不再横向扩张能力，而是验证已实现的主要格式工作面能否在桌面产品中稳定使用。覆盖 Markdown、TXT、JSON、PDF、DOCX、PPTX、CSV、XLSX、Mermaid 图表、OPML 脑图和 JSON Canvas。

每个工作面验证专业浅色、专业深色、高对比主题，以及 Windows 100%、125%、150% 等效缩放，共 99 个截图槽位。检查重点是布局截断、页面溢出、工具栏可达性、底部状态、加载完成和受管文件路由。

## 工具基线

- `scripts/ui4b-editor-visual-matrix.mjs` 固定 11 个格式工作面及其真实加载完成标志。
- `scripts/run-ui4b-editor-visual-audit.ps1` 创建隔离审计资料库；文本类样例使用确定性内容，PDF 使用版本化双页样例，DOCX/PPTX/XLSX 复用仓库兼容性样例。
- `scripts/capture-ui4b-editor-visual-audit.mjs` 只连接真实 Tauri WebView2，并统一从 `LibraryMode?path=...` 受管文件入口打开样例。
- `scripts/check-ui4b-editor-visual-harness.mjs` 校验矩阵、样例、Tauri 边界、路由和几何合同。
- `scripts/check-ui4b-editor-visual-audit.mjs` 只接收完整 99 张截图，并拒绝错误主题、错误缩放、路由漂移、外壳溢出、工具栏裁切或底栏越界。

## 接收顺序

1. 提交并推送工具基线，形成可追溯的干净采集提交。
2. 运行 `npm run audit:ui4b-editor-visual` 生成 99 张真实桌面截图。
3. 运行机器证据检查，并人工抽查每个工作面的三主题与三缩放代表图。
4. 发现问题时拒收整批证据，修复后在新提交上完整重采。
5. 证据接收后将 `check:ui4b-editor-visual-evidence` 加入补丁发布质量门禁，再进入 UI-4C。

在完整采集和人工复核前，UI-4B 不标记为完成。

首轮采集探针确认资料库会在消费 `LibraryMode?path=...` 后将 URL 规范化为 `#/library`。证据合同因此分别记录请求入口与最终规范路由，并额外要求样例文件名出现在活动编辑器中；这保留了受管入口证明，也避免把规范化行为误报为路由漂移或误拍空资料库。

第二轮探针通过 Markdown、TXT 和 JSON 后，在 PDF 加载完成标志处停止。审计确认 PDF 实际稳定标志与既有 B2A 桌面证据一致，应为 `.page-shell canvas`；矩阵已改为等待真实页画布，不使用仅代表组件挂载的根节点作为完成条件。

第三轮探针推进到专业浅色 150% 的 TXT 工作面。几何审计发现通用 `header` 查询命中了资料库嵌入模式下保留但隐藏的标签页节点，零尺寸矩形被误报为工具栏越界；采集器已改为只选择首个真实可见的工具栏和状态栏，并在清单中记录工具栏矩形，产品布局不因探针误报而修改。

第四轮使用可见工具栏矩形确认了真实 TXT 缺陷：150% 等效缩放下嵌入编辑器宽 642px，工具栏被格式策略栏的最小内容宽度撑至约 691px。TextEditor 已将网格列、工具栏和状态栏改为可收缩布局，并把紧凑规则扩展到 900px 逻辑视口，使编码策略栏在高缩放下内部滚动而不再撑宽整个工作区。

修复后的完整 99 图矩阵通过机器几何合同，但专业浅色和专业深色 150% 人工复核拒绝接收：固定在右上方的“关系上下文”入口系统性遮挡多个编辑器的保存或末端工具按钮。共享入口已改为右侧垂直居中的抽屉触发器，900px 以下收为仅图标按钮；证据合同新增触发器与任意可见工具栏相交检查，本批截图不作为最终接收证据。

关系入口修复后的重采继续审出了两处证据合同缺陷。其一，通用 `header` 选择器会把 PPTX 幻灯片内容标题误当作主工具栏；其二，首个 Markdown 路由可能在资料库壳层初始化完成前发出，而旧身份检查又允许侧栏文件名代替活动编辑器标题，导致空白欢迎页被误认为样本已打开。矩阵现为每种编辑器显式声明主工具栏、状态栏和文件身份选择器，主工具栏必须真实可见，关系入口只与这些主操作区比较；采集器也会先等待资料库壳层就绪，再发出首条托管路由。新合同已完成 99 槽位机器试采，但因试采发生在合同尚未提交时，该批截图仍不接收；下一次采集必须以包含本合同的提交作为 `sourceCommit`。

以 `f4ad245` 重采的 99 张证据通过机器检查，三主题 150% 人工复核确认所有编辑器均已加载且主工具栏可用，但高对比脑图暴露了最后一处布局瑕疵：右侧关系入口虽不再遮挡工具栏，仍悬浮在属性输入框边缘。资料库壳层现为关系入口预留 42px 侧轨，入口统一收为带 tooltip 和关系计数的 38px 图标按钮；新几何门禁要求关闭态入口不得与编辑器根区域相交。本批 `f4ad245` 截图因此拒绝接收，需在侧轨提交后完整重采。

最终证据以提交 `f8e995abbeba722a16a5d9024ed99315035fe584` 为 `sourceCommit` 完整重采。侧轨缩窄嵌入编辑器后暴露的 PDF 工具栏和 OPML 脑图页头问题，已分别通过容器查询和窄容器图标操作修复；三套主题、三档缩放、11 个工作面共 99 张截图全部通过机器合同，页面溢出、工具栏裁切、状态栏越界、关系入口遮挡和关系入口侵入内容区均为零。人工复核覆盖全部工作面，并重点复核三主题 150% 下的 PDF、脑图、Markdown、PPTX、XLSX 与 Canvas，确认内容已加载、文本可读、主操作可达且关系入口稳定留在独立侧轨。UI-4B 据此接收，证据检查加入补丁发布质量门禁，下一阶段进入 UI-4C 全面复核、事实源收敛与 `1.0.2` 发布判定。
