发布候选：否

## 1. 结论

M6-2 不继续增加产品功能。唯一接续点选择为 **M6-3 v1.0.18 质量债与发布就绪审计**：先对精确 M6-1 产品代码执行完整 Rust 测试和 `ci:patch-release`，真实失败必须复现、定位和修正；全部通过后才允许进入 1.0.18 原子版本迁移与候选打包。

这不是现在就发布。运行时与公开版本仍为 `1.0.17`，开发目标仍为 `1.0.18`，`releaseCandidate=false`。M6-3 失败时必须停留在当前版本，不得创建安装包、Tag 或 Release。

## 2. 为什么停止扩大范围

M6-1 已形成一个边界完整、用户可见的补丁能力：图谱独立全屏在暗色/reduced 与浅色/calm 两套真实 Tauri 会话中完成 6/6 次三视口进入/Escape 退出、2/2 次路由卸载，运行时错误 0、源摘要不变；测试还实际修正了用户激活、可访问名称和 Document 失活拒绝三项问题。

继续添加的候选均会显著扩大风险：

| 候选 | 当前实际 | 为什么不进入本补丁 |
| --- | --- | --- |
| 社区折叠/展开 | 只有过滤子图，没有代理节点 | 会牵动聚合边、选择历史、路径证据、缩略图、导出和恢复 |
| YAML/XML/TOML Schema | 没有验证依赖或 provider 映射 | 信任、解析、缓存、离线/隐私和诊断来源必须先独立选择 |
| 治理环 | 健康面板独立扫描，GraphView 没有逐节点治理事实 | 需要共享扫描所有权、来源、优先级和解释合同 |
| ODP 备注编辑 | 解析与只读展示存在 | LibreOffice/PowerPoint 备注保留仍不对称，正文事务明确排除 notes |

因此现在转入质量门比继续增加一个高风险半成品更符合 v1.0.18 的边界。

M6-3 不新增产品功能、不提升版本、不打包。必须执行完整 Rust 测试和完整 `npm run ci:patch-release`，同时保持 M6-1 证据哈希、真实 Tauri结果和 README 能力边界。任何非预期失败都要记录“预期—实际—根因—修正—复跑”链路，不能只改断言。
