# v1.1.8：单库真实监视误过期修正

## 实际问题与用户影响

真实 Wry 第五轮 [38969635399](https://github.com/Longyuyeee/Long_MarkDownReader/actions/runs/38969635399) 已接通端口并通过运行时/自有夹具配置核对，但第一次 `search_knowledge_page` 返回 `expired`。原生程序不是崩溃，也不能算搜索通过。此前四轮是启动接入失败，不能与本轮功能失败混为一谈。

检查原图发现当时仍在启动页，因此同时加强驱动，必须等实际设置页挂载、配置准备好才发起搜索；不自动重试搜索。但进一步原生回归在**完全没有前端的真实文件监视环境**也复现失败：只有读取、没有写入，监视代次仍因三个子目录通知从 0 增至 3，导致第二个工作步被拒绝。失败见 `evidence/v118-native-ipc/native-watcher-read-only-first.log` 和 `native-watcher-read-only-diagnostic.log`，后者保留触发路径。

用户影响：新启动软件后搜索带子目录的资料库，即使没有修改文件，也可能被要求重新搜索。不能把这类失败解释成资料真的变化，更不能以忽略监视事件或无条件重试遮住。

## 修正和安全边界

- 单库真实命令改走 `request_live`，在工作前后同时检查来源代次、显式索引状态代次、取消及监视健康。显式构建/替换不被吸收。
- 将跨库已有的目录通知证明提取为共同逻辑：至多检查 64 个有界通知路径，必须全是现存非链接目录；在**当前请求原有预算内**重新收集来源签名与关系摘要，全部一致且代次稳定才承接通知。不是删除事件、重置代次、重新解析全部正文或额外增加预算。
- “匹配仍准备中、但来源枚举已完整结束”也允许证明；来源仍未枚举完、截断/限量、文件真实增删改、链接/未知路径、索引替换、关系变化、监视失败或预算不够均仍拒绝旧页。对大型/深层库、持续变化库，证明可能无法在预算内完成；这时保守报过期，不宣称已完成所有极端规模的无中断续载。
- 不修改 UI、样式/动效、默认主区打开、显式参考或草稿/保存行为。运行时和公开版仍 1.1.7，没有安装器或 Release 变更。
