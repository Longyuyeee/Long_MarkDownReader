2026-10-11，接续 `7ee159b2`。只读预检增强，不修改 UI，不新增执行入口。

## 调用链与本步实现

核对 App.vue：初始化完成及脏状态变化时调用 set_window_dirty；没有针对本次归档的新请求/确认协议。lib.rs 在窗口 Destroyed 时删除缓存，生命周期层仍只是按窗口标签保存布尔值。因此不能把 false 命名为“已确认安全”。

归档预检现在在扫描前后分别枚举当前窗口并读取状态，返回 windowDraftAudit（before、after、blockers）。明确分类 reported_clean、dirty、unknown；已关闭窗口残留缓存不参与当前枚举，未上报窗口为 unknown。空窗口清单、前后窗口或状态变化、任一时点有草稿/未知状态均明确标记。

始终保留 fresh_window_acknowledgement_required，即两次相同且全部 reported_clean 也不解除门禁。观察结果同步到 editPreview 的批次 blockers；读取协调状态失败则预检返回错误，不猜测干净。不使用会抢焦点的 ensure_saved，不关闭窗口、不丢弃草稿、不保存正文。

新增 2 项纯状态测试覆盖未上报窗口、关闭窗口缓存排除、新窗口加入、dirty→clean 仍保留风险、空窗口集合，以及缓存干净始终要求新确认。命令层连线由 Rust 编译验证，未进行原生多窗口交互验收。

## 边界及下一步

这是观察，不是跨窗口确认协议，也不是逐文件草稿登记。枚举和读取不构成原子窗口快照；同标签重建、扫描期间 dirty→clean→dirty 的中间变化、观察完成后继续输入等均不能靠两个端点排除。窗口级脏状态可能来自不相关文件，当前宁可保守提示，不代表精确冲突判断。

下一步仍需设计带请求 ID、超时、窗口身份及状态版本的确认机制，并覆盖正在保存/继续编辑/新开关闭窗口/回执过期，不得直接使用本观察解除执行门禁。涉及前端或 UI 时实际查看页面；新增用户确认状态先示意审批。然后继续写回与恢复、标签/索引闭环。
