# 知识库初始化、目录创建与可恢复错误修复

基线：main / 780288e，运行版本保持 1.0.23。此文记录本地未发布改动，不是安装包或正式发布验收。

## 原因

1. `get_default_config` 只生成“文档/Long编辑知识库”的路径，没有创建目录；而 `scan_directory` 首先调用 `WorkspaceGuard::new`，要求路径已存在。此前取不到文档目录时还会回退到 C 盘根目录。
2. `LibraryMode` 的首次扫描没有局部处理异常，异步挂载可能中断；全局 Vue 错误处理器又把所有错误当作严重故障，在应用节点内追加 `height:100vh` 错误块，且只有刷新入口。这会破坏布局，也没有解决无效路径的办法。
3. 设置里的“添加库”仅向配置数组添加名称/路径，未建立磁盘目录，并且在异步保存完成前就提示成功。
4. 目录扫描原先忽略 `read_dir` 失败，可能把权限问题显示成空库。

这些是代码确认的原因。已保存路径还可能因目录移动、磁盘离线、账户权限或系统文档目录重定向而失效；没有用户故障机器日志，不能把所有用户情况归为同一种原因。

## 修改

- 首次生成默认配置时创建知识库目录；无法定位文档目录时采用应用数据目录，不再猜测 C 盘根路径。初始化失败时保留尝试路径供用户恢复。
- 已保存知识库失联时不自动重建，避免将离线旧库伪装为空库。
- 文件树显示局部恢复区：重试读取、管理知识库、明确提示后在原路径创建文件夹。原有工作区保持可用；恢复后刷新统计、标签和索引状态。
- 扫描捕获异常，并用请求代次和路径拒绝过期返回，防止旧库错误覆盖新库。
- 全局意外错误使用可关闭的有界提示，并提供管理知识库入口；错误内容用 textContent 渲染，不作为 HTML 插入。
- 添加知识库调用后端准备命令，递归建立输入的完整路径，保留已有文件；拒绝相对路径、上级跳转、文件占位或无法访问的路径。等待配置保存成功后才清空输入和提示成功，失败则保留输入并显示原因。
- 新回归已接入 `check-current-development-audit`。
