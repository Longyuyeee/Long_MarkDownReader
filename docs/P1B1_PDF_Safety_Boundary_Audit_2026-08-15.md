# P1-B1 PDF 安全编辑边界审计

审计日期：2026-08-15

阶段状态：审计完成，尚未新增 PDF 写入能力

## 1. 结论

现有 PDF 能力并不弱：软件已在原右侧 PDF 工作区完成渐进阅读、搜索、目录、批注与 OCR sidecar，以及页面旋转、改序、排除、范围提取、合并和插页的可靠新副本。但它仍没有 AcroForm 填写、永久脱敏、水印或元数据编辑能力，也不能宣称任意正文重排。

下一步必须先完成 P1-B2A 表单结构只读检查，再决定哪些字段能进入可靠副本填写。加密 PDF 和带数字签名/权限签名的 PDF 对所有新写入阶段保持强制阻断。

## 2. 当前真实能力

| 能力 | 当前状态 | 保存边界 |
| --- | --- | --- |
| 阅读、缩略图、目录、文本搜索 | 已完成 | 不写文件 |
| 高亮、区域批注、页评论 | 已完成 | `.annotations.json` sidecar |
| 离线 OCR、索引、知识图谱 | 已完成 | `.ocr.json` sidecar |
| 旋转、改序、排除页面 | 已完成 | 同目录可靠新副本 |
| 页面范围提取 | 已完成 | 同目录可靠新副本 |
| PDF 合并、插页 | 已完成 | 同目录可靠新副本 |
| AcroForm 检查与填写 | 未完成 | 当前稳定阻断 |
| 永久脱敏、水印、元数据编辑 | 未完成 | 无写入命令 |

所有页面级写入均使用资料库边界、源签名、SHA-256、资源上限、隔离生成、结构/文本复读、无覆盖原子新建和源文件不变验证。外部 PDF 继续只读预览。

## 3. 审计发现

### 3.1 格式能力登记低于真实能力

`shared/file-formats.json` 仍把 PDF 登记为 `edit: unsupported`、`read-annotate`、`saveMode: sidecar` 且 writer 为空；实际产品已经具备页面级可靠副本编辑。发布矩阵与安全降级合同也只描述 sidecar。

> 后续整改（2026-08-15）：P1-B2B0 已将上述登记欠报对齐为 `basic-edit / copy / pdf-copy`，只覆盖已经验证的页面级可靠副本与 sidecar 能力；PDF 表单填写仍未开放，须通过 B2B1 及后续验收后才能进入能力声明。

这不会造成数据风险，但会让能力中心、用户说明和开发门禁低估 PDF。P1-B2A 可以保持只读并行开发；在开放 P1-B2B 表单填写前，必须把注册表、发布矩阵与安全降级合同统一为“sidecar + 有界可靠副本”，同时保持外部 PDF 只读。

### 3.2 AcroForm 不能只读一个字段表

可靠检查必须同时遍历：

- `/AcroForm/Fields` 的规范字段树；
- 每页 `/Annots` 中的 `/Widget`；
- `/Parent`、`/Kids` 的继承关系；
- 重名但互不关联的字段、孤儿 Widget、循环引用和过深树；
- 字段类型、当前值、默认值、选项、只读/必填标志及 `/AP /N` 外观。

仅依赖页面渲染或 `/NeedAppearances` 都不能证明字段逻辑数据正确。

## 4. 高风险边界

- 加密 PDF：保持 `encrypted_pdf_unverified`，不尝试密码写回。
- 数字签名、权限签名和签名字段：保持 `digital_signature_unverified`，不填写、不扁平化、不迁移。
- 表单填写默认只生成新副本，不覆盖源文件或已有目标。
- P1-B2B 首批只考虑文本、复选框、单选框和受控选项字段；JavaScript 动作、富文本、计算脚本、文件选择、XFA 和歧义字段稳定阻断。
- 交互表单默认保持可交互；没有明确用户决定时不扁平化。
- 永久脱敏必须删除可恢复内容，黑色矩形覆盖不算脱敏。
- 水印必须隔离资源名并考虑 MediaBox/CropBox/Rotate；元数据编辑必须同时审计 Info 与 XMP。

## 5. 顺序开发计划

1. P1-B2A：AcroForm 规范字段树与页面 Widget 的只读检查、诊断和资源门禁。
2. P1-B2B：安全字段子集的可靠填写副本，验证规范值、Widget 有效值、非空外观、结构复开与页面渲染。
3. P1-B3：永久脱敏副本；先证明内容删除，再提供界面。
4. P1-B4：有界文字水印副本。
5. P1-B5：Info/XMP 元数据清单及允许字段编辑副本。

每个步骤分别完成代码合同、Rust fixture、真实 PDF 结构复开、Poppler/PDF.js 渲染、宽窄屏 UI、文档、独立提交和 GitHub 远端门禁。

## 6. P1-B2A 入口

P1-B2A 只读取资料库内 PDF，不生成副本。首批输出字段数量、Widget 数量、类型分布、规范字段与 Widget 关联、重复名、孤儿、缺失外观、XFA/JavaScript/签名风险和可填写候选数量；同时绑定源摘要并限制输入 128 MiB、字段/Widget 总数、树深、字符串与选项长度。

只有结构无歧义、无签名/加密/XFA/脚本风险且外观策略可验证的 fixture，才允许进入 P1-B2B。
