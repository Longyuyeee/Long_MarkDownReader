# F1 快速笔记：保存重试与窗口收尾

日期：2026-10-11。承接 `4bfb6bf2`，不改已确认的 R2 布局，不发布新版本。

后续：[跨库交接与超时边界实测](V1_1_0_F1_QuickNote_Handoff_Edges_2026-10-11.md) 已补上跨库拒绝、主窗超时恢复和等待交接期间原生关闭的验证；下文保留本轮原始记录。

## 修正

1. 新增 `save_quick_note`，操作标识固定对应一个 Markdown 文件。重复请求核对真实字节：一致则返回原路径，不同则拒绝覆盖并显示文件位置。写入仍使用现有可靠写入服务；即使原子创建后清理临时文件报错，也先核对是否已成功落盘。
2. 前端失败重试保留操作标识；只有收到成功结果才生成下一条标识。结果未确认时拒绝偷偷改库/改目录重试，防止在另一目录再建一份。正文变化且原文件已存在时明确冲突，不覆盖原件。
3. 保存/目录选择/模板确认期间维护忙碌状态，窗口关闭和退出处理器拒绝中断，未保存状态保持到操作结束。仅禁用界面按钮不足以处理系统关闭请求。
4. 托盘和命令复用同一快速笔记窗口构建函数；再次打开聚焦已有窗口，不尝试重复创建。WebView 命令使用异步入口，避免 Windows 同步建窗等待。

## 验证及失败记录

- Rust 定向测试：5 项通过，覆盖重复请求、同标识不同正文拒绝覆盖、非法标识/越界、目录修复重试、并发同标识只创建一份。
- 真实隔离 WebView + Rust 命令：14 项检查通过，保留上一轮 11 项用户流程，再验证相同请求的真实 IPC 重放返回同一路径、只存在一份文件、正文一致。见 [记录](evidence/v110-quick-note-reliability/checks.json)。
- 浏览器“落盘后丢回执”注入尝试失败：Tauri 的 invoke 属性不可写且不可重定义。未修改产品通信保护来配合测试；该端到端注入仍未完成，不能用命令重放冒充。
- 初次测试引用了未安装的 tempfile；改用标准库隔离临时目录，没有新增依赖。首次生产构建暴露 replaceAll 不符合当前 TS 目标，改为等价全局正则，没有提高编译目标来绕过。
- 原生窗口脚本首轮发现同步窗口命令等待，已改异步；后续导航检查失败时增加遮挡命中检查和现场诊断，不放宽主区正文必须真实出现的条件。
- 原生双窗口最终 5 项通过：真实 quick-note 标签、重复唤起复用窗口、关闭取消保留正文、保存后的正文实际出现在主编辑区、交接后快速窗口关闭。见 [窗口记录](evidence/v110-quick-note-windows/window-checks.json)、[快速窗口截图](evidence/v110-quick-note-windows/native-quick-note.png)、[主区复开截图](evidence/v110-quick-note-windows/main-opened-note.png)。调用的是托盘共用生产建窗函数，未声称物理点击了托盘图标。
- 最终 `npm run build`、原生调试构建、脚本语法检查及 `git diff --check` 通过。两份隔离脚本共 19 项检查，另有 5 项 Rust 定向测试；没有运行全部历史回归或安装发布验收。Rust 编译出现增量缓存目录访问警告，但最终编译和测试成功，没有清理或重置用户工作区。

## 边界与接续

- 重试标识由当前快速笔记会话保留；不宣称应用崩溃/重启后自动恢复未保存草稿，也不承诺用户手动删除已保存文件后再重试仍不重建。
- 尚需覆盖系统关闭发生在真实慢写入期间、模板确认取消、目录选择、深色与输入法，以及跨库拒绝/主窗超时路径。
