# M1A2 XLSX 规模与常用对象真实基线审计

日期：2026-08-25
状态：通过基线门禁；100k 性能余量不足，下一步必须修正

## 本阶段目标

建立 10k、50k、100k 单元格 XLSX 的真实桌面打开、末页、编辑、显式保存和复开证据；同时复核条件格式与 Excel Table 的真实 OOXML 写回边界。本阶段不增加公开能力声明，也不提升版本。

## 预期与实际差异

修正前没有按单元格规模分层的桌面证据，既有性能测试是 4 Sheet、10,000 行、12 列的后端总预算，不能直接回答用户在大表中的打开、翻页和保存体验。本阶段用 Rust 生成器创建三个实际 XLSX，每行 10 个有值单元格并包含周期性公式。

| 规模 | 预算：打开 / 末页 / 保存 | 修正后实际 | 结论 |
| --- | --- | --- | --- |
| 10k 单元格 | 3000 / 3000 / 4500 ms | 1855 / 103 / 1403 ms | 通过，余量充足 |
| 50k 单元格 | 5000 / 5000 / 6500 ms | 2737 / 2392 / 4473 ms | 通过 |
| 100k 单元格 | 7000 / 7000 / 8000 ms | 4313 / 6595 / 7708 ms | 通过，但末页仅余 405 ms、保存仅余 292 ms |

三个临时文件均在保存前保持 SHA-256 不变，点击“保存”后才改变；100k 文件刷新真实 Tauri 应用并重新载入末页后，修改值仍为 `M1A2-100000`。运行时错误为 0，没有错误边界。差异从“无分层事实”修正为可复核数据，但 100k 结果不具备稳定发布余量。

## 常用对象审计

### 条件格式

- 真实 `compatibility-baseline.xlsx` 写回测试通过。
- 创建、更新、删除和签名冲突保护已有包级复读证据。
- 当前交互仍通过多轮文字弹窗填写规则类型、操作符、阈值、视觉预设和停止规则，用户需要记忆内部枚举。
- 条件格式结构操作会立即写盘，未进入统一“草稿、撤销、显式保存”边界。

### Excel Table

- 真实 OOXML 测试通过创建与调整 Table，并复核 worksheet、关系、内容类型和 Table 部件。
- 样式、条纹、首末列强调、筛选和结构操作已有有界能力。
- Table 结构操作同样是立即写盘；后续不能在没有草稿模型和撤销证据时继续扩大对象编辑范围。

## 真实测试

1. `npm run audit:post-v115-m1a2-xlsx-scale`
   - 启动真实 Tauri/WebView2，逐个操作 10k/50k/100k 临时 XLSX。
2. `npm run check:post-v115-m1a2-xlsx-scale`
   - 对规模、预算、保存边界、复开值和运行时错误进行机器复核。
3. `cargo test --locked --manifest-path src-tauri/Cargo.toml commands::workbook::tests::writes_conditional_formats_with_signature_protection -- --nocapture --test-threads=1`
   - 条件格式真实工作簿写回与冲突保护通过。
4. `cargo test --locked --manifest-path src-tauri/Cargo.toml formats::workbook_ooxml::tests::creates_and_resizes_excel_table_package_parts -- --nocapture --test-threads=1`
   - Table 创建、调整及 OOXML 包部件复读通过。
5. `npm run build`
   - 类型检查与生产构建通过。

首轮桌面探针按固定 24 px 行高定位末页，和真实 XLSX 行高不一致，因此在 10k 档失败；探针改为读取实际渲染行高后重跑，未修改任何性能预算，三档完成。

## 下一步

M1A3 优先优化大表分页读取：当前每个新页面都会重新解析整个工作表值和布局，100k 末页耗时已接近门禁。目标是保持首次打开和文件安全边界，同时将 100k 末页稳定降到 4,500 ms 以内，并补重复翻页、文件外部变化与保存后缓存失效测试。

完成性能修正后进入 M1A4：把基础条件格式重构为可见字段、预设色板和实时预览的编辑器，并使对象变更进入统一显式保存与撤销边界。高级规则继续只读或阻断。
