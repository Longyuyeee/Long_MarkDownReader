# F1 批次编辑预览聚合审计

2026-10-11，接续 `5fa34fcb`。内部纯内存辅助逻辑，不修改 UI、不读写磁盘，不开放归档执行。

## 实现与用户风险

不能仅收集有 proposedTarget 的成功项，否则同一文档里的 Wiki、缺失提案或未解析引用会被遗漏。本步 batch_preview 遍历所提供报告的全部出链及入链候选，按来源文档聚合提案和阻塞项。

候选没有影响记录、需要改写却无安全提案、待核对依赖、来源快照缺失/变化均明确阻塞该文档。仅没有文档级阻塞时调用既有内存预览，重复编辑去重、冲突替换拒绝；不返回该文档的部分改写正文。无须改写及同名其他目标保留原文，但也校验来源快照。

每份报告的完整性限制保留为批次阻塞原因，空报告集合明确标记缺失；can_execute 始终 false。某文档有预览不等于整批可执行。正文摘要每个输入文档计算一次，证据直接比较，避免每条引用重复哈希整篇正文及序列化比较。

## 验证

新增 3 项单元测试：跨报告重复证据合并而不放开执行；成功提案与未解决 Wiki 并存时拒绝部分预览，并验证无影响记录/缺少来源快照；冲突报告、缺少提案和空报告集合明确阻塞。

验证命令：`cargo test --locked --manifest-path src-tauri/Cargo.toml --lib archive -- --nocapture`。最终 75 passed / 0 failed，本步新增 3 项，总数含既有压缩包测试。`git diff --check` 通过。未降低既有断言。

## 边界与接续

本辅助逻辑尚未接命令；它只能审核调用者提供的报告，不能证明调用者已提供整批所有报告。当前正文也由内部调用者传入，尚无执行时身份锁、草稿协调或外部进程隔离。阻塞原因去重，不替代逐引用原始报告。仍使用线性查找匹配影响记录，未做大库性能验收；尚未增加整体报告输入资源预算。

下一步在命令层从同一次完整批次预检收集报告，受限读取并核对来源，补缺失报告检查及序列化回执；之后才能接草稿/保存协调、安全写回、恢复及标签/索引。UI 修改前后实际查看页面，新恢复状态先示意审批。
