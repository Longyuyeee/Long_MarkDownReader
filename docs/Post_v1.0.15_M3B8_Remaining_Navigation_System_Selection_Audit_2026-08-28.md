# v1.0.15 后 M3B-8 剩余导航系统选择审计

日期：2026-08-28

进入基线：`main` / `35239785cf1f6b16a4cc36571b405fc887988ea1`

阶段：M3B-8

发布候选：否

## 1. 结论

本阶段只完成真实代码、M3-0 大图证据和当前 Tauri 桌面的选择审计，没有修改图谱产品运行代码。下一个最小增量冻结为 **M3B-9 有界语义缩略图与视口导航**。聚类展开/折叠、图谱全屏、状态环和 M3C 性能重构继续延后。

选择缩略图的原因是：M3B-7 已具备相机姿态、有界可取消过渡和 reduced 即时到位；M3-0 的 1,000/5,000 节点真实截图显示主要导航缺口是失去全局方位。缩略图可作为只读派生视图补充方位和视口框，不改变节点、边或探索语义。

## 2. 三个候选的真实代码差异

| 候选 | 当前实际 | 信息增益与成本 | 决策 |
| --- | --- | --- | --- |
| 缩略导航 | 无 UI；相机诊断在首次相机动作后可读 | 可显示全图、当前视口和快速跳转；复用现有相机合同，不需要代理节点 | 选择为 M3B-9 |
| 聚类展开/折叠 | 只有 Louvain 社区远景和 `17 → 4 → 17` 过滤子图往返 | 必须定义代理节点、聚合边、选择、路径、证据、历史、导出和恢复语义 | 延后，不能把社区过滤冒充折叠 |
| 图谱全屏 | WebView 的 Fullscreen API 可用，但产品无命令或生命周期 | 增加空间，却不解决方位和标签密度；还需处理 Escape、返回上下文和面板状态 | 延后 |

M3-0 真实性能证据为：100 节点首次可见/稳定 `231/2931ms`，1,000 节点 `638/11654ms`，5,000 节点 `19378/115802ms`；最长长任务分别为 `73/491/9334ms`。因此 M3B-9 必须限制缩略图绘制成本且不绘制节点标签，但本阶段不把这些旧指标写成 M3C 已完成。

## 3. 预期、实际与修正

| 项目 | 预期 | 首次实际 | 修正后的合同/结果 |
| --- | --- | --- | --- |
| 相机姿态 | 页面进入后即可读取 | `data-camera-pose` 初始为空，首次相机动作后才写入 | M3B-9 必须直接从实时内部相机状态初始化，不得要求用户先操作；测试用“适合窗口”验证同步后姿态可读 |
| 三档布局 | 1280/1000/720 均可容纳后续最小导航入口 | 三档页面均无横向溢出；Canvas 分别为 `1280×710`、`1000×610`、`720×590` | 通过，但缩略图仍须避开左侧图例与底部居中状态栏，并对 720 单独重定位/缩小 |
| 社区语义 | 当前若是聚类折叠，可作为候选基础 | 实测为 17 节点进入 4 节点/3 边过滤子图再返回 17，交互种类为 `filtered-subgraph` | 明确不能按折叠/展开宣称，聚类镜头延后 |
| 能力缺口 | 缩略图、聚类折叠、全屏至少一个已存在 | 三者测试身份与产品命令均不存在；Fullscreen API 仅为平台能力 | 确认是选择阶段，不误报已实现 |
| 运行安全 | 真实交互不改资料库且可返回 | 运行时错误 0，资料库 SHA-256 前后一致，成功返回资料库 | 通过 |

首次真实测试因把“相机能力存在”错误写成“三次视口采样都必须由当前采样初始化姿态”而失败。实际是第一次 `fit-all` 完成初始化，后续窗口沿用已同步姿态；测试已改为验证首个窗口从空到已同步、后续窗口持续可读，没有通过放宽产品目标掩盖差异。

## 4. M3B-9 冻结范围

M3B-9 必须同时满足：只读派生全图；当前视口矩形；点击与拖动视口导航；复用有界、可取消、reduced 安全相机；初始进入即可正确同步；不绘制节点标签；绘制成本有界；暗色、浅色和高对比可辨；1280/1000/720 不与图例、状态栏、详情或路径证据面板冲突；资料库内容不变。

本阶段不包含代理聚类节点、全屏、状态环、布局 Worker、脏帧总重构或任何“5,000 节点性能已解决”声明。
