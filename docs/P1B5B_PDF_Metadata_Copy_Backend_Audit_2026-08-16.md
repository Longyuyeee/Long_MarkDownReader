# P1-B5B PDF 元数据可靠新副本后端审计

审计日期：2026-08-16

## 1. 阶段结论

P1-B5B 已把 B5A 冻结的标题、作者、主题、关键词安全子集实现为资料库内 PDF 的后端能力。当前命令已注册，但原 `PdfView` 没有提前显示入口，因此用户文件写能力仍标记为关闭；只有完成 B5C 工作区、草稿保护和真实桌面证据后才会公开。

## 2. 已实现的可靠副本链

预览读取源字节并核对 SHA-256，使用 lopdf 的 PDFDocEncoding/UTF-16BE 文本字符串实现 Unicode 字段。空值会真实移除 allowlist 键；`Creator`、`Producer`、`CreationDate`、`ModDate`、`Trapped` 逐对象保留。输出执行非增量完整重写并移除 `Prev/XRefStm`，预览 SHA-256 锁定保存请求，目标只能是不存在的新 `.pdf`，落盘字节必须与预览完全相同，失败目标会清理且源文件保存前后再次复核。

## 3. 保真与阻断验证

重开验证覆盖请求字段、字段删除、保留 Info 对象、页数与页面几何、表单/书签/标签/批注/链接/附件清单，以及从 trailer Root 可达的全部非 Info 对象等价。中文元数据新副本、摘要一致、源不变、已有目标和源路径覆盖拒绝测试已通过。自定义 Info、XMP 与数字签名 fixture 均 fail closed；加密、PDF/A、附件对象、异常 Info、预算和控制字符继续由同一后端阻断。

## 4. 当前能力边界

这仍只是四项描述属性编辑，不是匿名化或完整隐私清理；正文、批注、表单、附件及其他对象可能含身份信息。XMP 同步、自定义字段、附件属性、外部 PDF 写入、源覆盖、签名/加密/PDF-A 修改均不开放。B5B 不包含面板、草稿离开确认或用户可见保存入口。

## 5. 下一步

P1-B5C 在原 PDF 右侧工作区加入紧凑元数据面板，复用现有字体、间距和窄屏结构；明确显示“不是隐私清理”，接入预验证、摘要锁定另存、草稿离开保护和保存后复开。随后执行真实 Tauri 宽窄屏、中文路径、新副本与独立 pypdf/Poppler 证据，再进行 P1 总收口。
