# v1.1.19 画布与脑图整理开发记录

本版深化现有 Canvas/OPML 的整理、保存和资料来源接续，保留所有工具与开放格式。公开仍为 v1.1.18；实施前依据 [代码预审](V1_1_19_Canvas_Preimplementation_Audit_2026-10-18.md) 和十三版基础能力路线，不另起平台。

## 实际页面失败

生产 CanvasView/MindMapView、正常输入和动效，在隔离9022服务复现了五处问题，原图和观察见 `evidence/v1119-before-r2/`：

1. Canvas 写入草稿后切换另一画布，没有确认且草稿丢失。
2. Canvas 点保存后继续输入，磁盘只有点击时的内容，页面却显示“已保存”。
3. OPML 点保存后继续输入，旧回包直接替换页面，后续输入丢失。
4. Canvas 同文件定位节点重新读盘，覆盖未保存文字。
5. OPML 同文件定位重新读盘，覆盖未保存备注。

这是实际 Vue 与模拟 IPC/磁盘的组件复现，不是原生验收。第一轮驱动在OPML调用中用 structuredClone 克隆响应式Proxy而失败；改用与真实IPC序列化一致的JSON克隆后完成，不改产品来通过。首轮三张原图在 `v1119-before/` 保留。

## 修改前方向

[交互示意](design/v1119-organizing.html) 在改页面前生成并实际查看。保留选择/文本/文件/图表/Mermaid/链接/分组/连线、所有复制对齐吸附、分支、撤销、布局和投影功能。只增加就近状态、来源反馈和安全兼容副本：

- 保存捕获文件归属与文档快照，允许继续输入；成功只确认那次快照，后续输入继续是草稿。失败和迟到结果不替换页面。
- 同文件定位只定位，不重读；切换与重新读取保护草稿。库内Canvas也必须以读取签名防止覆盖他人更新。
- JSON Canvas 的 file 按资料库根解析，与既有“添加知识库文件”、图谱和OPML投影的实际写法对齐。跨目录复制不再错误重基；来源不可用明确显示并允许重新指定。
- 改名/移动复用现有引用事务、原文记录、租约和跨窗口草稿保护，不另造按名称猜测的身份系统。外部Canvas仍不自动读取未授权引用。
- OPML常规字段继续编辑保存。确实无法保留的XML扩展在读取时列出具体原因，原件禁止有损覆盖；保留内存编辑，并提供明确确认损失后防覆盖的新兼容副本，不把未知内容删掉后称无损。

## 实施与封板顺序

先归属/快照/冲突与草稿保护，再来源语义/移动接续、直接操作和开放格式往返。每批审计/文档/推送后继续。完整本机质量与Rust、实际页面、固定安装器、本版和全部历版、独立同包、封板CI、原包公开回下载、README末尾/Release/身份及最终main/tag CI全部通过才交付。本页后续追加真实失败、修正和证据层级，不把计划当完成。

## 已实施与当前边界

组件正常动效回归21项通过（`evidence/v1119-browser-r3/report.json`）；新增原生回归涵盖签名、失效路径、防覆盖副本、XML扩展、精确来源和带原文事务的移动接续。完整Rust功能回归1060通过、5项既有忽略，另跑性能组。截图实看发现窄窗脑图仍使用宽窗中心导致内容移出视口，已以ResizeObserver保持视口中心，不改主题位置和缩放；需后续同包原生复核。

原组件驱动第一轮误用“取消”定位OPML实际的“继续编辑”按钮而超时；修正为匹配真实文案，不删除测试。历史失败原图保留。旧静态契约要求`routeForFile(path)`，现强化为先原生精确解析再`routeForFile(result.path)`，并加解析命令断言，不绕过注册路由。版本过渡脚本第一轮因转义的旧常量仍为17而原子校验失败，未写入身份文件；修正后44个活动身份一起切换，公开下载仍是18。

本版仍为 community-unsigned；releaseCandidate=false 表示尚未完成实际安装器及独立复核，不能据此声称企业签名RC。当前公开版需要手动下载安装；历史托管更新观察未完成的条目继续保留，不冒称自动升级已验收。README开头的软件图标、功能介绍不变，更新说明仅追加末尾，正式发布后才更新下载链接与摘要。
