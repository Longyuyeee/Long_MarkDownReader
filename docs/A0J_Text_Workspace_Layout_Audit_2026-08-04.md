# A0J 文本工作区布局审计

日期：2026-08-04
对应需求：UX-22，并同步覆盖 UX-29 中与 LOG 共用的布局故障
结论：TXT/LOG 尺寸合同已修复，等待下一安装包复测。

## 根因与修复

- TXT 和 LOG 原先依赖 Grid 自动排列：标签栏是第一行，但嵌入资料库后会被隐藏，工具栏、正文和状态栏随即上移一行。
- 正文因此落入固定的 `38px/46px` 行，状态栏则误占剩余高度，形成“编辑区只剩一行、状态信息占满页面”的故障。
- 两个工作区现在使用具名 Grid 区域。无论独立路由、资料库嵌入、无标签或禅模式，正文都固定占据 `minmax(0, 1fr)`，状态栏固定为紧凑行。
- 根工作区和嵌入容器保留 `min-height: 0`，状态信息禁止换行及纵向撑高；本阶段不改变文本读写、手动保存、日志只读策略或视觉主题。

## 自动验证

- `check:text-workspace-layout`：校验 TXT/LOG 具名区域、正文剩余高度、固定状态栏和资料库嵌入容器合同。
- 专项门禁已加入 `ci:patch-release`。
- `npm run build`、现有格式合同与开发阶段审计必须继续通过。

## 安装包复测

1. 在资料库中分别打开短 TXT、长 TXT 和 LOG，确认正文占满工具栏与状态栏之间的剩余空间。
2. 在 100%、150%、200% 显示缩放和窄窗口下复测；状态栏必须保持单行且不得挤压正文。
3. 打开多个标签、切换禅模式、返回资料库再重开，确认正文高度不随标签栏显隐发生变化。
