# M4E-0 能力事实、残余风险与版本决策审计

日期：2026-08-29

阶段：M4E-0

结论：累计开发价值足以进入 v1.0.16 发布冻结；当前仍不是发布候选

## 原始需求对齐

原始 M4 路线要求在对象定位、工作台行动、受控转换和临时产物清理完成后，汇总能力事实、真实测试、残余风险和用户可见变化，再决定是否进入版本提升。M4D 已关闭，因此本阶段可以作入口判断；但不能把“允许进入冻结”写成“版本已提升”或“可以发布”。

路线图中的 v1.0.16、v1.0.17、v1.0.18 是最小独立价值阈值，不是里程碑计数器。当前开发线自 v1.0.15 发布后持续声明下一补丁为 v1.0.16，且一次性累计了 M1 格式深化、M2 工作台、M3 图谱和 M4 跨格式工作流的完整价值；因此无需制造空的 1.0.17/1.0.18 中间发布。

## 已验证用户价值

- M1：XLSX 对象草稿、PPTX 受限对象事务、DOCX 3 个生产者/9 组复开、ODS 可靠副本、大 JSON 渐进只读、视频逐帧/截图/位置/字幕均通过退出审计。
- M2：工作台收敛为继续工作、今天要做和需要处理；1011 文件资料库首个可操作 801ms，空/加载/失败恢复、任务定位、创建清理和 1280/720/480 通过。
- M3：语义探索、专业视觉、减少动效、导航镜头和 100/1000/5000 节点 Worker 性能独立收口；5000 节点稳定 10631ms，稳定绘制 0/s，真实完整/过滤 SVG/PNG 导出通过。
- M4A：7 类搜索定位族和 7 类有界图谱内部对象使用统一导航合同，从搜索、图谱和关系上下文准确打开并返回。
- M4B：Markdown 与内部 Table 是仅有的工作台写回族，均有签名冲突与逐字节撤销；PDF 未引用批注保持只读定位。
- M4C：CSV/TSV→Table、OPML→Canvas、图谱→项目笔记和图谱→Canvas 四条路径具备写前披露、取消不写盘、编号目标、自动打开、目标复读和源安全。
- M4D：只清理四个有结构化替代证据的可重建负载，意外删除 0，冻结周期其余 927 个路径全部保留。

## 用户可见事实纠偏

- README 开发段落已补齐 M4A～M4D，不再只突出 M1/M2/M3。
- README 明确“真实界面、核心能力、格式能力”描述 `main` 开发线，公开下载仍是 v1.0.15，避免将尚未打包的能力误读为稳定版能力。
- 格式能力页继续显示“1.0.16 开发线 · 运行时 1.0.15”；矩阵列名由“公开能力”纠正为“能力层级”。冻结前不能把矩阵 `appVersion` 提前改为 1.0.16。
- Release Notes 草案保留完整边界，并明确只是允许进入冻结，不是候选或发布完成。

完整开发审计还发现两处历史检查器漂移。外部 OPML 检查器依赖按钮属性必须相邻、路由监听只能包含旧 `node` 参数的过窄源码片段；实际工作区已增加 `data-testid`，并在统一定位后同时监听 `locatorToken`。UX-38C Table 检查器仍要求旧的“创建后再选打开或定位”对话框，而 M4C-1 已验收为创建成功后自动打开真实编号目标。检查器现分别验证实际合同，没有回退产品实现或放宽外部写入安全边界。

## 残余风险

以下六类风险不阻断进入冻结，但必须继续明确披露或 fail closed：

1. 不提供完整 Office/OpenDocument 等价编辑；未验证对象只读、阻断或只允许可靠副本。
2. ODS 公式/自定义样式编辑和 ODP 编辑保持关闭。
3. 视频播放依赖系统解码器；外部窗口字幕、嵌入字幕拆封、字幕编辑和转码延期。
4. YAML/XML/TOML Schema provider 与 mapping 延期，未配置 Schema 时不制造业务错误。
5. 图谱代理聚类折叠、全屏、治理环和性能专项保存视图恢复未进入已接受范围。
6. ODT 因 WPS ODF 外部证据不足继续未注册，XLSX 数组公式计算与写回继续阻断。

## 版本决定

决定为：**允许进入 v1.0.16 发布冻结，但尚不是发布候选**。

进入冻结后仍必须完成九项门禁：冻结产品提交；package/Tauri/Cargo/矩阵的原子版本迁移；完整 `ci:patch-release`；当前候选 R5F 路由挂载与 R5G 桌面路由/I/O 烟测；无签名 MSI/NSIS；托管 Windows 安装生命周期；安装后工作区回归；制品 SHA-256 与最终说明；Tag/GitHub Release 与冻结提交绑定。历史 R5E 只证明当时的 Tauri API 阻断记录真实，不能作为当前候选通过证据。

任一门禁失败都必须回到事实与代码修复，不能通过修改版本说明掩盖。当前保持 package、Cargo、Tauri、能力矩阵、运行时和公开版本 `1.0.15`，开发目标 `1.0.16`，`releaseCandidate=false`。

## 下一接续点

下一阶段固定为 **M4F-0 v1.0.16 发布冻结入口审计**：冻结精确产品提交，列出原子版本迁移范围和完整发布门禁执行顺序。M4F-0 在完成入口审计前不得修改版本号、构建发布安装包、创建 Tag 或 GitHub Release。
