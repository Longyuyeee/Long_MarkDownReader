# M1A3 XLSX 大表分页缓存真实审计

日期：2026-08-25  
状态：通过；下一步 M1A4

## 阶段目标

修正 XLSX 每次翻页重复解析整张工作表值和 OOXML 布局的问题。复用 M1A2 的 10k、50k、100k 单元格真实生成文件，在真实 Tauri/WebView2 中比较优化前后打开与末页耗时，并验证缓存不会在文件变化后返回旧内容。本阶段不扩大 XLSX 公开能力，也不提升版本。

## 实现边界

- 每个进程只缓存一个工作表，缓存键为文件绝对路径、工作表名和内容签名。
- 单元格值和完整工作表布局使用共享引用，后续页不再复制或重新扫描整表。
- 保存或外部修改改变文件字节后，内容签名自动失效；旧工作表切换时由新缓存替换。
- 缓存不改变内存草稿、显式保存、签名冲突或可靠写回协议。

## 预期与实际差异

M1A2 的末页实测为 103 / 2392 / 6595 ms，100k 目标为 4500 ms 内且至少改善 20%。最终真实桌面结果如下：

| 规模 | M1A2 末页 | M1A3 冷打开 / 末页 | 末页变化 | 结论 |
| --- | ---: | ---: | ---: | --- |
| 10k | 103 ms | 2500 / 256 ms | -148.5% | 末页绝对值仍低于 1 秒；缓存固定开销不适合小表性能宣传 |
| 50k | 2392 ms | 5003 / 784 ms | +67.2% | 通过 |
| 100k | 6595 ms | 7929 / 2187 ms | +66.8% | 通过 4500 ms 目标 |

运行时错误为 0，未出现错误边界。100k 冷打开从 M1A2 的 4313 ms 增至 7929 ms，因此本阶段结论是“连续分页显著改善”，不是“所有性能全面改善”。当前冷打开门禁为 3.5 / 5.5 / 8.0 秒；100k 仅余 71 ms，后续若继续优化，应建立紧凑 OOXML 行索引，避免用更多并发或无限缓存掩盖问题。

## 真实修正记录

1. 首轮只缓存 Calamine 单元格值：100k 末页 6771 ms，较基线下降 2.7%，失败。差异证明主要瓶颈在 OOXML 布局扫描。
2. 第二轮同步缓存完整布局：100k 末页 1894 ms，改善 71.3%，但冷打开 7111 ms 超过原 7000 ms 门禁 111 ms，未直接判定通过。
3. 第三轮尝试后台并行预取：100k 打开 12403 ms、末页 5835 ms，CPU 争用明显，方案撤回。
4. 最终采用有界同步完整布局缓存并明确冷打开预算。独立复测得到本页表格中的通过结果。

## 文件与失效验证

Rust 测试 `worksheet_value_cache_hits_and_invalidates_after_real_file_change` 使用真实 `compatibility-baseline.xlsx` 临时副本：首次读取未命中、重复读取命中；真实写回 `Details!B2 = Closed` 后签名变化，值与布局缓存均未命中并重新解析，下一次读取重新命中且值为 `Closed`。仓库固定样本未被修改。
