# F1 表格在途保存与重新打开协调

日期：2026-10-11；基线 `4733b2a9`；目标 1.1.0；未封板。

## 实现

新增窗口内共享 `tableSaveOwnership`：保存占用不随 TableView 卸载消失，回执协调完成或失败后释放；重复释放不会解锁后续保存。键区分资料库、路径和外部文件模式，外部文件键不依赖当前资料库。此机制不替代原生签名检查/文件租约，也不解决 Windows 大小写、路径别名或跨窗口身份统一。

TableView 重新加载时等待同一键的在途保存，随后重新检查加载代次与目标路径/资料库/模式，再读取文件。等待页面退出后不会恢复过期加载。新实例保存时也需取得共享占用，避免绕过实例内 saving 标志。释放位于 finally，失败也能解除等待。

沿用原有加载区域和布局：等待时显示“正在等待上次保存完成…”，其余加载显示“正在加载表格…”。未新增操作入口或改变已有放弃草稿确认。

## 验证

- `node --experimental-strip-types --test scripts/test-table-save-ownership.mjs`：3 项通过，含共享占用、等待、幂等释放/重新占用、键隔离。
- Table 与 main/text 保存、加载及模式联合回归：41 项通过，包含历史缺陷复现用例，不将其全部称为当前功能验收。
- `npx vue-tsc --noEmit`、`git diff --check`：通过。未改 Rust，未执行 Rust 测试。
- 后台 `test-table-save-browser.mjs`：生产 TableView 的真实路由销毁/重建、DOM 输入和点击，模拟 IPC。成功及失败两条路径均确认：返回时显示等待、未新增读取、无旧单元格，回执后才读取；成功显示本次提交，失败显示之前持久化的内容。等待中再次离开，旧回执不会触发过期读取。连续输入、失败重试旧场景也通过，无 pageerror。

这些离开场景显式点击既有“放弃修改并离开”，**不宣称未提交草稿可在主动放弃后恢复**。失败返回只读取模拟的旧持久化内容，这是上述明确放弃场景的结果，不是草稿恢复功能。
