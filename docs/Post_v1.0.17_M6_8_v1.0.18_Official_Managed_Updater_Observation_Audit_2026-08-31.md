## 审计边界

M6-8 只验证公开 v1.0.17 到公开 v1.0.18 的受控更新链，不继续增加产品功能，也不使用本地重建包替代官方 Release。一次性 GitHub 托管 Windows 必须从官方 v1.0.17 NSIS 安装，通过应用内更新发现 v1.0.18，经过用户确认和 SHA-256 校验后覆盖安装并自动重启。

## 预期与实际差异

预期是官方 v1.0.17 能发现、确认、校验、安装并重启到官方 v1.0.18，同时保留合成资料库和配置。当前实际是两个 Release、Tag、NSIS 摘要和 v1.0.18 安装态主程序身份均已冻结，但托管更新生命周期尚未执行。因此本阶段保持 pending，不提前宣称更新链收口；纠偏动作是提交只读官方资产的托管工作流，并只接受真实 12/12 结果和人工复核后的截图。

## 验收条件

必须证明确认前安装器未启动、下载的官方 NSIS 大小与 SHA-256 匹配、安装根不变、覆盖安装成功、自动重启和首次启动成功、更新后报告 v1.0.18、资料与配置在覆盖和卸载后保留。证据不得包含真实用户内容；托管截图必须人工复核。

## 纠偏与结论

入口导入器最初沿用了 v1.0.17 阶段为修复候选文案而增加的固定句检查，要求正文出现“状态：已正式发布。”；v1.0.18 的官方正文采用不同措辞，但 GitHub API 已独立证明 Release 为 latest、非草稿、非预发布，且截图与发现证据对应当前官方正文。该历史固定句不属于最初需求，已纠偏为核对 v1.0.18 实际官方发布说明身份，不修改产品或 Release 来迎合测试。

M6-8 已通过，v1.0.18 正式 Release、远端制品和 v1.0.17 → v1.0.18 应用内更新链全部收口。公开与运行时版本保持 1.0.18，下一开发目标保持 1.0.19；后续工作应从 v1.0.19 范围选择和真实代码审计开始，不继续扩展 v1.0.18。
