# UX-40 文档切换卡死全面审计

状态：**代码与自动化门禁通过，待新安装包完成真实交付验证**

## 根因

v1.0.4 的“正在打开知识库 / 正在准备页面内容”不是文档自身的加载界面，而是全局路由遮罩。审计确认存在四条卡顿或卡死路径：

1. 每次文档路由变化都会重新显示遮罩，并强制保留约 420ms。
2. 跨格式路由使用 `out-in`，目标编辑器必须等待旧页面退场后才能挂载。
3. 遮罩收尾位于配置恢复、Tauri 事件注册和启动参数 IPC 之后；任一 Promise 不返回，遮罩就可能永久保留。
4. Markdown/TXT 共用编辑器没有请求代次保护；快速切换时旧磁盘读取可能晚于新文档返回并覆盖当前界面。

异步路由组件加载失败也缺少明确恢复入口，用户只能看到旧遮罩或空白状态。

## 修复

- 删除全屏路由遮罩及其全部样式和状态，启动与文档导航的阻塞遮罩预算均为 0ms。
- 删除 `out-in` 串行退场和模糊缩放动画，目标工作区立即挂载。
- 应用外壳先 `mount`，配置恢复与 `router.isReady()` 随后异步执行；路由就绪最长等待 8 秒，失败时保留可操作外壳。
- `get_config` 最长等待 4 秒，凭证状态和自启动状态最长等待 2 秒；失败时恢复本地标签状态并继续启动。
- 打开文件事件和启动参数读取最长等待 2.5 秒，且不再阻塞键盘事件与主界面初始化。
- 路由异步加载失败时保留当前文档，并显示非阻塞恢复条，可重新载入界面或关闭提示。
- Markdown/TXT 读取加入递增代次和活动路径校验；只有最新且仍为当前 Tab 的请求可以更新编辑器，组件卸载会使未完成请求失效。
- PDF、Office、工作簿和大型结构文件继续使用各自的局部加载状态，不再以全屏遮罩覆盖工作区。
