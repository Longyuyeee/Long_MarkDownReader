# UX-40 文档切换阻塞修复审计

状态：**代码与门禁通过，待下个安装包交付**

## 问题

v1.0.4 把每次 Vue 路由变化都视为顶层页面加载。切换文档 Tab 时，全屏遮罩会重新显示“正在打开知识库 / 正在准备页面内容”，并强制保留约 420ms；跨格式路由还使用 `out-in` 转场，目标编辑器必须等待旧页面退场后才能挂载。两项串行等待造成了明显卡顿。

## 修复

- 全屏加载遮罩只用于应用首次启动，文档导航不能重新激活遮罩。
- 首次启动反馈最短时间由 420ms 降为 120ms，配置读取完成后立即收尾。
- 路由性能计时与视觉遮罩分离，继续保留性能记录和后台 WebView2 的 250ms 计时兜底，但兜底不再阻塞界面。
- 移除路由 `out-in` 串行退场和模糊缩放动画，目标工作区立即开始挂载。
- PDF、Office、工作簿和大结构文件继续使用各自的局部加载状态，不以全屏遮罩覆盖已打开文档。

## 验证

- `npm run build`：通过，6216 个模块完成生产构建。
- `npm run check:r5b-desktop-startup-performance`：通过。
- `node scripts/check-route-loading-fallback.mjs`：通过，确认文档导航不可重新激活遮罩且不存在 `out-in`。
- `npm run check:current-development-audit`：通过，UX-34 至 UX-39 全链保持成立。
