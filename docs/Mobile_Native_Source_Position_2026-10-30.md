# 分段长文续读与按需跳段

本轮完成元数据审计的下一项：分段长文位置接入原生 `source-reading-v1.json`，修复“恢复前先写段首”。重开保持当前段、查询、命中、查询光标、正文选区和滚动。常驻只留翻段、当前位置及问号；点击段号打开短弹窗，输入不移动正文，明确前往才跳转。[原图核对册](evidence/mobile-native-source-position-2026-10-30/review.html)包含设计对照、实际页面、失败记录和数据收尾。

先核对 [KOReader 官方指南](https://koreader.rocks/user_guide/)的按需页号导航和回到跳转前位置，以及 [ReadEra 官方介绍](https://readera.org/)的自动保存当前页、阅读菜单及前后查找。采用保持阅读现场、将定位输入收进操作层的原则；未安装竞品走查，也未推断其内部存储方式。[交互规则及原型](design/mobile-native-source-position-v1/Interaction.md)在 SourceReader 接入前冻结。

实际行为包括：

- 保存按原身份与指纹隔离，正常文稿继续使用资料库和完整路径；文字导入、包导入、两种导出及恢复预览沿用独立身份。隐藏预览使用最后可见快照，避免保存零尺寸布局。
- 原生记录缺失时才验证迁移旧键。读取失败不冒充首次阅读，坏记录、未知字段与其他身份保持。单文档令牌与整个原生文件摘要都核对后，AtomicFile 写入并读回，确认后才成功；不静默裁成100条。
- 先恢复查询／命中、分段、段内锚点及选区，完成前暂停写入。新查询才定位第一处；同一查询重开保留当前命中。迟到回复遇到新的滚动／操作时保持当前现场。主题变化不重建长文 DOM。
- 跳段弹窗屏蔽背景、限定焦点，取消后回原入口。系统 Back 依次关闭帮助、跳段、查找及父任务；未提交段号在帮助、取消及重新打开期间保留。保存失败仍能阅读和返回，返回结果明确提示未确认保存。

初始原型的 Teleport 目标在根节点挂载前选成 body，导致主题不正确；保留初稿，修订为挂载后选根节点。实际分页栏390×61，去掉可见预览条后位于 y=711，与冻结稿一致；弹窗宽358、高309、左右16一致。原型视口844与预览872相差28，居中位置相差14，单列于[几何对照](evidence/mobile-native-source-position-2026-10-30/alignment.json)。示意正文、简化页头与底栏没有当成整页像素参考。

逐图检查发现旧截图脚本按预览条总高度裁切，即使它已滚出视口，导致短屏标题被截掉。最终弹窗图保留完整视口，新增标题、关闭和两项动作的可见／命中断言；320×372、200%字号均通过。旧裁切图保持，未重画、遮罩或移动截图像素。实际 Android 782×363 横屏也核对了两项48px动作，无需滚动。
