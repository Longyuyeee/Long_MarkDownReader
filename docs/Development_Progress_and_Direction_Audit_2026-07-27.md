# LongEdit 开发进度与后续方向综合审计

> 审计日期：2026-07-27
> 审计基线：`codex/a4-format-closure` / `fe4d1f3`
> 文档性质：当前能力事实、原始需求对齐、后续开发与验收基线

## 1. 审计结论

LongEdit 已经从 Markdown 阅读器发展为具备统一格式注册、右侧嵌入式工作面、本地索引、跨格式关系组织和可靠保存边界的多格式资料管理器，但还没有完成“日常文件管理与基础编辑全覆盖”的最终目标。

当前共享注册表覆盖 **30 类格式、62 个扩展名**：

- 13 类标记为 `完整编辑`；
- 14 类标记为 `基础编辑`；
- 2 类标记为 `仅预览`；
- 1 类标记为 `阅读/批注`。

这组数字描述的是注册表中的用户能力等级，不等于“30 种格式全部达到 Office 等价”。当前真正需要继续补齐的是 DOCX 读取与索引闭环、DOCX 安全基础编辑、PPTX、WPS/OpenDocument/旧版 Office 兼容方案，以及安装发布矩阵。

原始需求的三个目标当前状态如下：

| 原始目标 | 当前结论 | 说明 |
|---|---|---|
| 覆盖日常文件管理 | 基础闭环已形成 | 文件树、统一路由、最近、收藏、标签、集合、搜索、外部打开和工作区安全边界已存在 |
| 覆盖基础阅读与编辑 | 部分闭环 | 文本、开发格式、开放图表/脑图、表格和 PDF 已达到可用子集；DOCX 仍只读，PPTX/WPS 尚未进入实现 |
| 形成体系化管理 | 当前范围已闭环，仍可增强 | 索引、关系、知识图谱、工作台、对象定位已经贯通；更深代码语义和脑图—图谱双向协同属于增强项 |

因此，当前主线不应继续优先扩张单一 XLSX 高级能力或知识图谱视觉效果，而应按 **DOCX → PPTX → WPS/OpenDocument/旧版 Office → 管理与发布矩阵** 收口原始格式覆盖。

## 2. 审计依据

本次结论以以下可复核事实为准：

1. `shared/file-formats.json` 的 schema v2 能力注册表；
2. 前端工作面、Rust 命令与格式适配器的实际实现；
3. `npm run ci:check`、Rust 功能/性能回归和格式契约门禁；
4. `docs/a5-desktop-evidence/manifest.json` 的真实 Tauri Debug/WebView2 证据；
5. A5、G8、PDF B0～B1C、DOCX C1-2A 阶段审计；
6. 需求基线、执行指导和开发交接文档之间的一致性检查。

当前真实桌面证据包含 **35 项检查、27 张截图**，覆盖文本/开发格式、知识关系可见性、PDF 页面整理、DOCX 结构化阅读、基础版式、Microsoft Word 真实生产者文件与可靠另存重开。该证据证明的是已列出的安全子集，不代表未测试格式或高级对象已获得支持。

本次文档更新后的完整质量门禁结果：

- 前端类型检查与生产构建通过；
- 主题、格式、图谱、PDF 页面计划、桌面证据、工作簿和 XLSX 发布契约全部通过；
- Rust 功能回归 `295/295`、性能回归 `1/1` 通过；
- 100 MiB PDF 有界范围读取为 `64 ms / 255.9 KiB / 1 request`；
- 正式依赖审计为 `0` 个漏洞。

构建仍报告既有的大分包警告；它不影响本次文档与能力基线通过，但应保留在发布性能优化清单中。

## 3. 当前能力分层

### 3.1 完整编辑：13 类

Markdown、纯文本、INI、Properties、EditorConfig、GitIgnore、YAML、XML、TOML、JSON Canvas、Open Table、Mermaid 图表和 OPML 思维导图。

“完整编辑”表示该格式在当前公开子集内具有可编辑、可保存和可重开闭环，不表示拥有对应专业软件的所有高级功能。

### 3.2 基础编辑：14 类

`.env`、JavaScript、TypeScript、Python、Rust、Go、JVM 代码、C 系代码、Shell、SQL、Web 源码、JSON/JSONC、CSV/TSV 和 XLSX。

这些格式只开放已经验证的安全子集：

- 开发文本以源码编辑、搜索、校验、编码/换行保真和可靠保存为主；
- `.env` 默认遮罩且不进入正文索引；
- JSON/JSONC 支持源码/树形双视图、校验和受门禁结构编辑，软件内新建仍是计划项；
- XLSX 已具有较强的渐进式编辑和复杂 OOXML 保真能力，但不宣称完整 Excel 等价。

### 3.3 阅读或预览：3 类

- PDF：阅读、搜索、OCR、批注、索引、关系定位，以及页面旋转/改序/排除的安全计划与可靠另存；
- DOCX：结构化只读预览；
- LOG：有界只读、筛选、追尾、自动刷新和轮转识别。

日志保持只读是当前风险策略，不应被描述为功能故障。DOCX 则仍需继续补齐读取范围、全局索引和基础编辑。

## 4. 主要能力审计

### 4.1 统一管理工作面

已经完成：

- 共享格式注册与最长扩展名优先路由；
- 文件树、统一标签页和原 Library 右侧嵌入式工作面；
- 最近文件、收藏、标签、智能集合和治理队列；
- 跨格式全文搜索和可重建本地索引；
- 能力等级、保存方式、降级方式和外部打开提示；
- 工作区守卫、内容签名、外部冲突检测和可靠替换。

界面结构已经恢复为与 Markdown 相同的右侧工作面模型。后续新格式不得重新引入独立新窗口，也不得绕过共享字体、字号、间距和主题变量。

### 4.2 文本、JSON 与开发格式

A0～A5 已经收口。TXT、JSON/JSONC、YAML、XML、TOML、INI/CONF/CFG、Properties、点配置、`.env`、日志和代表性代码格式已进入统一路由与工作面。

仍保留的非阻断增强：

- 软件内新建 JSON/JSONC；
- 日志显式编辑模式；
- 语言服务、代码执行和调试。

这些增强不应阻塞 DOCX/PPTX/WPS 主线。

### 4.3 图表、思维导图与知识图谱

已经完成：

- Mermaid 源码与预览编辑；
- JSON Canvas 节点、连线和图表文件节点；
- OPML 思维导图树编辑、可靠往返与 Canvas 投影；
- CSV/TSV/Open Table 的表格工作面；
- 关系摘要进入工作台、搜索和当前文件上下文；
- 关系侧栏可展示同标签、集合、跨格式证据和对象定位；
- 图谱导航保持在应用主工作面内。

因此，知识图谱“日常可见”的 G8 范围已经闭环。下一步应以更高价值的语义增强为主，例如代码符号关系、脑图节点与图谱关系双向同步、关系解释和可控自动建议；不应仅增加装饰性节点或独立图谱页面。

### 4.4 PDF

已经完成：

- 阅读、页码导航、正文搜索、OCR、批注和关系索引；
- 页面旋转、改序、排除；
- 在隔离副本中验证页面计划；
- 不覆盖源文件的可靠另存、重开和兼容画像。

尚未完成：

- 合并、拆分、插入和独立提取页面的完整产品流程；
- 表单填写、数字签名和正文排版编辑；
- Acrobat 级内容编辑。

当前 PDF 已达到原始需求所需的“阅读/批注 + 安全页面整理”实用子集。合并、拆分和插页进入增强队列，不再阻塞 Office 格式覆盖。

### 4.5 XLSX

XLSX 已经超过简单预览，包含多工作表、单元格/区域、样式、公式重算、行列结构、合并、Table、筛选、名称、验证、条件格式、图表和受限 Pivot 验证等渐进式能力，并通过未编辑 OOXML 部件保真门禁。

边界仍需公开：

- 不等同于完整 Excel；
- 宏、外部连接、复杂 Pivot 重建、全部图表和未知扩展仍可能只读或阻断；
- S8-7E2F～S8-8 为专项增强队列，不再占用原始格式覆盖主线。

### 4.6 DOCX

C1-2A、C1-2B1 与 C1-2B2 已经完成：

- 安全 OOXML 解包与有界解析；
- 标题、段落、列表、表格、样式继承和编号语义；
- PNG/JPEG/GIF/WebP/BMP 的有界内部图片预览；
- 目录、文内搜索、高级对象兼容画像；
- 页眉、页脚、脚注、尾注和批注正文只读呈现；
- 正文引用与附属内容双向定位；
- 实时及持久化全局索引，结果定位到正文块或附属内容；
- 横向/纵向合并单元格、显式/渲染分页和基础节版式摘要；
- 35 项真实 Tauri 检查与 27 张证据图中的 DOCX 桌面打开、搜索、定位和 Word 生产者读取；
- 原 Library 右侧嵌入式只读工作面。

尚未完成：

- 任何 DOCX 写回；
- Microsoft Word 真实生产者已完成；WPS、LibreOffice 两类兼容矩阵仍待完成。

当前开发机未安装 Word、WPS 或 LibreOffice。现有合成 fixture 只能证明解析器边界，不能替代真实生产者证据，也不能据此开放编辑。

## 6. 后续开发方向与退出条件

### 阶段 1：C1-2B DOCX 读取与索引收口（已完成）

C1-2B1 已完成附属正文、引用绑定、全局索引和对象定位；C1-2B2 已完成合并单元格、分页/分节、基础版式摘要和真实桌面证据。

交付：

1. 已完成：页眉、页脚、脚注、尾注和批注正文只读呈现；
2. 已完成：合并单元格、分页符和基础版式摘要；
3. 已完成：全局索引，结果定位到段落、标题、表格或附属内容；
4. 未支持对象明确占位，不静默丢失；
5. 延续 Library 右侧工作面和原有视觉变量。

退出条件：提交 fixture、Rust 回归、前端构建、格式契约、真实桌面打开/搜索/定位全部通过；原文件保持只读。

### 阶段 2：C0-2 三类真实生产者矩阵

当前进度为 1/3：C0-2A Microsoft Word 已完成真实生成、隐私匿名化、Word 重开、SHA-256 清单与 Rust 解析回归；C0-2B WPS 和 C0-2C LibreOffice 仍待真实环境。

交付：

1. Microsoft Word、WPS、LibreOffice 各自产生可再分发 DOCX；
2. 记录生成步骤、应用版本、许可证、哈希和期望结构；
3. 覆盖标题、列表、表格、图片、页眉页脚、脚注、批注和兼容对象；
4. 三类文件均完成应用内截图、结构摘要和外部生产者重开证据。

退出条件：真实文件合法可再分发，读取语义和降级提示一致；没有真实环境时可以并行开发 C1-2B，但不得跳过该门禁进入覆盖原件写回。

### 阶段 3：C2 DOCX 安全基础编辑

按以下批次开放：

1. C2A：已完成隔离副本补丁、包差异审计、写后重读，不写用户原件；
2. C2B：已完成普通段落和标题文本的隔离语义补丁；
3. C2C：简单列表和表格文本；
4. C2D：基础字符样式和受限图片替换/插入；
5. C2E：冲突检测、可靠另存、三类生产者重开和真实桌面闭环。

退出条件：只修改目标 OOXML 部件，未编辑部件逐字节保留；修订、域、复杂绘图或未知扩展无法证明保真时整批拒绝；失败不得破坏源文件。

### 阶段 4：C3～C5 PPTX

先完成缩略图、放映、文本/图片/形状预览、备注、搜索和对象定位，再开放文本、基础样式、图片替换、简单形状和页面增删改序。动画、母版、SmartArt、复杂图表和未知扩展保持只读保真。

退出条件：应用内阅读、搜索、受限编辑、可靠另存和 Word/WPS/LibreOffice 对应演示生产者重开通过。

### 阶段 5：WPS、OpenDocument 与旧版 Office 审计

对 `.wps/.et/.dps`、`.odt/.ods/.odp`、`.doc/.xls/.ppt` 逐类给出：

- 公开规范和许可证；
- 可内置解析、可靠转换或仅外部打开的结论；
- 转换前风险提示、原件保护和另存目标；
- 文件树、搜索、最近、收藏和关系管理接入方案。

退出条件：每种扩展名都有明确的识别、预览、编辑、转换或外部打开状态，不出现空白页或伪支持。

### 阶段 6：管理与发布矩阵收口

交付：

- DOCX/PPTX/WPS/OpenDocument 接入最近、收藏、标签、集合、索引和关系侧栏；
- 所有工作面统一右侧嵌入、字号、主题、间距和能力提示；
- 安装包、文件关联、升级、卸载和数据保留策略；
- 多台 Windows 机器的安装、打开、保存、重开和恢复矩阵。

退出条件：普通用户无需开发环境即可安装；双击支持文件能进入正确右侧工作面；升级/卸载不破坏用户文件和可重建索引。

## 8. 统一完成定义

后续每个格式批次必须同时满足：

1. **可管理**：文件树、最近、收藏、标签、集合和外部打开有一致行为；
2. **可阅读**：内容和未支持对象均有明确呈现；
3. **可搜索**：进入可重建索引并可定位到文件内对象；
4. **可编辑**：只开放经过验证的安全子集；
5. **可保存**：冲突检测、可靠替换、写后重读和失败不破坏源文件；
6. **可关联**：关系侧栏和知识对象可以引用文件或内部对象；
7. **可验证**：单元/集成、格式契约、性能和真实桌面证据齐全；
8. **可发布**：能力边界、许可证、安装和兼容矩阵有文档。

任何“能打开”都不得单独等同于“完整支持”，任何合成 fixture 都不得单独等同于真实生产者兼容。
