# 第四十四批：输入密码后继续阅读 PDF

本批在 `codex/mobile-0.1.0-foundation` 接续第四十三批。先补查竞品和PDF.js当前安装版本，再用内置imagegen生成密码页，随后实现和核对真实页面。Android开发包序号1002048；本批没有推送、发布或改动桌面工作区。

## 用户可以完成的任务

- 选中有打开密码的PDF，先确认文件名，再输入密码。普通文件与仅带权限密码、打开密码为空的文件直接阅读。
- 显示/隐藏输入；用按钮或键盘“前往”打开；空输入不能提交。密码原样传递，不裁剪空格或改大小写。
- 输错后留在原页，显示明确错误，清空并隐藏输入，聚焦重试。取消或系统返回结束当前打开，返回资料库；阅读笔记回链则可返回原笔记。
- 关闭、进程重启后重新询问密码；解锁后恢复原文件的物理页、显示方向、缩放、阅读方式和位置。等待输入时不覆写阅读位置。
- 解锁后的混合页面可以使用目录、书签、连续阅读、旋转、摘录和原文回链。回链再次要求密码，成功后定位原页和高亮。

`MobilePdfPassword.vue`只持有当前输入；提交后清空并隐藏，后台时清空。`pdfPassword.ts`只持有一次性回调，重复点击不重复提交；成功/取消/切换/卸载时废弃回调，加载任务销毁终止等待。密码没有加入应用草稿或持久化字段，不生成解密PDF副本。已有笔记功能仍按用户明确操作写普通独立侧文件，不能据此认为摘录也已加密；也不宣称JavaScript内存可被可靠清零或接管系统输入法/自动填充。

## 调研与设计基准

调研：[Acrobat Android 官方打开指南](https://www.adobe.com/acrobat/hub/open-password-protected-pdfs-on-android.html)、[Xodo 官方密码文档指南](https://xodo.com/blog/how-to-open-a-pdf-with-password-protection)、[PDF.js 加载任务官方API](https://mozilla.github.io/pdf.js/api/draft/module-pdfjsLib-PDFDocumentLoadingTask.html)。前两者支持“选文件、输入、正确后阅读”的路径；公开说明没有足够依据还原所有错误/取消/键盘细节，本批未安装竞品逐页实测。设计决定与区别详见[竞品调研补充](Mobile_Competitor_Research_2026-10-23.md)。

## 复杂与加密语料

用自造六页混合PDF扩展四份加密语料：AES-256、AES-128（前后空格有意义）、RC4-128、仅权限密码的AES-256。均有父子目录；页面覆盖横/竖、90°与270°内置方向、小页、非零裁切原点、大矢量与2048×1024位图。不是从用户私有文档取样。

[语料清单](../scripts/fixtures/mobile-pdf-password.json)记录尺寸、公开测试密码及摘要；[生成器](../scripts/create-mobile-pdf-password-fixtures.py)保留既有文件，不静默覆盖。最初作者断言误用了并不存在的首页文字，已改为比较真实源页提取文字；已生成的第一份文件保留并重新读取核对。PDF操作标记先执行一次，四份最终文件均用pypdf重新打开、校验密码/页数/目录；AES-256另用Poppler渲染六页并人工检查[总览](evidence/mobile-0.1.0/pdf-password-native-2026-10-26/corpus-contact-sheet.png)。Poppler提示缺少Symbol/ArialUnicode候选字体，六页可见内容已核对，未把这项外部渲染警告当作应用通过证据。

## 候选失败与复核

保留所有候选，不用最终结果覆盖失败：浏览器1793001572675漏点“编辑本页书签”；1668814误把关闭时更新的时间戳当内容变化；1747182误用固定第三页，而连续模式旋转/缩放后实际可见页已变为第四页，改为比较真实关闭前锚点；1794959漏点“打开阅读笔记”和原文列表条目；1973543预置脚本误读阅读笔记沙箱iframe的localStorage，改为只在顶层初始化。2049119专项通过后，又在冻结构建的完整入口重新通过15组，未忽略页面错误。

原生取消与旋转候选的UIAutomator快照一度仅返回WebView根节点，断言失败；资料库返回后再采集也发生过，而独立辅助服务随后能按实际资料行执行点击并正常打开。取消截图已显示资料库，真实触摸有效，旋转稍后新快照也恢复完整节点。保留`cancel-library*`、`library-resumed*`、`library-after-reader*`、`encrypted-continuous-rotated*`和冷启动立即采得的空白候选。最终采集使用完整节点就绪检查、最多四次新UI转储，并保存未匹配转储，不降低应有文字断言。取消后曾用进程重启复核；未确定根节点快照问题的完整成因，不以此宣称所有原生无障碍时序均正确，完整TalkBack仍须单独验收。

## 后续顺序与边界
