# F1 统一只读恢复判断

日期 2026-10-11，接续 `5e7272be`。本步不改 UI、不接用户归档命令、不升版。

## 实现

新增 inspect_recovery，持有同一历史 lease 串联正文日志、history-policy 和历史发布核对，避免各检查之间释放同进程锁。正文检查增加供该协调器使用的带锁入口，返回已校验的日志身份；单独检查接口保留。

统一结果包含正文状态、历史状态（NotRequired/Pending/TargetMatches）及始终为 true 的 requires_review。无历史分支重新检查磁盘无历史，拒绝混入历史发布材料；有历史分支要求策略与准备清单一致，再检查发布结果。尚未发布时复查当前源历史与目标冲突，不能只凭“无发布意图”推断目标不存在。

正文双边存在/双边缺失、历史已匹配但正文仍在来源、正文与历史身份不符、策略与日志矛盾均报错并保留材料。目标内容匹配不代表完整归档成功，也不提供自动续作/删除授权。

## 验证与审计

新增两个 Windows 临时目录集成测试：有/无历史完成后的统一分类、篡改 historyRequired 后拒绝；正文已移动而历史冲突的拒绝、移开冲突后 Pending 分类、来源重新出现时拒绝并保留双边正文。未删除真实用户资料，冲突移开仅为测试状态构造，不是产品自动恢复行为。

首次编译因正文检查重构中的 Result 错误类型推断失败，已修正为直接枚举值，未修改业务预期。最终 `cargo test --locked --manifest-path src-tauri/Cargo.toml --lib archive -- --nocapture`：53 passed / 0 failed（新增 2 项，总数含既有名称筛选附带的 2 项压缩包测试）；git diff --check 通过。

这仍是只读判断，不是自动恢复/启动扫描/用户入口。外部进程可在检查间改动，lease 不是文件身份锁；没有草稿/引用依赖门禁、标签/索引完成记录或清理策略。损坏或缺失日志不自动修补。未执行 UI、安装态、强杀、断电或大库性能验收。
