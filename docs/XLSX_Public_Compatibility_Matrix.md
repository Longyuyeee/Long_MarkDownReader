# XLSX 公开兼容性矩阵

更新日期：2026-07-22
适用引擎：`calamine-ooxml-ironcalc-v14`
机器事实源：`shared/xlsx-compatibility-matrix.json`

## 1. 状态定义

- **支持**：能力已进入产品路径，并由自动化测试验证。
- **受限**：只支持公开说明的子集，不能推断为 Excel 等价。
- **保真**：不读取或编辑该对象，但保存其他内容时保持原 OOXML 对象。
- **计划**：尚未开放，不应出现在可用功能承诺中。

“可读取”“可编辑”“可计算”“可往返”是四件不同的事。本矩阵按维度公开能力，避免用一个笼统的“支持 XLSX”掩盖真实边界。

## 3. S6-10 命名区域契约

后端直接解析 `xl/workbook.xml`，保留名称、公式、工作簿或工作表作用域、隐藏标记，并只为安全的单一 A1 引用生成导航坐标。常量名称、公式名称、多区域、外部工作簿引用不会被伪装成可导航范围。

工作簿名称框只显示非隐藏且目标 Sheet 存在的单一区域。选择后切换 Sheet、加载对应分页、选中完整范围并滚动到左上角。超过当前 256 列预览边界的范围会明确提示，不会静默跳到错误位置。

命名区域公式由 IronCalc 在内存中显式重算；fixture 使用 `SUM(AmountRange)` 验证草稿修改后的依赖传播。名称的创建、修改和删除尚未开放，因此能力矩阵中的编辑状态保持“计划”。

## 4. S6-10 Fixture 证据

`compatibility-baseline.xlsx` 现在固定包含：

- 工作簿级 `AmountRange`、`ReportWindow`、`TaxRate`；
- Sheet 级 `Details!Codes`；
- 日期、带时间日期以及各自数字格式；
- 缓存为 `#DIV/0!` 的错误公式；
- 引用 `AmountRange` 的公式与缓存结果。

测试覆盖读取语义、全局/局部作用域、名称导航所需坐标、命名区域重算，以及修改普通单元格后 `workbook.xml`、日期和错误值保持不变。

## 5. S6-11 结构化数据契约

冻结窗格通过独立、受内容签名保护的结构命令写回，仅修改目标 Sheet 的 `sheetView/pane`；存在未保存单元格草稿时前端禁止结构写回，外部修改冲突会整次拒绝。

工作面读取工作表 `autoFilter`、关系文件指向的 Table 定义和数据验证规则。排序与筛选只改变当前会话中的显示顺序，最多预加载目标数据区 50,000 行，不修改 XLSX 的源数据顺序。S8-2A 新增签名保护的 Table 包级事务：可从单一连续选区创建普通 Table，也可把已有普通 Table 扩缩到选区并按首行同步列定义；事务同步维护工作表 `tableParts`、关系部件、内容类型和 Table XML。Table 改名、删除、持久化筛选、汇总行、计算列和扩展元数据仍未开放。

数据验证对字面量列表、整数/小数比较和文本长度规则执行保存前约束；引用公式、命名范围和自定义公式无法在当前本地验证器中可靠求值，因此只显示规则并保留原 OOXML，不伪装成完整 Excel 验证引擎。

Fixture 新增首行首列冻结、Details 自动筛选和列表验证，以及 Inventory Table。回归验证冻结窗格写入/取消、签名冲突拒绝、无效列表值拒绝和 Table 部件往返保真。

## 6. S6-12 图表与绘图对象契约

后端仅沿工作表内部关系读取 Drawing 部件，并继续沿 Drawing 关系识别图表与图片；外部关系和 `xl/` 之外的目标不会跟随。页面模型公开对象 ID、名称、替代文本、类型、起止锚点和部件路径；图表额外公开类型、标题以及系列名称、分类公式和值公式。

工作面以结构卡片呈现对象，可查看范围和系列来源并跳转到对象左上角。当前没有复刻 Excel 的布局引擎、主题样式、坐标轴、标签和图片像素渲染，也不能移动、缩放、创建或编辑对象，因此显示为“受限”、编辑为“计划”。

Fixture 的 Inventory Sheet 固定包含柱形图和嵌入图片。回归验证关系解析、锚点、标题、系列公式和替代文本；普通单元格写回后 Drawing XML、关系、Chart XML 与图片二进制必须逐字节保持。

## 7. S6-13 透视表、切片器与外部数据契约

工作簿检查阶段只读取 XLSX ZIP 内部的 Pivot Table、Pivot Cache Definition、Slicer、External Link、Connections 和关系元数据。透视表公开名称、所属 Sheet、缓存 ID、来源类型/Sheet/区域、连接 ID与刷新标记；切片器公开名称、缓存名和所属 Sheet；外部链接只公开对象类型、缓存项数量和目标类别。

所有 `TargetMode="External"` 关系只计数和分类，绝不跟随目标，不发起网络请求，也不读取知识库外文件。连接字符串、命令、凭据以及完整外部路径不会序列化到前端。工作面提供高级数据对象状态条和安全模式提示，但不执行 Pivot Cache 刷新、透视计算、外部查询或切片器筛选。

Fixture 固定包含工作表来源透视缓存、透视表、切片器、外部工作簿关系和带敏感占位连接字符串的数据连接。回归验证脱敏输出，并在普通单元格写回后逐字节保持所有相关部件。

## 8. S6-14 打印布局与保护契约

后端读取单个连续 A1 打印区域、页边距、纸张、方向、缩放/适页、打印网格线与标题、页眉页脚文本，以及工作簿和 Sheet 保护状态。工作面只提供结构化摘要，不模拟 Excel 分页引擎，不生成像素级打印预览，也不开放页面设置和页眉页脚编辑。

保护模型只公开是否启用、是否存在密码保护以及被阻止的操作类别；密码、旧式密码校验值、哈希值和盐不会进入 IPC。受保护 Sheet 的内容、样式、尺寸、合并和冻结窗格写回统一拒绝且文件字节保持不变；本产品不绕过密码、不解锁文件，也不把“可读取保护状态”解释为“可编辑受保护内容”。

Fixture 固定包含 Summary 的 `A1:F5` 打印区域、A4 横向适页、页边距、打印选项和奇数页页眉页脚，以及独立 Protected Sheet 和工作簿结构保护。回归验证完整读取、敏感保护值不序列化、受保护写入拒绝，以及普通单元格写回后页面设置和工作簿保护 XML 逐字节保真。

## 9. S6-15 发布差异、性能与兼容声明

机器发布档案为 `xlsx-progressive-editing-v1`。复杂 fixture 的复合内容、样式与结构写回必须保持 ZIP 部件集合完全一致，只允许目标工作表和 `styles.xml` 变化，所有其他部件解压后逐字节一致；写回后还必须重新读取修改语义。工作簿基准固定覆盖 4 个 Sheet、10,000 行 × 12 列和 1,000 行公式，并对检查、分页、写回、总耗时和文件增长设置 Debug CI 硬预算。

唯一允许的总体产品表述是“XLSX 渐进式编辑（以公开兼容性矩阵为准）”。当前不得宣传“完整 Excel 等价”“100% Excel 兼容”或“无损编辑所有 XLSX 功能”。部分维度的“支持”或“保真”不能推导为整个 XLSX 格式完整等价；正式声明见 `XLSX_Release_Compatibility_Statement.md`。

## 10. 安全与保真边界

S8-1A 的行列隐藏和大纲分组通过独立签名保护事务写回，只修改目标 Sheet 的 `row/col` 状态属性。不同宽度或样式的列区间保持拆分；受保护 Sheet、超过 7 级大纲、重叠列状态和超过 10,000 项的请求整批拒绝。详细契约见 `Workbook_Row_Column_Outline.md`。

S8-1B2A～S8-1C 的事务迁移目标 Sheet 行列与范围载体、跨 Sheet 公式、定义名称、Table 范围、Drawing 行列锚点、Chart 系列公式和计算链；完整删除普通范围对象时同步父节点计数。单一连续整行整列选择均已开放前端入口，并加入草稿/保护拦截、删除确认、旧历史清理、重载选区和已加载公式重算。完整 Table 删除或列数变化、透视表、批注、嵌入对象、未知扩展和活动筛选条件继续明确拒绝。详细契约见 `Workbook_Structure_Migration.md`。

- 名称最多 10,000 个，名称最多 255 字符，公式最多 8,192 字符。
- 单 Sheet 最多解析 10,000 条数据验证、10,000 个验证范围；会话排序筛选最多加载 50,000 行。
- 单 Sheet 最多读取 1,024 个绘图对象，单图表最多 256 个系列；标题和替代文本有长度上限。
- 高级数据对象和外部关系分别设置 4,096 项上限；元数据文本最多 1,024 字符，连接字符串不会进入公开模型。
- 页眉页脚文本最多 8,192 字符；保护元数据只公开布尔状态和受限操作类别，不公开密码校验值或哈希材料。
- 外部引用不生成导航目标，不触发网络或额外文件访问。
- ZIP 单部件与总解压上限继续生效。
- 只有矩阵中标记为“支持”的维度才能作为产品承诺；“保真”不等于“可读取”或“可编辑”。

矩阵结构由 `npm run check:workbook-contract` 校验，发布档案由 `npm run check:xlsx-release-gate` 校验，二者均已纳入 `ci:check`。新增或升级工作簿能力时必须同时更新机器矩阵、发布档案、fixture、测试证据和本文件。
