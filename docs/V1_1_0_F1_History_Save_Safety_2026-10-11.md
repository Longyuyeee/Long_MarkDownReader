# F1 历史保存碰撞与路径协调纠偏

日期 2026-10-11；接续 `799d775f`。本轮修复既有历史保存能力，不改 UI、不发布，归档入口仍未开放。

## 审计发现与实现

原 `save_history` 以 Unix 秒命名快照，并调用可替换目标的 `write_utf8`。同秒两份不同内容会使用相同路径；系统时间回退也可能命中旧记录。这与保留可恢复历史的初始要求冲突，应先修复再推进迁移。

现在扫描已有编号，选择不小于当前秒且大于已有最大编号的值，用 `write_new_bytes` 原子新建、不覆盖目标。编号溢出明确失败，原记录不动；枚举错误不再过滤掉后继续按不完整清单保存。正文去重仍按换行归一比较，保留数量策略不变。

保留现有秒级文件名/列表合同，未迁移历史格式。高频连续保存或系统时钟回退时，递增编号可能略晚于真实时间；这是兼容方案的边界，不声称毫秒精度时间戳。后续若分离时间与 ID，需要独立兼容迁移。

同时将库内/外部历史保存的 lease 获取前移到路径校验之前：与旧移动/删除入口协调时，不再先解析旧路径、等待到另一操作结束后写旧身份。辅助保存函数不再二次加锁。仍只是同进程上述入口间协调，不覆盖外部进程、普通正文写入和未实现的归档提交。
