# B1B PDF 可靠另存与重开审计

更新日期：2026-07-27

开发分支：`codex/a4-format-closure`

对应 Draft PR：#6

审计结论：**B1B 已完成“页面计划 → 隔离验证 → 同目录新副本 → 落盘复读 → PDF.js 重开”的用户闭环。源 PDF、任意已有目标和高风险 PDF 对象均不会被静默覆盖。下一步进入 B1C 复杂生产者与页面继承兼容矩阵，完成 PDF 页面基础编辑阶段收口。**

## 1. 目的对齐

用户最初要求在统一管理器中完成 PDF 的日常阅读和基础编辑。B0 已提供旋转、改序、排除和历史草稿；B1A 已证明这些操作能在隔离内存副本中生成并复读。本步骤只解决最后一个基础缺口：把已验证结果安全保存为新 PDF，并在应用中打开它。

本步骤仍不包含正文排版、表单填写、签名、擦除、附件迁移、合并、插页或对源 PDF 的覆盖保存。

## 2. 用户工作流

1. 在原 PDF 工作面右侧“页面”栏调整旋转、顺序和排除状态；
2. 点击“验证隔离副本”；
3. 验证成功后输入同目录新副本文件名；
4. 点击“另存新 PDF 并打开”；
5. 后端重新生成完全相同的验证字节，可靠创建新文件并复读；
6. 前端切换到新副本，PDF.js 重新解析和渲染；
7. 页面栏持续显示“可靠副本已落盘并重开”“源文件未修改”。

入口继续嵌在现有 PDF 工作面，不创建新窗口或另一套页面编辑界面。

## 3. 无覆盖写入设计

普通 `write_bytes` 支持可靠替换已有目标，不适合 B1B。新增 `write_new_bytes` 使用以下策略：

1. 写入与目标相同目录的隐藏临时文件；
2. 临时文件使用 `create_new`，写完执行 `sync_all`；
3. 通过同文件系统硬链接原子创建最终目标；
4. 若最终目标已存在，创建动作在文件系统层失败，现有文件保持不变；
5. 创建成功后删除临时链接并同步目标；
6. 上一轮残留的专用新建临时文件会在下一次尝试前清理。

应用级写锁负责阻止本进程并发写入交错，文件系统的无覆盖创建负责阻止应用外部竞争者在检查和提交之间替换目标。

## 4. 保存门禁

| 门禁 | 行为 |
|---|---|
| 源路径 | 必须位于当前知识库且为现有 `.pdf` |
| 目标位置 | 固定为源 PDF 同目录 |
| 目标名称 | 单一文件名、1～180 字符、必须以 `.pdf` 结尾，拒绝路径和 Windows 非法字符 |
| 源文件名作为目标 | 拒绝 |
| 任意已有目标 | 拒绝，不提供覆盖确认 |
| 源签名变化 | 拒绝并要求重新打开 |
| 隔离验证摘要缺失或非法 | 拒绝 |
| 重新生成摘要与先前验证不一致 | 拒绝并要求重新验证 |
| B1A 高风险对象 | 继续阻断 |
| 输出大小 | 继续受 256 MiB 上限保护 |

## 5. 落盘后复读

写入成功后，命令不立即返回，而是：

- 从目标路径重新读取完整字节；
- 对比预期字节及 SHA-256；
- 重新解析 PDF 结构并核对页数；
- 重新分页提取文本并核对页序；
- 再次读取源文件，对比打开时签名与 SHA-256；
- 返回目标路径、目标签名、摘要、页数、字节数及复读状态。

真实桌面随后用 PDF.js 独立重新打开目标，并验证只有计划保留的一页及其正文。由此形成 Rust 对象层、磁盘字节层和 PDF.js 渲染层三层证据。

## 6. 自动化与真实证据

后端测试覆盖：

- 两页 PDF 改序、旋转、排除后生成一页新副本；
- 目标 SHA-256 与隔离验证摘要一致；
- 目标结构和文本页序复读通过；
- 源文件完整字节保持一致；
- 第二次使用同名目标被拒绝，第一次目标字节不变；
- 目标等于源路径被拒绝；
- 陈旧/伪造验证摘要不产生文件；
- 非法文件名、路径跳转和非 PDF 扩展名被拒绝；
- 通用可靠写入层的 `write_new_bytes` 不覆盖已有目标。

真实 Tauri Debug/WebView2 覆盖：

- 在原工作面完成旋转、改序、排除、撤销和重做；
- 隔离副本验证通过；
- 新建 `G8 Research Saved.pdf`；
- Node 审计进程逐字节确认源 PDF 未变化；
- 新副本以 PDF.js 重开为一页并显示 `Second Page Beta`；
- 截图显示统一侧栏中的持久成功状态。

证据：

- `docs/evidence/a5-stage-a/b1b-pdf-reliable-save-reopen.jpg`
- `docs/evidence/a5-stage-a/audit-manifest.json`

当前完整门禁为 **283/283 项 Rust 功能测试、1/1 项性能测试、31/31 项真实桌面检查和 23 张截图**；100 MiB PDF 区间读取本轮为 55 ms、约 255.9 KiB 请求量。

## 7. 当前能力声明

| PDF 能力 | 状态 |
|---|---|
| 阅读、缩略图、目录、搜索、批注、OCR、索引、关系上下文 | 已完成 |
| 页面旋转、改序、排除、撤销/重做、离开保护 | B0 已完成 |
| 隔离生成、风险阻断、结构/文本/源字节验证 | B1A 已完成 |
| 同目录新副本、原子无覆盖创建、落盘复读、PDF.js 重开 | **B1B 已完成** |
| 覆盖源 PDF 或已有目标 | 禁止 |
| 加密、签名、表单、附件、Portfolio 等迁移 | 阻断 |
| 正文排版、合并、拆分、插页 | 未完成 |

产品现在可以准确描述为：**支持安全子集内的 PDF 页面基础编辑和可靠另存**。不能描述为完整 Acrobat、任意 PDF 保真编辑或正文排版编辑器。

## 8. 下一步：B1C 兼容矩阵收口

B1C 不再增加新操作，专门扩大真实 PDF 兼容证据：

1. 对象流与交叉引用流；

3. 页面树继承的 Resources/Rotate；
4. 图片型/扫描型无文本页面；
5. 多种生产者和不同 PDF 版本；
