# Post-v1.0.15 M3A-6 双节点比较审计

日期：2026-08-28

发布候选：否

## 1. 原始需求与实现边界

本阶段直接对齐 `Post_v1.0.15_Professional_Capability_Enhancement_Roadmap_2026-08-25.md` 的 M3A“双节点比较”，并延续关系证据可回到原对象位置的验收要求。此前 M3A-5 交接已纠正阶段遗漏：完成双节点比较后仍需实现邻居固定和选择历史，不能提前进入 M3B。

比较只作用于当前可探索图谱且不写回用户数据。打开比较会退出最短路径、邻居聚焦和社区筛选，避免多个解释范围叠加；筛选条件仍作为比较候选范围。

## 2. 冻结的比较语义

- 邻居成员关系按无向视角计算，平行边只贡献一个邻居；两个被比较端点互相排除，不会因彼此直连被误记为独有邻居。
- 输出共同邻居、仅左侧相邻和仅右侧相邻，节点按标题与 ID 稳定排序。
- 属性侧输出对象类型是否一致、路径、关系总数、唯一邻居数、入/出关系数，以及共同、左侧独有、右侧独有标签。
- 两节点之间的直接关系保留原始方向、关系类型、所有平行边和全部 mention；无 mention 的结构关系明确说明证据边界并可打开来源对象。
- 不同节点、相同节点和不存在节点分别返回 `compared`、`same`、`invalid`，不以空列表掩盖错误输入。

## 3. 独立算法审计

固定夹具构造左右节点、一个共同邻居、左右各一个独有邻居、两条方向相反的直接关系及两条 mention。审计确认：

- 共同邻居为 1，左右独有邻居各 1；
- 两节点端点不计入邻居差异，左右唯一邻居数均为 2；
- 两条平行直接关系、原始方向和两条 mention 均未被折叠；
- 共同与独有标签、不同对象类型、入出关系计数正确；
- 反转节点和边输入顺序后结果不变；
- `same` 与 `invalid` 边界状态明确。

## 4. 真实桌面审计

真实 Tauri 固定资料库包含 17 个节点、17 条边、11 类对象和 6 类实际关系。本次使用两组对照完成不同语义验证：

| 对照 | 预期 | 实际 |
| --- | --- | --- |
| 两个 Canvas 文件节点 | 展示共同、左右独有邻居和结构直连 | 共同 `System` 1 个；左侧独有 `NorthStar` 1 个；右侧独有 `Coverage chart` 1 个；有向 `supports` 1 条 |
| `NorthStar` 与 `Brief` Markdown | 保留所有平行关系和 mention | `depends-on`、`links-to` 两条关系，合计 3 条 mention |
| 证据回跳 | 精确定位来源 | 打开 `Brief.md` 并高亮第 3 行，两条 `depends-on` mention 均未丢失 |
| 响应式 | 1280/720 无页面横向溢出 | 均通过，窄屏面板内部可滚动且关闭入口持续可见 |
| 安全性 | 不修改资料库 | 审计前后目录 SHA-256 一致 |
| 稳定性 | 零错误并可返回资料库 | 运行时错误 0，返回通过 |

首次真实审计曾按截图推断两个 Canvas 节点只有共同邻居，实际代码数据还包含各自到原文件/表格视图的对象关系。审计没有放宽为模糊范围，而是按真实生成边纠正为 `1/1/1` 并固定精确预期。

证据位于 `docs/evidence/post-v115-m3a6-node-comparison/`，包括 `desktop.json`、宽窄比较面板、Markdown 直接关系证据和来源回跳截图。证据不包含用户内容，`releaseCandidate=false`。
