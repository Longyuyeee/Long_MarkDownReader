# 当前开发情况与后续收口计划审计

审计日期：2026-07-31

对应版本：0.7.0

对应开发基线：2026-07-31 C1A～C1C 知识图谱产品化与 D1A～D1C 统一体验阶段

当前发布阶段：R5N

发布结论：`releaseCandidate=false`

## 1. 审计结论

项目已经从最初的 Markdown 阅读器发展为一个以“统一右侧工作区”为核心的本地多格式知识与文件管理器。用户最初提出的基础目标——覆盖日常管理、基础编辑，并将文件、任务、关系和知识组织成体系——在工程功能层面已经基本实现。

当前 40 类注册格式中：

- 28 类已验证，可在既定能力边界内直接使用；
- 6 类已验证但存在明确限制；
- 6 类依赖外部 Office/WPS 兼容应用；
- 10 套发布能力配置明确规定了源文件策略、隐私边界和已知限制。

因此，当前产品不是“所有格式都具有原生专业软件的等价编辑能力”，而是已经形成了一个分级可信的多格式管理系统：

1. 文本、Markdown、JSON、配置文件和常见开发源码具备稳定的日常阅读与基础编辑能力；
2. PDF、Office、工作簿、图表、思维导图和知识图谱已进入统一产品结构；
3. 高风险或复杂格式采用只读、另存副本、sidecar、有限写回或外部打开策略；
4. 数据备份、知识索引恢复、冲突保护和发布证据链已建立；
5. 仓库内工程门禁已基本收口，但签名安装包在 Windows 10/11 隔离环境中的真实执行证据尚未完成，当前不能宣布 RC 或正式发布。

## 3. 当前能力分层

### 3.1 已验证：27 类

Markdown、纯文本、ENV、INI、Properties、EditorConfig、Gitignore、JavaScript、TypeScript、Python、Rust、Go、JVM 代码、C 系、Shell、SQL、Web 源码、JSON、LOG、JSONC、YAML、XML、TOML、Canvas、Table、Diagram、OPML。

这些格式已经覆盖日常知识记录、项目配置、开发资料、结构化数据、表格、流程图和思维导图的主体场景。

### 3.2 已验证但有限制：6 类

- PDF：正文只读，批注/OCR 使用本地 sidecar，页面操作输出新副本；
- DOCX、PPTX：开放经真实生产者复开验证的基础编辑子集，并另存新副本；
- ODS、ODP：当前以安全预览为主；
- Workbook/XLSX：仅对经验证的子集进行有限写回，复杂对象和数组公式保持阻断或只读。

### 3.3 外部依赖：6 类

旧版 DOC/XLS/PPT 通过本机兼容 Office 套件转换；WPS 文档、表格和演示原生格式通过用户确认后交给外部兼容应用。系统不会把“可以外部打开”误报为“应用内可编辑”。

## 4. 关键子系统审计

### 4.1 统一工作区与视觉一致性

此前出现的“新开发界面独立打开、没有进入原有右侧区域”的结构问题已经通过统一路由和 `WorkspaceTabs` 架构纠正。当前主要格式视图均进入统一工作区，文件库也能嵌入编辑器。

后续仍需一次面向真实安装版的视觉验收，重点核对：

- 字号、行高、工具栏密度和图标尺寸是否继承全局主题；
- 加载、空状态、错误、只读、保存中、冲突和保存成功反馈是否一致；
- 文件树到编辑器、编辑器之间切换、关闭和恢复是否保持同一种交互；
- 键盘导航、快捷键、缩放和高对比度状态是否完整。

### 4.2 知识图谱

知识图谱已经不再只是孤立的可视化页面。当前具备全局与局部图谱、文件关系上下文、关系新增/删除与来源证据、健康治理、过滤、保存查询、动态子图智能集合、知识索引维护、备份恢复，以及图谱到思维导图、可编辑 Canvas 和可执行项目笔记的流转入口。C1A 生成的项目笔记会进入现有全文搜索和首页待办扫描；C1B 子图集合会随当前关系实时刷新；C1C 允许用户确认、隐藏和恢复共同标签推断关系，并把已确认状态同步用于图谱、动态集合和孤立文件治理。

下一阶段的重点不应继续堆叠图形效果，而应增强图谱对管理行为的驱动：

1. 在已有关系新增/删除基础上补充确认、隐藏和恢复状态；
2. C1C 关系状态治理已完成；集合重命名降为非阻塞易用性增强；
3. 实现“文件 → 图谱 → 思维导图/Canvas → 文件”的可解释往返；
4. 提供孤立节点、失效链接、关系来源、索引覆盖率和图谱健康指标；
5. 可选增加本地语义相似关系，但必须展示来源和置信度，并允许关闭；
6. 在首页、文件详情和搜索结果中持续呈现相关节点，而不是要求用户主动进入图谱页。

这样才能把知识图谱从“一个功能页面”升级为整个管理系统的组织层。

### 4.3 思维导图与图表

思维导图已采用 OPML 作为可交换的数据基础，支持大纲与可视图同步、节点编辑、拖拽、折叠和检索，并能生成 Canvas。它已经满足基础思维导图效果，不再只是静态预览。

图表采用 Mermaid 文本源与渲染结果并存，具备可编辑、可保存和可纳入管理体系的特征。后续专业化工作应集中在模板、快捷创建、布局控制、导出和跨格式引用，而不是另起一套不兼容的数据模型。

### 4.4 PDF、Office 与 WPS

当前策略是安全、诚实且可维护的：

- PDF 提供专业阅读、搜索、批注、OCR 和页面级加工，但不冒充完整 PDF 正文编辑器；
- DOCX/PPTX 只开放经过验证的基础编辑子集，并通过副本保存保护源文件；
- ODF 以预览为主，等待更多生产者证据；
- 旧 Office 格式通过隔离转换；
- WPS 原生格式只提供受控外部打开。

如果未来要求达到 Adobe Acrobat、Microsoft Office 或 WPS 的同等级原生编辑，必须作为独立产品项目评估内核、授权、兼容性和维护成本，不能把它混入当前“日常管理与基础编辑”的收口标准。

### 4.5 数据可靠性

项目已经建立本地可靠写入、签名冲突保护、敏感内容边界、知识索引删除/重建/恢复、管理数据备份导出与恢复、卸载/回滚保留验证等机制。R5L 已把管理备份与索引恢复纳入安装生命周期。

仓库内逻辑和证据结构已经具备，但仍需在隔离 Windows 安装环境中完成最终运行闭环。

## 5. 发布与质量状态

当前阶段是“工程 Beta / Pre-RC”，不能标记为 Release Candidate。

已完成：

- 格式注册表、能力矩阵和分级保存策略；
- 构建、契约测试、性能检查与大量格式专项证据；
- 未签名安装包的工程侧生命周期与工作区烟测准备；
- Windows 10/11 双通道证据导入、拒绝错误通道、签名清单绑定；
- 签名、时间戳、人工批准与最终晋级的 fail-closed 门禁；
- 外部执行手册与脱敏证据结构。

尚未完成：

- 可用的 Windows 10 与 Windows 11 一次性运行环境；
- Windows SDK `signtool.exe`；
- 带私钥的合格代码签名证书与时间戳；
- 两个系统通道的已签名安装、运行、管理备份/恢复、卸载/回滚证据；
- 已签名安装包清单、人工批准和最终 RC 晋级。

R5N 当前环境审计明确记录了 5 个阻塞项，最终晋级预检仍为 `automatedGatesPassed=false`、`promotionEligible=false`、`releaseCandidate=false`。

## 6. 后续开发阶段

### 阶段 A：外部发布执行与 RC 收口（P0）

目标：完成当前已经准备好的发布流程，不再新增重复门禁。

执行顺序：

1. 准备干净的 Windows 11 x64 和 Windows 10 x64 一次性虚拟机或专用 runner；
2. 安装 Windows SDK 签名工具，配置合格代码签名证书和可信时间戳服务；
3. 对专用签名目录中的安装包签名，生成并校验签名安装包清单；
4. 先执行 Windows 11 已签名生命周期，修复仅在 guest 出现的问题；
5. 导入 Windows 11 脱敏证据，再执行并导入 Windows 10 证据；
6. 核对安装、统一工作区、TXT/JSON 编辑、代表性路由、备份恢复、知识索引恢复、卸载与回滚；
7. 全部门禁通过后记录人工批准，重新运行晋级审计；
8. 仅当审计输出允许时，将版本晋级为 RC。

退出标准：

- 两个已签名系统通道均接受；
- 安装包哈希、签名者和时间戳指纹一致；
- 管理备份/恢复和知识索引恢复通过；
- 人工批准存在；
- `promotionEligible=true`，且没有绕过门禁。

### 阶段 B：剩余格式证据闭环（P1）

目标：把现有“有限制”状态中的可验证部分完成，不承诺等价编辑。

任务：

- 将可信 WPS ODF/ODT 生产者证据从 2/3 补齐到 3/3；
- 将 XLSX 数组公式生产者证据从 1/3 补齐到 3/3；
- 建立来自 Microsoft Office、WPS、LibreOffice 和真实用户脱敏样本的回归语料库；
- 对 DOCX、PPTX、XLSX、PDF 页面操作执行跨生产者复开与视觉抽检；
- 将所有失败样本映射为“安全降级、只读或明确阻断”，禁止静默损坏。

退出标准：外部门禁完整，真实样本回归稳定，能力矩阵与实际行为一致。

### 阶段 C：知识图谱产品化（P1）

目标：让知识图谱成为日常入口与管理引擎，而不是独立展示页。

任务：

- 增加关系编辑、关系来源与置信度界面；
- 在首页、搜索结果、文件上下文和任务中显示相关知识；
- 已完成项目笔记、任务、动态子图集合、思维导图与 Canvas 入口，以及共同标签推断关系生命周期；
- 完成图谱、OPML、Canvas 的往返关联与来源追踪；
- 增加孤立文件、断链、重复关系、索引覆盖率等健康指标；
- 评估可选本地语义索引，默认本地、可解释、可关闭。

退出标准：用户无需主动进入图谱页，也能在文件管理主流程中感知并使用关系能力。

### 阶段 D：管理效率与统一体验（P1）

目标：把现有功能骨架打磨成稳定、高频、统一的专业管理体验。

任务：

- 完成所有编辑器的字号、间距、工具栏、空状态和保存状态统一；
- 强化批量标签、批量移动、批量导出、自定义元数据和项目模板；
- 统一快捷键、撤销/重做、自动保存提示和冲突处理；
- 增加首次使用引导、能力边界提示和格式降级解释；
- 完成安装版可访问性、性能和大文件体验验收。

退出标准：高频管理任务可在少量步骤内完成，各格式视图没有明显“拼接感”。

### 阶段 E：可选高级能力（P2，需另行确认范围）

这些能力不应阻塞当前基础目标收口：

- PDF 正文/对象级编辑；
- DOCX/PPTX/ODF 的复杂布局和高级对象编辑；
- WPS 原生格式内核级解析与写回；
- 多人协作、角色权限、云同步和企业审计；
- 插件市场或第三方自动化集成。

进入本阶段前，应分别完成商业价值、授权风险、兼容性成本、数据安全和长期维护评估。

## 7. 推荐的实际推进顺序

真实签名仍是进入 RC 的唯一发布主线，但当前确认没有可用代码签名证书，因此阶段 A 保持 fail-closed 并转为未来外部执行项。仓库内不再增加同类发布脚本，也不以自签名或未签名结果替代正式证据。

当前本机产品收尾主线调整为：

1. 建设真实文件回归语料库；
2. 关系编辑、项目笔记、动态子图集合和关系生命周期已经完成；
3. D1A～D1C 已完成跨编辑器矩阵、结构化源码编辑器、高频复杂工作面和关键键盘焦点收口；
4. D2 跨格式安全降级回归已完成：40 类格式已由机器契约统一验证只读、另存副本、sidecar、外部打开、冲突和失败恢复；
5. D3 最终产品验收已完成并随高级能力增量更新：9 个核心领域已纳入机器总账，40 格式、10 发布配置、6 安全通道及现有真实证据被统一核对；
6. E0 高级能力差距审计已完成：Excel 等价、新格式编辑器、主题扩展和复杂 Office/WPS 已有机器优先级矩阵；

11. 将“产品能力收尾”与“签名 RC 收口”保持为两个明确状态，后者继续为 `false`。

建议决策线：

- 需要尽快发布：先完成阶段 A，再进入 C/D；
- 需要先增强产品感知：在等待外部环境期间推进 C/D，但保持 `releaseCandidate=false`；
- 需要追求 Office/WPS 等价编辑：单独立项阶段 E，不改变基础版的能力承诺。

## 8. 收口定义

“基础需求收口”应同时满足：

- 日常管理、基础编辑、统一工作区和知识组织能力稳定；
- 40 类格式按照明确等级被支持，不发生能力夸大；
- 关键文件写入可恢复、复杂格式默认安全；
- 知识图谱能参与文件、任务、思维导图和 Canvas 的实际管理流程；
- 已签名安装包通过 Windows 10/11 隔离生命周期；
- 发布门禁、人工批准和回滚计划全部成立。

在完成上述最后两项外部发布证据前，可认为“产品能力基本对齐，发布尚未收口”；完成后才可认为这一阶段真正结束。
