# A0X DOCX 超链接显示文字编辑审计

日期：2026-08-04
阶段：UX-33G
结论：代码与自动化证据通过，UX-33 继续进行中。

## 本步完成

- DOCX 页面编辑器可识别正文或简单表格中的单一超链接显示文字，并明确提示“地址保持不变”。
- 编辑只进入内存草稿；撤销、重做、单项/批量隔离验证、覆盖原文件和另存副本继续复用既有可靠事务。
- 后端只替换 `word/document.xml` 中唯一 `<w:t>` 的文本字节；语义复读同时核对 `hyperlink-label` 载体，链接外壳和目标属性必须保持原字节。
- 超链接目标不开放字符格式工具，避免改动链接样式、关系或其他运行属性。

## 安全门禁

仅开放一个段落内恰好一个 `<w:hyperlink>`、一个运行、一个文本节点，且链接具有非空 `r:id` 或 `w:anchor` 的情况。以下内容继续只读：

- 无目标、多个或嵌套链接；
- 链接与普通正文混排、跨运行显示文字；
- 字段型链接、修订、内容控件、批注、脚注、尾注、书签、绘图和浮动对象；
- 链接地址、关系部件和链接字符样式。

## 验证证据

- `cargo test --manifest-path src-tauri/Cargo.toml docx --lib`：31 项通过。
- 新增三类生产者派生包往返：Microsoft Word、WPS Writer、LibreOffice Writer 的真实 fixture 仅注入内部锚点链接外壳，再验证标签替换、语义复读和文本节点两侧逐字节不变。
- 新增拒绝测试：无目标链接与多链接段落不能进入可编辑目标。
- 生产构建和 DOCX 页面/批量/当前格式契约均作为提交前门禁执行。

这里的三生产者证据是基于真实生产者包的确定性派生测试，不等同于三款 Office 原生创建、保存并重开的超链接兼容证据。
