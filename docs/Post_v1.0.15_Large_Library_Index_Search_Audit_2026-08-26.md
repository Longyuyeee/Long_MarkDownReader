## 1. 开发目标

使用 100 个真实目录中的 10,000 个物理文件验证资料库索引，而不是用内存循环代替文件系统。格式按 Markdown、TXT、JSON、YAML 均匀分布，固定唯一检索词、关系链和逐文件 SHA-256 清单。验收覆盖首次构建、已建索引查询、外部变化检测、过期查询、单文件刷新、主动取消、进程重启复用、720px 布局与源文件不变。

冻结预算位于 `shared/post-v115-large-library-index-policy.json`。修复前与修复后使用同一生成器、同一命令和同一测量脚本；证据位于 `docs/evidence/post-v115-large-library-index/`。

## 2. 修正前实际

| 项目 | 目标 | 修正前实际 | 结果 |
| --- | ---: | ---: | --- |
| 首次完整构建 | <= 12,000 ms | 15,796 ms | 未通过 |
| 已建索引查询 | <= 500 ms | 4,229 ms | 未通过 |
| 外部变化检测 | <= 1,500 ms | 3,574 ms | 未通过 |
| 过期状态查询 | <= 5,000 ms | 9,001 ms | 未通过 |
| 单文件刷新 | <= 2,000 ms | 15,926 ms | 未通过 |

根因是每次状态和查询都重新读取 12 MB 快照并扫描全部来源；单文件变化触发完整图谱与搜索段重建；图谱重复递归目录；运行时没有快照缓存、文件变化事件或取消令牌。直接把 10,000 文件资料库交给 Library 自动准备时还观察到单核持续占用和长时间无响应，因此性能命令使用空壳资料库隔离前端自动索引竞争，并直接对同一真实大库调用 Tauri 后端命令。这个隔离用于定位后端差异，不替代 720px 截图和真实进程重启。

## 3. 实现与安全边界

- 运行时缓存已验证快照，查询不再重复解析磁盘快照。
- `notify` 递归监视资料库，只记录真实变化路径；状态检查无需扫描 10,000 个文件。
- 单个安全文本文件变化使用覆盖搜索段和增量快照；新增、删除、多文件变化、sidecar、Office/ODF 或含关系语义的 Markdown 继续全量重建。
- 过期查询只覆盖变化文件；无法证明覆盖安全时退回实时完整搜索。
- 图谱首次遍历同时建立 Markdown 名称索引和文件清单，后续直接消费清单。
- 构建支持显式停止；取消后不发布半完成快照，界面显示“已停止”，不会自动重新开始。
- 所有索引、查询、取消和重启步骤前后，fixture manifest SHA-256 必须一致。

## 4. 修正后实际

最终候选由真实 Tauri debug 程序执行；它保留调试开销，因此不优于正式安装包。正式 release 二进制已成功构建，但自动化启动被当前已安装实例的单实例锁接管，且 E2E 配置按设计只在 debug 生效；本轮没有关闭用户正在运行的软件来伪造 release 测量。

## 6. 需求对齐与下一步

本阶段强化的是专业知识工作区的基础性能与可控性，没有增加无意义入口，也没有扩大格式写回声明。索引仍是本地缓存，不修改用户正文；所有格式继续遵守“内存编辑，点击保存才写回”的基本需求。

大库索引基线已收口。下一步按路线图进入 **M1B2A DOCX 生产者对象选择审计**：使用真实 Microsoft Word、WPS Writer 与 LibreOffice Writer 样本，先比较页眉页脚、表格、图片布局、段落样式和超链接的当前解析与目标差异，再选择最小安全实现范围。当前版本保持 1.0.15，不打包、不更新 Release，`releaseCandidate=false`。
