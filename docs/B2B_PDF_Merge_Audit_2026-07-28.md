# B2B PDF 多文件有序合并阶段审计

> 审计日期：2026-07-28
> 产品基线：LongEdit `v0.7.0`
> 开发分支：`main`
> 阶段状态：B2B 已完成，下一开发入口为 B2C PDF 插入页面

## 1. 阶段结论

B2B 已交付 Library 内多个 PDF 的显式有序合并。用户可以加入 2～16 个 PDF、调整文件顺序、先在内存中构建并验证合并副本，再创建新的 PDF 并自动重开。整个流程不覆盖任一源文件，也不覆盖已有目标文件。

本阶段仍是经过门禁的页面级安全编辑子集，不代表 PDF 正文、表单、签名或 Acrobat 等价编辑能力。

## 2. 已交付能力

- 当前 PDF 自动成为合并输入，用户可通过系统选择器或 Library 内路径加入其他 PDF。
- 输入文件可显式上移、下移和移除；输出页面严格按文件顺序及各文件内部页序拼接。
- 后端统一执行知识库路径守卫、PDF 扩展名和文件签名检查，拒绝重复输入及处理中变化的源文件。
- 单批限制为 16 个输入、128 MiB 总输入、20,000 页；加密、损坏、超预算和现有高风险兼容对象稳定阻断。
- 隔离构建重建单一 Catalog/Pages 树，重新编号跨文件对象，并把页面继承的资源、MediaBox、CropBox 和 Rotate 物化到叶子页面。
- 保存前校验结构页数、跨输入文本顺序、页面尺寸、裁剪框和旋转；输出摘要与保存请求绑定。
- 保存采用只创建新文件策略，拒绝覆盖任一源文件或已有目标；落盘后逐字节复读，并再次验证结构、文本和页面几何。
- 保存成功后清空合并草稿并自动重开新文件，避免离开保护误拦截已完成操作。

## 3. 安全边界

- 源文件是事实源，B2B 不提供原地覆盖或增量更新。
- 当前文件必须出现在合并输入中，所有输入和目标都必须位于同一 Library 安全边界内。
- 数字签名、表单、附件、加密、线性化、增量更新和无法可靠解释的复杂对象继续沿用 B1C 兼容阻断策略。
- 输出只承诺页面级顺序、文本、尺寸、裁剪框、旋转和可重开性；不承诺高级交互对象跨文档合并。

## 5. 下一阶段

唯一开发入口切换为 **B2C PDF 插入页面**：

1. 选择一个来源 PDF 和明确页范围。
2. 指定插入到当前 PDF 的页前、页后或文档末尾。
3. 复用 B2B 的跨文档对象重编号、继承值物化、预算、兼容画像和源文件不变证明。
4. 验证插入点前后页面顺序、文本、尺寸、旋转及保存后重开。
5. 继续只创建新 PDF，不覆盖源文件或已有目标。
