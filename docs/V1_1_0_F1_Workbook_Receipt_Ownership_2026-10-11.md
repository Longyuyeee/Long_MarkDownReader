# F1 工作簿保存回执归属保护

日期：2026-10-11；基线 `4b02eb4f`；目标 1.1.0，未封板。

## 本轮实现

工作簿的既有 generation 也会在切换工作表时递增，不能直接用它判断整本工作簿是否已经替换。本轮增加独立文档 epoch，在 loadWorkbook 开始和卸载时递增。保存捕获工作簿对象、路径、资料库和 epoch；回执只有仍属于该文档时才能应用。离开/替换后不清另一本文档的草稿或撤销记录。

保存接入 beginWindowSave，保护持续到成功、失败或回执协调结束；组件卸载不会提前释放。失败提示包含原提交文件名，避免导航后误认失败对象。未调整页面布局、输入禁用策略或草稿清理策略。

**这不是工作簿后续草稿问题的完整修复。** 同一工作簿成功回执仍清理草稿和撤销栈；切换工作表后回执仍恢复提交前工作表。下一步需按实际可达入口及撤销语义处理，不能通过本轮归属保护宣称这些风险已经消失。

## 审计纠偏与下一步

实际页面确认公式输入框在 saving 时原本就禁用。本轮没有新增此限制。之前直接向草稿 Map 加入编辑的模拟用例证明成功回执缺乏批次区分，但不能单独证明用户能在保存期间继续输入公式栏。保留这份历史证据，同时把入口可达性与代码鲁棒性分开描述。

下一步盘点保存期间仍可触发的工作表切换、撤销/重做、样式、合并、条件格式及异步对话框入口，复现真实用户路径后设计提交快照与后续草稿/历史协调；不能只比较 dirty 数量，也不能简单重复提交旧对象操作。然后补跨实例重开与后台原生落盘验证，继续跨窗口确认及归档闭环。

本轮页面是模拟 IPC，不是真实 XLSX 写盘或原生多窗口验收；外部工作簿只读边界未改变。F1 及整体计划尚未完成，版本不变、不发布。
