## 安全的外部 API 故障注入

启动命令：`node node_modules/vite/bin/vite.js --config scripts/vite.version-audit.config.ts --host 127.0.0.1 --port 9000 --strictPort`，配合既有独立标识测试程序。

此专用 Vite 配置仅替换 `appUpdater.ts` 的两个外部依赖导入（Tauri invoke 与系统 opener），不修改组件、computed、更新状态流转或实际运行版本。桥接脚本从真实运行时读取版本和应用标识，仅允许 `com.longyuye.mdreader.version-audit` 的开发模式使用；始终拒绝安装。未涉及的 IPC 仍转发真实后端。

被 Git 忽略的 `version-audit.local/scenario.json` 选择外部结果：`check` 为 `offline` / `available` / `current`，`open` 为 `failure` / `success`。模拟更新明确写“验收模拟发布”，不是 GitHub 新 Release。修改场景后由用户界面的“检查更新”触发，不直接赋值响应式状态。

普通 `vite.config.ts` 和产品源码不引用该测试配置。专用配置拒绝 build，已实际运行构建命令确认报 `Version audit fixture cannot build production assets`（预期退出码 1）。8 项隔离/禁安装/错误传播/真实版本保留测试和 13 项产品状态回归通过。

## 观察顺序与判定

1. “我暂时没网，想检查更新”：手动检查应呈现失败并保留当前版本；不能伪装最新，也不能出现下载按钮。
2. “恢复网络后再试”：切到 current 后点击检查，应恢复已是最新，清除检查错误。
3. “有新版，先看看改了什么”：切到 available 后检查，当前版本保持 1.0.22、目标 1.0.23；弹窗不冒称已安装。
4. “发布详情打不开”：点击详情触发 opener 失败，应保留更新弹窗、可安装状态并独立解释失败。不要实际点击安装。
5. “再打开一次”：切到 opener success 后从同一按钮重试，应清除网页错误并保留更新状态。

本专项输出必须标注“原生操作 + 外部 API 故障注入”，不能作为真实断网、真实系统浏览器失败、正式安装或升级成功的证据。
