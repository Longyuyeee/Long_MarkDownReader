# M4F-6 v1.0.15 → v1.0.16 官方应用内更新观察

日期：2026-08-31

状态：**真实托管执行待运行**

## 开发目标与需求对齐

本阶段只验证已经公开的两个官方 Release 之间的应用内更新，不构建新安装包、不改变产品功能，也不复用 M4F-3 的直接安装升级冒充更新器结果。真实验收必须覆盖：

1. 已安装 v1.0.15 从 GitHub latest API 发现 v1.0.16。
2. 用户确认前不得下载或启动安装器。
3. 确认后下载官方 NSIS，并在安装前核对 65,788,796 bytes 与 SHA-256 `e1a688…`。
4. 在同一安装目录静默覆盖到 v1.0.16，并由更新链自动重启。
5. 首次启动后设置页显示当前已是最新 v1.0.16。
6. 合成资料库、配置以及卸载后的用户数据保持。

所有执行只允许在 GitHub 托管的一次性 Windows 上进行，不触碰当前用户主机的已安装软件和资料。

## 预期与实际差异

入口审计发现旧工作流把 Release API 的 `target_commitish` 当作 Tag 对应提交。v1.0.16 的实际 API 字段为 `main`，但 annotated Tag `v1.0.16^{}` 正确指向产品提交 `757d54309ddb35f445344d909fa4c7ba2567bc58`。新工作流因此显式 fetch 并解引用 Tag，`target_commitish=main` 只作为实际观察记录，不再错误要求二者相等。

其他预期与实际差异必须等真实运行后补录；任何失败都保留为证据并修正后重跑，不把部分通过写成发布后更新链收口。
