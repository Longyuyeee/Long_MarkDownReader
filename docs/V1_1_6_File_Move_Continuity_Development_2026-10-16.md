## A：统一历史迁移（2026-10-16）

实际代码发现单项改名/拖动各自移动一个路径对应的历史目录；批量/撤销另行递归，目录读取和历史迁移失败均可能被忽略。机械抽取原 `move_to` 行为后，真实磁盘测试先运行：校正为生产使用的 Windows 规范路径后，5 项中 **3 项失败、2 项通过**，确认目标历史占用、来源没有历史却接上目标旧历史、嵌套目录中历史冲突都仍被报告成功。

第一轮 4 个失败中另有 1 个夹具问题：用带 `/` 的字符串构造历史键，与真实目录枚举的 Windows 路径不同。仅统一夹具为规范根及逐层路径连接后，该成功/撤销用例在旧实现也通过；它不计为修复的产品缺陷。两轮失败原日志均保留。

实现 `services/file_move_history.rs`：

- 单项改名、拖动移动、批量、目录移动和撤销统一经过 `file_management::move_to`；仍使用原有授权目录、历史租约、系统级禁止覆盖改名及手动关系维护，不改变 IPC 参数或新增 UI。
- 完整枚举目录，不忽略读取异常；检查每个来源历史、目标历史和快照摘要。目标哪怕是空历史目录也不会静默合并；来源没有历史时也禁止接上同名旧文档历史。
- 单次目录至多 20000 项、历史总计 64 MiB/20000 快照；复用原历史检查的普通文件、数字快照、符号链接和单份 1000 快照边界，不以无限扫描换取“安全”。
- 历史先通过禁止覆盖的移动接续；中途失败或正文/关系移动失败时，在位置明确的条件下逆序回退本次历史迁移。回退遇到其他写入者的新历史不覆盖，原快照保留并明确要求核对，不宣称全恢复。
- 正文位置已不明确时，不把历史盲目搬回，也不声称原位置未变化。保留现有材料和具体错误；**完整中断日志、状态恢复以及前端“需核对”与可重试项的区分尚待本版后续完成**。

## B：只读引用影响计划（2026-10-16）

新增 `services/file_move_links.rs`，复用既有引用解析、源范围验证、SHA-256 和相对路径计算。旧归档预览的只读边界没有删除或放宽；新计划也始终 `can_execute=false`，没有注册写入 IPC、移动文件或写回正文。

- 对单次文件/目录移动投射全部普通 Markdown 引用：移动文档的出站引用与其他文档的入站引用同时检查；目录内一起搬动的相对引用保持不变，外部共享资源只计算新引用，不移动资源。
- 使用可见资料范围，排除 `.longedit`、隐藏记录和 `.assets` 目录里的 Markdown；不修改回收内容或历史。原 `archive_dependencies::scan` 行为保持，新增可见范围入口，不改写其“未穷尽语法”的原有事实。
- 原样保留代码示例、远端/data/锚点引用；支持已验证的普通相对路径、中文/空格编码、查询和片段。缺失目标、歧义 Wikilink、没有安全编辑范围的引用定义/HTML 等明确列为需核对，不猜测替换。
- 复用单份 2 MiB、总计 32 MiB Markdown、20000 项目录/候选预算；再次读取源文也有硬上限并校验摘要。未承诺任意语法、其他格式入站引用或跨库移动；计划明确携带范围限制，不把 blocker 为空当成写入许可或整批必然成功。

新增 **11 项真实磁盘只读回归通过**，完整功能 **750 通过、0 失败、5 个既有 ignored、1 项独立性能未在该命令执行**；本批完整 `npm run ci:patch-release` 再次通过，生产依赖 0 漏洞。所有测试检查原文/资源仍在原位置。[本批证据清单](evidence/v116-link-plan-development/summary.json) 区分原生只读证据和 UI 提案。执行保护、持久中断恢复、真实安装器及新界面仍未完成。

正式改 UI 前已提供 [HTML 示意](../design/v116-move-continuity-proposal.html) 与 [示意图](evidence/v116-link-plan-development/move-proposal.png)，明确标注不是运行软件截图：沿用移动/改名弹窗，仅补充有关引用说明；部分失败区分“已完成／未执行／需核对”，只有已确认未执行项可以直接重试。已请用户确认，正式产品 UI 尚未修改。用户确认不等于已具备安全写回权限。

下一执行批次必须注意：现有 `archive_confirmation::WindowRegistry` 和 App 的窗口回复只观察版本/草稿，不冻结编辑；`document_coordination` 是进程内排斥，`reliable_write` 是文件写入原语，都不能独立当成完整移动事务。不得直接启用旧 `preflight_archive` 的 can_execute，也不得因几次只读回归通过就把无保护正文改写接到移动按钮。需围绕原操作建立有界且可取消的受影响文档保护、执行前身份重验、持久日志和可核对恢复状态，再连 UI。

## C1：中断证据与安全重试边界（2026-10-16）

复现“目录第一份历史已移动、下一份尚未执行时中断”：旧实现没有持久意图，原生回归按预期失败（0/1 通过），不是 UI 夹具推断。新增 `file_move_journal.rs` 并接入 A 的真实历史迁移：

- 在第一处历史/文件变动前，将原路径、目标路径、每份历史的路径及快照摘要写入应用历史缓存 `.file-moves/.move-stage-*/intent.json` 并同步文件；不夹带正文或快照正文。它不是另一套归档功能，也不新增用户操作步骤。
- 已明确完成或进程内完整回退后，写入绑定原意图 SHA-256 的终态，再退役记录。清理仅删除本次已知记录文件，不递归删除未知内容；清理失败留下已完成材料，不把完成操作再执行一次。
- 中断、位置不明、回退受阻或完成记录写入失败时保留材料，错误具有 `needsReview` 和记录编号；确定没有执行或已完整回退才是 `notExecuted`。批量移动、改名、撤销保留类型，不从中文错误文案猜状态；单项旧 IPC 参数及字符串错误兼容。
- 重新读取待核对记录时只检查，不自动回放、回退或替用户保存；同一路径、父子路径和 Windows 大小写别名阻止再次移动。已知无关路径仍可操作。损坏/未知记录保守阻止；普通“清空历史”也不能抹掉待核对材料。
- 回退前再次验证已搬动历史的完整清单/摘要；其他写入者改变了内容时留在当前位置并要求核对，不盲目搬回然后宣称已恢复。
- 单份意图最多 16 MiB、总读取 32 MiB、待核对 128 项、目录检查 1024 项；历史原有预算仍保留。记录文件 `sync_all` 与进程重启留痕不等于 Windows 断电下的多文件原子事务，也不构成跨进程编辑锁。

本批最终文件移动相关 **35 项通过**（历史 16、日志 8、只读引用 11），完整原生功能 **762 通过、0 失败、5 个既有 ignored、1 项独立性能未在该命令执行**；完整 `npm run ci:patch-release` 通过，生产依赖 0 漏洞。中途一次 34/1 失败来自 Windows verbatim `PathBuf::join` 已规范化 `..` 的夹具构造；改用原始持久字符串真实测试路径穿越，没有删断言或放宽校验。此前一次缺失 `Debug` 的编译错误也保留在开发原日志，不计为产品故障。

证据清单见 [C1 原始日志及摘要](evidence/v116-move-recovery-development/summary.json)。本批不改产品 UI，未实现引用写回；日志暂不提供用户核对/恢复入口，前端对 `needsReview` 的展示和排除重试是紧接的 D1，不因后端阻止了重试便声称交互闭环。之后仍须补齐受影响草稿/保存与多窗口短暂冻结、完整正文/关系/历史协调和固定安装版验收。
