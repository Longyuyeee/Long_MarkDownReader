# B2A PDF 页范围提取阶段审计

> 审计日期：2026-07-28
> 产品基线：LongEdit `v0.7.0`
> 开发分支：`main`
> 起始提交：`bdf3413 feat: close PPTX basic editing release stage`
> 对应需求：`FR-PDF-008`

## 1. 阶段结论

B2A 已完成。LongEdit 现在可以在现有 PDF 页面整理工作面中输入显式页范围，例如 `1-3,5,8-10`，按用户给出的顺序生成新的 PDF。整个流程复用 B0～B1C 的页面计划、兼容画像、隔离构建、可靠另存、结构复读和应用内重开能力。

本阶段只创建新文件，不覆盖源 PDF 或已有目标，也不把页面提取描述为 PDF 正文编辑。下一开发入口为 **B2B PDF 合并**。

## 2. 已交付能力

- 页范围解析支持单页、连续范围和逗号组合，并保留输入顺序。
- 空范围、格式错误、降序范围、零页、越界页、重复页和完整自然顺序复制会被稳定拒绝。
- 前端将提取范围转换为完整页面计划，提取页置前，其余页面标记为排除。
- 后端使用独立的页范围提取命令再次校验页数、范围、重复项和源文件状态，不信任前端计划。
- 验证动作只生成内存隔离副本，并复读页数、文本和结构摘要。
- 保存动作采用同目录新文件、无覆盖和可靠落盘策略；成功后在应用内重开新 PDF。
- 加密、损坏、超预算和不兼容输入继续沿用 B1C 的稳定阻断策略。

## 3. 安全与兼容边界

| 项目 | B2A 结论 |
|---|---|
| 源文件 | 保存前后字节摘要一致，不修改 |
| 目标文件 | 只允许创建不存在的新 PDF，不静默覆盖 |
| 页面顺序 | 以用户输入顺序为准 |
| 最少输出 | 至少 1 页 |
| 完整复制 | 引导用户使用页面整理，不重复提供无变化提取 |
| 加密/损坏输入 | 在写入前阻断 |
| 正文、表单、签名 | 不编辑；仍属于后续独立能力 |
| 合并/插页 | 未包含，分别由 B2B/B2C 交付 |

## 4. 自动化与桌面证据

- 前端生产构建：`npm run build`
- 页计划契约：`npm run check:pdf-page-plan-contract`
- Rust B2A 回归：页范围计划校验、真实两页 PDF 提取、文本复读、源文件不变和目标无覆盖
- 真实桌面审计：`npm run audit:b2a-pdf-page-extraction`
- 证据复核：`npm run check:b2a-pdf-page-extraction-evidence`
- 全量门禁：`npm run ci:check`

最终 `ci:check` 通过：Rust 主回归 349 项通过、性能门禁 1 项通过，100 MiB PDF 范围读取基准约 91 ms，生产依赖审计为 0 漏洞。

真实 Tauri WebView2 审计通过 6 项检查并生成 3 张截图，覆盖 1280×820 页面计划/隔离验证和 960×720 保存重开。证据位于 [`docs/evidence/b2a-pdf-page-extraction`](./evidence/b2a-pdf-page-extraction/)。

桌面审计使用两页真实 PDF，选择第 2 页后生成 `B2A Extracted Page 2.pdf`。输出以 1 页 PDF 重开并显示 `Second Page Beta`，源文件 SHA-256 保持不变；紧凑视口同时检查页面宽度、工作面宽度和工具栏标签几何，未发现横向溢出或文字竖排。

## 5. 下一阶段

下一批只处理 **B2B PDF 合并**：

1. 允许选择多个 PDF，并在写入前显式调整输入顺序。
2. 每个输入执行路径、签名、大小、页数、加密和兼容画像校验。
3. 仅生成新的目标 PDF，拒绝覆盖任一源文件和已有目标。
4. 验证合并后总页数、跨输入页面顺序、页面尺寸/旋转、资源继承、文本和结构复读。
5. 覆盖损坏、加密、重复输入、超预算和处理中源文件变化等失败路径。
6. 完成真实桌面保存重开、阶段审计、完整 CI 和 GitHub Quality Gate 后，再进入 B2C 插页。
