# Workbook 数据验证编辑目标保护

日期：2026-10-11。承接格式/填充边界审计，目标版本仍为 1.1.0，未封板。

## 最新接续：数据验证写入回执归属

`commitDataValidationChange` 过去会在异步写入后无条件替换工作簿并清空撤销栈。本步捕获原工作簿对象、路径、资料库和文档 epoch，写入返回后仅在归属仍一致时应用结果；替换文档或卸载后的旧回执不再修改当前文档/历史。增加保存中入口防护，接入 `beginWindowSave`，成功、失败、过期结果均释放窗口在途登记。失败提示带原文件路径，避免导航后误认失败对象。

验证：`test-workbook-edit-boundaries.mjs` 9 项通过（新增成功、替换文档、epoch 变化、失败四种回执场景），`vue-tsc --noEmit` 通过。后台实际 WorkbookView 的规则创建、取消、删除失败后保留规则及再次删除成功全部通过；已查看 [写入失败页面](evidence/v110-workbook-validation-browser/03-write-failure.png)，原文件错误信息、原规则与重试入口可见。没有接管桌面，模拟 IPC 失败不是原生磁盘失败验收。

边界：本步只保护写入返回时的文档归属，不代表随后回读的全部异步链路已协调。同一工作簿写入期间切表、回读期间导航/切表、后续草稿历史和其他对象写入仍待审查。下一步优先解决规则写入后的切表/回读协调，再扩展其他入口；F1 与原生持久化验收仍未完成，未封板。

## 后续修复：未修改的旧值不作为新输入校验

已定位上一轮截图中的误报：`commitDataValidationChange → restoreTableSelection → recalculateLoadedFormulas → commitFormulaInput` 在回读后自动提交公式栏。该栏虽然没有变化，原代码仍按新列表规则校验旧值，导致成功与错误提示并存。

现于 `commitFormulaInput` 校验前比较输入与当前有效单元格内容；未变化则直接返回，不新增草稿、撤销记录或错误。真实的新非法输入仍报错且不提交，合法输入仍形成可撤销草稿；不删除规则、不放宽列表校验。

验证：边界测试现为 8 项通过，类型检查通过。后台实际页面创建列表后无错误提示；手工式输入“其他状态”会显示既有错误文案且单元格保持原值，Escape 放弃输入后可继续取消/确认删除。测试额外断言错误观察器能捕获真实非法输入，避免无效监听造成假通过。已重新查看删除确认截图，说明和按钮正常；截图更新为修复后状态，修复前图片可从提交 `5f0db2ca` 查看。

本步不改布局、不接管桌面。测试依然是实际 Vue 页面配合模拟 IPC，不代表原生 XLSX 写盘验收。接下来继续数据验证写入回执归属、条件格式/对象异步入口及草稿协调；未封板。

## 代码审计与本步修复

原有 `editDataValidationRule` 在多步弹窗结束后直接使用当时的 `activeSheet`，同时沿用打开时的规则索引/范围；删除确认回调也混用了这两种时间点的状态。若等待期间编辑上下文变化，存在操作其他目标的风险。

本步在 `WorkbookView.vue` 中：

- 数据验证每一步弹窗返回后复核最初捕获的编辑上下文，失效则提示重新设置并停止后续弹窗。
- 最终创建/编辑提交前再次复核；删除确认捕获原上下文，确认时失效则不提交。
- 取消操作仍安静退出，不写入、不当作输入错误。正常参数及原生写入合同不变。

保留原布局与所有入口，不新增 UI 设计。符合原计划的本地文件安全与显式确认要求，不把本步描述为完整保存协调。
