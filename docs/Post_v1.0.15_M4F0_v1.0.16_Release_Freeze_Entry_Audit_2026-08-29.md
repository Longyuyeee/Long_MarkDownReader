# M4F-0 v1.0.16 发布冻结入口审计

日期：2026-08-29

阶段：M4F-0

结论：产品范围冻结，允许进入原子版本迁移；尚未修改版本、构建候选或成为发布候选

## 原始需求与冻结对象

原始 M4 要求在跨格式工作流、证据清理和能力事实决策之后才进入发布冻结。M4E-0 已确认累计价值达到 v1.0.16 阈值，因此本阶段把精确产品提交 `7e10c340fa0d528b598c9ca6be391c48b15a463f` 冻结为功能范围基线。选择时该提交与 `origin/main` 一致，工作区干净，仓库不存在 `v1.0.16` Tag。

冻结的含义是后续候选不得混入新功能。M4F-0 自身只增加审计、证据、门禁和交接文档，不修改运行时版本或构建安装包；如果后续发现产品缺陷，必须退出当前候选、修复、重跑相关审计并重新冻结。

## 原子版本迁移范围

实际扫描得到 44 个必须在同一提交迁移的版本文件：

- 6 个主事实源：`package.json`、`package-lock.json`、`src-tauri/Cargo.toml`、`src-tauri/Cargo.lock`、`src-tauri/tauri.conf.json`、`shared/development-version-policy.json`；
- 38 个当前仍以 `appVersion=1.0.15` 与运行时版本绑定的共享能力、图谱、R4/R5、Windows、社区发布和能力矩阵合同。

五个 post-v1.0.15 历史基线策略保持 1.0.15，不参与迁移：M0 基线、显式保存对齐、M2A2、M2A3 和 M2 退出。它们记录“从 v1.0.15 之后开始”的历史事实，不是当前二进制身份；机械改写会破坏证据语义。

M4F-1 还必须把社区发布策略重置为 `v1.0.16-community-release-quality-gate-pending`，当前公开版本继续是 v1.0.15，发布能力矩阵和开发界面可以显示 1.0.16 候选准备中，但 `releaseCandidate=false` 保持不变。

## 当前运行烟测纠偏

M4E-0 曾把门禁简称为“当前版本 R5E 运行路由烟测”。实际代码显示 R5E 是 2026-07-31 留下的历史失败证据，状态为 `browser-preview-runtime-smoke-blocked-by-tauri-api-dependencies`；它的检查器通过只表示失败记录真实，不能证明 v1.0.16 当前候选可运行。

本次将发布门禁纠正为：在版本迁移后的候选提交或候选产物上，重新执行 R5F 浏览器路由挂载合同，并执行 R5G 桌面路由、TXT/JSON I/O 与性能导出烟测。历史 R5E 继续保留，不篡改为成功证据。
