## 1. 指导目标

本文档把“覆盖日常管理和基础编辑，并把内容进行成体系管理”的基础需求拆成可连续交付的开发步骤。后续开发不再按单一技术模块无限深入，而是按用户可以完成的完整任务闭环推进：

```mermaid
flowchart LR
  A["发现并识别文件"] --> B["应用内阅读"]
  B --> C["完成基础编辑或批注"]
  C --> D["安全保存并重开"]
  D --> E["搜索、分类与再次定位"]
  E --> F["加入集合、引用或关系"]
  F --> A
```

一个阶段只有同时打通识别、打开、使用、保存、搜索和再次定位，才算形成产品交付。仅完成解析器、模型、内存预览或格式登记，不得标记阶段完成。

## 2. 全程执行原则

### 2.1 产品优先级

1. P0：数据安全、原文件不损坏、外部冲突不丢失。
2. P1：日常格式覆盖、阅读体验、基础编辑、可靠保存。
3. P1：统一文件管理、全文搜索、集合和再次定位。
4. P2：格式内部的专业增强能力。
5. P3：高级 Office 等价、自动化和 AI 增强。

在阶段 A～C 完成前，Excel Pivot、高级图表对象和其他单格式深层能力只处理缺陷与数据安全问题，不继续作为唯一开发主线。

### 2.2 垂直切片

每个格式按以下顺序开发：

1. 真实格式与许可证审计。
2. 在共享注册表中声明 `planned`。
3. 完成文件识别、大小限制、外部授权和错误降级。
4. 完成只读解析、预览和真实 fixture。
5. 接入搜索、最近文件和统一打开。
6. 完成受限编辑、可靠保存、冲突检测和语义重读。
7. 达到全部门禁后才把能力改为 `supported`。

禁止先登记为 `supported` 再补实现。

### 2.3 事实源与分层

| 层级 | 当前入口 | 后续职责 |
|---|---|---|
| 共享能力契约 | `shared/file-formats.json` | 扩展名、MIME、大小、路由、能力和适配器事实源 |
| 前端格式消费 | `src/config/fileFormats.ts` | 类型、能力展示、最长扩展名匹配和路由 |
| 前端工作面 | `src/views/` | 阅读、编辑、状态栏和用户交互 |
| Rust 格式层 | `src-tauri/src/formats/` | 解析、序列化、结构验证和保真规则 |
| Rust 命令层 | `src-tauri/src/commands/` | 权限、参数、事务编排和 Tauri 边界 |
| 安全与持久化 | `services/workspace_guard.rs`、`reliable_write.rs` | 路径授权、冲突检测、临时文件和可靠替换 |
| 索引与管理 | `services/knowledge_index.rs`、`commands/search.rs`、`commands/workspace.rs` | 搜索段、对象定位、集合和工作台 |
| 自动化门禁 | `scripts/`、`package.json` | 契约检查、构建、测试、性能和发布审计 |

新业务不得继续堆入 `LibraryMode.vue`、`lib.rs` 或单个巨型命令文件。公共编辑能力放入 composable、组件或服务；格式语义留在独立格式模块。

## 4. 阶段 A：统一文本与 JSON 闭环

这是下一开发主线，对应 `FR-TEXT-001～006`、`FR-JSON-001～006`、`FR-DEV-001` 和 `FR-MANAGER-001`。

### A0：格式契约和能力展示升级

目标：先让系统能够准确表达“识别、预览、基础编辑、批注和安全保存”，避免继续用单一 `edit` 布尔语义误导用户。

开发任务：

1. 审计 `shared/file-formats.json` schema v1 的字段是否足以表达预览、批注、导出、保存和敏感索引策略。
2. 如需 schema v2，先为前后端增加兼容解析，再迁移数据，不直接破坏 v1。
3. 前后端文件匹配统一改为“最长扩展名优先”，不能依赖注册表排列顺序。
4. 新增格式能力徽标模型：完整编辑、基础编辑、阅读/批注、仅预览、外部打开、不支持。
5. 文件树、标签页和工作面状态栏消费同一能力模型。
6. 未支持文件仍显示在目录中，并提供外部打开和复制路径。

重点文件：

- `shared/file-formats.json`
- `src/config/fileFormats.ts`
- `src/views/LibraryMode.vue`
- `src/router/index.ts`
- `src-tauri/src/formats/file_registry.rs`
- `src-tauri/src/commands/files.rs`
- `scripts/check-format-contract.mjs`

测试门禁：

- `.table.json` 必须优先于普通 `.json`。
- `.canvas` 使用专用工作面，不能进入通用 JSON 编辑器。
- 大小写扩展名、伪扩展名和扩展名冲突有回归测试。
- `planned` 和 `unsupported` 不能出现可写保存入口。

退出条件：前后端能力声明一致，未知/只读/部分编辑状态可见，最长扩展名匹配不依赖数组顺序。

### A1：可靠文本读取与保存内核

当前风险：现有 `read_text_document` 能检测编码，但 `write_text_document` 始终调用 `write_utf8`。直接扩展更多文本格式会导致原编码、BOM 和换行符策略丢失。

目标：建立所有开发文本格式可复用的无损基础。

开发任务：

1. 新增 `TextDocumentSnapshot`：
   - 规范路径。
   - 内容签名。
   - 检测到的编码及置信状态。
   - BOM 类型。
   - 主换行符 `LF/CRLF/CR`。
   - 是否有末尾换行。
   - 文件字节数、只读原因和修改时间。
2. 读取时区分“确定编码”“用户需要确认”“二进制/拒绝”。
3. 写入命令必须携带读取签名和保存策略，拒绝静默覆盖外部修改。
4. 保存默认保留原编码、BOM、换行符和末尾换行；转换编码必须是显式命令。
5. 将 `reliable_write.rs` 的可靠替换用于最终字节，写后重新读取并验证。
6. NUL、损坏编码、超限文件和只读权限返回结构化错误。
7. 大文件增加按字节范围读取接口；超过编辑阈值默认进入渐进只读模式。

建议模块：

- 新增 `src-tauri/src/formats/text.rs`
- 扩展 `src-tauri/src/commands/formats.rs`
- 新增 `src/types/textDocument.ts`
- 新增 `src/composables/useTextDocument.ts`

真实 fixture：

- UTF-8、UTF-8 BOM、GB18030/GBK 可判定样本。
- LF、CRLF、混合换行、无末尾换行。
- 空文件、大文件、NUL 文件、无效字节序列。
- 外部修改、写入中断和只读文件。

退出条件：打开、编辑、保存、重开后编码与换行策略符合用户选择；外部冲突不会被覆盖；失败不会损坏源文件。

### A4：日志、YAML、XML、TOML 和配置格式

开发顺序：

2. `.yaml/.yml`：源码编辑、语法校验和结构大纲。
3. `.xml`：源码编辑、折叠、格式化和树形只读预览。
4. `.toml/.ini/.conf/.properties`：语法高亮、键值搜索和编辑。
5. 常见代码扩展：先识别、阅读、语法高亮和搜索，再开放轻量编辑。

敏感文件规则：

- `.env` 默认遮罩值。
- `.env`、密钥和凭据疑似文件默认不进入索引、图谱、日志和遥测。
- 用户解除遮罩和允许索引必须分开授权。
- 任何代码执行、脚本运行和依赖安装均不属于本阶段。

退出条件：各格式均有真实 fixture、正确路由和降级状态；新增扩展不破坏现有格式；敏感文件默认保护。

### A5：阶段 A 桌面验收

必须在真实 Tauri 桌面完成以下路径：

1. 从文件树打开 TXT/JSON。
2. 从 Windows 文件关联或拖拽打开。
3. 编辑并保存。
4. 使用外部程序修改同一文件，验证冲突处理。
5. 重启应用并从最近文件再次打开。
6. 全文搜索定位到行号或 JSON Path。
7. 加入收藏或智能集合。
8. 验证 `.env` 不进入搜索。
9. 验证大文件进入只读降级。
10. 验证损坏 JSON 不覆盖最后合法版本。

阶段 A 完成后，更新注册表能力、主 PRD、格式需求矩阵、开发审计和发布说明。

## 5. 阶段 B：PDF 实用页面编辑

对应 `FR-PDF-008～011`。目标不是立即实现 Acrobat 级正文排版，而是覆盖日常最常用、风险可控的页面整理。

### B0：页面计划与写入边界（已完成）

B0 已交付页面身份、旋转/改序/排除草稿、原页映射、60 步历史、最少一页和离开保护，并明确不增加写回命令。真实桌面以两页 PDF 验证完整交互；详细审计见 `docs/B0_PDF_Page_Plan_Audit_2026-07-27.md`。

停止条件：

- 无法可靠保留未知对象。
- 写入会静默移除签名、附件、表单或加密信息。
- 许可证不适合项目分发。

触发停止条件时只做“另存副本/外部打开”，不开放覆盖原文件。

### B1：安全事务模型

1. 所有页面操作先生成操作计划，不直接写用户文件。
2. 展示页数变化、源文件、目标文件和签名失效风险。
3. 默认另存为新文件；覆盖源文件需要显式确认。
4. 写入临时副本后执行包解析、页数、页面尺寸和可打开性验证。
5. 验证成功后使用可靠替换。
6. 密码、签名、加密、表单或未知高风险对象默认阻断或降级。

### B2：首批页面操作

按风险从低到高交付：

1. 旋转页面。
2. 提取页面并另存（B2A 已完成）。
3. 页面排序。
4. 删除页面。
5. 拆分 PDF。
6. 合并 PDF（B2B 已完成）。
7. 插入其他 PDF 页面（B2C 已完成）。

每个操作都要覆盖撤销计划、另存、覆盖冲突、重开和索引刷新。

### B3：PDF 管理闭环

- 编辑后的新文件进入最近、搜索和工作台。
- 原批注 sidecar 在页面变化后必须迁移、明确失效或要求用户确认，不能静默错页。
- 缩略图和全文索引按新签名重建。
- 文件关系在另存时提供“继承关系/作为新对象”选择。

阶段 B 退出条件：七项页面操作完成真实 PDF 往返；失败不损坏源文件；批注和页码关系无静默错位。

## 11. Definition of Done

需求只有同时满足以下条件才能标记“已完成”：

- 有明确需求编号和用户路径。
- 真实文件可识别并进入正确工作面。
- 支持的阅读内容通过 fixture 验证。
- 支持的编辑操作可撤销或有明确恢复路径。
- 保存使用可靠写入并检测外部冲突。
- 保存后可由 LongEdit 重开。
- 交换格式可由至少一个目标第三方程序重开。
- 未支持对象不丢失，或保存前明确阻断。
- 文件进入最近记录、搜索和统一管理入口。
- 错误提示可理解且不泄露敏感内容。
- 前后端测试、契约检查和构建通过。
- 文档中的状态和限制与代码一致。

以下情况只能标记“部分完成”：

- 只有解析器或内存模型。
- 只能打开，不能可靠保存。
- 只有单一手工样本。
- 高级对象会丢失但界面未阻断。
- 尚未接入搜索、最近文件或统一打开。
- 只能在浏览器模拟，未在真实 Tauri 桌面验证。
