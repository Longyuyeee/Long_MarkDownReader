# P1-B5A PDF 元数据安全副本审计

审计日期：2026-08-16

## 1. 需求对齐与审计结论

用户的基础目标是日常管理和基础编辑，而不是把 PDF 变成任意对象编辑器。P1-B5 首批能力因此限定为资料库内 PDF 的标题、作者、主题、关键词四项描述属性，并且只可靠另存新副本。本阶段只冻结安全语义与实现顺序，不注册命令、不显示 UI、不写用户文件。

“编辑描述属性”与“隐私清理”必须分开：即使四个字段为空，正文、批注、附件、表单、书签、自定义 Info、XMP、对象历史或嵌入文件仍可能包含身份信息。产品必须明确提示这不是匿名化、取证擦除或完整隐私清理。

## 2. 元数据位置与威胁模型

PDF 描述信息至少存在于 trailer `/Info` 与 catalog `/Metadata` XMP 两条主路径，还可能出现在批注作者、附件文件参数、表单、签名、页面内容、自定义对象和旧增量修订中。只改 `/Info` 而保留相冲突的 XMP 会造成阅读器显示不一致；增量保存会让旧元数据继续留在历史对象；静默删除未知键或命名空间又可能损害业务、归档或合规信息。

首批安全子集会先盘点 Info/XMP/签名/加密/PDF-A/附件。现有 XMP、自定义 Info 键、嵌入文件元数据、异常引用或预算超限均阻断，而不是部分修改。签名、认证、加密和 PDF/A 继续 fail closed。

## 3. 冻结的安全子集

只允许 `Title`、`Author`、`Subject`、`Keywords` 变更或删除；每项使用固定 Unicode 标量预算，拒绝 NUL、控制字符和双向覆盖符。空白规范化后为空表示删除对应键，而不是写入可能被误认为有值的空字符串。`Creator`、`Producer`、`CreationDate`、`ModDate`、`Trapped` 必须保持字节等价，所有未知 Info 键一律阻断。

实现采用源文档完整克隆、规范 Info 字典和非增量全量重写。预览输出摘要绑定保存请求；目标只能是不存在的新路径；保存后必须复读规范字段、保留字段、页面/交互结构清单和 trailer，再确认源 SHA-256 未变化。

## 4. 验证计划

后端至少覆盖 Unicode/PDFDocEncoding/UTF-16BE、字段删除、保留键字节等价、重复预览确定性、摘要冲突、已有目标、签名/加密/PDF-A/XMP/自定义键阻断、输出复开和源不变。工作区阶段还需真实 Tauri 宽窄屏、草稿离开保护、预验证、风险提示、另存复开证据；独立 pypdf 检查四字段与保留字段，Poppler 像素比较确认页面视觉等价。

## 5. 实施顺序与能力边界

P1-B5B 才实现受限 Info 后端，命令存在但 UI 继续关闭；P1-B5C 再接入原 `PdfView` 侧栏并完成真实桌面与独立验证。XMP 同步编辑、完整隐私清理、自定义字段、附件级属性、外部 PDF 写入、源覆盖和签名文档修改均不属于这一安全子集，未来若扩展必须另立合同与证据。
