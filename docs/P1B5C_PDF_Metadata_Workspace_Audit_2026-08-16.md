# P1-B5C PDF 元数据原工作区接入审计

审计日期：2026-08-16

## 1. 阶段结论

标题、作者、主题、关键词已接入原 `PdfView` 的 PDF 侧栏和顶部命令条，仍处于初版“左侧导航/资料库 + 右侧阅读编辑区”结构内，没有创建新顶层窗口或脱离文档上下文。能力只对资料库内 PDF 开放，外部 PDF 继续只读。

## 2. 原工作区交互

用户打开“文档属性”后，系统先在内存中审计并读取现有 Info 字段；安全文档以当前值作为无修改基线，避免把尚未读取的空输入误当作删除。四字段使用 256/512 字符预算，清空表示从新副本真实移除。修改后必须先生成并复读验证，验证摘要与当前字段绑定，任意再次输入都会使验证失效。

## 3. 安全保存与草稿保护

验证通过后才显示新副本名称、范围确认和另存入口。用户必须确认“四字段属性编辑不等于匿名化或完整隐私清理”；后端只接受不存在的新目标，保存后复核字段、保留 Info、可达非 Info 对象、完整重写和源文件不变，再在同一工作区打开新副本。属性修改进入统一 PDF 草稿徽标、路由离开确认和窗口关闭保护。

## 4. UI 对齐

面板沿用水印与表单侧栏的 300px 宽度、`WorkspaceStateNotice`、主题色、边框、圆角、紧凑字号和 30px 输入控件；主题、间距、按钮状态与原 PDF 界面一致。侧栏标签保持可滚动，窄屏继续由原容器响应式规则保证页面和属性入口可达。

## 5. 证据边界与下一步

当前已完成静态合同、类型检查和生产构建，但尚未把能力标记为桌面证据完成。下一步 P1-B5D 使用真实 Tauri WebView2 覆盖宽屏、窄屏、中文字段、草稿离开保护、预验证、可靠另存和保存后复开；独立 pypdf 核对四字段与保留字段，Poppler 比较源/副本页面像素。证据通过后再进行 P1 总收口。
