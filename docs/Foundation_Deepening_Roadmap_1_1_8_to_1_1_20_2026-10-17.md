# v1.1.8—v1.1.20：现有基础能力深化路线

2026-10-17，用户要求在实际代码与原始需求基础上至少规划后十个版本，并确认“写入开发文档，然后继续开发”。本文登记已确认的 **13 个后续版本方向**，延续 [v1.1.6—v1.1.11 原路线](Foundation_Deepening_Roadmap_1_1_6_to_1_1_11_2026-10-16.md) 中 1.1.8—1.1.11 的顺序，不将原计划推倒重来。

当前公开/运行时均为 **1.1.7**，保存与历史深化已完成同包复核和公开回下载核验，详见[正式发布审计](V1_1_7_Unsigned_Community_Release_Audit_2026-10-16.md)。下一开发目标 **1.1.8 搜索深化**，先按预备代码审计 A—D 推进；不重复开发已经发布的 1.1.7。当前事实见 [开发交接](Development_Handoff.md)。版本号表示推进次序，不是日期承诺；以下十三版仍为计划，不是已开发、已验收或已发布声明。

## 一、需求基线与不变的规则

产品主线仍是：让用户找资料、读资料、写内容和整理本地文件更加顺手。深化现有编辑器和管理能力，不为凑版本扩张新平台、新格式、插件生态、AI 平台或另一套资料管理系统。格式长期目标仍以 [原始产品需求](Product_Requirements_and_Development_Roadmap.md) 和 [统一文件管理格式需求](Unified_File_Manager_Format_Requirements.md) 为准，不把支持打开当成完整编辑，也不将单个补丁称作 Excel/Word/PowerPoint 全能力等价。

- 每版围绕一条主要用户任务收口。数据丢失、覆盖草稿、错误恢复等安全问题随时作为 P0 处理，不排队等待“备份版”。范围确有依赖时先纠偏、记录原因，可拆分调整，不降低验收条件。
- 每批先读实际代码，区分已有、缺口、风险与最小实现。已完成的搜索、模板、图谱 Worker、历史恢复等不能换名重复立项。
- 保留现有功能、六种风格、正常动效和紧凑布局，把空间留给编辑区。文件操作用右键，低频能力用具名菜单/按需弹窗，不摊开成新常驻面板。
- UI 正式修改前先给示意；修改后实际运行并查看相关页面，覆盖宽窄窗口和受影响风格。优先隔离/无头验证，不接管用户日常桌面。
- 模拟用户场景、正常操作与用户措辞。先复现再修复，保留失败，不删断言、不关闭动效、不清真实草稿来过验收。
- 用户仍显式保存；内部核对可在保存流程自动完成，不能自动写回正文、猜测覆盖或额外要求“先保存、再手动归档”。快速笔记保存时就选合适位置。
- 性能使用固定样例、清楚的环境和前后基线；逐版验证相关流程及受影响回归，不无边界重复无关测试，不用单次指标代表整体改善。
- 每批审计、文档、提交、推送后再推进。发布要求固定源码、固定安装器、质量门、安装/覆盖升级与数据保留、同包独立复核；通过后发布并回下载核对摘要。
- 组件模拟 IPC、原生磁盘、开发程序、正式安装态分层记录，不互相冒充。未签名社区版不等于企业签名 RC，覆盖安装不等于应用内更新。
- README 保留开头软件图标和产品介绍；更新说明集中在末尾。正式发布前不把公开下载改成未发布版本，不重建替换已经验收的字节。

## 三、逐版范围、代码接续与验收

### v1.1.8：搜索完整、结果可信

实际调用链、提前截断风险、文件分组分页和 A—D 实施顺序见[预备审计](V1_1_8_Search_Preimplementation_Audit_2026-10-17.md)。A/B1 排序、B2a 预算、B2b 单库与 C 跨库后端已完成验证；最新 D 已按推荐示意接入两处原搜索入口并实看，见[页面审计](V1_1_8_Search_UI_Audit_2026-10-17.md)及[开发总览](V1_1_8_Search_Development_2026-10-17.md)。下一步真实 IPC/端到端大库及固定包验证，不混入 1.1.7 安装器，不说安装用户已经收到 1.1.8。

**场景：**“明明有这份资料，为什么搜不到？这些结果到底全不全？”

现状：`src-tauri/src/commands/index.rs` 已有跨格式索引、范围和多库搜索；当前结果上限 200，多库逐个查询，有 `limit_reached` 与警告，但返回类型没有续载游标。不是没有搜索功能，也不能简单无限提高上限。

实施顺序：

1. 复现超过首批上限、同名资料、内容更新和慢/离线资料库，记录基线；明确“总数未知/还有结果/查询失败”。
2. 在现有查询和身份规则上补稳定分页/续载，支持相关性及修改时间排序；排序、范围变化使旧游标失效，不混入旧结果。
3. 多库改为有界并发，减少过期查询消耗；单库失败不能使其他结果丢失，也不能被当作成功空结果。
4. 原搜索界面内解释完整性和索引新鲜度，保留默认主区打开、显式侧边参考、键盘和草稿保护。

**验收：**首批 200 之后仍可找到目标；连续输入/翻页/切排序无重复漏项与乱序覆盖；离线、权限和索引问题可辨别。使用固定大库比较首屏、续载与取消开销，不只测小空库。

### v1.1.9：工作现场与换机接续

**场景：**“换了电脑和资料目录，能不能接着昨天的标签页和参考写？”

现状：`src/utils/workSessions.ts`、`WorkSessionBar.vue` 已保存标签、搜索、视图和参考等现场，记录与本地根路径有关，并已有草稿合并保护。重点是迁移和失效处理，不再做一套现场保存。

实施顺序：

1. 定义可迁移现场及兼容版本，尽量使用库内相对路径；区分布局状态、正文、模板和密钥，不默认夹带私人正文/完整旧路径。
2. 通过既有入口导出/导入，预览旧库到新根目录的映射及缺失项，允许保留可恢复部分。
3. 分批/懒加载恢复标签顺序、阅读位置、参考与搜索；失效项可跳过或重新定位，不让一个坏文件挡住全部现场。
4. 合并前保护当前草稿，取消、重复导入、旧版本记录和失败后均可继续原工作。

**验收：**同库搬到新根目录后恢复有效部分；当前未保存内容不被替换；缺失项有原因。现场不宣称等于正文备份。

### v1.1.10：标签与集合真正好用

**场景：**“标签数量和列表不一致，改名后集合还对吗？我筛了一半别被刷新清掉。”

现状：`src-tauri/src/services/smart_collection.rs` 已支持目录、标签组合和修改时间等条件，先筛选再截取 200 条，并有截断反馈；前端已有集合与标签入口。

实施顺序：

1. 对齐标签统计、集合结果、修改时间排序和 1.1.8 的续载能力，验证增删改及不可用库。
2. 保留用户尚未提交的筛选条件与阅读位置，刷新不能打断编辑或恢复错误状态。
3. 深化批量标签整理，先显示影响范围，明确是否会修改正文；确认后才执行，逐项记录失败。
4. 接续改名/删除后的集合条件、路径和关系，失效目标沿原入口解释或修复。

**验收：**数量与可见结果语义一致；组合筛选和首批之后可用；取消/失败保留原组织和条件，不静默批量写正文，不扩成另一套文件管理器。

### v1.1.11：图谱清楚、稳定、可探索

**场景：**“很多节点挤在一起，我不知道看什么，也不想每次刷新重新找位置。”

现状：`GraphView.vue` 已有 Worker、语义缩放、密集布局、选择历史与局部图。已有单击选择/双击打开等交互不重复立项。

实施顺序：

1. 用真实密度的授权/生成资料实看当前标签、字体、层级、拖动和缩放，先保留基线及方向示意。
2. 改善标签避让、选中节点及关系来源强调，让用户知道关联为何存在。
3. 深化局部展开、返回前一视角、筛选后的连续探索；增量刷新保留合理视角与选择。
4. 减少无变化时的后台布局/刷新工作，保留正常动效，不以关闭动画或隐藏功能代替性能修复。

**验收：**密集数据下拖动、选择和打开明确区分，不缩放闪烁或无故重置；六风格、宽窄窗口、刷新前后持续操作可用；性能结论有固定基线。

### v1.1.12：本地备份与可靠恢复

**场景：**“文件和批注究竟备份了没有？恢复会不会覆盖现在的资料？”

现状：`src-tauri/src/commands/backup.rs` 的管理备份是脱敏、允许清单约束的管理记录包，明确排除正文、密钥、系统凭据等；不能宣传为完整资料备份。

实施顺序：

1. 保留管理备份原语义，设计用户明确选择的本地内容包：分别选择正文、附件、批注、历史；说明体积、外库边界和敏感内容。
2. 建立有版本的清单、相对路径、大小和校验摘要，预估空间，处理中断/缺失；不纳入凭据或默认上传云端。
3. 恢复前预览内容、冲突及损坏，优先恢复到新目录；覆盖原位置必须另有明确确认与保护。
4. 用故障样例验证新目录恢复、资源/批注关联、缺文件、坏摘要、空间不足和取消。

**验收：**恢复后的文件实际可打开且资源对应正确；原资料库保持不变，未包含和无法恢复的内容说清楚。不是只导出一个“成功”提示。

### v1.1.13：PDF 阅读到笔记闭环

**场景：**“读完一篇文献，把几条批注整理成笔记，以后还能回到原页。”

现状：`PdfView.vue` 已有阅读、搜索、批注、OCR、摘录和来源变化处理等大量能力；不是再新增一个 PDF 阅读器。

实施顺序：

1. 深化现有批注筛选与多批注选择，保留页码、文本及来源身份。
2. 复用现有摘录到笔记流程，支持选定批注生成有结构的阅读笔记，插入/保存由用户明确选择。
3. 从笔记返回真实来源页/批注；源文件变化导致定位失效时明确提示并允许手动重关联。
4. 核对伴随记录、原 PDF、工作现场和移动改名后的接续，不为生成笔记改写原 PDF。

**验收：**“批注→笔记→来源”真实走通，页码和身份正确；失效不假装定位成功；原 PDF 与当前草稿不被覆盖。OCR 识别效果和耗时按实际样例记录。

### v1.1.14：写作、模板与文章交付

**场景：**“套模板写文章、插图片，导出或交给别人后还看得见。”

现状：`NoteTemplateManager.vue`、`QuickNote.vue` 已有自定义模板、迁移、目标目录与选择；Markdown 已有 HTML/PDF 导出等能力。

实施顺序：

1. 在原模板上深化参数填入及预览，解释保存目标与继承规则；快速保存时就确定位置，不恢复额外归档步骤。
2. 对齐粘贴/拖入/选择图片的资源位置和相对路径，维护共享资源，不自动搬走其他文档使用的文件。
3. 深化已有 HTML/PDF 导出的字体、图片、分页与失败反馈；按需评估 Markdown 连同本地资源的交付包。
4. 用中文路径、空格、多图、长文和移动后的导出样例验收；明确 PDF/HTML 与可继续编辑源文件的差异。

**验收：**移动/交付到另一目录后资源可用；导出失败保留正文、图片及未保存内容；不把选模板变成额外复杂配置流程。

### v1.1.15：轻量表格日常工作

**场景：**“粘贴名单、筛出几行修改再撤销，编号和换行别悄悄变掉。”

现状：`TableView.vue` 已有网格/看板/图表/仪表盘、撤销和 CSV/XLSX 导出等；重点是连贯与数据语义。

实施顺序：

1. 深化多单元格输入/粘贴，导入前显示分隔符、表头与类型解释，允许用户确认转换。
2. 使筛选/排序后的编辑、粘贴和撤销始终绑定正确行身份，不按当前屏幕序号误写原行。
3. 保留视图、选择和阅读位置；大数据使用有界渲染，减少无关全量重算。
4. 明确 `.table`、CSV/TSV 与 XLSX 的保存/导出差异，包含丢失类型、样式或视图的预告。

**验收：**前导零、中文、多行、空值不被静默改变；筛选后改的是目标行；显式保存与重开一致。CSV/TSV 不承诺存储完整类型、样式和视图。

### v1.1.16：XLSX 高频操作深化

**场景：**“已有工作簿接着算、填、筛选复制，保存后别的表格软件还能正常用。”

现状：`WorkbookView.vue` 及原生命令已覆盖多种单元格、格式、名称、筛选、绘图、打印和透视相关操作；保留原先兼容性与外部执行限制。

实施顺序：

1. 实看跨表引用、填充和筛选后的复制/粘贴路径，优先修正常见失败，不让高级透视工作抢占基本输入。
2. 对齐计算或明确不支持的反馈、格式/撤销/保存状态，保持未触及部件。
3. 深化现有打印/页面设置与高频选择操作，保留工作表及视角。
4. 用实际生成工作簿完成编辑、计算/不支持提示、保存、其他生产者重开，单独记录性能。

**验收：**筛选复制目标正确、格式和计算状态不误报；未经授权不刷新外部源；不静默损坏公式或包部件。长期 Excel 等价目标保留，但不声称一个版本已经全部实现。

### v1.1.17：DOCX 编辑更自然

**场景：**“我只想改这段文字、列表或表格，不想先理解 OOXML 审计步骤。”

现状：现有 DOCX 已有受限编辑、对象选择、样式及生产者复核，复杂内容有边界。

实施顺序：

1. 明确可编辑与只读内容及原因，沿用预览/编辑页深化文字、列表、表格和支持的样式。
2. 简化目标选择和长文导航；技术核对放在显式保存内部，不暴露为用户必须手动执行的包审计任务。
3. 保留原件/副本保存、草稿与未触及复杂对象，写回失败可继续编辑或另存。
4. 按真实生产者样例验证支持范围及复杂对象保留。

**验收：**用户知道正在改哪一处；改后重开正确，失败保留源文件和草稿，不用删掉复杂对象换取保存通过。

### v1.1.18：PPTX 编辑与演示接续

**场景：**“选中这一页的标题修改，调一下页序、备注，接着演示。”

现状：PPTX 已有对象/文字/图片/形状/幻灯片相关操作与受保护写回，不重新立项基础预览或包级修改。

实施顺序：

1. 深化对象选择与编辑面板联动，视觉上说清真正的编辑目标，减少技术化目标清单。
2. 在既有支持范围完善文字、备注、幻灯片复制和顺序，与撤销/重做一致。
3. 保存、切页、演示返回后接续当前目标与草稿；保留原件/副本及未触及部件。
4. 用真实生产者文件保存后重开，核对支持的内容、布局及原有对象。

**验收：**选的对象就是改的对象；顺序/备注/撤销/保存连续，未编辑对象不丢。不是完整 PowerPoint 能力声明。

### v1.1.19：画布与脑图用于真实整理

**场景：**“把几个文件和想法放到一张图里，整理后还能回到资料。”

现状：已有画布/脑图、多选、撤销和开放格式等；先核对实现，不再把基础多选、撤销或文件卡片当成从零新增。

实施顺序：

1. 沿现有多选、对齐、分组和节点编辑改善直接操作，区分拖动、编辑及打开来源。
2. 深化文件卡片的身份/来源导航，移动或改名后接续引用并解释失效项。
3. 核对 JSON Canvas/OPML 的导入、编辑和导出；转换有损时先说明具体会丢什么。
4. 验证密集节点、中文、跨目录来源及显式保存后重开。

**验收：**拖动不误开、编辑不丢、来源可追踪；保留开放格式，不通过私有化或删能力来简化实现。

### v1.1.20：结构化文件修改可信

**场景：**“找到配置的这一项，知道为什么错，修改时别把注释和其他配置都变掉。”

现状：JSON/JSONC、YAML、XML、TOML 已有源码/树、导航、格式化、校验与部分 Schema 支持；不重复做一套基础编辑器。

实施顺序：

1. 深化路径查找和校验错误到源码位置的联动，明确各格式与 Schema 的实际支持范围。
2. 格式化或结构化修改前预览差异，有损转换说明注释、顺序或表达形式的影响；可取消。
3. 复用现有冲突保护，保留未修改区域；树与源码同步绑定当前文件及版本，过期结果不回写。
4. 大文件采用有界树/按需展开，保留源码编辑与定位，不承诺完整 IDE。

**验收：**注释、顺序和未触及内容不被静默损失；格式化失败、源文件变化或校验失败不覆盖草稿。结构模式不能保真时解释限制而不是假称无损。

## 四、逐版实施模板

每版按同一顺序记录：实际代码/需求审计 → 用户任务与最小范围 → UI 示意（涉及界面时）→ 分批实现与故障回归 → 实际页面检查 → 原生磁盘与相关功能/性能回归 → 固定安装器与同包复核 → 发布、README 末尾记录、公开附件核验 → 下一版审计。

每批文档至少含：已实现、仍缺什么、真实失败、修正内容、验证命令/结果及证据层级、代码提交和下一步。不能仅记录“测试完成”。后续范围如需调整，要写清哪个用户痛点、代码事实或安全依赖使原方案不合适。

## 五、竞品参考与取舍

以下是制定路线时查阅的官方资料，仅提取成熟工作流，不整套照搬产品或无边界追加能力：

- [Obsidian Search](https://help.obsidian.md/plugins/search)：搜索条件、上下文与排序；本项目重点是完整性和稳定续载，不因参考而追加所有操作符。
- [Obsidian Workspaces](https://help.obsidian.md/plugins/workspaces)：按任务恢复标签与布局；本项目补路径迁移和失效项，不把现场当备份。
- [Obsidian Canvas](https://help.obsidian.md/plugins/canvas)：开放画布、卡片和组织；本项目已有相关基础，深化实际整理。
- [Zotero PDF Reader](https://www.zotero.org/support/pdf_reader)：批注到笔记再回来源；保留原 PDF 与伴随记录的清楚边界。
- [Typora Images](https://support.typora.io/Images/) 与 [Export](https://support.typora.io/Export/)：图片资源路径与文章交付；优先改善现有写作/导出。
- [Joplin Import/Export](https://joplinapp.org/help/apps/import_export/)：区分内容/元数据导出和可恢复性；管理备份不能冒充内容备份。
- [VS Code JSON](https://code.visualstudio.com/docs/languages/json)：路径导航、校验及 Schema；只深化现有配置编辑，不扩成开发 IDE。

这些参考支持的是方向选择，不证明本项目能力、性能或验收已完成。每版最终以本项目实际代码、用户任务和固定包证据为准。
