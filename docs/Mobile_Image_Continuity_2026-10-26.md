# 手机端图片核对与任务返回

本轮继续阶段 1B，只推进“为当前笔记选择图片、核对后插入，或取消回原处”这一项用户任务。沿用移动独立工作目录与分支，不修改桌面工作目录，不改变原生附件存储格式。

## 现场问题与竞品复核

改前实页把说明输入、引用检查、所有历史记录和图片预览堆在一个面板。预览后的返回会关闭整个任务并丢掉说明；选图成功后立即改变私有草稿，没有单独的核对动作。[改前采集](evidence/mobile-image-continuity-2026-10-26/before/report.json) 中三个缺陷字段均为 `true`，`passed` 只表示观察完成。

| 官方资料 | 可确认的行为 | 本项目采用的判断 |
| --- | --- | --- |
| [Notion 图片、文件与媒体](https://www.notion.com/help/images-files-and-media) | 添加媒体和查看原始媒体有各自入口；文档说明手机上可从媒体菜单查看原图。 | 添加、查看图片与修复引用分层，核对图片时保留来源任务。 |
| [Joplin 附件](https://joplinapp.org/help/apps/attachments/) | 附件可从笔记打开；移动端有附件大小限制，下载可按打开笔记等条件控制。 | 保持图片可查看、资源有预算；保留本项目现有的 2 MiB / 800 万像素边界。其文档没有证明 Android 选择器和返回细节，不据此声称录制了竞品实机。 |
| [Android 导航原则](https://developer.android.com/guide/navigation/principles) | 应用任务内向上返回和系统返回应沿页面历史回退。 | 图片详情先回历史或选择页，历史再回实际的插入/替换任务，最后回原编辑器或设置。 |

“选图后先核对再插入”是针对本项目会先生成附件副本的产品判断，并非声称竞品都采用相同的确认步骤。本轮调查是官方文档复核，没有安装或运行竞品 App。

## 正式行为

- 入口页只显示目标笔记、资料库、插入位置、图片说明，以及“笔记中的图片”“导入记录”两个二级入口。
- 选择图片先导入副本并进入核对页，确认前不修改草稿。核对页展示图片、文件名、尺寸、大小和明确动作；插入后仍需保存正文。
- 引用列表按出现顺序标记“第几处”，修复页明确目标引用。同地址的另一处引用、旧图片和周围文本不会被一并替换。
- 导入记录使用紧凑列表，点开才查看图片、错误、文件位置和较早尝试路径。设置中的记录补充资料库和笔记名，不提供插入当前笔记的动作。
- 返回保留当前图片任务内的说明、原始插入位置、滚动与焦点；取消选择器不生成记录。任务繁忙时消费重复返回，问号说明仍优先关闭。
- 图片失效或读取失败时不能确认插入；明确重新读取后才恢复动作。确认时再次读取并比较图片内容、尺寸和大小；如果已变化，展示当前图片并要求重新确认，草稿继续保留。
- 未确认写入仍可预览私有恢复副本。失败重试保留记录；成功重试仍停留在核对页，不自动改动正文。较早尝试路径继续保留，不自动删除图片文件。
- 附件位置和较早尝试放入折叠详情，格式限制与返回规则放入可点击问号。保留必要的失败、未确认和保存状态。

输入与页面位置只在本次图片任务内保留；完全退出后重新进入，说明会重新填写，已导入图片仍可从历史找回。系统选择成功时附件副本可能已经写入，取消核对不会删除该文件，不能将其解释成撤回文件写入。

390 × 844 实页测量：顶部栏 64px，内容边距 16px，图片区域 358 × 224px，底部主要动作高 48px。实际测试覆盖 320px、200% 文字、深色和短视口，长内容可滚动，决策动作可达。

并排核对还发现编辑工具栏的触摸高亮残留在新页面底部，已只针对图片入口关闭原生高亮，保留原截图供核查。没有重画参考图消除差异。

开发中的一次补验复现了“预览后文件换成另一张有效图片仍直接插入”的问题，失败截图与报告保存在 [迭代记录](evidence/mobile-image-continuity-2026-10-26/iterations/changed-image-before-guard/report.json)。正式确认动作已增加内容比较；当前图片与预览不一致时，必须重新核对，不直接更改正文。

如实保留的差异：正式引用页有独立重新检查工具行，首行位置比参考图低 48px；实际数据增加引用序号、资料库来源和第三处重复地址，用于辨别操作目标。历史数据的条数、图片名、实际大小、错误文本与原设计占位数据不同。核对状态采用“确认后更新草稿”，不把历史中已经使用过的图片一概说成尚未插入。字体、图标和折叠行高度略有差异，不声明逐像素一致。

## 验证与后续

验证入口与结果、源码和构建资产哈希见 [验证记录](evidence/mobile-image-continuity-2026-10-26/verification.json)。新增 `npm run test:mobile-image-layers-browser`，保留原附件浏览器测试的数据、字节、格式、原文及恢复断言，只按新页面路径增加显式核对动作。

构建与 289 项现有逻辑测试通过。本轮共 55 组相关浏览器验证：图片任务 12、附件格式与副本 7、导航 8、恢复任务 9、帮助 14、可访问性 5。新增图片任务含六次窄屏深色大字扫描及一次内容变化提示扫描，未检测到所选 A/AA 规则违规；这不等于完整读屏验收。最后增加图片变化核对，之后重新构建并重跑图片任务 12 组和附件回归 7 组，不反复重跑全部历史脚本。构建仍有原有分包体积提示。

Android 原生选择器取消、真实键盘、预测性返回、后台及进程死亡仍需单独验收。本轮没有生成新 APK，也未增加相机或新文件格式。阶段 1B 接下来处理外部来源与分享进入编辑任务的返回链，再按计划进入根导航的完整迁移。
