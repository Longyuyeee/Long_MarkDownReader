# v1.0.15 后 M2 工作台 2.0 收口审计

日期：2026-08-26

阶段：M2 closure

版本：1.0.15（非发布候选）

结论：通过，M2 已收口

## 1. 本阶段目标

本阶段只补齐工作台退出条件，不扩张新的统计或治理概念：

1. 提供可由键盘操作的快速新建与打开入口。
2. 从工作台待办精确返回 Markdown 原文行。
3. 明确展示加载、空资料库和失败恢复状态。
4. 在真实大型资料库和 720/480 窄窗口下验证性能与布局。

## 2. 修正前实际差异

| 项目 | 修正前实际结果 | 预期结果 |
| --- | --- | --- |
| 快速操作 | 工作台没有直接新建或打开文件入口 | 在首页完成新建和打开，文件类型由菜单选择 |
| 任务定位 | 点击任务只打开文件，不能定位原文 | 打开目标 Markdown 并定位到任务所在行 |
| 状态表达 | 加载过程、已配置但为空和读取失败缺少完整区分 | 三种状态均明确且失败可重试 |
| 键盘路径 | 原生按钮默认行为在 Tauri 中未可靠触发菜单或打开 | Enter/Space 可执行，Escape 可关闭菜单 |
| 大库验证 | M2A 阶段没有覆盖千文件工作台退出预算 | 固定 1011 个真实文件并记录首个可操作时间 |

## 3. 实现结果

- `WorkspaceHome` 新增“新建”和“打开文件”快捷操作；新建菜单覆盖 Markdown、纯文本、Canvas 及已有格式注册表中的结构化文件和图表格式。
- 新建操作调用真实后端命令创建文件，随后刷新工作台并打开新文件；测试结束会删除临时创建文件并核对资料库摘要。
- 待办路由携带行号与唯一定位标识，`LibraryMode` 在 Vditor 内容完成渲染后滚动到对应块并显示可辨识高亮。
- 工作台新增显式加载提示、已配置空资料库操作页，以及带“重试”的非阻断失败状态。
- 快捷操作补齐 Enter、Space 和 Escape 行为，避免依赖桌面 WebView 对原生按钮默认键盘行为的差异实现。

## 4. 真实测试差异与修正

测试不是一次性按预期通过，实际迭代如下：

1. 首次运行时，Enter 未打开新建菜单；改为受控下拉状态并显式处理 Enter/Space/Escape。
2. 第二次运行使用 DOM `click()` 未能代表 Naive UI 菜单的真实选择；测试改为 ArrowDown + Enter，验证真实键盘路径。
3. 第三次运行已真实创建并打开 Markdown，但“打开文件”按钮的 Enter 未触发路由；补齐显式键盘处理。
4. 状态测试最初依赖原生 `title`，而全局工具提示治理会迁移该属性；改用稳定的结构和测试标识验证，不改变产品语义。

这些差异均在同一轮真实 Tauri 审计中修正并重新执行。

## 6. 需求对齐结论

工作台现在围绕“继续工作、今天要做、需要处理”组织，统计与知识治理详情没有重新回流首页。快速操作、任务写回与原文定位、治理队列、空/加载/失败状态、大库预算及宽窄窗口退出条件均有真实证据，M2 可以收口。

本阶段没有扩大格式能力声明，也没有提升版本或生成 Release。下一阶段回到主路线的 **M1B2A：DOCX 生产者对象选择审计**，先从真实 Microsoft Word、WPS 与 LibreOffice 样本选择安全、用户价值明确的 DOCX 常用对象，再决定实现范围。
