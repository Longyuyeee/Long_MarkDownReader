## 1. 结论

M3C-3 已把关系网络力布局计算从 UI 主线程迁移到模块 Worker，并把每节点每 tick 的密集单元斥力候选冻结为 48。Worker 使用单调 job ID 隔离陈旧结果；主线程只构造可转移 TypedArray、派发任务、应用有界结果并唤醒 M3C-1 脏帧。

真实 100/1,000/5,000 节点 Tauri/WebView2 复测中，三档布局、交互、稳定绘制、失焦、返回和源安全均通过。5,000 节点从 M3C-2 的 120 秒内未稳定改善为 `10964ms` 稳定；原 `29481ms` 主线程布局调用降为派发最大 `7.6ms`、结果应用最大 `26.7ms`。因此 M3C-3 目标完成。

下一步进入 **M3C-4 大图性能退出审计**，验证大图过滤范围 SVG/PNG 导出、Worker/监听器清理，并判断剩余非连续 Canvas/社区语义长任务是否阻断 M3C 退出。视口裁剪、标签缓存、保存视图和视觉重做仍不得自动并入。

## 2. 冻结合同

- 真实 Markdown 有向链资料库：100/99、1,000/999、5,000/4,999 节点/边。
- 固定随机种子，源文件全程只读。
- 每节点每 tick 斥力候选 `<=48`；总检查量 `<=节点数×48`。
- UI 主线程布局单次任务 `<=50ms`；5,000 节点布局稳定 `<=120000ms`。
- Worker 结果分批应用；稳定后绘制 `<=2/s`。
- 活跃布局失焦后任务失效，恢复后新 job 继续；重置、筛选、切换和卸载使用同一陈旧结果防线。
- 三档缩放、平移、框选和聚焦完成，运行时错误 0，源摘要不变并返回资料库。
