# v1.0.22 迁移前：历史证据与当前发布门禁分离

日期：2026-09-12；前置提交 `5bdbdc7759164f8bc00fed098141643b27a62f78`。

## 对齐与实际问题

按范围冻结文档进入版本迁移前审查，复读主 PRD 1.1、既有原子版本迁移脚本、通用社区发布检查器及 v1.0.21 更新观察检查器。本轮不扩展已冻结的两项搜索修复，处理发布前置门禁的实际矛盾：

1. v1.0.21 历史观察检查器硬编码当前运行版本必须为 1.0.21，且要求活动社区政策始终使用 1.0.20 → 1.0.21 路径；切到下一版候选会误报，即使历史证据完全没变。
2. 通用社区发布检查器的 `lifecycleVerified`（安装生命周期通过、最终发布审计未完成）分支却要求官方更新路径为 passed。候选尚未公开，不能完成“只使用公开 Release 安装包”的官方观察；这会迫使接续者错误提前填 passed。

## 实现与安全边界

- v1.0.21 历史校验仅放行当前已计划的运行时 1.0.22 候选，公开版必须仍为 1.0.21、目标必须为 1.0.22，运行身份必须与社区政策一致；未泛化放行未知后续版本。
- 历史观察必须已经完成，历史回执仍必须记为 1.0.20 → 1.0.21 passed；新版社区政策必须使用自身 1.0.21 → 1.0.22 路径及目标 Tag。不修改历史回执，不把旧观察复制为新版通过。
- 通用发布门新增独立更新观察校验：未发布候选不得 passed；已发布也可保持 pending；宣称 passed 必须有匹配前后版本、完成状态及独立成功 run 的观察政策。专用检查器继续验证文件摘要、安装身份及人工截图审阅记录，通用状态检查不替代实物证据校验。
- 安装生命周期通过但未发布的分支改为要求 pending，其他安装包/身份/回滚/哈希门禁不变。
