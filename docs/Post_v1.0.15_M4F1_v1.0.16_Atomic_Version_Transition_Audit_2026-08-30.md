# M4F-1 v1.0.16 原子版本迁移审计

日期：2026-08-30

阶段：M4F-1

结论：44 个版本文件已原子迁移到 1.0.16，候选元数据已重置为质量门禁待执行；当前公开版本仍为 v1.0.15

## 原始需求与实际执行

M4F-0 冻结的产品范围提交是 `7e10c340fa0d528b598c9ca6be391c48b15a463f`，M4F-1 从已推送的冻结入口审计提交 `7fded3d1d270e955f2cd400be0dff5a09cb3a26f` 开始。实际迁移严格覆盖冻结清单中的 44 个版本文件：package/lock、Cargo/lock、Tauri、开发版本策略，以及 38 个当前运行时、能力、R5、Windows 和社区发布合同。

五个记录 post-v1.0.15 起点的历史策略继续固定为 1.0.15：M0 基线、显式保存对齐、M2A2、M2A3 和 M2 退出。迁移没有修改产品功能范围，也没有构建安装包、创建 Tag 或远端 Release。

## 候选元数据归零

`shared/v1-community-release-policy.json` 现在描述目标 v1.0.16，但 `releaseCandidate=false`。前端构建、Rust 锁定检查、生产依赖审计、运行烟测、MSI、NSIS、哈希、Windows 生命周期、Quality Gate 和 GitHub 发布状态全部重置为 false；旧 v1.0.15 的候选提交、Actions run、产物哈希和 Release 回执均已清空。

目标 Tag 和 URL 只是待执行目标，不代表远端对象存在。M4F-2 必须把本阶段推送后的精确提交绑定为候选源码，不能把迁移前提交或未来混入产品改动的提交当作同一候选。

## 事实消费纠偏

实际代码复核发现 `releaseCapabilities.ts` 把“社区目标策略版本”和“当前公开版本”假设为相同。该假设在已发布状态成立，但在候选准备期会错误拒绝“运行时 1.0.16、公开 1.0.15”的合法状态。

本阶段将合同纠正为：社区候选策略版本必须与 package/能力矩阵的当前二进制身份一致，公开版本则由开发版本策略及不可变 `v1.0.15` Tag 独立约束。界面继续明确显示“v1.0.16 候选准备中 · 当前公开 v1.0.15”，不会把目标版本误报为已发布。

同类问题也存在于主界面版本按钮的无障碍说明：旧实现直接把 package 版本同时称为运行时和当前公开版本。现已独立导出 `PUBLIC_RELEASE_VERSION`，主界面朗读“候选准备线 v1.0.16、运行时 v1.0.16、当前公开版本 v1.0.15”，格式能力页也同时展示候选、运行时和公开版本。

候选合同检查还曾无条件读取不存在的 `v115-managed-updater-lifecycle-policy.json`。实际 v1.0.15 远端发布回执明确保存 `1.0.14-to-1.0.15-pending`，而本次 M4F-3 会完整重跑 1.0.15→1.0.16 安装和升级生命周期。因此检查器现接受“已远端复核且显式 pending”的上一公开版本回执作为历史基线，但 ready/published 状态仍必须具有本次候选的完整托管生命周期，不能继承旧回执代替当前证据。

P2-D 格式事实审计还发现 ODS 已在 M1C-B/M1C-D 实现并验收“有界可靠副本”，但 `safe-degradation-contract.json` 仍把它放在严格只读通道。该合同现拆分出 `verified-ods-reliable-copy`，要求不覆盖源文件、拒绝旧签名和既有目标、结构与语义复读以及失败清理；ODP 与外部 ODS 仍留在只读边界。此修正只对齐已存在能力，不扩大 ODS 公式、自定义样式或 ODP 编辑范围。

## 发布边界

- 二进制、构建和当前能力合同版本：1.0.16。
- 当前公开版本和 Tag：1.0.15 / `v1.0.15`。
- 当前候选状态：Quality Gate pending，`releaseCandidate=false`。
- `v1.0.16` Tag、安装包、哈希、Actions 回执和 GitHub Release：均不存在或未执行。
- 九道发布门禁已完成冻结与原子迁移 2 项，剩余 7 项。

## 下一接续点

下一阶段固定为 **M4F-2 v1.0.16 候选 Quality Gate 与当前运行烟测**。先以推送后的 M4F-1 提交作为唯一候选源码执行完整 `ci:patch-release`，再重跑 R5F 路由挂载和 R5G 桌面路由、TXT/JSON I/O 与性能导出；任何失败均停止进入安装包阶段并保持 `releaseCandidate=false`。
