# E2A 外部应用发现与统一打开审计

> 日期：2026-07-30
> 基线：`f0e74f3`
> 结论：E2A 代码、机器契约、工作区入口和本机发现证据已完成，下一阶段进入 E3。

## 1. 本阶段交付

- 新增 `shared/external-application-capabilities.json`，固定 Microsoft Office、WPS Office、LibreOffice 的角色程序、格式路由和安全策略。
- 后端从 Windows App Paths 和进程 `PATH` 发现真实可执行程序，不依赖安装目录常量。
- Windows 通过文件版本元数据返回产品版本；发现结果在单次应用会话内缓存。
- WPS 的 `et.exe`、`wpp.exe` 注册项允许白名单内的统一 `wps.exe` 启动器，不接受其他重定向。
- Library 右侧工作面和文件树菜单复用同一个“外部打开”入口，可选系统默认应用或已发现且适配当前扩展名的套件。
- 后端只接受应用 ID，不接受前端传入任意可执行路径；指定应用会重新绑定到发现清单中的角色程序。
- 打开目标必须是工作区内、已登记格式的真实文件。接管前后计算 SHA-256，返回源文件未变化回执；启动失败、未知应用、角色缺失和摘要漂移都有明确诊断。

## 4. 能力边界

- 外部打开不等于 LongEdit 内置读取、编辑、转换或可靠保存。
- 外部应用接管后由用户执行的修改属于该应用行为；LongEdit 只保证启动交接时自身没有修改源文件。
- `.wps/.et/.dps` 尚未登记为工作区格式，必须等待 E3 真实 fixture、隐私清理、元数据与能力工作面。
- `.doc/.xls/.ppt` 的隔离转换仍等待 E2B/E2C。
- `.ods/.odp` 的结构预览与真实生产者矩阵仍等待 E1C。
