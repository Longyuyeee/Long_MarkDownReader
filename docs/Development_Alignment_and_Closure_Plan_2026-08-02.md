# Long编辑当前开发对齐审计与收口计划

审计日期：2026-08-03

审计基线：`main@9f74a43`，并包含本轮 P0 路由收敛实现

当前版本：`1.0.1`

文档状态：当前开发事实源；旧阶段文档仅用于历史追溯

## 1. 审计结论

Long编辑已经越过“能否形成产品”的阶段：v1.0.1 无签名社区版已经正式发布，统一格式注册表包含 41 类格式和 74 个扩展名，29 类为已验证、6 类为有限能力、6 类依赖外部程序；文本、JSON、PDF、DOCX、PPTX、表格、工作簿、图表、思维导图、Canvas 和知识图谱均已有实际产品路径。

与最初需求相比，核心方向没有发生根本偏离：产品仍以本地文件为事实源，目标仍是覆盖日常管理和基础编辑，并把文件组织成可搜索、可关联、可维护的体系。功能广度、可靠保存、发布证据和知识关系能力已经超过最初最低目标。

当前不能把“全量开发”或“全量 UI”标记为最终收口。P0 已统一内部文件打开入口，剩余主要问题已经转为视觉与管理页面一致性治理：Workbook、PDF、WorkspaceHome 等页面存在大量 7–9px 微字号；工作台、设置、图谱和格式能力页尚未共享统一管理壳层；历史计划文档存在多个互相冲突的“当前入口”。

因此，下一阶段不应继续横向增加大型格式或高级编辑能力，应按顺序完成 UI-1～UI-4 和事实源治理，再决定是否发布下一个补丁版本。

## 2. 最初需求基线

最初需求可以归纳为五项不可降级目标：

1. 在同一个本地文件管理器中识别、分类、搜索和管理日常文件。
2. 在软件内阅读 PDF、图表、思维导图、WPS/Office、TXT、JSON 和开发常用格式。
3. 对可安全写回的格式提供基础编辑；不能安全编辑时明确提供只读、批注、转换、另存副本或外部打开。
4. 通过目录、集合、标签、最近、收藏、全文搜索、批注、引用、关系和可重建索引形成体系化管理闭环。
5. 知识图谱、Canvas、仪表盘和 AI 用于增强管理闭环，不得取代或阻塞基础文件管理与编辑。

最初执行路线为：

- A：文本、JSON 与开发格式闭环；
- B：PDF 实用页面编辑；
- C：DOCX/PPTX 基础工作面；
- D：体系化管理与格式广度；
- E：高级等价能力，长期渐进；
- R：安装、升级、卸载、更新和发布验证。

## 3. 当前能力盘点

### 3.1 日常格式覆盖

| 能力域 | 当前结果 | 审计判断 |
| --- | --- | --- |
| 格式注册 | 41 类格式、74 个扩展名、10 套发布能力配置 | 已形成统一事实源 |
| 文本与开发格式 | TXT、JSON/JSONC、YAML、XML、TOML、配置、代码文本和日志均有分级工作面 | A 阶段完成；日志保持有界只读 |
| PDF | 阅读、搜索、复制、批注、OCR、页面计划、提取、合并、插入和可靠另存已有证据 | B 阶段基础目标完成；正文排版编辑仍属长期能力 |
| DOCX | 结构化阅读、索引、受限编辑和可靠另存副本 | C 阶段基础目标完成 |
| PPTX | 结构化阅读、放映、搜索定位、文本/备注/图片/基础形状/页面生命周期编辑和可靠副本 | C 阶段基础目标完成；复杂排版与动画不承诺 |
| 表格与 XLSX | CSV/TSV、开放表格、图表、公式与渐进式工作簿能力 | 基础编辑已具备；Excel 高级等价仍为部分完成 |

| WPS/旧版 Office/ODF | 已识别并按能力矩阵提供预览、转换或外部打开降级 | 格式广度已覆盖，内部原生编辑并未全部完成 |

### 3.2 体系化管理

当前已经具备资料库文件树、7 个左侧管理 Tab、统一标签页、全文搜索、集合、标签、历史、备份、最近文件、跨格式索引、文件关系上下文、全局图谱、局部关系、关系治理建议和可重建索引。

知识图谱不再只是独立展示页，已经进入工作台、搜索结果、文件关系、跨格式对象定位和治理流程。功能存在感达到最初“进入日常工作流”的目标；剩余问题主要是视觉层级、入口一致性和真实内容下的信息密度，而不是缺少图谱功能。

### 3.3 发布状态

- 当前版本为 `1.0.1`。
- GitHub Release `v1.0.1` 已于 2026-08-02 正式发布，非 Draft、非 Prerelease。
- 发布通道为 `community-unsigned`；没有 Authenticode 签名是明确公开的产品边界，不再作为本社区版的阻断项。
- 更新签名、安装资产、SHA-256、安装生命周期证据和 GitHub Quality Gate 已形成闭环。
- 当前能力矩阵仍保持 `releaseCandidate=false`，表示没有把无签名社区版伪装为企业签名 RC。

## 4. 与原计划的对齐情况

| 原计划阶段 | 原目标 | 当前状态 | 是否偏移 |
| --- | --- | --- | --- |
| A | 文本、JSON、开发格式可识别、编辑、保存、重开和搜索 | 已完成并有真实桌面证据 | 无实质偏移 |
| B | PDF 页面级实用编辑与安全另存 | 基础目标完成，正文等价编辑延期 | 符合既定边界 |
| C | DOCX/PPTX 阅读与受限基础编辑 | 已完成基础工作面和生产者复开证据 | 无实质偏移 |
| D | 统一管理、跨格式搜索、关系和格式广度 | 功能主干完成，UI 与入口一致性未完成 | 有体验层偏移 |
| E | Excel/PDF/Office 高级等价能力 | 已提前投入较多 Excel/PPTX 深层能力，但仍保持有限能力声明 | 出现优先级前置 |
| R | 安装、更新和发布 | v1.0.1 无签名社区版已发布 | 已完成社区发布闭环 |

### 4.1 保持对齐的部分

- 本地优先、用户文件为事实源、安全保存和明确降级边界始终保持。
- 常用格式没有用“能打开”冒充“完整编辑”，能力矩阵继续区分已验证、有限能力和外部依赖。
- 知识图谱、Canvas 和工作台总体仍服务于文件管理，没有成为使用基础编辑器的强制前置条件。
- 用户明确选择无代码签名社区发布后，发布路线已按该决定调整，这属于需求变更而不是开发偏移。

### 4.2 已发生的偏移

1. **高级能力前置**：Excel 数组、Pivot、PPTX 对象生命周期和知识治理证据投入较深，早于全局 UI 体系化收口。
2. **主框架短暂漂移**：提交 `725e655` 曾把启动页从 `/library` 改为 `/workspace`；`5de7a7a` 已恢复初版“左侧 Tab + 右侧编辑区”。
3. **入口已经收敛**：P0 已将资料库内部文件打开动作统一到共享导航服务，并用机器门禁禁止图谱、关系面板、Canvas、搜索定位和内部转换重新直跳顶层格式路由。
4. **视觉治理滞后**：当前静态扫描仍发现 223 处小于 10px 的字号定义，其中 Workbook 68 处、PDF 41 处、WorkspaceHome 10 处。
5. **事实源膨胀**：历史执行指导持续追加多个“最新入口”，旧开发审计门禁和 G9 策略身份仍校验 1.0.0/R5N 事实，已不能代表 v1.0.1 主线；本次审计已将当前门禁和 G9 策略版本重新对齐 1.0.1。

## 5. 当前 UI 收口审计

### 5.1 已通过

- 根路由进入 `/library`。
- 1280×720 实测显示 260px 左栏、1019px 右侧编辑区，页面无整体溢出。
- 文件、集合、目录、标签、引用、历史、备份 7 个 Tab 保留。
- 浅色、深色和高对比主题均可切换，主壳层没有固定浅色遮挡。
- P0 已完成：命令面板、标签栏、图谱、关系面板、Library 搜索与引用、Canvas、PDF/Table/Workbook 内部转换与另存、思维导图转换和 WorkspaceHome 均使用共享 `openManagedFile` 入口，并保留定位参数与左侧管理上下文。
- `check:ui-consistency` 与可访问性合同通过。

### 5.2 未通过

- 223 处小于 10px 的样式定义尚未治理，工作台运行时最小字号为 9px。
- WorkspaceHome、Settings、Graph 和 ReleaseCapabilities 仍采用不同页面壳层。
- 格式能力页仍显示 `R2 收口中`，与已经发布的 v1.0.1 状态表达不一致。
- 当前路由门禁已覆盖静态入口绕行，但 UI 门禁尚未覆盖真实路由截图、Windows 缩放和微字号增量。

结论：**启动结构与内部文件路由已经收口，全量 UI 尚未收口。**

## 6. 后续开发计划

### 阶段 P0：事实源与路由收敛（已完成）

1. 建立唯一的内部文件打开函数；所有资料库内文件统一进入 `LibraryMode?path=...`。
2. 修复 GraphView、FileRelationContext、LibraryMode 搜索定位、Canvas 和 WorkspaceHome 的顶层格式路由调用。
3. 顶层格式路由只保留外部单文件、临时模式、深链接恢复或明确的沉浸模式用途。
4. 增加门禁：禁止已登记嵌入格式从内部管理流程直接跳转独立编辑器。

退出条件：从文件树、搜索、最近、集合、图谱、关系面板、Canvas 和命令面板打开同一文件时，均保留左侧管理上下文。

完成回执：共享导航服务位于 `src/services/fileNavigation.ts`；11 个内部入口面已迁移；`check:managed-file-routing` 禁止已登记嵌入格式重新绕过资料库壳层，并已加入补丁发布门禁。外部单文件文本入口继续显式使用独立路由。

### 阶段 UI-1：字号与共享组件

1. 建立共享工具栏、文件身份区、状态栏、字段、分段控件和空状态组件。
2. 普通界面正文不低于 12px，辅助文字不低于 11px；10px 只允许经过登记的高密度数据标签，7–9px 清零。
3. 优先治理 Workbook、PDF、WorkspaceHome 和 DiagramStudio。
4. 将压缩为单行的大段 CSS 拆分为可审查结构。

退出条件：自动扫描不存在未登记的 7–9px 字号；四个高风险页面通过正常与紧凑密度检查。

### 阶段 UI-2：颜色与状态语义

1. 将界面 chrome 的直接颜色迁移到 surface、border、text、primary、success、warning、danger 令牌。
2. 保留文档内容、图表系列和用户自定义颜色，不机械替换内容色。
3. 统一加载、空状态、错误、只读、有限编辑、外部依赖和保存成功回执。

退出条件：浅色、深色和高对比主题下，关键状态含义一致且不存在固定背景遮挡。

### 阶段 UI-3：管理页面壳层

1. 为工作台、设置和格式能力建立共享管理页头、返回资料库入口、内容宽度和操作区。
2. 图谱保留沉浸画布，但统一返回路径、筛选控件、状态栏和检查器尺寸。
3. 工作台继续作为管理概览，不重新成为默认启动页。

退出条件：管理页面拥有统一导航语法，任何管理页均可一步返回资料库主壳层。

### 阶段 UI-4：真实视觉回归与版本判定

1. 使用真实样例覆盖资料库、Markdown、TXT、JSON、PDF、DOCX、PPTX、CSV、XLSX、图表、脑图、Canvas、图谱和设置。
2. 每个代表页面验证专业浅色、专业深色、高对比，以及 Windows 100%、125%、150% 缩放。
3. 检查截断、重叠、可点击尺寸、焦点、加载切换、空状态和保存回执。
4. 将截图矩阵、字号门禁、内部路由门禁加入 Quality Gate。
5. 全部通过后再评估发布 `1.0.2`；在此之前不扩大格式承诺。

## 7. 最终收口定义

只有同时满足以下条件，才能宣布当前需求收口：

- 41 类注册格式的公开能力与实际行为一致，有限能力和外部依赖继续清晰展示；
- 所有日常资料库文件从任一内部入口打开时均保留左侧管理上下文；
- PDF、Office、文本、JSON、图表、脑图和表格能够完成与能力等级匹配的阅读、基础编辑或明确降级；
- 保存后可通过搜索、集合、标签、最近或关系再次定位内容；
- 7–9px 未登记界面文字清零，核心页面完成三主题与三档缩放视觉回归；
- 工作台、设置、格式能力和图谱具有一致的返回与导航语法；
- 前端构建、Rust 检查、格式、图谱、UI、发布和当前开发审计全部通过；
- GitHub Quality Gate 对最终提交返回成功。
