# UX-50L / EA-4B 外部 JSON Canvas 工作区审计

日期：2026-08-07

## 本阶段结论

EA-4B 已完成 `.canvas` 外部直开、完整画布编辑与显式保存。用户从系统文件选择器、Windows 启动参数或格式能力页逐项选择 LongEdit 打开 JSON Canvas 时，可直接进入画布工作区，不需要先建立资料库或导入副本。

外部能力现为：

- `edit`：25 类，只有点击保存才写回源文件。
- `preview`：8 类，只读且没有写回入口。
- `import`：10 类，继续要求导入、转换或系统打开。

## 需求与安全边界

- 外部 Canvas 保留节点、分组、链接、连线、关系类型、颜色、拖动、缩放、框选、复制粘贴、撤销重做和右键菜单。
- 保存前明确提示将覆盖外部源文件；编辑只驻留内存，只有保存按钮或 `Ctrl+S` 才写回。
- 新增独立的外部 Canvas 读写命令，必须通过用户授权和 `.canvas` 格式校验。
- 读取与保存统一执行 JSON Canvas 结构校验和 20 MiB 上限；节点、连线、端口、端点、关系和颜色边界保持不变。
- 读取返回源文件签名。保存前再次验证签名；源文件在编辑期间变化时拒绝覆盖，并在界面明确提示重新打开。
- 合法保存会返回新签名，后续保存继续基于最新源文件身份。
- 外部 Canvas 中的文件节点只作为引用数据展示，不会自动读取或打开未单独授权的文件；资料库图表和 Mermaid 嵌入工具仅在资料库模式提供。
- 资料库创建、Markdown/图谱投影、索引和知识关系能力没有开放给外部文件。
- 安装器关联仍只有 `.md/.markdown`，是否让 LongEdit 默认打开 `.canvas` 继续由用户在 Windows 中逐项决定。

## 自动化证据

- `check:external-canvas-workspace`：锁定注册表、25/8/10 能力计数、专用命令、结构校验、签名保护、引用隔离和安装器关联。
- Rust 外部 Canvas 回归覆盖未授权读取、损坏结构拒绝、合法写回、新签名和外部修改冲突；所有失败路径保留源文件。
- `check:external-file-workspace` 与 `check:ux38e-canvas-explicit-save`：通过，既有外部格式和资料库 Canvas 显式保存边界未回退。
- 前端类型检查、生产构建、Canvas/外部授权回归、Rust 锁定检查与当前开发总审计在提交前执行。
