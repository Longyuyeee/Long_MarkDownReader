## 源码与验收缺口

TextEditorView 的 save 在等待写入 IPC 后直接访问可变的 `editor.state`；onBeforeUnmount 会 destroy 并设 editor=null。安装脚本在磁盘出现新内容后立即切往工作台再重开，检查正文可见与全局 fallback，但没有检查保存报错和保存状态。这解释了“文件落盘、旧组件已卸载、保存回调报错”的竞态风险。

这是源码和远端截图支持的原因判断，尚无本机手动复现或错误堆栈，不把推断写成完整根因验证。不能简单延迟脚本切页、屏蔽错误 toast、修改截图或忽略未保存标识来通过。

## 冻结用户场景与下一步

1. **保存后立即切换**：“我保存这条笔记，马上去看另一份。”通过真实输入、保存按钮/快捷键、点击另一文件再返回复现；核对正文、保存状态、磁盘及下一次保存。失败保留原图和步骤。
2. **失败后重试**：“资料库刚才断开了，现在恢复了，能直接重试吗？”普通关键词与标签分别验证，不改查询来绕开原失败。
3. **窄窗口辨认与打开**：“这几个文件名字很像，我想打开客户会议纪要。”使用自然文件名/正文，验证完整名称、长标题、键盘焦点与打开目标；不改样本使其更容易通过。
4. **键盘与暗色**：“我习惯用键盘，晚上用深色主题。”按真实键盘顺序检查重试与打开，不直接调用组件方法充当用户操作。
