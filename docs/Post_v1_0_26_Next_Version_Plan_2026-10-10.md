# v1.0.26 之后的开发建议

> 2026-10-11：本页为上一轮候选建议，已由用户确认的 [v1.1.0 产品与 UI 计划](./V1_1_0_Product_and_UI_Plan_2026-10-11.md) 接替。下一产品版本为 1.1.0，包含四项核心工作流升级及封板前逐界面 UI 重构；每页先示意、经用户确认再修改。以下保留为历史设计依据。

本文件是下一版候选方向，不表示功能已经实现，也不扩大 v1.0.26 冻结范围。优先完善现有资料库、搜索与写作体验，不新增独立“报告/摘要”模块。

## 建议顺序

1. **恢复工作现场**：用户关掉软件后再打开，能选择恢复上次搜索、主文档和只读参考。仅保存路径、查询与位置；先验证文件存在及资料库归属，不把未保存内容或摘录全文隐式写入会话。跨资料库隔离，提供清除记录入口。
2. **来源失效处理更容易发现**：现版支持点击失效来源后手动重新关联。下一步先改善提示和文件选择体验，再考虑由用户确认的批量修复；不能仅凭同名自动替换，不能悄悄改写全库。
3. **大资料库搜索更顺畅**：从真实任务测量输入到可见结果的耗时、取消旧查询的响应、滚动位置恢复和内存占用；只优化已测得的瓶颈。覆盖中文、长路径、无结果、索引重建和多格式混合库。
4. **窄屏与键盘连贯性**：延续“结果默认主区打开，参考为显式动作”；检查参考展开/收起、摘录插入后继续写作、Tab 顺序和读屏标签。不重新引入先预览再固定的强制步骤。

## 验收方式

- 用用户任务描述案例：“昨天查到的资料今天接着写”“来源挪了目录但我不想丢掉引用”“搜索很快切换几个词，不要跳回旧结果”。
- 从空会话、已有未保存草稿、文件移动/删除、切换资料库分别测试；同时观察主区内容、焦点、提示与磁盘结果。
- 先记录失败，再修改实现。不得放宽预期以让验收通过；原始失败与复验记录分别保存。
- 一个闭环完成后做代码审计、回归、文档和推送；下一次发版仍须使用固定提交构建与真实安装态证据。

发布后的官方 v1.0.25 → v1.0.26 应用内更新观察是单独待办；覆盖安装通过不能替代该结论。产品版本保持 1.0.26，待下一版范围确定再进行原子版本迁移。
