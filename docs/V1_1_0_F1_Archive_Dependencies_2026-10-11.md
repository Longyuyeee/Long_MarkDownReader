# F1 归档依赖候选检查

日期：2026-10-11。接续 `c99fa9a5`。后端只读变更，无 UI 修改、无实际移动、不发版。

## 已实现与用户价值

归档前不能只查来源中的图片：其他笔记可能引用待移动文件。新增库内 Markdown 扫描，单次扫描结果供整个批次使用，逐项返回 `dependencies.outgoing` 与 `incomingCandidates`，包含来源文件、行号、引用目标和语法类型，便于后续弹窗解释风险。

覆盖普通 Markdown 链接/图片、引用式定义、带引号的 HTML src/href、现有 Wiki 解析和 PDF 引用解析。外部 HTTP(S)、邮件、data、电话与当前文档锚点不纳入本地文件候选；百分号编码解码前先拆查询和片段，避免把文件名中的编码 # 误当锚点。库内嵌套目录参与检查，不因 Inbox 外部而漏掉引用来源。

入链使用保守文件名/双链标题匹配，不调用图谱“同名取首个”的解析逻辑；同名候选可能多报，不自动选定目标、不重写正文。普通链接的代码示例也可能成为候选。这是风险清单，不是完整 Markdown 语法树或已解析依赖图。

发现候选返回 `dependency_candidates`；目录/文件不可读、无效 UTF-8、符号链接、数量或体积超限返回 `dependency_scan_incomplete`，不伪装为零引用。每次最多遍历 20000 条目、扫描 32 MiB Markdown、单文件 2 MiB、20000 引用候选；跳过 .git。符号链接不跟随。预检整体放入 `spawn_blocking`，不在异步运行线程内进行同步磁盘摘要/扫描。

## 必须保留的边界

- `dependencies.complete` 当前始终为 false，并提供 limitations；零候选不代表允许归档，`canExecute` 仍为 false。
- 未覆盖非 Markdown 文档中的引用、全部复杂/跨行 Markdown 语法、动态 HTML/CSS、所有 URL 方案、外部库入链；不是完整依赖安全证明。
- 扫描不是原子快照，执行前必须再次验证文件身份、引用和草稿状态。
- 历史批次总预算、取消/过期任务、多请求并发限流仍待处理；后台运行不等于大库交互性能已验收。
- 本次不移动附件、不修复链接、不改变旧拖动行为、不开放归档按钮。
