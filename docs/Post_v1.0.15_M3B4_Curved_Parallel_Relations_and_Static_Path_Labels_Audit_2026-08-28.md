# v1.0.15 后 M3B-4 曲线/平行关系与静态路径标签审计

日期：2026-08-28

进入基线：`main` / `a0cf535910baa1be8461f9dd60e71cbb2a66a9df`

阶段：M3B-4

发布候选：否

## 1. 需求与修正前事实

本阶段直接对齐专业能力路线图 7.2 和 M3B-3 选择审计，只处理静态关系可读性基础：确定性 network 曲线、平行/互反边分离、沿事实方向的切线箭头、仅选中路径显示的关系标签，以及路径证据面板与可用画布共同取景。

进入时屏幕 Canvas 和 SVG 的 network 边均为直线；同端点关系没有视觉路由身份，平行及互反关系重叠；箭头使用端点直线角度；路径虽保留 3 条真实边和全部证据，但没有 Canvas 标签，证据面板覆盖路径主体。方向动画、减少动效消费、缩略导航、聚类镜头、状态外环和 M3C 性能明确不属于本阶段。

## 2. 实现结果

- 新增独立纯函数路由层，按规范化端点、事实方向、关系类型和 mention 签名稳定排序，不依赖后端边输入顺序，也不修改关系事实。
- 单关系使用稳定轻曲率；平行及互反关系使用互异曲率槽。三边乱序夹具得到完全一致的路由 ID 和偏移，所有曲率非零且互异。
- Canvas network 和 SVG/PNG 导出共用同一路由、二次曲线几何、曲线上点、切线和标签位置函数；没有建立屏幕与导出的第二套事实。
- 有向箭头在曲线 72% 位置按切线旋转，反向关系仍沿原始 `source → target` 事实方向，不按遍历方向改写。
- 只有经过独立 BFS 验证的活动最短路径显示静态关系标签并提高边可见度；普通全局图不铺满标签。标签沿曲线法线偏移 20px，减少与节点标题和线段重叠。
- `fitGraph()` 根据证据面板之外的候选区域和路径包围盒宽高比选择真实可用取景区；窗口变化时重新取景。中窄屏限制面板高度并保留内部滚动，使面板和路径同时可见。

## 3. 真实效果差异与修正记录

真实审计没有一次性通过，实际发现和修正如下：

1. 三条平行边的中心槽最初退化为零曲率，与“曲线路由”不一致；改为稳定非零轻曲率。
2. 首次 Tauri 审计按剩余矩形面积选择相机区域，`1280×800` 安全门禁失败；改为按路径宽高比比较候选区域可用缩放。
3. 审计脚本最初找不到 Canvas 稳定测试身份，明确失败而非把缺失元素视为通过；补齐 `graph-canvas` 身份后重新执行。
4. `720×680` 的 DOM 边界和节点坐标一度通过，但人工截图显示面板仍覆盖几乎全部路径；收紧中窄屏面板高度并保留滚动后，路径在面板下方完整可见。
5. 第二轮窄屏路径虽可见，但标签与标题偏拥挤；增加可用画布并把标签沿法线偏移由 14px 调至 20px，再重跑三主题最终证据。

这些失败均没有通过修改验收目标或删除检查掩盖。

## 4. 独立合同与真实桌面结果

独立合同直接调用生产路由函数，验证乱序稳定性、平行/互反分离、非零曲率、切线与事实方向点积为正、共享 SVG 路径数据和有界标签位置。生产构建通过。

真实跨格式资料库保持 17 节点/17 边，实际存在 2 条平行/互反视觉路由。`NorthStar → Evidence` 仍为 4 节点/3 边，Canvas 显示 3 个静态关系标签，证据面板仍展示 3 条路径边及全部既有 mention/结构证据。

暗色、浅色、高对比主题均在 `1280×800`、`1000×700`、`720×680` 验证：页面适配、面板在视口内、路径相机位于未遮挡区域、3 个标签可见。三套运行时错误均为 0，审计前后资料库 SHA-256 一致，并成功返回资料库。证据位于 `docs/evidence/post-v115-m3b4-curved-parallel-relations-static-path-labels/`，不含用户内容。
