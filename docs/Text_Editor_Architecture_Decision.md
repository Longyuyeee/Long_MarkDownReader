# 统一 TXT 编辑器架构决策

## 状态

2026-07-24，A2 第一批采用；A2 第二批补齐外部打开、最近文件和自动保存。

## 决策

TXT 独立工作面使用 CodeMirror 6，并通过 `TextEditorView.vue` 按路由懒加载。Markdown 继续使用 Vditor；两者共享 A1 的 Rust 文本快照、编码策略、签名冲突和范围读取内核，不共享前端编辑器实例。

## 选型比较

| 方案 | 包体与加载 | TXT 日常能力 | 大文件与只读 | Vue/Tauri 风险 | 结论 |
|---|---|---|---|---|---|
| CodeMirror 6 | 模块化，独立路由可拆包 | 行号、查找替换、跳行、选择与扩展 API 完整 | 可动态只读，可与后端范围读取组合 | DOM 编辑器，对 WebView2 兼容风险较低 | 采用 |
| Monaco Editor | Worker、语言服务和静态资源较重 | 能力最完整 | 大文件能力较强 | Tauri 资源路径、Worker 和首载成本更高 | 暂不采用 |
| Vditor | 项目已有依赖 | 偏 Markdown 语义，纯文本查找、行号和保存策略不自然 | 已验证超大内容需要额外降级 | 复用简单，但会继续耦合 LibraryMode | 仅保留 Markdown |
| 原生 textarea | 无新增依赖 | 搜索替换、行号、撤销与跳行需自行实现 | 大文本 DOM 行为不可控 | 初始简单，长期维护成本高 | 不采用 |

## 边界

- CodeMirror 只负责编辑状态、选择、行号、查找替换和键盘交互。
- 编码检测、BOM、换行、末尾换行、可靠保存和外部冲突由 Rust A1 内核负责。
- 超过格式完整编辑阈值后不把完整文件装入编辑器；工作面进入只读范围模式，每次请求默认 512 KiB、后端强制上限 1 MiB。
- A2 后续语法扩展仍按格式注册表分派，不在 TXT 工作面硬编码 YAML、XML 或代码语言。

## 后续

A2 最后一批建立跨 Markdown/TXT 工作面的统一标签模型，并统一标签关闭、工作区切换和应用退出时的未保存协调。查找状态持久化可随统一标签模型落地；真实 Tauri 交互证据集中在 A5。A3 再复用同一内核建设 JSON/JSONC 源码与树形工作面。
