# P1 最终能力与最初需求对齐审计

审计日期：2026-08-16

结论：有界通过，可进入 `1.0.11` 无签名补丁版本发布流程。

## 1. 总结论

最初的核心目标不是复刻所有专业软件，而是在一个资料库管理器中覆盖日常管理、阅读和基础编辑，并把文件、引用、搜索、标签、关系与历史组织成体系。当前实现已达到这个有界目标：43 类格式、91 个扩展名进入统一注册表和 11 套能力配置，其中 30 类已验证、7 类有限能力、6 类依赖外部程序。

“支持格式”不等于“所有格式具备同等编辑深度”。本审计明确拒绝全格式等价、完整 Office/WPS 等价、任意 PDF 正文编辑、完整匿名化和企业签名版等越界表述。

## 2. 最初需求逐项对齐

- 日常管理：资料库、搜索、标签、保存视图、引用、历史、备份、文件上下文和工作区标签形成统一流程。
- 基础编辑：Markdown/TXT/JSON/JSONC/YAML/XML/TOML/日志及常见代码/Web 源文件可在受管编辑器中显式保存；CSV/TSV/Table、Canvas/Mermaid/OPML/Draw.io 有各自的有界编辑工作区。
- PDF：阅读、搜索、批注/OCR sidecar、页面副本操作、安全表单子集、永久脱敏图片型副本、文字水印和四字段文档属性可靠副本均已进入原右侧工作区并通过真实桌面/独立验证。
- Office/表格：DOCX、PPTX、XLSX 具备有界基础编辑和可靠保存/副本；ODS/ODP 只读预览，旧 Office 走显式转换，WPS 原生格式依赖外部 WPS。
- 统一结构：默认仍是左侧资料库/导航和右侧编辑区，专项能力不得另起割裂界面；外部文件采用独立顶层窗口是明确的外部打开策略，不占用主资料库。

## 3. 格式能力分层

第一层是可直接日常编辑的轻量文本、结构化源文件、表格源和图形源；第二层是需要保真门禁的 PDF、DOCX、PPTX、XLSX 与图片可靠副本；第三层是只读预览或外部程序承接的 ODF、旧 Office、WPS 原生和视频。发布说明必须展示层级和限制，不能只展示扩展名数量。

XLSX 不执行宏、不刷新外部数据，也不承诺 Excel 全对象等价；DOCX/PPTX 不承诺复杂跨部件和厂商对象全保真；PDF 不覆盖源文件、不任意重排正文；图片和视频不是专业制作套件。这些边界是可靠性的组成部分。

## 4. 知识图谱与思维导图结论

知识图谱已从隐藏关系视图提升为工作台可见的知识网络脉冲：展示对象/关系/覆盖率/孤立对象/热门主题，可从中心图谱导航；画布支持五种布局、三种主题、平移缩放、框选/多选、组合拖动、键盘移动、撤销重做和本地布局持久化。跨 Markdown、PDF、表格、Canvas、OPML、PPTX 等代表格式的合成资料库验收已通过。

知识图谱仍是“从资料库派生的关系探索”，不是自由绘制思维导图的源编辑器。自由或结构化思维导图编辑由 Canvas、OPML、Mermaid 和 Draw.io 工作区承担。真实用户资料库上的推荐质量仍需用户同意后的长期观察，不能在本补丁中虚构完成。

## 5. 发布边界

P1 没有剩余的版本阻断型功能开发。外部生产者矩阵、复杂 Office/Excel 对象、真实资料库图谱推荐质量、企业签名和协作治理属于后续增强，不阻止无签名社区补丁版。

`1.0.11` 仍为无 Authenticode 签名社区版本；必须保留未知发布者说明、SHA-256、严格附件名、受控更新源和不发布旧式 `latest.json`/`.sig` 的既有策略。

## 6. 下一阶段执行顺序

1. 同步 package、Cargo、Tauri、能力矩阵和发布策略到 `1.0.11`，更新 README 与 Release Notes。
2. 运行完整补丁质量门并冻结产品提交。
3. 从冻结提交构建 NSIS/MSI，生成和复核 SHA-256。
4. 运行 GitHub 托管的一次性 Windows 安装生命周期，回写候选证据。
5. 发布 GitHub Release，重新下载三项附件并核对名称、大小与摘要。
6. 单独执行官方 `1.0.10 -> 1.0.11` 应用内更新、自动重启和资料保留观察。
