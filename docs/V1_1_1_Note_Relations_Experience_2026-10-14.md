# 关系页：从笔记引用继续阅读

2026-10-14，接续用户反馈“关系 tab 用途迷惑，功能摊开且缺少设计”。在 `codex/inbox-experience` 上与收集箱、标签切换、智能集合、文内标签改进一并开发；公开安装包仍为1.1.0，本轮未打包发布。

## 用户用途与页面安排

关系页首先回答两个具体问题：这篇笔记提到了哪些笔记？哪些笔记提到了它？这些关系来自 Markdown 正文中的 `[[笔记名]]` 引用。

- 顶部显示当前笔记，避免不知道正在查看谁的关系。未保存时说明正文引用已经更新，而其他笔记的引用来源以保存内容为准。
- 用“我提到的 / 提到我的”两个方向切换，替代同时展开的“链出 / 链入”列表。默认以可打开的引用列表为主，同一目标多次出现只展示一个入口。
- “提到我的”展示来源笔记、库内路径和简短引用句，完整句子可以展开。名称和路径没有悬停浮窗，点击打开原文件并保持关系标签可见。
- 图谱操作归入按需展开的“查看关系图”：保留以当前文件为中心打开知识图谱、在编辑器右侧固定关系图，并可从本面板取消固定。右侧原有深度、筛选、证据、思维导图和可编辑画布功能继续使用原组件。
- 完整用法归入折叠说明；没有引用、没有打开笔记、非 Markdown 分别提供具体例子或打开笔记入口，其他类型的关系仍可进入知识图谱查看。

## 引用读取与打开

`NoteRelationsPanel` 使用当前标签草稿提取正文引用，正文改变后350ms更新；只有进入面板、切换文档或主动刷新时扫描其他笔记的引用来源。两侧读取独立，失败一侧可重试，不清空另一侧。文档/资料库和请求序号共同核对，旧回执不能覆盖当前页面。

打开正文引用时，使用既有 `search_library` 查找文件名，随后按当前资料库、Markdown 扩展名和目标名称筛选。显式子目录路径匹配对应位置，普通名称优先唯一的同目录笔记；其他同名笔记提供带路径的选择列表。未找到时在面板内提示，并提供“在文件中查找”。不依赖用户先展开文件树，也不直接改写标签选中状态；继续使用主编辑区原有文件导航。

`search_library` 新增可选 `namesOnly` 参数，关系定位传入 `true`，无需读取所有笔记的正文。默认和跨库搜索仍保留原有文件名/正文搜索语义；没有新增原生命令或写文件流程。别名提取、引用语法及反向引用的原生规则沿用现有实现。
