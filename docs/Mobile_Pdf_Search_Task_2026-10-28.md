## 冻结设计与操作契约

[八屏设计源](design/mobile-pdf-search-v1/index.html)覆盖初始、结果、无匹配、查找中、停止、读取失败、部分结果和空词校验。[冻结回执](evidence/mobile-pdf-search-task-2026-10-28/design-freeze.json)为 `2026-10-28T02:54:02.588Z`，HTML SHA-256 为 `06707f42b4656584e4ea134d5fb9be190e12a6948c6015e149676fb717ccba47`。先查看八张冻结图，再修改运行时代码。后续修复未覆盖冻结源、时间或图片。

设计中的普通片段直接取实施前真实九页 PDF 查找结果；部分状态对应仓库已有生成器产生的真实 501 页 PDF。原型仍是静态 HTML，不把示例状态当作正式能力验证，实际 App 独立重新捕获。

- 独立任务覆盖 PDF 工作区，原阅读区域保持挂载和尺寸，隐藏且 inert。初始只提供输入和返回，不重复展示“输入后查找”等说明；原“不含扫描图片文字”、匹配方式、页码规则和预算进入问号。
- 输入后明确查找，结果显示物理页码、该页匹配数与首处附近原文。选择只到该页，不承诺精确高亮或定位到某一行；选择当前页不重新渲染／复位。片段按文字渲染，不执行 PDF 文字中的 HTML。
- 普通返回、顶部返回、继续阅读和 Escape 保留查询原写法、输入选区／方向、结果、展开数量、列表滚动及可恢复的焦点。再次打开从原现场继续，不强制回输入框；关闭整份 PDF 后清除会话查找准备。取消且尚未选择结果时，原页、缩放和横纵滚动保持原样。
- 结果 → 阅读页构成可返回的子任务。阅读页顶部返回的无障碍名称为“返回查找结果”；该动作和系统返回桥接先恢复结果列表与所选行焦点。列表“继续阅读”／关闭结束这层关系，停留在现在的阅读页，不回跳查找前旧页。阅读设置等辅助层先返回自身，保持查找上下文；明确用其他页码／导航选页会结束结果返回关系。
- 查询修改会清掉不再对应的结果，并取消旧请求；英文大小写与首尾空白一致时保留相同匹配。明确查找读取输入框可见值，模拟未提交合成后的 model 更新不会清掉已完成结果；这不等于真实 Android 输入法验收。
- 查找中可以停止；停止／关闭保留查询与已检查页数，迟到结果不能覆盖新词或已停止状态。停止不会把未完成显示为无匹配；当前引擎没有逐步发布命中，重新查找从首页开始。
- 空词是字段错误；完整无匹配、读取失败和部分结果各自显示。读取失败保留原词并提供“重新查找”。达到原有 500 页、累计约 209 万字符或 1000 处匹配预算时明确标为部分结果；单页提取上限仍为 20 万字符。
- 结果先展示 50 页，可再展开 50 页；展开数量与浏览现场一起保留。只限制显示数量，不改变引擎已经返回的结果或统计。
- 帮助先关闭并恢复问号焦点。进入查找前沿用批注草稿保护；保护失败留在评论输入并显示错误。PDF 字节、已有笔记和草稿不因查找变化。深色、320px、200% 和短视口独立验收。

新增 `MobilePdfSearch.vue` 承担查找任务与会话状态，宿主保留阅读／手势／连续阅读／权限引擎并提供既有文字提取。页码与导航测试改为先关闭查找再进入同级任务，回来仍验证未确认词和页码保留。阶段 4A／4B1 关于内联查找可在其上直接打开导航或页码的操作，由本轮独立任务规则替代；不是删除原能力或删掉恢复断言。

首轮[七组通过版本](evidence/mobile-pdf-search-task-2026-10-28/before-short-fix-report.json)的[短屏图](evidence/mobile-pdf-search-task-2026-10-28/before-short-fix-results-short-320-200.png)仍让底部重复动作占据结果区域。看图后改为短屏只保留顶部返回，收起文件信息与可见重复标签；输入仍有可访问标签。[收起底部后的图](evidence/mobile-pdf-search-task-2026-10-28/before-short-count-results-short-320-200.png)又显示完整统计占两行，随后只在短屏改用简短结果计数和更紧的正文留白。最终专项断言正文至少 120px、首条结果标题完整进入视口，原图另保留实际滚动。极短大字视口仍需滚动阅读完整片段，没有声称能同时显示全部内容。

返回链补查[真实复现失败](evidence/mobile-pdf-search-task-2026-10-28/settings-return-failure-report.json)：选择第 9 页结果 → 打开阅读方式 → 关闭阅读方式，`返回查找结果` 上下文消失。原因是辅助设置无条件调用查找 hide，即便查找列表已关闭也清掉预览关系。现改为只关闭实际打开的查找，阅读设置和权限层保留已有结果返回关系；最终同一场景通过。

准备阶段还出现设计捕获脚本的 `top` 未定义和首次类型检查的未使用 root ref，均在浏览器候选验收前修正；前者发生于冻结回执生成前，不记作产品失败或通过结果。最终构建与验证之后没有再改运行时代码。
