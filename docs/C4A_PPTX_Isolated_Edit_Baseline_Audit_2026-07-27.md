# LongEdit C4A PPTX 隔离编辑基线审计

审计日期：2026-07-27

## 1. 目的对齐

C4A 不负责交付可见的 PPTX 文本修改，也不允许保存或覆盖用户文件。本阶段先建立后续编辑必须依赖的安全底座：

1. 打开时生成源文件签名，编辑准备前检查外部修改冲突；
2. 只在内存和操作系统临时目录中建立隔离副本；
3. 对每个 OOXML 部件记录名称、大小和 SHA-256；
4. 证明隔离副本与源包逐部件一致、完整包摘要一致；
5. 真实落地临时 PPTX 并重新读取、重新解析；
6. 再次读取源文件，证明其签名、摘要和字节均未变化；
7. 只公布后续候选编辑部件，不在 C4A 开放任何修改或保存命令。

这与基础需求“日常管理和基础编辑，但必须安全、成体系”保持一致：先解决可恢复性和原件保护，再开放编辑能力。

## 2. 已实现能力

### 2.1 OOXML 隔离基线内核

新增 `src-tauri/src/formats/pptx_edit.rs`：

- `PptxEditBaselineReport` 提供结构化审计结果；
- 逐个读取 ZIP 部件并计算 SHA-256；
- 拒绝不安全路径、重复部件和空包；
- 内存副本保持完整 PPTX 包字节一致；
- 源包和隔离包都必须通过 `parse_pptx` 结构复读；
- `changedParts`、`addedParts`、`removedParts` 在 C4A 必须为空；
- `editingEnabled=false`、`writesUserFile=false` 是强制边界；
- 仅把 `ppt/slides/slide*.xml` 和 `ppt/notesSlides/notesSlide*.xml` 标为 C4B 候选部件，其余部件保持保护状态。

### 2.2 命令层保护

新增 `audit_pptx_edit_baseline`：

- 使用 `WorkspaceGuard` 校验库目录和 `.pptx` 扩展名；
- 使用文件大小和纳秒修改时间组成签名握手；
- 签名过期时拒绝建立基线；
- 使用独立临时文件落地、同步、复读隔离包；
- 临时文件通过 RAII 自动清理；
- 审计结束后再次核对源文件字节和签名；
- 不暴露 `write_pptx`、覆盖保存或另存命令。

### 2.3 原界面内的编辑准备入口

“编辑准备”位于原 PPTX 阅读器工具栏，结果仍显示在 Library 右侧详情面板：

- 不打开新窗口或新页面；
- 使用原有字号、颜色变量、按钮和详情面板样式；
- 显示隔离方式、OOXML 部件数、候选部件数、原样保全部件数、临时副本复读结果和源文件写入状态；
- 状态栏明确显示“原文件未修改”；
- 960px 宽度继续使用原有右侧覆盖式详情面板，不产生横向溢出；
- 文案明确 C4A 仍是只读保护基线，C4B 才开放隔离文本/备注补丁。

## 5. 下一步：C4B

C4B 只实现一个安全垂直切片：

1. 枚举只含安全普通文本载体的单文本对象；
2. 枚举演讲者备注中的安全单段文本；
3. 每个目标提供稳定 ID、所属幻灯片、原文本摘要和目标部件摘要；
4. 替换操作只作用于内存/临时副本；
5. 差异白名单必须精确为一个 slide XML 或一个 notesSlide XML；
6. 所有其他 OOXML 部件必须逐摘要不变；
7. 输出必须重新解析并验证目标语义；
8. 继续禁止用户文件写入和保存按钮。

当 C4B 通过三生产者结构回归和真实桌面审计后，再进入基础字符样式及形状文本安全子集。
