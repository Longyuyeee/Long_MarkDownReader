# Markdown 持续卡顿与系统打开权限修复

用户确认：同一文档在外部窗口和知识库里都会卡顿，静止时也影响鼠标移动。因此不能归因于外部窗口启动流程。

共用正文 SCSS 为标题、代码块等逐项创建循环动画，并使用模糊背景与段落进入动画。119,130 字符、225 个标题、71 个代码块、约 9,172 个 DOM 节点的生成文档在原样式中有 296 个持续动画；本机浏览器样本的较慢帧（90 帧的 P95）为 54.3 ms。编译修改后的实际 SCSS 后，持续动画为 0，P95 为 6.3 ms；复测为 6.2 ms。环境负载影响绝对帧时间，不将这些数字作为所有机器的承诺。

已在共用正文样式中禁用装饰动画、过渡及 backdrop-filter，保留排版与编辑模式。两种模式仅在显示大纲时观察正文；大纲变动合并到 120 ms 一次，读取 textContent 避免 innerText 触发布局，标题未变化时保留原树引用，重建及销毁时清理观察者和定时器。知识库隐藏大纲时也不再逐标题测量滚动位置。

这证实并消除了一项持续渲染负担，尚不能证明原用户文档的所有输入延迟消失。合成文档的 Markdown 全文序列化仍约需 100–230 ms；真实键盘探针到下一帧约 138–249 ms。没有用静止帧改善冒充输入延迟改善，也没有自动降级用户的所见即所得模式。用户文件没有上传或纳入证据。

`opener:default` 的实际插件权限仅含 URL 打开、文件定位，不包含 `open_path`。文件树改用 revealItemInDir；媒体打开显式配置与格式注册表一致的 17 种图片/视频扩展名范围，兼容大小写，仅系统默认应用，未开放可执行程序路径。两处失败均在页面处理，不再逃逸为未处理 Promise。

验证：6 项大纲/正文回归、3 项打开权限/失败恢复回归、28 项安装证据验证器测试通过；生产前端构建、当前开发审计、Rust cargo check 通过。安装验收增加生成长文档的静止动画、实际输入与保存，以及原生 opener 命令和路径范围检查。当前还没有包含这批修改的新安装包通过记录，不能把旧包验收继承为通过。
