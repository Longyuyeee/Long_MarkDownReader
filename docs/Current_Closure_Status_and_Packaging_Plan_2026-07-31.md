## 后续顺序

### 1. E5 高级能力最终收口审计

1. 对齐高级能力路线图、格式注册表、发布矩阵、安全降级合同、产品验收冻结和交接文档。
2. 运行完整 `ci:check`，确认前端构建、Rust 功能/性能回归、格式合同、发布合同和依赖审计全部通过。
3. 只修复审计发现的遗漏或回归，不新增大型编辑能力，不扩大已冻结的格式承诺。
4. 输出 E5 审计结论，明确“已完成”“外部阻塞”“延期评估”三类事项。

### 2. 未签名安装包收口

1. 从 E5 通过的干净 `main` 构建当前 MSI 与 NSIS 安装包。
2. 记录版本、提交、构建时间、文件大小和 SHA-256，确保安装包能够追溯到唯一源码提交。
3. 在当前可用 Windows 环境执行安装、启动、文件关联、升级/覆盖边界、卸载和用户数据保留冒烟。
4. 将结果标记为“未签名内部候选包”，继续保持 `releaseCandidate=false`，不得替代真实签名与隔离 VM 证据。

### 3. 正式发布外部门禁

以下条件具备后才能继续正式 RC：

- 取得真实可信代码签名证书并验证 MSI/NSIS 签名链；
- 在干净 Windows 10/11 隔离环境完成安装、升级、降级拒绝、卸载、文件关联恢复和应用数据保留矩阵；
- 完成已安装产物冒烟、发布说明、回滚方案与人工发布批准；
- 所有机器门禁保持通过，安装包摘要与被批准提交完全一致。

## 收口判定

- E5 通过：表示当前高级产品能力与文档总账完成收口。
- 未签名安装验证通过：表示可以形成内部交接安装包，不代表正式 RC。
- 真实签名、Windows 10/11 隔离证据与人工批准全部通过：才允许重新评估 `releaseCandidate=true`。

接手后先执行 E5，不继续开发新的大型功能；E5 通过后再进入未签名安装包构建与验证。
