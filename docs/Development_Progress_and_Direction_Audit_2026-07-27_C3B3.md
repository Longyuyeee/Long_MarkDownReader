## 3. C3C 架构审计

C3C 不是单一注册表修改，当前代码存在四个必须同时闭环的缺口。

### 3.1 注册与索引适配器

`shared/file-formats.json` 中 PPTX 仍为：

- `capabilities.index = planned`
- `adapters.indexer = null`

必须在解析、定位和回归全部到位后，才能提升为 `supported / pptx`。提前修改会让系统宣称支持但实际搜索不到内容。

### 3.2 持久化索引与实时降级

当前 `knowledge_index.rs` 的持久化搜索段和 `commands/index.rs` 的实时扫描分别处理 PDF、DOCX 和通用文本。PPTX 必须同时接入两条路径，否则索引 `ready` 与索引缺失/过期时会返回不同结果。

实施时应抽出可复用的 PPTX 搜索段生成函数，避免复制两套幻灯片遍历逻辑。每张幻灯片至少输出：

- 标题或文件名匹配段。
- 幻灯片正文/对象文本段。
- 备注段。
- `pptx-slide` 定位器、稳定幻灯片 ID、页序和位置标签。
- 可选的 `pptx-object` 定位器与对象 ID。

解析继续受 96 MiB 文件上限、ZIP 展开预算、对象数量上限和现有安全关系策略约束。

### 3.3 搜索结果精确打开

当前 Library 搜索只对 PDF 和 DOCX 有专门定位分支；PPTX 会退回普通文件打开。`PptxReaderView` 也只读取 `path`，尚未消费幻灯片或对象定位参数。

需要建立统一导航契约：

- 搜索结果携带 `locatorKind = pptx-slide | pptx-object`。
- `locatorObjectId` 使用源文件中的稳定幻灯片/对象 ID。
- 路由携带定位 ID 和一次性 `locatorToken`。
- 阅读器加载后选中目标幻灯片、滚动缩略图并高亮对象。
- 重复点击同一结果仍可重新定位。

### 3.4 KnowledgeObject 与关系管理

当前图谱适配器已覆盖 PDF、Table、Canvas 和 OPML 的细粒度对象，尚无 PPTX 分支。C3C 应增加：

- PPTX 文件对象。
- 幻灯片细粒度对象及 `contains` 关系。
- 有稳定 ID 且具备可搜索内容的对象定位信息。
- 文件级最近、收藏、集合继续复用既有通用能力。
- 幻灯片/对象级关系上下文接入共享侧栏，不新建 PPTX 专属管理孤岛。

第一批不解析外部超链接、图表数据关系或 SmartArt 语义关系；无法证明稳定性的关系明确留待增强。

## 4. 后续阶段与退出条件

### C3C：索引与管理闭环

建议拆为四个连续批次：

1. **C3C1 索引内核**：共享 PPTX 搜索段生成器、注册表 indexer、持久化索引和实时扫描一致性。
2. **C3C2 精确定位**：全局搜索结果定位幻灯片/对象，重复定位、隐藏页和备注命中进入回归。
3. **C3C3 对象与关系**：PPTX 文件/幻灯片 KnowledgeObject、`contains` 关系和共享关系侧栏。
4. **C3C4 收口审计**：索引重建、过期降级、资源上限、真实 fixture 和 Tauri 搜索定位证据。

退出条件：索引存在与不存在时结果语义一致；搜索可精确打开；删除索引后可重建；原 PPTX 字节不变；格式契约和完整 CI 通过。

### C3D：生产者与视觉收口

1. 获取合法可再分发的 WPS Presentation fixture，记录版本、生成步骤、哈希和外链/隐私审计。
2. 为 PowerPoint、WPS、LibreOffice 建立统一结构期望和应用内回读矩阵。
3. 建立真实 Tauri 多尺寸视觉矩阵，覆盖缩略图、放映、搜索定位、图片/组合/连接线/表格/复杂对象降级。

退出条件：生产者矩阵 `3/3`；视觉证据来自真实 Tauri/WebView2；不能用合成截图替代真实生产者证据。

### C4：PPTX 基础编辑

建议依次推进：

1. C4A 隔离副本、签名握手、部件差异白名单和写后复读基础。
2. C4B 普通文本及基础字号、颜色、对齐。
3. C4C 受限图片替换。
4. C4D 基础矩形、圆形和线条。
5. C4E 页面新增、复制、删除、排序及用户可见可靠另存。

动画、母版、SmartArt、复杂图表、宏、外链和未知扩展继续只读；无法证明未编辑部件保真的文件整批拒绝。

### C5：Office 桌面验收

- 支持子集完成真实编辑、另存、应用内重开和原生产者复开。
- 未编辑 ZIP 部件通过差异门禁。
- 高级对象和阻断原因在用户界面可见。
- DOCX/PPTX 的最近、搜索、收藏、集合和关系管理形成最终闭环。

完成 C3C、C3D、C4、C5 后，PPTX 阅读与基础编辑阶段才算收尾。

## 5. PPTX 之后的方向

主线顺序保持：

1. WPS 原生格式 `.wps/.et/.dps` 的识别、许可与安全转换审计。
2. OpenDocument `.odt/.ods/.odp` 的阅读、搜索及可编辑子集。
3. 旧版 Office `.doc/.xls/.ppt` 的外部打开与显式转换策略。
4. 安装、升级、卸载、文件关联和多机器发布矩阵。
5. 回补 XLSX S8-7E2F～S8-8、PDF 合并/拆分/插页及更深图谱语义等专项增强。

这些阶段不得以只增加扩展名白名单代替真实读取、降级、保存或外部打开闭环。
