# M4C-4 图谱→项目笔记披露审计

状态：通过；下一接续点为 M4C-5 图谱→Canvas 资格纠偏与快照披露

版本边界：运行时/公开 `1.0.15`，开发目标 `1.0.16`，`releaseCandidate=false`

## 1. 结论

M4C-4 已按原始 M4 受控转换要求关闭图谱→项目笔记的写盘前披露缺口。顶层 Markdown/PDF 图谱对象现在会先显示资料库相对中心、当前 1～4 层深度、同目录候选 Markdown、不覆盖/编号策略、生成模板、排序与 100 个关联对象上限，以及独立时间点派生语义；确认后继续自动打开后端返回的实际目标，中心和关联来源不写入。

本阶段没有修改项目笔记生成算法、图谱扫描或图谱→Canvas。现有后端边界经过超过 100 个关联对象的真实桌面复核后原样保留。

## 2. 原始需求与实际代码

原始 M4 要求每条跨格式输出在写盘前披露来源、目标路径、覆盖策略和转换损失，保持源安全，并自动打开实际目标。实际代码在本阶段前已经具备：

- 前后端一致限定顶层 Markdown/PDF 中心；
- `build_local_graph` 把深度收敛到 1～4 层；
- 目标位于中心同目录，名称为“`中心标题 项目.md`”，碰撞时递增编号；
- 生成追溯元数据、固定目标/关联资料/下一步结构和待办模板；
- 关联对象按标题、路径排序，最多写入 100 个并记录省略数；
- 使用新 UTF-8 文件写入，不覆盖已有来源或目标；
- 前端自动打开后端返回路径。

唯一产品缺口是“生成项目笔记”按钮直接写盘，没有让用户在生成前理解这些事实。

## 3. 产品实现

`GraphView` 的入口现在先打开结构化确认框：

- 显示资料库相对中心、当前深度和同目录候选目标；
- 明确绝不覆盖、同名编号和自动打开实际文件；
- 说明会写入中心/深度/生成标记，不复制中心正文；
- 说明固定目标、关联资料、下一步和待办模板；
- 说明按标题/路径排序、最多 100 个关联对象及正文省略数；
- 说明目标可独立编辑，但不会与图谱或中心来源自动同步；
- 明确中心及其他关联来源保持不变。

创建期间入口保持禁用。成功后通知资料库刷新、显示实际文件名并等待路由打开完成。对话框按图谱工作区宽度收敛，内容高度有界且可滚动。

## 5. 审计过程纠偏

1. 首轮预置碰撞文件由无 BOM PowerShell 5.1 脚本创建，中文“项目”文件名被错误解码，导致后端正确创建未编号目标，而脚本错误等待编号目标。碰撞夹具改由 Node 使用 Unicode 路径创建，再从全新隔离资料库重跑；没有修改产品编号逻辑。
2. 首次数据门禁通过后的人工视觉复核发现窄屏目标截图仍处于异步确认框关闭过程，且残留上一目标成功提示。审计增加等待旧提示消失和确认框完全关闭，再完整重跑四张证据；产品数据门禁未放宽。
