# UX-47 自动检查与受控安装审计

## 问题结论

已发布的 v1.0.4 没有自动安装能力。该 Release 只有 NSIS、MSI 与 `SHA256SUMS.txt`，没有旧 Tauri Updater 必须使用的 `latest.json` 和更新签名；原私钥不可用后，源码又按当时策略主动关闭了运行态检查。因此“检查更新”只能打开下载页，这不是偶发网络故障。

## 本次实现

- 应用启动后每 24 小时最多自动检查一次，设置页保留随时手动检查。
- Rust 后端固定查询 `Longyuyeee/Long_MarkDownReader` 的 GitHub 最新稳定 Release，不接受前端传入下载 URL、文件路径或哈希。
- 仅接受名称严格匹配 `LongEdit_<版本>_x64-setup.exe` 的 Windows x64 NSIS 附件；草稿、预发布、错误仓库路径和异常体积全部拒绝。
- 下载后使用 GitHub Release API 提供的附件 SHA-256 摘要校验；缺少摘要、下载不完整或摘要不一致时不启动安装器。
- 检查发现新版本后先向用户说明版本、大小、覆盖安装和未签名风险；只有用户点击“下载并安装”才下载并静默覆盖安装，随后退出当前应用。
- 更新失败使用中文产品提示，并保留官方 Release 页面作为人工兜底。

## 迁移边界

v1.0.4 已安装程序本身不包含本次代码，无法通过修改仓库让它自动升级。下一安装包仍需由用户完成一次手动覆盖安装；从包含 UX-47 的版本开始，后续符合相同附件合同的稳定版本才可以自动检查和安装。历史 v1.0.4 发布策略与证据不修改，也不会伪造 `latest.json` 或旧私钥签名。

## 验收

1. 运行 `npm run check:community-updater`，核对固定源、后端信任边界、自动/手动入口、哈希校验和安装参数。
2. 运行 Rust 单元测试，覆盖数字版本比较、不可信下载地址和无效 SHA-256 拒绝。
3. 运行生产构建和 Rust locked check。
4. 下一安装包发布前，在隔离 Windows 环境用一个更高测试版本验证：自动发现、稍后提醒、下载、哈希通过、静默覆盖、重启版本变化和用户资料保留。
