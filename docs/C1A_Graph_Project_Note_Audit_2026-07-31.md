# C1A 图谱项目笔记闭环审计

审计日期：2026-07-31

阶段状态：已完成

发布状态：`releaseCandidate=false`

## 本批目标

在 R5N 外部签名环境仍不可用期间，按综合审计的阶段 C 推进知识图谱产品化。现有主干已经具备关系新增/删除、来源证据、健康治理、局部图谱、思维导图模式和 Canvas 生成，因此 C1A 不重复实现关系编辑，而是完成“图谱节点转化为可执行管理对象”的首个闭环。

## 已完成

- 图谱节点详情新增“生成项目笔记”。
- 按当前节点和 1～4 层局部图谱生成新的 Markdown 项目页。
- 项目页记录 `longedit-generated`、中心对象和图谱深度，保留可解释来源。
- 项目页包含中心对象、最多 100 个关联对象、目标清单和下一步任务。
- 生成的 Markdown 自动进入现有全文搜索、关系解析和首页待办扫描。
- 新文件与中心对象保存在同一目录；同名时自动递增，绝不覆盖现有文件。
- 后端只接受知识库内 Markdown/PDF 中心对象，拒绝不安全 Wikilink 路径。

## 验证

- Rust 回归 `graph_generates_traceable_project_note_with_tasks` 通过。
- 前端 `vue-tsc --noEmit` 通过。
- Vite 生产构建通过。
- R3、R5N 和当前开发审计契约继续保持通过。

全仓 `cargo fmt --check` 仍会报告本批之前已经存在的若干格式化漂移。本批只格式化了实际修改的 Rust 文件，没有扩大提交范围。

## 边界

- 本批生成的是可继续编辑的 Markdown 项目骨架，不自动修改任何源笔记或图谱关系。
- 任务状态仍以 Markdown 任务列表为事实源。
- 项目笔记不会自动成为显式路径集合；子图智能集合需要后续扩展保存搜索模型。
- R5N 的真实签名、Windows 10/11 生命周期和人工批准仍未完成，本批不改变 RC 状态。

## 下一步

C1B 建议完成“子图保存为智能集合”：在保存搜索配置中增加受限的显式路径成员或图谱查询条件，让用户从节点生成可持续刷新的专题集合，并在首页、文件关系上下文和集合侧栏中统一打开。
