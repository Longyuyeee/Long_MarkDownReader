# A14 文件树新建与重命名审计

日期：2026-08-05

阶段：UX-36

结论：文件树新建与重命名阶段已收口。资料库空白区和目录右键菜单均以“新建”为第一项，可创建文件夹，并按文档、数据、图表与画布、代码与配置列出格式注册表中全部 18 种可创建格式。重命名显示完整文件名，允许在已注册格式间修改后缀，但不会覆盖同名项目，也不会把改后缀伪装成内容转换。

## 修复内容

- 右键新建菜单直接由 `shared/file-formats.json` 的创建能力生成，分类只承担用户信息组织，不维护第二份格式能力事实源。
- 空白区以资料库根目录为目标，目录节点以自身为目标；文件节点继续提供打开、收藏、重命名和删除，不混入无意义的新建入口。
- 重命名输入保留完整文件名与复合后缀；空名、首尾空格/句点、非法字符、Windows 保留名称和未注册后缀在前端直接拒绝，Rust 层再次执行同类安全校验。
- Rust 在移动前显式拒绝同名目标，并返回可理解的中文原因。后缀变化采用单弹窗两步确认，明确“只修改文件名，不转换内容”。
- 文件或目录重命名后同步打开标签、活动标签、收藏、最近记录、选择项、展开项和当前路由。

## 真实桌面验收

使用 Tauri Debug WebView2 和隔离临时资料库完成验收。根目录与目录右键首项均为“新建”，四个分类完整展示，实际创建 JSON 成功；重命名弹窗显示 `.md` 完整名称，同名冲突保留原文件并显示明确错误；`.md` 改为 `.txt` 时先显示不转换内容的提示，再进入同一弹窗的确认状态。确认后树节点、标签和路由均同步到新路径，运行时异常为 0，阻断错误页未出现。

三张截图均已人工检查。首次自动化通过时发现嵌套确认对话框重叠，产品改为单弹窗两步状态后重新采集并接受。证据位于 `docs/evidence/ux36-file-tree-actions`，不含用户资料和完整本机路径，`releaseCandidate=false`。
