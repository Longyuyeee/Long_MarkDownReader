# UX-38D2 DOCX 与 ODT 工作区审计

## 结论

UX-38D2 的 DOCX 受管工作区已完成独立验收。DOCX 页面编辑、显式保存边界、知识图谱返回上下文和窄窗口布局通过真实 Tauri Debug WebView2 验收；格式注册表、发布矩阵和安全降级合同已从旧的“只能另存副本”修正为真实的“有界覆盖保存或可靠副本”。

ODT 阅读器的直接预览路由、只读边界、滚动恢复和窄窗口布局也已通过，但 `.odt` 仍不进入统一格式注册表：Word 与 LibreOffice 生产者已验证，WPS Writer 因缺少可信 ODF 组件保持机器阻断，门禁仍为 2/3。不得把直接预览写成资料库已正式开放。

## 产品变更

- DOCX 与 ODT 按文件记忆正文双向滚动位置；DOCX 同时记忆编辑面板和编辑模式。
- 路由显式定位优先于历史滚动位置，修复加载状态结束前定位 DOM 不存在的问题。
- DOCX/ODT 按实际工作区容器宽度响应；DOCX 极窄窗口使用右侧覆盖编辑面板，ODT 极窄工具栏折行。
- DOCX 注册表显示“受限页面编辑”：草稿只驻留内存，隔离验证后由用户确认覆盖源文件或另存可靠副本；复杂对象继续只读。
- ODT 保持只读、无 writer、无保存，不绕过三生产者发布门禁。
