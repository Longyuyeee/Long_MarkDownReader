# UX-50D / EA-3A 外部媒体只读预览审计

日期：2026-08-07

## 本阶段结论

EA-3A 已完成。LongEdit 现在可由应用内“打开外部文件”、Windows 启动参数或用户主动设置的默认应用入口，直接打开图片和视频，但媒体工作区严格保持只读，不提供保存或写回命令。

外部打开能力现分为两类：

- `edit`：23 类 Markdown、文本、代码和结构化源码；只有用户点击保存才写回。
- `preview`：图片与视频 2 类；只读预览，永不写回。

## 需求对齐

- 图片支持 PNG、JPEG、GIF、WebP、BMP、ICO、AVIF，保留缩放、适应窗口、旋转和透明网格。
- 视频支持 MP4、WebM、OGV、M4V，并按系统解码器尝试 MOV、MKV、AVI、MPEG、MPG；保留倍速、定位、循环、画中画和全屏。
- 外部媒体进入独立工作区，显示“外部文件”“只读”“不会写回”，可返回资料库，也进入统一文档标签会话。
- 启动参数、单实例二次打开和文件选择器都复用显式外部授权；未经授权的绝对路径不能调用媒体预览命令。
- 媒体授权和可编辑授权分开保存，图片/视频不能进入任何外部写入命令。
- 安装器文件关联没有扩张，仍只有 `.md/.markdown`；图片和视频是否以 LongEdit 打开由用户在 Windows 中按格式逐项选择。
- “格式能力”页面分别显示 23 类可编辑格式和 2 类只读媒体，不再把预览描述成编辑。

- `npm run check:external-file-workspace`：通过，原有 23 类外部编辑边界未回退。
- `npm run check:media-workspace`：通过，8 种图片扩展名和 9 种视频扩展名仍走受保护的 Range 流式预览。
- `npm run build`：通过。
- `cargo test ... services::external_file_access::tests`：4/4 通过。
- `cargo test ... commands::media::tests`：2/2 通过。
- `cargo check --locked`：通过。
- `ci:patch-release` 所含代码门禁已逐项通过，包括 43 格式注册表、发布能力矩阵、Windows 生命周期和当前开发审计链。桌面会话中的系统 `npm.cmd` 在首次完整构建后从 PATH 消失，因此没有重复执行末尾的网络依赖审计；本阶段未修改依赖版本，EA-2B 基线的生产依赖审计为 0 漏洞。

## 保留边界

- 本阶段没有把 PDF、Office、表格或图形格式一并登记为外部预览；这些格式包含注释、转换、可靠副本或资料库关系语义，需要逐类审计，不能只改路由。
- 系统解码器兼容视频仍可能因机器缺少编解码器而无法在 WebView2 播放，此时继续提供系统播放器入口。
- 源码门禁不能替代下一安装包中的真实启动参数、文件选择器、单实例二次打开和默认应用回归。
