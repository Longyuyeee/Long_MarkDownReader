# F1 正文移动与历史发布内部串联

2026-10-11，接续 `4bbdb567`。无 UI 修改、无 Tauri 执行入口、无版本发布。

## 已实现

新增内部 move_with_history：同一缓存 lease 覆盖路径检查、历史暂存、正文意图写入并同步、无覆盖正文移动、历史副本发布全过程。prepare/publish 拆分为独立获取 lease 的包装与要求匹配 lease 的内部步骤，避免递归加锁失败或阶段间释放锁。源路径规范化前拒绝非普通文件/符号链接；目标目录必须存在且在库内，目标冲突不移动。

正文移动之前在暂存中写 document-intent.json（来源、目标、版本）。返回逐阶段回执 document_moved/history_published/error/stage：正文已移动后历史失败，不会返回一个模糊的整体失败来掩盖前一步。保留原历史、暂存副本和冲突目标，不盲目回滚、不覆盖、不删历史。

## 范围与审计限制

- 这只是内部磁盘顺序执行，不是用户归档授权。没有前端调用，也没有注册命令；canExecute 仍为 false。
- 首批要求存在历史暂存。无历史文件尚无独立事务日志，明确拒绝，不悄悄跳过保护。
- 日志目前记录路径，不含正文身份摘要；未完成外部并发身份锁、草稿/链接依赖检查、正文保存互斥、标签/索引更新、自动重试或崩溃恢复。绝不能据此开放入口。
- document_moved 表示本次系统移动成功，不是持续磁盘快照；外部程序随后变化仍需恢复核对。history_published 只表示历史发布步骤成功，不表示归档闭环。
- 失败准备可能已留下暂存，错误包含位置；正文移动之后的失败以结构化回执返回。跨进程、父目录替换、断电、网络盘仍未验收。
- 原历史不退役，失败回滚策略未实现。未来上层必须展示部分完成状态，不能标为全成功或让用户无脑重复执行。
