## 与原始需求及实际代码对齐

继续服务“在本地资料库找全、找准，找到后接着读写”的原任务。没有扩张 AI、平台、格式或第二套资料管理系统；不代存、不替换草稿、不改变权限/隐私排除和显式保存边界。保留原导航、文件筛选、标签快捷搜索、图谱集合、关系摘要、组内 PDF/Office 定位、命令/最近文件、只读参考和摘录入口。

1. 两处入口共用 `src/services/searchPages.ts`，分别调用 `search_knowledge_page` 与 `search_knowledge_libraries_page`。默认每页 **40 个文件**，不再以旧数组 200 条原始匹配作为这两处入口的终点。其他旧 API 消费者仍有各自限制，不能说所有集合/搜索能力均已改页。
2. 只追加同一快照、预期页尾的下一文件页；失败保留旧列表，重试同一游标。过期/条件不符重新搜索时保留旧文件等待结果，不混页。关闭、换词、换库、卸载退休自己的会话；迟到响应不能覆盖新查询或关闭新会话。
3. 跨库健康结果先可用，每库状态可展开；结果不全、全部失败与真正无结果区分。后台新排序就绪先提示，用户明确刷新才替换视图；后台完成不重置键盘选中项。相关性/修改时间切换重新请求原生排序，不只排当前已加载页。
4. 一文件一张卡，常显资料库/相对目录，避免同名混淆；前三个位置直达，其余按需展开，保留页码/批注/对象身份。摘要按需渲染，明确不代表全文或所有出现次数。恢复到第五个批注时会展开其位置区域。
5. `#标签` 原本走无页旧接口；本批补上原生 **tag 模式**，仍仅匹配 Markdown 正文中的确切、区分大小写标签，不误命中文件名、TXT 或相似前缀。复用来源扫描、正文/时间/载荷预算、快照及页合同；标签模式也绑定游标，不以旧无界接口绕过保护。
6. 资料库格式筛选继续针对**已加载文件**；若暂时没有所选格式，会说明仍可续载/调整，不冒称全库零结果。没有把格式筛选假装成原生全库条件。
7. 默认打开仍在主编辑区，显式“在侧边参考”独立。命令面板仅对当前资料库页面内、当前库可预览资料显示参考入口；跨库参考没有偷偷切库。跨库主区打开仍检查所有未保存草稿，配置保存中的 Esc/重复点击锁不变。
8. 搜索返回保留条件、格式、排序、已加载深度和选中位置；重新查询最多恢复 10,000 文件，并受 8 秒协作窗口限制。暂未加载原选中项时保留选择并说明原因，不提前当成已删除。命名工作现场也保留新增深度/排序字段，不存搜索结果或正文。

## 实看发现及修正

实际运行本仓库 Vue App，而非只查看示意图。全程无头浏览器、独立示例资料与模拟原生适配器，不接管用户桌面、不读取用户库。

- 首轮窄侧栏中标题被参考按钮挤碎；窄卡片改为标题与参考动作上下排，目录保留完整身份，短计数与排序保持紧凑。
- 六风格截图显示搜索面板透出背后的文档文字，干扰阅读；在原渐变下补主题实色底层，保留各风格的边框、阴影、渐变和正常光效，没有关闭正常动效来过验收。
- 组内折叠位置恢复时，状态已置位但 `<details>` 未打开；已绑定展开状态，并以实际组件 SSR 覆盖第五/第六批注位置。
- 补审发现后台搜索完成会将命令面板选择重新归零；删除该重置，保留初次查询归零及按文件身份接续选择，实际键盘流程覆盖。
- 图谱集合重试仍使用自己的集合加载流程，没有交给空关键词分页请求。
