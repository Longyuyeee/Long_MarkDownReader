# UX-50K / EA-4A 外部日志工作区审计

日期：2026-08-07

## 本阶段结论

EA-4A 已完成 `.log` 外部直开与显式保存工作区。用户从系统文件选择器、Windows 启动参数或格式能力页逐项选择 LongEdit 打开日志时，可直接进入专业日志查看器，不需要先建立资料库或导入副本。

外部能力现为：

- `edit`：24 类，只有点击保存才写回源文件。
- `preview`：8 类，只读且没有写回入口。
- `import`：11 类，继续要求导入、转换或系统打开。

## 需求与边界对齐

- 外部日志复用有界范围读取、尾部跟随、级别高亮、搜索筛选和自动刷新；不会因为大文件直接载入完整正文。
- 进入编辑模式后才读取完整日志，编辑上限保持 8 MiB；具备撤销、重做和未保存状态。
- 只有用户确认覆盖影响并点击保存，才调用专用外部日志写入命令；通用文本写入不能绕过日志门禁。
- 保存必须同时通过显式外部授权、`.log` 格式匹配、8 MiB 上限和文件签名检查；源文件在编辑期间变化时拒绝覆盖并保留外部版本。
- 标签记录 `external` 状态，外部日志与资料库日志切换时重新初始化工作区，不借用资料库根路径。
- 安装器关联仍只有 `.md/.markdown`；是否让 LongEdit 默认打开 `.log` 继续由用户在 Windows 中逐项决定。

## 本轮审计范围

- JSON Canvas、开放 Table、Draw.io、Mermaid 和 OPML 虽已具备资料库内编辑器，但仍依赖各自的专用命令与状态模型，本阶段保持 `import`，避免只改能力矩阵却没有可靠外部保存。
- `.doc/.xls/.ppt/.wps/.et/.dps` 继续保持显式转换或系统打开，不宣称原格式直接编辑。

## 自动化证据

- `check:external-log-workspace`：锁定注册表、前端外部路由、专用写入、授权、冲突保护、剩余导入格式和安装器关联。
- `check:log-workspace-editing`：既有专业查看器与资料库内受保护编辑合同通过。
- Rust 回归覆盖未经授权、未确认覆盖和源文件签名冲突，源文件在失败路径保持不变。
- 前端类型检查、生产构建、Rust 锁定检查与当前开发总审计在提交前执行。
