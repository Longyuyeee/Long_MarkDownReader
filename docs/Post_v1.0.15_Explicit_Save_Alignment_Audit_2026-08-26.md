# v1.0.15 统一显式保存需求纠偏审计

## 1. 审计结论

本阶段发现并修复了一项与原始需求直接冲突的行为：Markdown 编辑器曾在输入停止约 2 秒后自动覆盖源文件。用户已经明确要求所有可编辑格式均只在点击“保存”后写入，因此该行为属于开发偏移，不是体验增强。

修复后，Markdown 编辑内容先保留为内存草稿并显示未保存状态；只有用户点击保存按钮或使用明确的保存命令时才写入源文件。历史快照仍可按设置的间隔写入独立历史记录，但不能覆盖正文。

## 2. 预期与修正前实际差异

| 场景 | 需求预期 | 修正前真实结果 | 判断 |
| --- | --- | --- | --- |
| 编辑后等待 3.5 秒，不点击保存 | 源文件字节不变，标签保持未保存状态 | SHA-256 从 `c12ba4ea...` 变为 `91a249d5...`，未保存状态被清除 | 失败，确认偏移 |
| 点击保存 | 只有此时写入源文件 | 自动保存已提前写入，用户无法控制提交时机 | 失败 |
| 历史快照 | 写入独立历史，不覆盖正文 | 设置名称容易被理解为正文自动保存 | 表述不清 |

修正前场景使用提交 `87c6bd5` 的 `LibraryMode.vue`，在当前相同 Vite、Tauri、WebView2 和依赖环境内运行，避免由不同环境造成假差异。

## 3. 修复内容

- 删除 Markdown 输入回调中的两秒延迟源文件写入及相关计时器。
- 保留标签脏状态和内存草稿同步；切换模式不再隐式清除保存计时器。
- 为主保存按钮增加稳定测试定位点，真实测试通过界面点击完成保存。
- 设置页将“自动保存间隔”改为“历史快照间隔”，明确正文只在点击保存后写入。
- 格式需求文档统一显式保存、历史快照和外部冲突边界。

## 5. 需求对齐与边界

- 本次恢复了“所有格式显式保存”的基本产品原则，没有提升版本，也没有新增格式能力声明。
- 本次直接修复 Markdown 主编辑器。其他编辑器已有显式保存合同，后续全量门禁继续防止自动写盘回归。
- 历史快照、内存草稿和正文保存是三种不同职责；只有正文保存需要修改当前源文件。
- 当前版本仍为 `1.0.15`，`releaseCandidate=false`。

## 6. 下一步

在进入 M1B2A DOCX 生产者对象选择审计前，先建立 10,000 文件真实资料库的索引与搜索性能基线，确认本轮工作台收口没有掩盖大库扫描、查询响应和取消任务问题。该阶段只记录并修正可复现差异，不扩张格式承诺。基线通过后恢复 M1B2A。
