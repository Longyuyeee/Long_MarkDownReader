# LongEdit 当前开发情况与后续收口计划审计

> 审计日期：2026-07-28
> 产品基线：LongEdit `v0.7.0`
> 代码基线：`b0d1d61 feat: add safe PPTX basic shape lifecycle` + C5C 当前批次
> 开发分支：`main`
> GitHub PR：[Longyuyeee/Long_MarkDownReader#7](https://github.com/Longyuyeee/Long_MarkDownReader/pull/7)（已合并）
> 文档地位：本文件是 2026-07-28 起判断“当前做到了什么、还缺什么、下一步做什么”的权威入口；历史分批审计继续作为证据，不覆盖本文结论。

## 1. 审计结论

项目已经完成统一文件管理架构、主要文本和开发格式、知识图谱与思维导图核心、PDF 阅读研究链路、XLSX 较强的基础编辑、DOCX 基础编辑闭环，以及 PPTX 从结构化阅读到受限安全编辑的大部分主干。当前状态应定义为：

> **核心架构与多数高频路径已经可用，项目已进入基础需求收口期；但所有初始需求尚未 100% 对齐，不能宣传为完整 PDF、Office、WPS 或 Excel 等价编辑器。**

`main` 已快进吸收 PR #7 的全部成果。C5A1/C5A2 已关闭图片替换，C5B 已关闭白名单基础形状增删；C5C 又完成幻灯片新增、复制、删除和排序、真实 Tauri/WebView2 桌面审计，以及 PowerPoint、WPS Presentation 和 LibreOffice Impress 3/3 输出复开。下一项唯一开发入口是 C5D PPTX 发布收口。

### 1.1 对最初需求的总体判断

| 最初目标 | 当前判断 | 说明 |
|---|---|---|
| 覆盖日常文件管理 | 已完成核心闭环 | 统一打开、工作台、目录、搜索、最近、收藏、集合、标签和关系管理已经形成主干 |
| 覆盖常用格式的阅读 | 大部分完成 | 文本、开发格式、PDF、XLSX、DOCX、PPTX 等已有分级阅读；WPS 原生格式、旧版 Office 和 OpenDocument 尚未进入产品闭环 |
| 覆盖基础编辑 | 部分完成 | 文本、开发格式、图表、思维导图和表格较完整；PDF、PPTX 仍需收口；WPS 原生格式尚未开始 |
| 形成体系化管理 | 已完成核心闭环 | 搜索、索引、集合、关系、知识对象、局部/全局图谱均已接入，但图谱仍有进一步增强空间 |
| 知识图谱具备明显存在感 | 核心能力已完成，产品表达仍可增强 | 默认工作台、当前文件、搜索结果、共享关系侧栏和图谱入口已有关系信息；直接关系编辑与更丰富的跨格式画布节点仍未完成 |
| 像思维导图一样工作 | 核心完成 | Canvas、Mermaid、OPML 和图谱转 Canvas 已覆盖主要创建、编辑和可视化路径；不是完整专业脑图软件等价能力 |
| 成为完整专业 Office/PDF 套件 | 不属于当前已完成范围 | 产品目标是可靠的日常管理和基础编辑，不是复制 Acrobat、Word、PowerPoint、Excel 全部能力 |

## 2. 当前能力矩阵

状态定义：

- **完成**：已有真实文件、保存/重开、桌面或契约门禁，并进入统一管理闭环。
- **基本完成**：日常任务可用，但仍有一项低风险基础能力或发布声明待补齐。
- **部分完成**：已有可靠子集，但不能宣称该格式已经完成基础需求。
- **未开始**：尚未进入受支持的产品闭环。

| 领域/格式 | 当前状态 | 已有能力 | 主要缺口与边界 |
|---|---|---|---|
| 统一文件管理 | 完成 | Library 右侧工作区、统一打开、最近、收藏、集合、标签、跨格式搜索、索引和关系入口 | 需要最终发布能力矩阵统一公开措辞 |
| Markdown / TXT | 完成 | 阅读、编辑、可靠保存、搜索、语法和管理闭环 | 超大文件继续采用受控降级，不以 IDE 能力为目标 |
| JSON / JSONC | 基本完成 | 源码/树视图、精确 AST、重复键和数值精度保护、结构化增删改、可靠保存 | 缺少软件内“新建 JSON/JSONC”入口 |
| YAML / XML / TOML / 配置格式 | 完成 | 识别、语法高亮、搜索、基础编辑和可靠保存；敏感 `.env` 默认遮罩 | 不提供语言服务、执行或调试 |
| 常见代码格式 | 完成基础管理与编辑 | 高亮、搜索、行定位和轻量可靠编辑 | 不宣传为 IDE，不提供执行、调试、重构和语言服务器等价能力 |
| Canvas / 思维导图 / OPML | 完成核心 | JSON Canvas 可视编辑、Markdown/文件/Mermaid/表格图表节点、OPML 导入导出、图谱转 Canvas | 图片/PDF 批注和数据图表的更丰富节点预览尚未完成 |
| Mermaid / 图表 | 完成核心 | 结构化编辑、预览、SVG/PNG 导出，与 Canvas/Markdown 组合 | Draw.io 往返和更广泛 SVG 编辑尚未进入主线 |
| 知识图谱 | 完成核心、增强项部分完成 | 全局/局部图谱、关系筛选、健康检查、链接修复、关系侧栏、同标签/智能集合关系、跨格式知识对象 | 直接创建/修改语义关系、更多跨格式可视节点和更强工作流存在感仍可增强 |
| CSV / TSV / `.table.json` | 完成 | 表格编辑、图表、仪表盘、Markdown/Canvas 嵌入和可靠保存 | 不以完整电子表格引擎等价为目标 |
| XLSX | 部分完成但基础能力较强 | 多工作表、区域和 TSV 粘贴、基础格式、公式重算、行列尺寸、合并、结构操作、冲突检测、OOXML 局部可靠写回 | Pivot、外部数据、复杂绘图对象和完整 Excel/LibreOffice 等价往返不在当前基础闭环 |
| PDF | 部分完成 | 阅读、分段、批注、OCR sidecar、全文索引、关系管理、页面旋转/排序/排除的安全子集和可靠另存 | 合并、拆分、插入页面仍是基础收口缺口；表单、正文/排版编辑、签名等属于后续高级能力 |
| DOCX | 基础编辑完成 | 结构化阅读、样式/列表/表格/附属内容/图片、搜索定位、受限文本与基础样式编辑、可靠新副本、Word/WPS/LibreOffice 复开 | 修订、域、复杂分页和高级排版不在基础能力范围 |
| PPTX | 基础编辑实现完成，待发布收口 | 结构化阅读、真实生产者输入、缩略图/放映、搜索定位、知识关系、文本/样式/替代文本编辑、可靠新副本、单引用 PNG/JPEG 替换、白名单基础形状增删、幻灯片增删/复制/排序及三生产者复开 | C5D 尚需统一能力注册表、发布矩阵和公开边界 |
| WPS 原生 `.wps/.et/.dps` | 未开始 | 可通过 WPS 验证 OOXML 输出兼容性 | 尚无原生识别、预览、安全转换或编辑闭环 |
| 旧版 Office `.doc/.xls/.ppt` | 未开始 | 无 | 计划先做外部打开和显式转换，不承诺原生编辑 |
| OpenDocument `.odt/.ods/.odp` | 未开始 | LibreOffice 已用于 OOXML 生产者验证 | 尚无产品内阅读、搜索或安全转换闭环 |

## 3. 可以宣传与不能宣传的能力边界

### 3.1 当前可以准确宣传

- 本地优先的多格式文件管理与知识工作台。
- TXT、Markdown、JSON/JSONC、YAML、XML、TOML、配置文件和常见代码文件的阅读、搜索与轻量基础编辑。
- Canvas、Mermaid、OPML、开放表格和图表的创建、编辑及组合管理。
- 跨格式搜索、集合、标签、最近、收藏、批注、关系侧栏和知识图谱。
- PDF 阅读、批注、OCR、搜索以及经过门禁的页面级安全整理子集。
- XLSX 的较强基础编辑子集、DOCX 的受限安全基础编辑，以及 PPTX 的结构化阅读和有限安全编辑。
- 对高风险 OOXML 操作采用“源文件不变、生成可靠新副本、应用内重开、真实生产者复开”的安全策略。

### 3.2 当前不能宣传

- “所有最初需求已经 100% 完成”。
- “完整支持 PDF 编辑”或“等价 Acrobat”。
- “完整支持 Word、PowerPoint、Excel”或“等价 Microsoft Office/WPS”。
- “原生支持 `.wps/.et/.dps/.doc/.xls/.ppt/.odt/.ods/.odp`”。
- “可以无条件覆盖源 Office 文件”。
- “知识图谱已经替代日常文件管理”——图谱是体系化管理的增强层，不是唯一入口。

## 4. 关键缺口与风险审计

### 4.1 P0：阻断当前 PPTX 阶段收口

1. `shared/file-formats.json` 仍把 PPTX 标注为 `preview-only / none`，已经落后于 C4/C5 的真实受限编辑能力。C5D 必须统一升级为经过验证的 `basic-edit / copy`，并同步界面和发布矩阵。

### 4.2 P1：阻断“初始基础需求总体收口”

1. PDF 缺少日常高频的合并、拆分和插入页面。
2. JSON/JSONC 缺少软件内新建入口。
3. WPS 原生、旧版 Office 和 OpenDocument 尚未形成最小可用的识别—阅读/转换—管理闭环。
4. 尚缺一份面向发布的统一格式能力矩阵，用同一套术语公开“完整编辑、基础编辑、阅读/批注、仅预览、外部转换”。

### 4.3 非基础阻断项，但影响“专业系统”上限

- 知识关系的直接编辑、关系证据治理和更丰富的跨格式 Canvas 节点。
- PDF 表单、正文排版、签名和敏感信息擦除。
- XLSX Pivot、外部连接和复杂对象高保真往返。
- DOCX 修订/域/高级排版，PPTX 母版/动画/SmartArt/复杂图表。
- Draw.io 往返、完整 SVG 编辑和更多专业格式。

## 5. 后续开发与收口顺序

后续仍按“每一批独立审计、独立提交、独立推送”的规则推进。不得跨越未关闭的 P0/P1 门禁。

### 阶段 C5：PPTX 基础编辑收口（P0）

| 批次 | 交付内容 | 强制退出条件 |
|---|---|---|
| C5A2（已完成） | 对 C5A1 图片替换输出做三生产者复开 | PowerPoint、WPS、LibreOffice 3/3 可打开；目标图片可解码；哈希前后不变；证据已入库 |
| C5B（已完成） | 基础矩形、椭圆和线条的安全新增/删除 | 只修改白名单幻灯片部件；源文件不变；4 份新副本应用内重开；复杂对象明确只读；PowerPoint/WPS/LibreOffice 3/3 复开 |
| C5C（已完成） | 幻灯片新增、复制、删除和排序 | 正确维护关系、内容类型和顺序；复制备注和未编辑部件保真；4 份可靠副本通过应用内及三生产者重开 |
| C5D（下一步） | PPTX 阶段发布收口 | 注册表升级为真实能力等级；界面和文档统一写“基础编辑”；正常/紧凑与明/暗桌面矩阵通过；完整 CI 通过 |

已关闭的 C5A2 固定验证对象：

- 输出：`fixtures/pptx/output-reopen/c5a-image-copy.pptx`
- C5A1 记录的 SHA-256：`ad25ec6bfb35c5db2f250db160c3c89ee3bacdec88a4bb557c315c93f912bcc3`
- 生产者：Microsoft PowerPoint `16.0`、WPS Presentation `12.1.0.26895`、LibreOffice Impress `26.2.4.2`
- 验证结果：3/3 完成；PowerPoint/WPS 直接解码目标图片，LibreOffice 隔离配置渲染；哈希前后不变。

### 阶段 B2：PDF 日常页面操作收口（P1）

建议拆成三个可验证切片：

1. **B2A 拆分/提取**：按页范围生成新 PDF，保留源文件，应用内重开并验证页面顺序。
2. **B2B 合并**：多个输入显式排序，输出新文件，处理加密、损坏和超预算输入。
3. **B2C 插入页面**：在明确位置插入来自另一 PDF 的页面，验证页面树、资源继承和复杂对象安全边界。

表单填写可作为 B3 独立能力；正文/排版编辑、签名和擦除继续属于长期高级范围，不阻断基础需求收口。

### 阶段 A3R：JSON 创建与注册表对齐（P1）

- 在统一新建入口增加 `.json` 和 `.jsonc`。
- 使用现有编辑器、验证器和可靠保存内核，不创建第二套工作区。
- 新建、首次保存、冲突处理、最近/搜索/集合回查形成闭环。
- 同步能力注册表、界面文案、契约测试和发布矩阵。

### 阶段 E：WPS、OpenDocument 与旧版 Office 最小闭环（P1）

该阶段先审计格式规范、可用转换器、许可证、包体积和安全边界，再做实现。推荐顺序：

1. `.odt/.ods/.odp`：识别、只读预览/搜索、外部打开或显式安全转换。
2. `.wps/.et/.dps`：识别和能力提示；优先采用明确、可审计的转换或外部打开，不伪装为原生编辑。
3. `.doc/.xls/.ppt`：外部打开和用户确认后的 OOXML 转换，原文件保持不变。
4. 每类格式都必须进入统一打开、最近、搜索和能力展示；不能只增加扩展名白名单。

### 阶段 R：基础版本发布矩阵（P1）

- 为所有注册格式生成统一公开矩阵：识别、预览、搜索、编辑、保存策略、外部程序验证、已知限制。
- 完成正常/紧凑尺寸和明/暗主题桌面抽样。
- 对安装、文件关联、升级、卸载、恢复和多机器验证建立发布证据。
- 基础版本只在本文第 7 节的全部阻断项关闭后进入 release candidate。

### 阶段 G9/F：专业增强（P2）

P1 收口后再排期：

- G9A：在文件详情和关系侧栏直接创建、修改、删除带证据的关系。
- G9B：Canvas 增强 PDF 页、批注、图片、表格图表和 Office 对象节点。
- G9C：围绕项目、人物、来源和任务提供可保存的局部图谱视图与关系模板。
- PDF、XLSX、DOCX、PPTX 的高级等价能力按真实用户需求单独立项，不挤占基础格式广度。

## 6. 每一批开发的统一验收模板

每个切片只有同时满足以下条件才能标记“完成”：

1. 从真实用户任务定义输入、操作、输出和不支持边界。
2. 在 Library 原有右侧工作区完成，不创建风格割裂的新页面。
3. 字号、间距、颜色、按钮和空状态复用现有设计令牌，并验证正常/紧凑布局。
4. 真实文件可识别、可打开，并进入正确工作区。
5. 写操作默认使用可靠新副本或已有可靠写入内核；源文件和已有目标不被静默覆盖。
6. 未编辑部件保真，高风险对象明确阻断或只读降级。
7. 保存后可由 LongEdit 重开；交换格式还需由目标第三方程序重开。
8. 搜索、最近、集合、关系和能力状态按该格式的设计进入统一管理闭环。
9. 单元/契约/集成测试通过；高风险阶段执行完整 `npm run ci:check`，生产依赖审计为零漏洞。
10. 写入阶段审计、更新权威入口，单独提交并推送 GitHub；远端 Quality Gate 通过后再进入下一批。

## 7. “所有初始需求已经对齐”的判定条件

只有以下条件全部满足，才可以把基础需求总体状态改为“已对齐”：

- PPTX C5A2、C5B、C5C、C5D 全部关闭。
- PDF B2A、B2B、B2C 至少覆盖拆分/提取、合并和插入页面，并通过可靠保存与重开门禁。
- JSON/JSONC 可以从软件内创建并进入完整管理闭环。
- WPS 原生、OpenDocument 和旧版 Office 至少达到经过审计的“识别 + 阅读/外部打开或安全转换 + 统一管理”最小等级；不要求伪造原生编辑能力。
- 所有支持格式在统一发布矩阵中使用真实能力等级，界面、注册表、PRD、审计和发布说明一致。
- 当前已经完成的统一管理、知识图谱、Canvas/思维导图、文本、开发格式、XLSX 和 DOCX 能力没有回归。

完成以上条件后，可以准确表述为：

> LongEdit 已覆盖日常文件管理和主要常用格式的阅读与基础编辑，并能通过搜索、集合、标签、批注、关系和知识图谱形成体系化管理；高级 Office/PDF 等价功能仍按明确边界持续增强。

## 8. 当前立即执行项

下一次开发提交只处理 **C5D PPTX 阶段发布收口**：

1. 将 PPTX 注册能力从 `preview-only / none` 对齐到已验证的 `basic-edit / copy`。
2. 在能力说明中明确文本、样式、替代文本、单引用图片、白名单基础形状和页面生命周期子集。
3. 继续明确母版、动画、SmartArt、复杂图表和源文件覆盖不受支持。
4. 完成正常/紧凑与明/暗主题发布抽样、统一发布矩阵和完整 CI。
5. C5D 单独审计、提交、推送并等待 GitHub Quality Gate 后，PPTX 基础阶段收尾。
