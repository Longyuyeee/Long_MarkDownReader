## 1. 审计结论

项目已经完成统一文件管理架构、主要文本和开发格式、知识图谱与思维导图核心、PDF 阅读研究链路、XLSX 较强的基础编辑、DOCX 基础编辑闭环，以及 PPTX 从结构化阅读到受限安全编辑的大部分主干。当前状态应定义为：

> **核心架构与多数高频路径已经可用，项目已进入基础需求收口期；但所有初始需求尚未 100% 对齐，不能宣传为完整 PDF、Office、WPS 或 Excel 等价编辑器。**

`main` 已快进吸收 PR #7 的全部成果。PPTX C5D、PDF B2A/B2B/B2C、A3R、E0 和 E1A 已收口。E1B 的 ODT 解析器、只读命令、Library 工作面、双索引与定位代码已经完成；LibreOffice 与 Microsoft Word 真实 fixture 已通过。Word 原阻塞已定位为未被 `DisplayAlerts=0` 抑制的格式兼容性提示，现已完成真实保存、关闭和 Word 原生重开；WPS 仍缺可验证的 ODF 组件，因此三生产者发布门禁仍未通过，`.odt` 继续未登记。下一项唯一入口是 E1B 的 WPS 生产者门禁收口。

2026-07-29 已进一步完成 WPS ODF 环境门禁加固：隔离探测确认当前 WPS `12.1.0.26895` 注册转换器为 0、ODF 命名组件为 0，`SaveAs2(..., 23)` 生成 OLE 而非 ODT ZIP；机器证据、强制预检和失败清理已进入合同。该批次没有改变 E1B 2/3 状态。

## 2. 当前能力矩阵

状态定义：

- **完成**：已有真实文件、保存/重开、桌面或契约门禁，并进入统一管理闭环。
- **基本完成**：日常任务可用，但仍有一项低风险基础能力或发布声明待补齐。
- **部分完成**：已有可靠子集，但不能宣称该格式已经完成基础需求。
- **未开始**：尚未进入受支持的产品闭环。

| 领域/格式 | 当前状态 | 已有能力 | 主要缺口与边界 |
|---|---|---|---|
| 统一文件管理 | 完成 | Library 右侧工作区、统一打开、最近、收藏、集合、标签、跨格式搜索、索引和关系入口 | 需要最终发布能力矩阵统一公开措辞 |
| Markdown / TXT | 完成 | 阅读、编辑、可靠保存、搜索、语法和管理闭环 | 超大文件继续采用受控降级，不以 IDE 能力为目标 |

## 3. 可以宣传与不能宣传的能力边界

### 3.1 当前可以准确宣传

- 本地优先的多格式文件管理与知识工作台。
- TXT、Markdown、JSON/JSONC、YAML、XML、TOML、配置文件和常见代码文件的阅读、搜索与轻量基础编辑。
- Canvas、Mermaid、OPML、开放表格和图表的创建、编辑及组合管理。
- 跨格式搜索、集合、标签、最近、收藏、批注、关系侧栏和知识图谱。
- PDF 阅读、批注、OCR、搜索以及经过门禁的页面级安全整理子集。
- XLSX 的较强基础编辑子集、DOCX 的受限安全基础编辑，以及 PPTX 的结构化阅读和有限安全编辑。
- 对高风险 OOXML 操作采用“源文件不变、生成可靠新副本、应用内重开、真实生产者复开”的安全策略。

### 3.2 当前不能宣传

- “所有最初需求已经 100% 完成”。
- “完整支持 PDF 编辑”或“等价 Acrobat”。
- “完整支持 Word、PowerPoint、Excel”或“等价 Microsoft Office/WPS”。
- “原生支持 `.wps/.et/.dps/.doc/.xls/.ppt/.odt/.ods/.odp`”。
- “可以无条件覆盖源 Office 文件”。
- “知识图谱已经替代日常文件管理”——图谱是体系化管理的增强层，不是唯一入口。

## 6. 每一批开发的统一验收模板

每个切片只有同时满足以下条件才能标记“完成”：

1. 从真实用户任务定义输入、操作、输出和不支持边界。
2. 在 Library 原有右侧工作区完成，不创建风格割裂的新页面。
3. 字号、间距、颜色、按钮和空状态复用现有设计令牌，并验证正常/紧凑布局。
4. 真实文件可识别、可打开，并进入正确工作区。
5. 写操作默认使用可靠新副本或已有可靠写入内核；源文件和已有目标不被静默覆盖。
6. 未编辑部件保真，高风险对象明确阻断或只读降级。
7. 保存后可由 LongEdit 重开；交换格式还需由目标第三方程序重开。
8. 搜索、最近、集合、关系和能力状态按该格式的设计进入统一管理闭环。
9. 单元/契约/集成测试通过；高风险阶段执行完整 `npm run ci:check`，生产依赖审计为零漏洞。
10. 写入阶段审计、更新权威入口，单独提交并推送 GitHub；远端 Quality Gate 通过后再进入下一批。

## 7. “所有初始需求已经对齐”的判定条件

只有以下条件全部满足，才可以把基础需求总体状态改为“已对齐”：

- PPTX C5A2、C5B、C5C、C5D 全部关闭。
- PDF B2A、B2B、B2C 至少覆盖拆分/提取、合并和插入页面，并通过可靠保存与重开门禁。
- JSON/JSONC 可以从软件内创建并进入完整管理闭环。
- WPS 原生、OpenDocument 和旧版 Office 至少达到经过审计的“识别 + 阅读/外部打开或安全转换 + 统一管理”最小等级；不要求伪造原生编辑能力。
- 所有支持格式在统一发布矩阵中使用真实能力等级，界面、注册表、PRD、审计和发布说明一致。
- 当前已经完成的统一管理、知识图谱、Canvas/思维导图、文本、开发格式、XLSX 和 DOCX 能力没有回归。

完成以上条件后，可以准确表述为：

> LongEdit 已覆盖日常文件管理和主要常用格式的阅读与基础编辑，并能通过搜索、集合、标签、批注、关系和知识图谱形成体系化管理；高级 Office/PDF 等价功能仍按明确边界持续增强。
