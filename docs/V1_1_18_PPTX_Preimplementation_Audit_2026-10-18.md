# v1.1.18 PPTX 接续预审（不是实施或验收）

本页在1.1.17固定安装包构建期间审查下一既定方向。当前状态以开发交接和1.1.17发布审计为准，不提前改运行版本、公开下载或PPTX产品代码。

## 已有实际代码，不能重复立项

`PptxReaderView.vue` 已有页面/对象展示与搜索定位、切页和演示键盘返回、正文/备注、字符、图片说明/替换、形状及幻灯片相关受限操作。`stageVerifiedCandidate` 以已验证候选累积内存事务，`refreshDraftPreview` 重放，撤销/重做保留操作与标签；`savePptxSource` 使用 `save_pptx_patch_source_transaction`，前端复核可靠替换/回滚和结构/语义复读。原生事务还重算输出摘要、复核原件字节/签名并做确定性重放；副本分支另外检查未触及部件和三生产者基线。不能把这些写成下一版全新发明，也不能混淆两个分支的回执字段。

实际副本分支 `savePptxCopy` 仍要求只有一个草稿操作；现有原件事务与副本能力不对等，需要先核对原生复制事务支持，再决定怎样缩小用户理解负担，不能只在界面上解除限制。图片/形状/复杂对象预算与保真边界继续保留。

## 下一次先复现再判断

1. `prepareEditBaseline`、各隔离预览与 `savePptxCopy` 有异步返回后直接更新状态的分支；原件保存也会在完成时清空草稿并重新读取。先用延迟、切目标/页/资料库、保存期间后续编辑复现，不能仅凭静态观察宣称已经丢稿。
2. `loadPresentation` 用全局loading阻止重入，没有DOCX本轮的完整请求归属保护；路径watch会丢弃草稿再尝试加载。要核对普通路由保护是否已经覆盖，以及延迟读取时切文件的真实行为。
3. `requestReloadPresentation` 在用户确认后先丢弃草稿再读文件。应验证读取失败是否会失去恢复机会；明确取消、失败和显式保存的用户结果。
4. 先画紧凑示意，再改善对象选择与面板联动，把安全检查放进合理的显式操作中；保留全部现有工具，不为简化技术列表删除对象能力。
5. 重点走“选这一页的标题/备注—改两项—撤销/重做—切页—演示返回—保存/副本—重开”的完整任务，真实生产者文件/原生包部件、六风格/窄页、固定安装器及独立同包都需要新证据。

本页没有承诺任意PowerPoint兼容，也没有实施PPTX修改。路线尚有18演示、19画布/脑图和20总收口，未到重开新平台或新十版本规划的阶段。
