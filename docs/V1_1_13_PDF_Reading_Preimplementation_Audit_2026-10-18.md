# v1.1.13 PDF 阅读到笔记：实际代码接续审计

本文件在1.1.12固定候选等待远端验证时预审，**不是1.1.13已开发/验收，也不是1.1.12发布证明**。按既定1.1.8—1.1.20路线接续原能力，不另起PDF阅读器。下一版本正式开发前先复现和出示受影响界面示意，再修改实际页面并实看。

## 已有能力，不重复立项

- 实际入口是 `src/views/PdfView.vue`（路线旧文的文件名大小写需对齐），已分阅读/文档/页面/批注工具，保留表单、脱敏、水印、OCR、页面整理等全部功能。
- 高亮/区域/页评论、颜色、评论、sidecar保存、单条复制引用和插入当前Markdown已经存在；不能将其重新命名为新功能。
- `src-tauri/src/commands/pdf.rs::build_pdf_annotation_reference` 生成库内相对路径、页码、批注ID的 `longedit://pdf` 链接及摘录；`src/utils/pdfReference.ts` 拒绝绝对路径、父路径和非法页码；`LibraryMode.vue::openPdfReference` 已回到专用PDF页面。
- 来源指纹变化会只读提示；批注不存在会告知“已定位到引用页码”。工作现场已保留page/annotation，文件移动和1.1.12内容恢复需继续覆盖，不重复造现场系统。

## 当前实际缺口与优先级

1. 批注列表当前逐条显示、单选；没有独立的批注范围筛选、多选及按页/主题组织的阅读笔记预览。先用长PDF与数百条批注复现查找/整理痛点，保留正常滚动和选择。
2. `insertSelectedAnnotationReference` 当前直接调用 `write_markdown_file` 后更新标签内容，而非只插入待保存草稿；目标只取当前活动Markdown标签。正式扩展前优先复现“目标已有未保存内容／生成引用期间用户继续输入／磁盘外部改写／目标切换”是否会代存或覆盖，不能在原有直接写盘逻辑上叠批量生成。要求改成明确目标、只合并草稿、用户显式保存，安全问题如确认则先修。
3. 批注引用目前携带path/page/ID，不含强来源身份。指纹不匹配时禁止继续声称定位准确；需分别处理文件缺失、批注被删、PDF被替换、改名搬移、复制/恢复后的引用，保留旧链接兼容。
4. 生成多条笔记需显示实际条目范围、原页/摘录/评论与来源链接，选择新笔记或插入已有草稿，不能为生成而改写原PDF、夹带范围外批注或自动保存用户正文。

## 顺序与封板条件

1. 先实际复现现有插入流程的草稿/并发安全和来源回跳，固定合法生成PDF、批注sidecar及Markdown源摘要，记录真实失败而非先改断言。
2. 给出原批注面板内紧凑筛选、多选及按需笔记预览示意，保留已有单条/评论/颜色/OCR/页面工具；不新增常驻大面板。
3. 先安全草稿插入与准确来源身份，再批注整理和笔记预览。取消、重复点击、异步晚回复、目标改变和原生失败保留当前工作。
4. 六风格/深浅/宽窄与实际操作实看；真实“批注→笔记草稿→显式保存→点来源→原页原批注”及无效来源提示闭环。PDF和未选文件原始摘要不变。
5. 逐批审计推送；完整质量/原生、固定安装包与历版功能同包复核通过后才封板发布。README更新仍放末尾，签名社区/企业RC/应用内更新分别记录。
