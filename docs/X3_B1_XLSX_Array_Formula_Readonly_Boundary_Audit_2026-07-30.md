# X3-B1 XLSX 数组公式只读边界审计

更新日期：2026-07-30
阶段结论：**已完成代码与自动化证据；能力保持受限，不声明 Excel 动态数组等价。**

## 1. 本阶段与初始需求的关系

初始目标是让管理器覆盖日常文件的应用内阅读、基础编辑和体系化管理。本阶段不是新增独立页面，而是在既有右侧 XLSX 工作面补齐一种高风险内容的“可识别、可定位、可解释、不可误写”能力，避免动态数组工作簿看似可编辑却被破坏。

## 2. 已交付能力

- 仅识别 OOXML 明确声明为 `<f t="array" ref="…">` 的公式，不把标量 `XLOOKUP/XMATCH` 误判为数组。
- 输出传统数组/动态数组类型、锚点、声明范围、公式、声明单元格数、缓存覆盖数和阻断原因。
- 在原有右侧工作簿界面显示紧凑的“数组公式 · 只读”提示，可从下拉框定位完整范围；不创建新窗口或新路由。
- 数组范围采用轻量视觉标记，锚点有独立边框；字号和控件密度沿用原工作簿界面。
- 公式栏输入、粘贴、清空和填充在前端阻止；后端事务边界再次拒绝范围内内容写入。
- 含数组公式的目标工作表拒绝行列结构迁移；本地公式重算保持关闭。
- 每个 Sheet 最多读取 1,024 个声明，声明范围合计最多 1,000,000 个单元格。

## 3. 证据和数据安全

- 确定性 fixture：`src-tauri/tests/fixtures/workbook/array-formula-boundary.xlsx`
- manifest 明确标记为 `library-generated`，不是 Excel/WPS/LibreOffice 真实生产者证据。
- 回归覆盖传统数组、带 `cm` 元数据的动态数组、缓存覆盖统计、标量公式不误判、超大范围拒绝和读取前后源字节摘要不变。
- 机器合同：`shared/xlsx-formula-capabilities.json` 与 `shared/xlsx-compatibility-matrix.json`。

## 4. 当前边界

当前能力是“受限读取/显示 + 安全阻断”，不是动态数组编辑或计算：

- 不执行 spill 推导、冲突检测或 `#SPILL!` 语义。
- 不改变数组公式、声明范围或缓存结果。
- 不把 IronCalc 标量函数能力扩展解释为数组返回能力。
- 尚无 Excel、WPS、LibreOffice 三生产者输入样本，因此不能提升为完整支持。

## 5. 下一阶段：X3-B2

1. 分别取得 Excel、WPS、LibreOffice 原生生成并复开的数组/动态数组样本。
2. 建立生产者差异矩阵：`cm`、扩展元数据、前缀、缓存空洞和单锚点声明。
3. 建立“声明范围—实际缓存—占用冲突”的只读诊断模型，显示潜在 spill 冲突，但仍不计算。
4. 增加真实桌面视觉证据：正常/紧凑、明/暗、定位、源文件不变。
5. 只有三生产者和事务回归都通过后，才评估将读取/显示从“受限”提升为“支持”；编辑和计算仍需独立阶段。
