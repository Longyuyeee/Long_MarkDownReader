# v1.0.23 后续切片计划

最新：v1.0.22 官方更新已 12/12 收口；本计划第一优先切片已完成源码修复和 8 项回归，完整补丁门通过。当前接续以 [版本身份切片](./V1_0_23_Version_Identity_Slice_2026-09-22.md)为准，页面及新生产安装验证仍待完成；以下是选择时的原计划。

本计划来自 v1.0.22 安装截图和实际代码审阅；不是已完成实现，也不提前把运行版本升到 1.0.23。主线仍是本地资料查找、阅读、基础编辑、安全保存。

## 第一优先：我到底安装了哪个版本？

已确认问题：`LibraryMode.vue` 的 displayedAppVersion 与 versionIndicatorLabel、`releaseCapabilities.ts` 和 `ReleaseCapabilitiesView.vue` 直接读取构建时开发政策。正式包因 main-development 字段仍显示 DEV 和旧公开版本；后续 main 把开发目标改为 1.0.23 时，还可能把目标号当已安装号显示。当前 1.0.22 Release 明确披露该限制。

1. 先追踪 Tauri getVersion、开发模式、更新检查结果和能力页的所有版本来源，列出已安装/开发目标/远端最新三种事实，不做全仓版本号替换。
2. 已安装版本优先使用真实运行时版本；开发目标只在明确开发信息中显示。正式包不因路线图字段而显示 DEV。离线时不能把构建时 publicVersion 宣称为当前远端最新版。
3. 回归开发构建、生产安装包、离线、发现更新和更新失败；从侧栏进入设置和能力页均应一致，旧版用户不被误报已升级。
4. 仅冻结这一有限修复后再判断是否需要新候选；安装验收、版本迁移、发布清单与官方更新证据各自保留。不能重命名 1.0.22 的既有安装包为 1.0.23。

## 第二优先：为什么出现几条看起来一样的搜索结果？

事实：同一合成库关键词截图可见额外相似卡片，标签截图为两份；目前未记录全部结果路径、对象和 locator，不能直接断言索引重复。先分别检查路径命名空间、对象身份与同文件不同位置命中。

若是同一文件同一位置重复，修复规范化/去重并验证不会吞掉合法不同位置；若是合法多位置命中，补清楚相对路径与命中位置，而非简单去重。验收目标是“不看源码也能辨认确认版、内部草稿和命中位置”。既有完整名称提示、Tab/Enter 打开已通过，不重复实现。

## 后续备选：图谱恢复与大库体验

复测布局、缩放/相机、筛选、选择恢复，及拖动不误打开；用稀疏、密集、无关系库和减少动态效果设置确认，再选择一处真实痛点。当前 12 节点最终观察约 552ms 清除加载提示，不可外推为 540 节点性能结论。暂不加入更多特效或重启已收口的历史格式验收。
