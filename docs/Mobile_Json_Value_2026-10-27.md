# 移动端：找到并修改一个 JSON 字段值

2026-10-27。阶段 3C1，沿用独立分支 `codex/mobile-0.1.0-foundation`，起点 `fad535d32`。本轮只收整字段值修改这一项用户任务，遵循[按用户任务推进](Development_User_Task_Plan_2026-09-22.md)与[移动端交互重设计](design/mobile-interaction-v2/interaction-spec.md)。桌面工作目录未修改。

实际观察发现：原结构页同时放字段详情、编辑表单与核对结果，并保留源码顶栏和底栏；核对状态的返回直接清空输入。本轮将它们拆为独立页面，用户按“找到字段 → 修改 → 核对 → 应用到草稿 → 显式保存文件”完成操作。

## 页面与返回契约

五个设计状态是本层字段列表、字段详情、修改、核对、输入错误。[冻结设计源码](design/mobile-json-value-v1/index.html)及[五屏截图和冻结摘要](evidence/mobile-json-value-2026-10-27/design-freeze.json)在运行时代码修改前生成；设计源 SHA-256 为 `d7c36b33cf12a22a8b92d76c9873bc470b7ba2e680e877840495b3e33afd2d9d`，冻结时间 `2026-10-27T03:26:58.384Z`。

- 列表有本层筛选、分页与全树查找；进入子项后返回恢复筛选、页码、滚动和该项焦点。
- 字段详情只显示位置、类型、原值和源码入口。字段名特殊字符与同名项序号保留辨认信息。
- “修改这个值”进入整页表单；编辑中的 Back 回详情并暂存该字段的类型、值、选区和滚动。“继续修改”可恢复，每个字段的待改输入独立。
- “核对这次修改”进入原值/新值核对页。返回或“继续修改”恢复表单；明确“取消修改”只丢弃当前字段的临时表单。
- “应用到草稿”回到原源码编辑器并恢复焦点，沿用单次可撤销事务。保护草稿失败时，当前源码输入仍在，已保存文件不变；不显示成功承诺。只有显式保存才写文件。
- 全树命中返回结果时保留查询、结果分页与命中焦点；结束全树查找恢复进入前的列表位置。结构页面优先消费浏览器中的 Android 返回桥接回调，底层文稿查询留待结构退出后处理。
- 说明收进 `?`。移除阅读模式、核对后仍需保存等重复段落；可执行错误、超限回退和无变化状态仍显示。用“应用到草稿”与“保存”区分保存阶段。

关闭结构保留同一文稿的临时现场，同时停止工作线程。源码或文稿身份变化清除过期模型、字段表单和候选；下次浏览重新分析。预算、超时、工作线程失败及前往源码回退沿用原边界。

本轮没有重做重命名/增删/移动等结构操作表单，也没有重做 JSON 检查/排版入口；这些已有能力仍可使用，将在后续独立切片收整。YAML、XML、TOML 与 PDF 界面不在本轮迁移范围。阶段 3 整体仍进行中。
