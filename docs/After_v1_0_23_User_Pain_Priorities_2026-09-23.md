# v1.0.23 之后：用户痛点优先级（待本版发布后选择）

本页不是发布声明，也不扩大已冻结的 1.0.23。先完成当前固定候选安装与发布，下一补丁才选择一个有界问题。

## 首选：我选择了直接退出，为什么 Alt+F4 只是隐藏？

实际依据：隔离窗口观察中，前端关闭按钮可退出，Alt+F4 却隐藏。`src-tauri/src/lib.rs` 的主窗口 `CloseRequested` 无条件 `prevent_close` 后 `hide`；`src/App.vue` 的 `closeWindow` 则根据 `exitStrategy` 分流，`handleExit` 检查未保存文档。这是两个入口行为不一致，不是需要增加一个退出设置。

实施顺序：

1. 先复现主窗口三种偏好（询问、直接退出、后台运行）下的关闭按钮、Alt+F4、系统关闭菜单；记录窗口/进程/托盘实际状态。
2. 设计统一的关闭请求入口，复用既有确认和未保存保护；防止原生事件与前端关闭相互递归，连续按键不叠加对话框。应用尚未就绪时保留安全降级，不能为修复退出而丢弃草稿。
3. 真实使用：写一段未保存文字→关闭→取消→继续编辑→保存→再退出→重开核对；后台运行则检查恢复后草稿仍在，不把隐藏等同退出。
4. 覆盖临时编辑窗口、外部文件窗口、系统托盘退出及自动更新退出路径。只统一主窗口策略，不把外部窗口误改成隐藏，也不破坏更新后的自动重启。
5. 代码回归、真实窗口观察、固定安装候选验证后再决定发布；发现草稿保护缺口优先处理，不降低验收。

## 次选：几个相似搜索结果，我该打开哪个？

先采集相对路径、文件身份和命中位置，区分合法多位置命中与同一位置重复；只有后者应去重。目标是不用打开每份文档就能区分交付确认版、内部草稿和同名文件。保留现有键盘重试、Tab/Enter 打开以及查询保留能力。

## 后续：返回图谱后还能找到刚才的位置吗？

用实际资料组织任务验证筛选、相机/缩放、选择和返回恢复，再选择一个确实复现的问题；包含稀疏、密集和无关系库，以及减少动态效果设置。不能把小库结果外推到 540 节点，也不优先添加新特效。
