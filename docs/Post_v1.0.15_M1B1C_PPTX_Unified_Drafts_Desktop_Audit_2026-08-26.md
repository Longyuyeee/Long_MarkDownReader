# M1B1C PPTX 统一草稿与显式保存桌面审计

日期：2026-08-26  
阶段：M1B1C  
结论：通过，不提升版本

## 1. 开发目标

- PPTX 的受限对象操作先进入统一内存草稿，保存前不得改写源文件。
- 提供统一撤销、重做、脏状态、离开保护和顶部显式保存。
- 保存前重放完整事务，用户确认后才可靠覆盖原文件；单项草稿继续保留可靠副本路径。
- 用真实 Tauri 桌面和真实 Office 生产者文件比较预期与实际，不用静态页面代替产品验收。

## 2. 完成内容

- `PptxReaderView.vue` 已把现有七类有界操作接入统一 `draftOperations`，每次候选操作均调用事务预览。
- 草稿历史支持撤销和重做；标题、顶部保存按钮和标签脏状态共享同一事实。
- 刷新、关闭和路由离开均保护未保存草稿。
- 显式保存调用 `save_pptx_patch_source_transaction`，要求确认、源签名一致、结构/语义复开成功并具备失败回滚保护。
- 格式注册表已从旧的“基础编辑副本 / 原文件始终只读”更新为“受限演示文稿编辑 / 有界覆盖”。

## 3. 预期与实际差异

| 检查点 | 修正前实际 | 目标结果 | 修正后实际 |
| --- | --- | --- | --- |
| 进入真实文件 | 测试直接写 `#/library?path=...`，路由会清理参数 | 按用户路径从资料库打开 | 改为点击真实文件树节点，稳定进入 PPTX 工作区 |
| 草稿建立 | 单项隔离预览成功后草稿又回退 | 预览成功后源文件不变并显示 1 个草稿 | 定位为 Vue Proxy 不能 `structuredClone`，改用 `toRaw` 后草稿稳定建立 |
| 同路由文件切换 | 只有 `onBeforeRouteLeave`，切换到另一个 PPTX 会复用组件并直接清空草稿 | 任意文件切换都必须先确认 | 增加 `onBeforeRouteUpdate`；真实点击第二个 PPTX 后取消，仍停留原文件、草稿数仍为 1、源摘要不变 |
| 撤销时机 | 测试在事务复预览完成前点击，按钮尚未启用 | 只有历史可用时执行撤销 | 等待按钮可用后执行，草稿 `1 -> 0 -> 1`，源摘要始终不变 |
| 原文件保存 | 旧 UI 只能可靠另存副本 | 明确确认后一次覆盖并复开 | WPS 真实样本保存后 SHA-256 变化，目标文字复读为 `LongEdit M1B1C desktop verified` |
| 窄桌面布局 | 未覆盖统一草稿工具栏 | 960x720 无工作区横向溢出 | 实测通过，运行时错误 0 |

## 5. 边界与下一步

- 本阶段没有把 PPTX 宣称为完整等价编辑器；母版、动画、SmartArt、复杂图表和未知对象继续只读或阻断。
- M1B1 到此收口。下一阶段为 **M1B2A DOCX 常用对象选择审计**：使用 Microsoft/WPS/LibreOffice 真实样本比较页眉页脚、表格、图片布局、段落样式和超链接，选择一个可证明保持未修改对象的有界编辑子集。
- M1B2A 先做事实与差异审计，不因路线图预期提前开放能力，也不自动提升版本。
