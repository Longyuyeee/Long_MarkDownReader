# F1 无历史文件内部归档支持

日期 2026-10-11；接续 `81bead61`。无 UI 修改、无 Tauri 执行入口、无升版。

## 实现与需求对齐

新收集的笔记可能尚未生成历史，不能永久因“没有历史”拒绝归档。内部 move_with_history 现在支持该分支：必要时创建历史缓存，仅创建独立 `.archive-stage-document-*` 日志目录，不创建来源/目标快照目录。先持久化 history-policy.json（historyRequired 及预检清单）和 version 2 正文摘要日志，再进行有界正文校验与无覆盖移动。

CoordinatedReceipt 新增 history_required；无历史成功时 document_moved=true、history_required=false、history_published=false、error=None，避免把“不需要迁移”伪装为“已发布历史”。现有历史分支仍保留暂存和历史发布。

移动前复核历史状态；无历史分支移动后也复核。如果外部操作新增历史或目标冲突，回执说明正文已移动但需要核对，不删除新增历史，不制造成功发布记录。正文重启核对可读取该分支的 document-intent；清空历史仍会保护这些日志目录。

## 审计边界

这是内部磁盘路径支持，不是完整用户归档闭环。history-policy 是持久化依据，尚未接自动恢复决策；inspect_staging/inspect_publication 面向有历史副本，不能直接用于这种纯正文日志目录。需要上层按政策分流，不能将缺少快照日志误报数据丢失或自动清理。

保留旧边界：内容摘要不是身份锁；没有外部进程排他、草稿/引用依赖门禁、标签/索引更新、失败重试或用户恢复入口。canExecute 仍为 false，不注册可绕过门禁的命令。创建缓存前有已有 inspect 的目录检查，但外部父目录替换竞争仍未解决。
