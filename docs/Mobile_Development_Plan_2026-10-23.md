## 为什么先做交互设计再批量迁移

桌面依靠侧栏、右键、多标签、快捷键和多窗口，手机需要单页主任务、触摸菜单、系统返回和软键盘配合。先照搬所有功能会把桌面布局和窗口模型一起迁入；先完成全部高保真页面又会延后发现外部目录无法读取或保存的问题。

因此，先用最小诊断页面证明 Android 启动、授权读取和写回可以实现，再设计资料库、文件列表、阅读编辑、搜索、恢复草稿这条主路径。技术试验只承载必要操作；真实存储接入后，沿同一套 Vue 移动组件逐步增加功能。桌面端仍沿用已有页面和工作流。

## 公共逻辑与平台接口

维持一个仓库和一份格式能力事实来源。优先从正在迁移的用户任务中抽离接口，逐步减少 Tauri command、真实路径和界面组件之间的耦合。

| 层 | 职责 | 迁移原则 |
| --- | --- | --- |
| 公共业务 | 格式解析、准确范围修改、搜索规则、关系语义、保存前核对 | 保留现有 Rust 与 TypeScript 实现和针对性测试，按调用边界抽离 |
| 文档访问 | 文档身份、列表、读取、分段读取、创建、写回、移动、删除 | 使用资料库 ID、库内相对位置和不透明访问句柄；桌面路径不作为全部平台的唯一身份 |
| 平台服务 | 目录授权、分享接收、外部打开、凭据、生命周期 | 桌面、Android、iOS 分别实现；界面按真实能力显示操作 |
| 界面 | 桌面工作区、手机工作区和平板布局 | 复用编辑内核、通用组件和主题变量，分别组织导航和操作入口 |
| 数据兼容 | 文件正文、附件相对引用、批注与关系元数据 | 继续识别既有资料；新增格式带版本和迁移规则，设备权限及绝对路径留在本机 |

Android 需要同时考虑应用内资料库与经 Storage Access Framework 授权的外部目录。外部访问句柄不转换成假定可用的路径字符串。涉及路径型解析器时可使用受管的本地工作副本，写回前重新核对来源；文档提供器没有原子替换能力时，必须明确提交状态和失败恢复方式，并在能力不足时保留恢复材料或提供副本保存。

草稿在应用私有存储中持续保存恢复记录，与原文件的显式保存分开。记录包含文档身份、编辑代次、来源签名、草稿内容和保存回执；恢复时核对来源，防止旧任务回执清除后续编辑。Android Keystore 与 iOS Keychain 通过凭据接口接入，Android 不使用当前 keyring 默认 mock 作为正式存储。

## 与桌面端同时推进

1. 当前桌面目录保持原分支；移动工作始终在本计划的独立 worktree 中进行。
2. 以正式发布版本为同步点，记录移动端吸收的桌面提交和新增能力。阶段内按需同步相关修复，避免重复移植同一变更。
3. 共享逻辑的小范围改动在移动分支完成后，独立提交并向桌面集成；同步前识别相同改动，处理契约或数据版本冲突。
4. 变更公共解析、保存或数据结构时，执行对应桌面功能回归和 Android 任务；页面专属改动执行所属平台检查。
5. 保留桌面质量门；Android 新增独立构建、模拟器任务和安装包记录。浏览器模拟 IPC、原生测试、模拟器和真机各自标注。
6. `/.gitignore` 当前忽略整个 `/src-tauri/gen/`。初始化移动工程时改为选择性忽略，纳入 Android 原生源码、Manifest、构建配置及 Gradle wrapper，排除 build、缓存和本机路径；干净检出验证可构建。
