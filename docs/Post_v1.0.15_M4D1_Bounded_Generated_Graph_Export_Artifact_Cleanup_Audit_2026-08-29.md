## 未来重跑合同

新增专用清理器只读取 M4D-0 的四个精确路径。每次删除前，它必须逐个核对当次文件大小和 SHA-256 是否等于当次 `tier-5000.json` 的对应指标；缺失、路径异常或指标不符都会失败。

M3C-4 runner 仅在完整三档或明确运行 5000 档、且原有性能 checker 成功后调用清理器。审计失败时负载会保留用于诊断；通过时结构化指标已落盘并验证，随后才清除可重建负载。只跑 100/1000 档不会错误要求不存在的 5000 节点负载，M3C-0 至 M3C-3 也不调用清理器。

本次没有为验证清理器而重跑整套真实 5000 节点审计，因为当前四个真实负载本身就是与既有结构化指标一致的输入。清理器已在这四个文件上实际执行；删除后原 M3C-4 checker 仍只依赖三档 JSON 并通过。这验证了新增边界，同时避免无意义重写已经冻结的性能与截图证据。
