# 1.1.0 用户流程纠偏（当前优先依据）

日期：2026-10-12。用户明确要求：快速保存时选择合适位置，不引入额外归档步骤；从用户视角继续开发到封板。本记录覆盖旧计划中冲突的 F1 归档门禁，不取消 F2–F4 的既定需求，也不表示全界面重构或发布验收已经完成。

## 当前产品流程

资料库、保存到、模板仍在同一行。第一次默认当前资料库，用户可选择项目目录；保存成功记忆目录，下次直接使用。收集箱只是可选临时目录，不强制中转。显式选择过收集箱的用户保留该选择；不擅自移动已有文件。

收集箱回到原有目录浏览和主编辑区打开；撤下新加的归档勾选/预检入口。不删除归档相关内部代码、未挂接组件或历史证据，它们不参与本版主流程，也不再因“归档全过程暂停编辑”等要求阻塞本版封板。历史文档中的未封板结论仍需按本记录的新范围重新核对，不能靠删除门禁宣称其他要求完成。

## 验证

- `scripts/test-capture-destination.mjs`：首次根目录、已记忆目录、显式收集箱偏好及旧偏好迁移通过。
- `scripts/test-quick-note-direct-browser.mjs`：真实 QuickNote 页面，选择客户项目目录、失败保留正文、相同 operationId 重试、直接写入所选路径、不调用归档/移动、重开记忆目录通过。IPC 与目录选择返回值模拟，不是原生文件写入证明。
- `scripts/test-inbox-archive-browser.mjs` 根据本次新需求改为验证无归档勾选/入口且正常打开；保留未挂接结果组件的独立回归。预期变化来自用户明确纠偏，不是为了通过旧验收。
- 原生 Rust `quick_note` 5 项通过，包含同操作重试与内容冲突保护。UI 截图在 `docs/evidence/v110-direct-save-browser/`，已实际查看，工具栏保持一行。

## 连续开发顺序

1. 直接保存与打开的失败恢复、目录选择记忆与跨库边界。
2. 切库、配置持久化失败时不丢失当前工作内容；恢复原有标签与上下文。
3. 既有常用搜索和历史恢复能力的实际用户问题；复用现有入口推进 F2–F4，不另造用户需要理解的新流程。
4. 未批准的新布局仍先给示意；不以“封板”绕过真实验收。按最终候选提交运行回归、构建和安装升级验证后才通知封板。
