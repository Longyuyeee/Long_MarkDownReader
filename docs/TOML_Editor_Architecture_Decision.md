# TOML 编辑器架构决策

更新日期：2026-07-26

## 决策

TOML 以源码为唯一事实源，Rust 使用固定版本 `toml_edit 0.25.13` 做权威解析和带范围分析。前端结构提纲只读，不把 TOML 转成普通对象后整体序列化覆盖。

原因是 TOML 的注释、键顺序、引号风格、数字与日期字面量、点键、内联表和表数组都可能承载人工维护语义。保存未经结构变换的源码可继续复用 A1 文本内核保留编码与换行。

## 资源和保存边界

- 源码分析上限：8 MiB。
- 节点上限：100,000；深度上限：128。
- 跨 IPC 提纲上限：20,000。
- 无效 TOML 默认返回 `invalid-toml-save-blocked`，只有明确确认才能按原始源码保存。
- 写入继续使用工作区守卫、内容签名和可靠替换。

## 分批

1. A4-T1：解析、诊断、键路径提纲、资源限制和保存门禁。
2. A4-T2：格式注册、语言高亮、独立工作面、草稿、创建、索引和全量回归。
3. INI/CONF/Properties 必须使用各自契约，不复用 TOML 解析器伪装兼容。

## 不承诺

- 首批不做结构化表单写回。
- 不自动合并重复键或重排表。
- 不执行配置中引用的命令、路径或网络资源。
