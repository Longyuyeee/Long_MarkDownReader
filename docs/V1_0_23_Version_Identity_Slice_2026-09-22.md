# v1.0.23 版本身份显示：第一切片

当前运行/公开仍为 1.0.22，开发目标 1.0.23。本页记录源码修复，不代表 1.0.23 已打包或发布；已公开的 1.0.22 包和 Tag 不改。

## 用户问题与实际代码

用户说“我装的到底是哪一版？”：旧 LibraryMode 在 main-development 分支将 DEVELOPMENT_TARGET_VERSION 当侧栏版本，能力页把静态 publicVersion 当“当前公开”；正式生产包也因共享政策显示 DEV。更新设置则读取真实 getVersion，几个页面会互相矛盾。符合最初需求中的可信状态与明确反馈，本切片不涉及格式写入、图谱特效或新更新协议。

## 已实施

- `resolveVersionIdentity` 分开处理真实运行版本、构建回退、开发目标和已观察远端版本。发现可更新或正在安装时不把目标显示为已经安装；检查失败/进行中不复用旧 latest 值当最新事实。
- 侧栏、格式能力页、更新设置共用 Vue computed 状态，初始化和更新检查完成后同步刷新；真实 1.0.0 也不再被当占位值排除。
- updater 初始值来自当前 package，而非写死 1.0.0；先读取运行版本再初始化进度监听，使监听失败不阻止已经取得的真实版本显示。
- DEV 由实际 Vite 开发构建标志决定，不由发布路线图决定。生产能力页只写“社区版 · 未签名”，不离线宣称远端最新版；开发目标仅作为明确的开发说明。

## 验证与纠偏

8 项回归通过，包含真实公共 computed 的响应性测试，覆盖初始化后版本变化、更新可用→失败状态，不仅测试文字存在。静态连接检查只证明三个工作面使用共同来源，不冒充实际页面验收。

首次类型检查发现移除 updaterState 导入时遗漏侧栏按钮 loading 绑定，已恢复该导入，保留行为。随后完整 `npm run ci:patch-release` 通过：6,283 模块生产构建、链式合同、Rust locked check、生产依赖 0 漏洞。身份和 UI 事实检查更新为验证新来源与禁止旧静态公开文案，不保留导致问题的旧文案作为验收条件。
