# LongEdit 开发进度与后续阶段审计（2026-07-23）

## 1. 审计结论

项目当前已从 Markdown 阅读器演进为具备知识库治理、跨格式对象关系、专业工作台和渐进式 XLSX 编辑能力的本地知识管理系统。实际功能进度已完成至 **S8-6B：查找/引用与条件聚合函数族**。下一开发入口为 **S8-6C：多条件聚合与非易失日期函数**；现代查找函数、动态数组、易失函数、外部引用和保护设置修改继续独立验收。

当前版本可以继续开发，但不应宣传为“完整 Excel 等价”或“完整 Office 套件”。公开口径仍应保持：XLSX 渐进式编辑、图表与高级数据对象受限、外部数据默认离线、兼容边界以机器可读矩阵和公开矩阵为准。

- 本地索引可删除、重建、报告状态，并在失效或损坏时安全回退实时扫描，不成为唯一事实源。

### 3.2 知识图谱与思维导图

- 当前短板不是“没有图谱”，而是图谱在日常文档工作面中的入口仍不够持续：关系上下文、路径解释、对象级影响分析和思维导图同步需要在 G8 主线继续增强。

### 3.4 仍然明确受限的能力

- `.xls`、`.xlsb`、`.ods` 尚无正式产品编辑入口。
- 图表高级主题色绑定、透明度/色调变换、渐变/图片/图案填充、逐点样式、高级轴格式、组合图、三维图和未知扩展继续只读。
- 图片型或超过受限文本边界的高级页眉页脚和保护设置仍以读取、保真和拒绝绕过为主；页面布局不提供分页计算或打印预览。
- 易失函数、动态数组、完整区域运算和 Excel 全函数语义尚未完成。
- 透视表刷新、切片器交互和外部数据查询未开放；软件不会隐式访问网络或外部文件。
- PDF 以阅读、批注、OCR sidecar 和索引为主，不是通用 PDF 内容重排编辑器。

## 5. 工程风险排序

### P1：工作簿核心体积与变更耦合

`src-tauri/src/formats/workbook_ooxml.rs` 约 13,160 行，`src/views/WorkbookView.vue` 约 3,097 行。继续直接叠加图表、页面和公式能力会放大审查、冲突和回归成本。S8-4C 必须同步建立 `workbook_ooxml/chart` 与前端图表工作面边界，不以单文件继续增长作为默认实现方式。

### P2：桌面端 E2E 自动化仍需扩展

S8-4D4 已补真实 Tauri WebView 的图表保存重开与主题视觉证据，但执行仍包含人工桌面操作。后续可将 Debug 隔离知识库能力接入跨平台 WebDriver，并继续补多窗口尺寸；在此之前，每个可见功能仍须提供可复核的桌面步骤和截图证据。

### P1：产品能力口径风险

本地预览证明数据引用可解释，不代表复刻 Excel 样式、布局或计算结果。公开文档、发布页和演示必须继续引用兼容性矩阵，不使用“完整 Office”“完整 Excel”或“无损编辑所有 XLSX”等表述。

### P2：累计批次过大

本项目按当前约定直接在 `main` 连续推进。每个子阶段仍须保持独立提交、完整门禁、文档审计和推送后远端一致性核对，避免多个未验收阶段堆入同一提交。

### P2：知识图谱存在感仍需产品化

图谱底层对象、关系和索引已具备，但文档工作流中仍缺少持续可见的“当前文档关系侧栏、关系路径解释、影响范围和一键投影思维导图”。这应作为 G8 产品主线推进，而不是继续扩展底层图算法后才补 UI。
