# UX-42 Table 看板体验审计

日期：2026-08-06
结论：通过

## 用户问题

在 `测试结果记录 2.table.json` 中新增看板后，原界面把全部字段、视图入口和说明文字挤在固定高度的单行区域内。长字段名和长内容会造成按钮越界、卡片错位和信息层级混乱。

## 本次重构

- 将四个“新增视图”文字按钮收纳为一个图标菜单，视图标签保持稳定宽度并支持省略显示。
- 将看板配置独立为清晰工具区：分组字段、标题字段和卡片字段分别配置，不再平铺全部字段按钮。
- 卡片字段选择器采用两列弹层，限制最多八项；分组和标题字段不会在卡片正文重复显示。
- 新看板会根据真实数据优先选择有内容的文本字段，避免默认使用编号作为分组和标题。
- 卡片标题最多显示两行，字段值改为可换行编辑区；列、卡片和控件均具有稳定尺寸与溢出约束。
- 窄窗口下配置区可横向滚动，创建入口收为图标，避免压缩看板内容。

## 验证结果

使用用户文件的隔离副本在真实 Tauri WebView2 中创建看板。13 个字段、11 条记录成功生成 11 张卡片；桌面、字段选择弹层和 760px 窄窗口均无页面越界、控件撑破或运行时错误。原文件与隔离副本的 SHA-256 在测试前后保持一致。

证据位于 [`evidence/ux42-table-board`](./evidence/ux42-table-board/)，专项质量门为 `npm run check:table-board-experience`。

## 后续边界

本阶段解决 Table 看板的信息架构、默认配置、长文本适配和响应式布局。后续如继续扩展看板，应优先补充列折叠、字段类型专用编辑器和卡片批量操作，不得重新把高频配置堆回单行工具栏。
