# v1.0.8 受控更新生命周期审计

状态：**托管执行发现自动重启失败，已转入 v1.0.9 恢复补丁**

## 目标

- 从官方 `v1.0.7` NSIS 安装开始，通过应用内检查发现官方 `v1.0.8`。
- 保持用户确认边界，确认前不得下载或启动安装器；下载后严格核对官方附件大小与 SHA-256。
- 验证同目录覆盖安装后由更新助手自动重启 `v1.0.8`，测试脚本不得手动启动新版应用。
- 在自动重启的进程中验证“当前已是最新版本”，并核对安装二进制身份与合成资料保留。
- 覆盖安装和卸载后都必须保留合成资料库与配置标记。

## 隔离边界

- 仅在 GitHub 托管 Windows 一次性环境运行，必须同时提供 `ConfirmDisposableMachine` 与 `AllowInstallerMutation`。
- 工作流只下载公开 Release 资产，不重建产品，不读取本机 LongEdit，也不包含真实用户资料。
- 当前安装包仍为 `NotSigned`；本观察不构成企业签名或商业发布资格。

## 验收门槛

共 12 项检查必须全部通过，其中 `automatic-relaunch-after-managed-update` 必须来自更新助手拉起的进程；如果覆盖安装完成后未出现新版进程或 WebView2 端口，流程直接失败。

## 首次运行结论

- Quality Gate `31486160580` 通过后，托管运行 [`31486852139`](https://github.com/Longyuyeee/Long_MarkDownReader/actions/runs/31486852139) 使用官方 v1.0.7 与 v1.0.8 NSIS 执行。
- 官方 Release 发现、用户确认、严格 SHA-256、下载缓存和同目录覆盖安装均成功；安装后的 `tauri-app.exe` 已确认为 v1.0.8。
- 覆盖安装后十分钟内没有发现更新助手自动启动的 LongEdit 进程，流程在 `automatic-relaunch-after-managed-update` 失败，没有伪造首启、最新版或卸载资料保留结论。
- 根因是 v1.0.8 助手将 `Start-Process` 调用成功等同于重启成功，没有检查新进程是否立即退出。v1.0.9 改为延迟启动、持续存活检查、失败重试和脱敏重启日志。

## 下一步

提升到 v1.0.9，重新执行质量门、打包、安装生命周期和官方 `v1.0.8 -> v1.0.9` 更新；只有 12/12 检查通过后才能关闭自动重启回归。
