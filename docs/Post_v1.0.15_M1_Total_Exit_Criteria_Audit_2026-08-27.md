# v1.0.15 后 M1 总退出条件审计

日期：2026-08-27

阶段：M1 total exit criteria

运行时/公开版本：`1.0.15`

开发目标：`1.0.16`

结论：通过，M1A 至 M1D 在有界范围收口；下一步进入 M3 知识图谱 2.0 选择审计

## 1. 审计目标

本阶段不增加产品能力，只验证 M1 是否满足退出条件：

1. 汇总 XLSX、DOCX/PPTX、ODS、JSON 与视频的真实文件和失败样本。
2. 在当前代码重新运行代表性 Tauri 桌面路径，不只复述历史证据。
3. 核对 Word、WPS、LibreOffice 外部生产者证据和源文件安全边界。
4. 核对格式注册表、发布能力矩阵、设置页、README 与开发版说明。
5. 保留明确延后项，不把未实现能力误记为回归或已完成。

## 3. 预期与实际差异

### 3.1 测试基础设施差异

预期：多个真实桌面脚本可在同一 E2E 二进制上顺序执行。

修正前实际：PPTX 脚本无条件重新编译普通桌面配置，随后 ODS 使用 `-SkipBuild` 时 60 秒内没有发现 CDP 目标，验收失败。

修正：PPTX 脚本新增真实 `-SkipBuild` 参数；需要编译时明确注入 `src-tauri/tauri.e2e.conf.json`。

修正后实际：重新编译 E2E 二进制后，ODS 的 Tauri 编辑、可靠副本和 LibreOffice 独立验证全部通过。

### 3.2 用户文档差异

预期：M1 新能力和边界同时进入格式事实源、设置页、README 与未来发布说明。

修正前实际：DOCX、PPTX、ODS 的事实源已更新，但 README 仍是旧概括；视频描述未包含逐帧、截图、位置记忆和字幕，大 JSON 未说明渐进只读。

修正：更新格式注册表和发布矩阵；README 新增明确标记“尚未发布”的 `1.0.16` 开发状态，并新增 `RELEASE_NOTES_v1.0.16_DRAFT.md`。

修正后实际：机器门禁同时校验能力描述、开发说明、延后边界与下一阶段。

### 3.3 生产预检证据差异

预期：完整格式合同可核对当前 `1.0.15` 的 production 路由资产。

修正前实际：`R5D` 目录仍保存 `1.0.0` 的历史预检清单，完整合同因版本不一致失败。

修正：不手改历史数值，直接对本轮 production `dist` 重新执行 R5D 预检。

修正后实际：当前 `1.0.15` 构建检出 11/11 路由资产族和 117 个 JS 资产，运行时导出标记存在，证据保持非发布、无用户正文。

完整 `check:format-contract` 随后继续到 R5E，并因该目录仍是 `1.0.0` 的历史浏览器预览阻断证据而停止。R5E 至 R5N 包含安装器、隔离安装、托管 Windows 和外部发布证据；当前没有 `1.0.16` 候选安装包，不能仅替换 JSON 版本伪造复验。此项保留为 M4 发布冻结前的真实重采门禁，不影响本阶段由当前 Tauri/Office/LibreOffice 证据完成的 M1 功能退出判定。

## 4. 需求对齐

- **完整 Excel 方向**：M1A 深化日常对象草稿、条件格式、Table、数据验证和大表性能，但仍不宣称完整 Excel 等价编辑器。
- **新格式与薄弱格式**：DOCX/PPTX、ODS、大 JSON 和视频均完成明确用户任务；无法证明的高级对象继续只读、可靠副本或延后。
- **显式保存**：所有可编辑路径仍先进入内存草稿；源覆盖或可靠副本均有签名、确认和复开证据。
- **真实测试**：当前复验包含真实桌面、真实文件、失败样本、独立生产者和源 SHA-256；没有以静态合同替代用户路径。
- **版本边界**：当前不是发布候选，不提升 package、Cargo、Tauri 或公开标签。
- **发布门禁边界**：当前开发质量门、生产构建和 Rust 检查通过；R5E-R5N 必须在 M4 使用真实候选安装包和外部环境重采，不能沿用或改写旧版本证据。

## 5. 保留边界

以下项目没有在 M1 中开放：完整 Office 等价编辑、ODS 公式编辑、自定义样式创建、ODP 编辑、外部窗口字幕、嵌入字幕拆封、字幕编辑、视频转码，以及 YAML/XML/TOML 的 Schema provider/mapping。

## 6. 阶段结论

M1 已满足“至少一个高频 Office 子阶段和一个非 Office 子阶段、真实复开与失败样本、用户文档和事实源同步”的退出条件。M2 工作台 2.0 已在此前独立收口，因此下一阶段固定为 **M3 知识图谱 2.0 选择审计**：先用 100/1000/5000 节点真实图谱记录语义、视觉、算法正确性和性能基线，再选择 M3A 的最小实现，不直接堆叠视觉效果。
