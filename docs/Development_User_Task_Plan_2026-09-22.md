## 2. 本轮用户视角观察与限制

准备独立合成资料库：`客户会议纪要-九月交付确认.md` 与 `客户会议纪要-九月交付确认-内部草稿.md`，正文分别表达“先核对预算再给客户回复”和“未经审批不要对外发送”。用户目标是“打开给客户的确认版，不要误开内部草稿”。

真实 debug 暗色约 1000×700 窗口已显示两份文件：约 200px 文件树中两者可见标题都截断为相同前缀。**这是辨认风险，不是确认已无法区分**：仍需验证既有悬停提示、键盘详情预览和搜索上下文是否足以区分；不得直接宣布这些能力缺失而重复开发。

computer-use 输入连续报 `call get_window_state before using this window`，重新激活、刷新返回的窗口绑定后仍失败，按技能恢复规则停止输入。因此本轮没有输入查询、没有完成键盘打开，不记录这些场景 passed。这是工具阻断，不是产品缺陷证据；没有改用隐藏 DOM 操作冒充用户操作，也没有修改样本让其更易辨认。

## 4. 后续版本方向（建议槽位，不是已冻结承诺）

| 优先级 | 用户任务和痛点 | 只选一个有限切片 | 验收出口 |
| --- | --- | --- | --- |
| P1，1.0.23 候选 | “这么多同名/近似名资料，哪份才是我要的？” | 先验证完整名称、相对路径、命中上下文、键盘焦点；只补实际无法辨认或打开的断点 | 不改样本，用鼠标和键盘准确打开目标；重命名/失效目标有可理解反馈 |
| P2，下一补丁候选 | “上次图谱看到哪了？这些孤立圆点有什么用？” | 复测已有布局、相机、筛选恢复，选择最痛的一处恢复或无关系引导问题；不先加特效 | 稀疏/密集/无关系库，拖动不误开、缩放不闪、状态能恢复，兼顾减少动态效果 |
| P3，后续工作簿切片 | “表打开慢，改完导出去还对不对？” | 先量测首屏/滚动/保存，再选一个性能瓶颈或公式/格式往返缺陷 | 固定样本与外部重开，数据/公式/格式正确；不宣称完整 Excel 等价已实现 |
| P4，独立交付切片 | “换电脑或发给同事，怎么不丢文件和链接？” | 项目集合的缺失提示、来源清单和导出预览，复用既有导出；暂不引入云同步 | 原件不变，输出可独立打开，迁移不依赖原机绝对路径 |
| P5，按实际需求选择 | “配置报错到底改哪一行？” | JSON 本地诊断定位或有界 YAML/TOML 校验，二选一 | 错误定位明确，不隐式联网，不自动写源文件 |

对原建议顺序的调整：图谱不再机械绑定 1.0.23。先完成当前搜索场景实测，再决定近似文件辨认是否有值得独立发布的实际缺陷；没有就跳过并回到图谱恢复审查。不为了版本号重复开发已具备的功能。

每次仅推进“一个用户任务→实际观察→必要修复→针对性验证→文档与推送”。基础功能没有变化时不反复跑全部历史验收，不再以脚本数量作为开发进度。
