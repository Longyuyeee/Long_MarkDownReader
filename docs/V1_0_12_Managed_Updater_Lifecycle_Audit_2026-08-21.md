# v1.0.12 托管更新生命周期审计（2026-08-21）

## 目标

在 GitHub 托管的一次性 Windows 主机上，仅使用公开 `v1.0.11` 与 `v1.0.12` Release 安装包，验证应用内更新的用户确认、SHA-256、覆盖安装、自动重启、版本确认和资料保留。

## 修正前差异

- `v1.0.12` 已发布且远端附件复核通过，但社区发布策略仍将 `1.0.11 -> 1.0.12` 标为 pending。
- 仓库只有到 `v111` 的托管更新工作流，无法对当前版本形成可重复证据。

## 执行合同

- 工作流必须从官方 Release 下载两版 NSIS，不得用当前源码临时构建替代。
- 下载前后核对 Release 状态、Tag、目标提交、文件名、大小和 SHA-256。
- 更新器必须先显示确认界面；用户确认前不得下载或启动安装器。
- 安装必须覆盖原目录，并由更新助手自动重启；测试脚本不得手动启动新版冒充自动重启。
- 更新后必须显示 `v1.0.12` 且报告已是最新版；覆盖与卸载后合成资料库、配置均须保留。
- 证据不得包含真实用户文档、完整用户路径、凭据或机器身份。

## 当前状态

`shared/v112-managed-updater-lifecycle-policy.json` 与 `.github/workflows/v112-managed-updater-lifecycle.yml` 已准备，状态为 `hosted-execution-pending`。只有托管 Windows 运行成功、截图人工复核、九份证据导入并通过哈希门禁后，才能写为 `hosted-managed-update-passed`。
