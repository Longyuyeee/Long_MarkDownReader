## M7-0 范围选择回执

真实代码盘点重新比较结构化 Schema、图谱代理折叠、治理环和 ODP 备注。唯一选择 **M7-1 本地 JSON Schema sidecar provider/mapping 可行性审计**：JSON/JSONC 已有有界解析、稳定路径与行列、诊断和安全保存基础，最接近最初“可选 Schema、错误路径定位、未配置零误报”的要求。

M7-1 不直接开放完整 Schema Studio，只冻结本地同目录确定性映射、大小/引用预算、来源说明、实例路径定位和安全失败。联网、远程 `$ref`、YAML/TOML 投影、XSD、源码写入和版本提升全部关闭。完成真实样本与桌面基线后，再决定是否进入 M7-2 有界产品实现。

## M7-1 可行性回执与 M7-2 接续

M7-1 可行性通过：Draft 2020-12 后端内核已冻结同 stem `.schema.json`、1 MiB / 5 万节点 / 64 引用 / 200 诊断预算，并以双重边界关闭网络和外部引用。9 个内核测试、28 个既有 JSON 回归和 Rust 检查通过；真实 JSONC/sidecar 验证前后文件摘要不变，错误可映射到既有 JSONPath 与行列且文档值脱敏。

当前进入 **M7-2 有界产品实现与真实 Tauri 审计**。只在现有 JSON 编辑器接入只读命令、来源/状态和分层诊断，补文档或 sidecar 变化刷新、宽窄窗口与源安全证据。M7-1 尚无 UI，不能算产品验收；M7-2 前后均不自动提升版本，完整质量门和发布就绪审计通过后才进入版本迁移与打包。

## M7-2 产品回执与 M7-3 接续

M7-2 产品验收通过：只读 Tauri 命令复用资料库路径授权，JSON/JSONC 编辑器分开呈现语法和 Schema 事实、来源、脱敏业务诊断与源码定位；外部文件、大文件模式和 Schema 文件递归发现均明确关闭。13 个 JSON 命令测试、9 个内核测试、前端构建以及 `1280×800` / `720×680` 真实 Tauri 状态矩阵全部通过，文档和恢复后的 sidecar 摘要不变，运行时错误 0。

当前进入 **M7-3 v1.0.19 质量债与发布就绪审计**。先跑全仓 Rust、完整补丁发布门和生产依赖审计；通过前继续保持 1.0.18 运行时且不打包。M7-3 通过后才能原子提升版本并构建 v1.0.19 候选。

## 延后边界

- YAML/TOML 到 JSON Schema 的投影需要独立处理标签、多文档、数字和日期等语义。
- XML 使用 XSD，import/include、namespace 与外部资源必须单独建模。
- 社区代理折叠仍缺代理身份、聚合边、路径/证据、历史、缩略图、导出和相机恢复合同。
- 治理环仍缺逐节点事实、来源与解释。
- ODP 备注仍受 LibreOffice/PowerPoint 生产者保真不对称阻塞。
