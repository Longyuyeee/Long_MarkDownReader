# M1D 媒体与结构化文本对象选择审计

日期：2026-08-27
开发线：`1.0.16`
运行时与当前公开版本：`1.0.15`
结论：通过对象选择审计；下一步为 M1D-A 大 JSON 渐进只读与流式搜索。

## 1. 开发目标

使用真实临时文件比较大型结构化文本与视频的当前能力，不预设要开发的对象。测试必须记录修正前实际结果、目标、差异和选择依据，不能因为某项已有静态代码就宣告可用。

## 2. 真实样本

- 10 MiB 合法 JSON：30,000 个真实对象，尾部带唯一搜索标记。
- 50 MiB 合法 JSON：与 10 MiB 使用同一结构，扩大尾部内容以验证读取边界。
- 1080p 与 4K WebM：由真实 WebView2 `Canvas + MediaRecorder` 现场生成 VP9 视频。
- 损坏 MKV：用于验证解码失败说明与外部打开退路。

所有源文件只存在于临时资料库，测试前后计算 SHA-256；仓库不保存原始正文、媒体或本机绝对路径。

## 3. 预期与实际差异

| 项目 | 预期 | 当前实际 | 判断 |
| --- | --- | --- | --- |
| 10 MiB JSON | 完成首屏、搜索和树形切换 | 98,758 ms 后仍在“正在读取并分析”，搜索与树形不可用 | 严重差距 |
| 50 MiB JSON | 有界读取或明确失败 | 699 ms 明确提示超过 16 MiB 读取上限 | 安全但能力不足 |
| 1080p WebM | 加载真实元数据 | 292 ms，1920×1080，`readyState=4` | 通过 |
| 4K WebM | 加载或记录解码失败 | 141 ms，3840×2160，`readyState=4`，横向溢出 0 | 通过 |
| 损坏 MKV | 可理解的失败退路 | 162 ms 显示缺少编解码器并提供系统程序打开 | 通过 |

首次测试在 10 MiB JSON 上持续占用 CPU 超过 200 秒且 CDP 无响应，人工终止后所有临时进程与端口均已清理。审计随后增加 30 秒 CDP 看门狗，并将高风险样本放到最后，使失败本身也能形成脱敏证据。第二次测试还修正了媒体生成脚本误用 Node 变量导致的 `ReferenceError`；该错误没有计入产品缺陷。

## 4. 选择结论

M1D-A 选择 **大 JSON 渐进只读与流式搜索**：

- 大文件不得先进入全量 CodeMirror 与完整结构分析。
- 10 MiB 和 50 MiB JSON 应快速显示首段内容，支持分段导航和不加载全文的搜索。
- 大文件模式明确只读，树形与结构编辑说明不可用原因；小 JSON 继续保持完整编辑、树形和显式保存。
- 首屏、尾部搜索、内存边界、源码摘要和 1280/720 响应式都要由真实 Tauri 验证。

M1D-B 再做视频逐帧、截图、位置记忆和字幕轨。Schema、跨格式转换在大型结构稳定后评估，避免在当前冻结路径上继续增加同步分析负担。

## 5. 测试与边界

- `npm run audit:post-v115-m1d-selection`：通过对象选择审计。
- 真实 Tauri/WebView2：通过；运行时错误 0。
- 两份 JSON 源摘要测试前后相同。
- 本阶段没有改变格式注册表、保存能力或发布声明，`releaseCandidate=false`。
