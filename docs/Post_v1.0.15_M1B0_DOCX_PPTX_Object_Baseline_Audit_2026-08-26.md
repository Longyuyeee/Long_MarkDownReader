# v1.0.15 后 M1B0 DOCX/PPTX 对象基线审计

日期：2026-08-26  
状态：通过当前事实审计，仍有明确产品差距  
版本：不提升版本

## 1. 开发目标与结论

M1B0 的目标不是提前增加 Office 能力，而是用真实文件确认 DOCX/PPTX 已经做到哪里，并把下一步缩小为可独立验收的完整流程。

审计纠正了路线图中的宽泛假设：DOCX 与 PPTX 并非仅有基础预览。DOCX 已具备草稿、撤销/重做、隔离验证、显式覆盖原文件和可靠副本；PPTX 已具备文本、备注、基础字符样式、替代文字、图片替换、基础形状和幻灯片生命周期的有界操作，并可可靠另存副本。

当前真实差距集中在 PPTX：一次只能提交一个已验证操作，没有统一草稿撤销/重做，且只能另存副本，不能在确认后可靠覆盖源文件。这与“可编辑格式点击保存才写回、所有编辑器提供撤销/重做”的产品要求未完全对齐。

## 2. 预期与实际差异

| 项目 | 目标 | 修正前实际 | 审计后结论 |
| --- | --- | --- | --- |
| DOCX 显式保存原文件 | 支持 | 已支持 | 对齐 |
| DOCX 草稿撤销/重做 | 支持 | 已支持 | 对齐 |
| PPTX 可靠另存副本 | 支持 | 已支持 | 对齐 |
| PPTX 显式保存原文件 | 支持 | 不支持 | M1B1A 补齐 |
| PPTX 草稿撤销/重做 | 支持 | 不支持 | 后续统一草稿阶段补齐 |
| 真实生产者基线 | DOCX/PPTX 各 3 份 | 已存在 | 6/6 纳入证据 |

高级 DOCX 的页眉页脚、批注、脚注/尾注、域和浮动对象，以及 PPTX 的母版、动画、SmartArt、复杂图表和未知对象继续保持只读、原样保持或明确阻断，不推测性开放。

## 3. 真实测试

真实样本来自 Microsoft Office、WPS 与 LibreOffice：3 份 DOCX、3 份 PPTX。证据记录了每个文件的字节数和 SHA-256，不包含用户文档正文。

- DOCX 生产者矩阵：3/3 通过。
- PPTX 生产者矩阵：3/3 通过。
- DOCX/PPTX 六个真实文件解析通过。
- DOCX 三生产者可靠副本保存并重开通过。
- PPTX 三生产者文本可靠副本保存并重开通过，源文件未覆盖。

审计过程产生了两次有价值的预期修正：静态检查最初使用了与产品实际不一致的提示文案；文件门禁最初把 18,288 B 的有效 LibreOffice PPTX 按任意 20 KB 阈值误判。修正后以实际文案、ZIP 签名、真实解析和 10 KB 最小防空壳阈值共同判断，完整审计通过。

证据：[`docs/evidence/post-v115-m1b0-office-object-baseline/`](./evidence/post-v115-m1b0-office-object-baseline/)

## 4. 下一步

进入 **M1B1A：PPTX 可靠原文件保存基础**：

1. 新增受源内容签名和预览输出摘要保护的 PPTX 原文件保存命令。
2. 写入前再次检查外部修改，采用可靠原子写入；写后必须重新解析并验证操作语义，失败时回滚。
3. 保留现有可靠副本路径，不把覆盖源文件变成隐式行为。
4. 使用三生产者真实 PPTX 副本验证目标修改、未改部件保持、旧签名拒绝、保存后重开和失败不破坏源文件。

M1B1A 只建立可证明的后端保存基础；统一多操作草稿、撤销/重做和前端显式保存随后独立验收。达到完整用户流程前不更新公开能力声明，也不提升版本。
