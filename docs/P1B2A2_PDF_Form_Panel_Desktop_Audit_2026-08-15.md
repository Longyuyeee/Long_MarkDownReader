# P1-B2A2 PDF 表单检查面板桌面审计

审计日期：2026-08-15

阶段状态：只读检查闭环完成，下一步进入 P1-B2B 受限填写副本

## 需求对齐

表单能力接入原有 PDF 工作区，不新增路由、窗口或另一套视觉系统。软件仍保持左侧资料库导航、右侧阅读/编辑区；“表单”只是 PDF 内部侧栏的新标签。外部 PDF 不显示该入口，本阶段没有填写、保存或覆盖按钮。

## 产品实现

- 工具栏和 PDF 侧栏共用“表单”入口，按需调用 B2A1 只读检查，普通 PDF 打开速度不受额外完整解析影响。
- 汇总字段、Widget、可填写候选、缺失外观、孤儿控件、源大小和风险阻断。
- 字段卡显示类型、值、必填/只读/多行/候选等标记；密码字段值始终隐藏。
- Widget 页码可跳到对应 PDF 页面；字段可按名称、现值或默认值筛选。
- 前端一次最多渲染 300 个字段，每个字段最多展示 20 个 Widget 页码，避免合法大表单拖垮 WebView。
- 组件只使用既有主题变量、紧凑字号、圆角和状态色；窄屏标签自动分为两行。

## 真实桌面证据

使用临时生成的标准 AcroForm（1 页、文本框与复选框各 1 个）在 Tauri debug custom-protocol WebView2 验证：

- `1280×800`：原资料库/编辑器结构不变，272 px 表单侧栏与 PDF 页面同时可见；
- `720×680`：六个侧栏标签分为两行，字段卡、筛选和页码操作仍可达；
- 后端报告 `inspectable`、2 字段、2 Widget、2 个可填写候选；
- 两次视口均无根级横向溢出、无写入操作、无可见错误；
- 检查前后 PDF SHA-256 不变，运行时错误为 0；
- 截图与结构化证据位于 `docs/evidence/p1b2a2-pdf-form-panel/`，不含用户内容。

审计还确认本机 Windows 将 `8963–9062` 保留为 TCP 排除范围，项目开发端口 9000 无法监听；因此本次采用 custom-protocol 构建验收，与发布包加载方式更一致，不将环境端口问题误归为产品缺陷。

## 下一步

P1-B2B 只允许对 `inspectable` 且无阻断项的 `Tx`、`Btn`、`Ch` 字段建立内存草稿，并生成同目录新 PDF。必须在保存前复核源摘要、字段集合、外观生成和源文件不变；签名、加密、XFA、JavaScript、动作、重复字段名和孤儿 Widget 继续阻断。PDF 能力登记应在可靠填写副本完成后从 sidecar-only 修正，不能因本阶段只读面板提前宣称“支持表单编辑”。
