# 1.1.22 计划：文件整理记录与重启接续

状态：已完成并正式发布；实际交付与边界见 [发布记录](V1_1_22_Unsigned_Community_Release_Audit_2026-10-20.md)。以下为实施前计划。

## 用户要完成的事

“昨天把文件移动、改名了，今天想知道现在在哪；如果整理错了，希望只还原其中一项，不影响后来写的内容。”

文件栏右键增加“最近操作…”，打开一个可查找的弹窗。默认只看当前资料库，列表显示时间、动作、文件名、结果；选中一项后在弹窗里查看原位置、新位置和可执行操作。正常文件页面不新增历史面板。尚未执行、已完成和需要核对分别说明，不把技术日志原样摊给用户。

## 实际代码起点

- `src/services/libraryFileOperations.ts` 的 `lastLibraryMove` 是进程内 `ref`，重启后丢失；现有“撤销上次移动”不能当作持久操作记录。
- `file_move_journal.rs::Journal::finish` 和 `file_move_transaction.rs::Stage::finish` 会退休并尽力清理完成记录；它们用于处理中断，不能直接当成所有已完成动作的历史列表。
- `file_activity.rs` 用于短期并发排除和当前进程的目录接续，不承担历史查询。
- `FileMoveRecoveryDialog.vue` 已能列出未完成移动、还原、按当前位置核对和导出原文。继续复用这些动作与原生事务，不另建一套与现有恢复记录竞争的执行逻辑。
- `cross_library_copy.rs` 的计划和幂等回执目前留在进程内。本版先明确如何持久关联结果，不把未知复制状态直接当作可重试失败。

## 实施顺序

1. 在现有文件事务完成和中断的交界保存有限的操作摘要，记录实际逐项结果、稳定 ID、库根、时间、动作与源/目标；完成记录的保留与临时事务的清理分开。重启只读取记录，不自动执行撤销或重试。
2. 接入“最近操作…”弹窗的查询、文件名查找和位置查看。待核对项直接进入现有恢复弹窗。复制只提供查看结果与必要核对，不把“撤销复制”解释为直接删除副本。
3. 对具备充分依据的移动和改名提供“还原此项…”。操作前自动核对实际文件、原位置、关联引用与正在保存/编辑的内容；明确受到影响的范围。目标已被继续编辑、改名、移动或原位置被占用时保留现状，说明原因并提供查看或核对。
4. 接续部分完成：已还原项留在原记录中，下一次只处理剩余项。旧“撤销上次移动”和新列表使用一致的记录与结果，避免两处各自重复执行。

## 交付边界

- 不提供永久删除、外部程序整理或正文任意修改的万能撤销。清除操作记录不删除用户文件，不清除仍需恢复的原文和事务材料。
- 未保存内容保留在原编辑器；读历史不要求先保存。确实影响当前草稿的还原，复用已有保护与局部说明，不增加日常确认流程。
- 只记录本版开始后实际发生且可确认的动作，不补造过去的操作，也不把 1.1.21 内存回执声明为已经支持重启恢复。

完成判断以用户任务为准：移动/改名后重启可查，定位到实际文件，按项还原，后续修改与未保存草稿保留；部分失败可以接续，原有图片、链接、历史与多窗口操作不被破坏。只验证受影响的流程，再完成既有发版检查，不扩展为新的管理平台。
