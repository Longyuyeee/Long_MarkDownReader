# Library 右侧统一工作区结构审计

更新日期：2026-07-26

审计结论：**用户反馈成立。A2～A4 新工作面功能完整，但知识库内打开方式偏离了最初 Markdown 的管理器结构；现已完成结构修复与视觉对齐。**

## 1. 问题表现

原 Markdown 文件在 `LibraryMode` 内打开：

- 左侧始终保留文件树、搜索、集合、标签、引用和历史；
- 右侧显示标签、工具栏和编辑内容；
- 用户可以连续管理、切换和编辑，不丢失当前位置。

TXT、JSON/JSONC、YAML、XML、TOML 和 LOG 后续虽然接入了统一标签，却直接跳转到独立路由。结果是：

1. 左侧管理器消失，用户误以为打开了新界面；
2. 返回文件树需要额外操作，连续管理被打断；
3. 独立页重复渲染一套标签和返回按钮；
4. 各工作面自行定义标题、工具栏高度和字体，产生视觉漂移；
5. 命令面板、工作台、Canvas 文件节点和最近文件可能走不同打开路径。

这属于空间架构不一致，不应仅通过调整颜色或字号掩盖。

## 2. 根因

A2～A4 开发时，为隔离 CodeMirror、结构分析器、大文件和日志生命周期，每种专业工作面被实现为独立懒加载路由。这一选择有利于代码隔离，却错误地把“编辑器组件边界”等同于“用户界面边界”。

正确关系应为：

```text
Library 管理器壳
├── 左侧：文件、搜索、集合、标签、引用、历史
└── 右侧：按格式懒加载的编辑器组件
```

编辑器可以独立实现，但知识库内文件不应因此离开管理器。

## 3. 修复后的打开策略

### 知识库内文件

下列工作面统一嵌入 Library 右侧：

- TextEditor：TXT、INI/CONF/CFG、Properties、`.env`、点配置和代码文本；
- JsonEditor：JSON/JSONC；
- YamlEditor；
- XmlEditor；
- TomlEditor；
- LogViewer。

文件树、最近文件、工作台、命令面板、统一标签和 Canvas 文件节点共同消费 `opensInLibraryShell`，避免每个入口重新判断。

### 外部单文件

系统文件选择器或启动参数打开的外部文本仍使用独立 TextEditor 页面。原因是外部授权只在当前进程有效，且外部文件不应伪装成知识库成员或进入持久化最近记录。

因此当前策略是“知识库内嵌入，外部文件独立”，而不是删除独立路由。

## 4. 右侧视觉合同

Library 提供统一嵌入容器：

- 继承原主题的背景、边框、圆角、字体和文字颜色；
- 只保留 Library 顶层标签，隐藏子工作面重复标签；
- 隐藏嵌入状态下无意义的“返回知识库”按钮；
- 标题统一为 12px，辅助信息和状态栏统一为 11px；
- CodeMirror 正文统一为 13px；
- YAML/XML/TOML 工具栏统一到 48px，与 Text/JSON/LOG 对齐；
- 格式专属操作、结构树、保存策略和安全提示继续保留。

该合同只统一界面层级和尺度，不强行把 JSON 结构树、日志筛选或文本编码栏压缩成 Markdown 工具栏。

## 5. 路由与标签行为

1. 点击知识库文件时，先把 URL 对齐到 `/library?path=...`，再激活对应标签，避免编辑器以旧路径短暂挂载。
2. Markdown 与嵌入格式之间切换时，左侧管理器不卸载。
3. 嵌入格式之间切换时，只替换右侧懒加载组件。
4. 关闭脏标签仍使用统一确认逻辑。
5. 应用重启后，从最近文件恢复 LOG 时仍进入 Library 右侧，而不是旧 `/log` 页面。
6. 独立路由继续作为外部文件和兼容深链的安全入口。

## 6. 验收证据

真实 Tauri Debug/WebView2 回归已升级为 **18 项检查、10 张截图**：

- 每个 A5 fixture 现在通过 `/library?path=...` 打开；
- 断言 `.library-mode` 存在；
- 断言左侧栏宽度大于 180px；
- 断言对应编辑器位于 `.library-embedded-editor`；
- 断言子工作面的重复标签被隐藏；
- 新增 JSON → Text → JSON 标签切换，三次均保持 Library 管理器；
- 重启恢复断言同步改为 Library 右侧 LOG；
- 保存、冲突、敏感遮罩、非法 JSON、大文件和日志轮转原有语义全部继续通过。

格式契约还会阻止以下回归：

- 六类日常编辑器从嵌入清单被删除；
- Library 不再使用动态右侧组件；
- 统一标签、命令面板或 Canvas 节点绕回独立页面。

## 7. 后续界面治理

本批解决 A2～A4 日常编辑器。PDF、Canvas、Workbook、Diagram 和 MindMap 当前仍是专业全屏工作面；它们是否全部嵌入右侧不能机械处理，需要逐项审计画布尺寸、侧栏冲突、沉浸模式和窄屏行为。

后续原则：

1. 文件管理和普通编辑默认留在 Library 右侧；
2. 需要大画布的专业工作面可以全屏，但必须提供明确的管理器返回和上下文恢复；
3. 新格式必须先声明 `Library 右侧 / 专业全屏 / 外部独立` 三种空间模式之一；
4. 新工作面必须复用视觉合同，不再自行发明标题字号和工具栏尺度。
