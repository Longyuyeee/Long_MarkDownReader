## 0. 不可偏离的基础需求

> **覆盖用户日常使用中的文件管理和基础编辑，并把分散文件组织成一套可持续使用、可查找、可关联、可维护的管理体系。**

这是本产品不可被后续技术路线、阶段编号或高级功能降级的最高产品原则，包含两个同等重要的结果：

1. **日常管理与基础编辑**：常用文件能够被识别、预览、搜索、分类、打开和安全保存；对 PDF、图表、思维导图、WPS/Office、TXT、JSON 及开发常用格式提供与其风险相匹配的基础编辑能力。
2. **体系化管理**：文件不只是散落在目录中，而是通过统一工作台、目录与集合、标签、全文搜索、最近与收藏、批注、引用、关系和可重建索引形成完整管理闭环。

开发优先级必须遵循：

- 先保证常用格式“可管理、可阅读、可完成基础编辑”，再追求单一格式的高级等价能力。
- 知识图谱、Canvas、仪表盘和 AI 是体系化管理的增强手段，不能成为使用基础功能的前置条件。
- 新功能若不能直接提高格式覆盖、基础编辑可靠性或体系化管理效率，默认不得挤占 P1 主线。
- 每次阶段审计必须同时报告“日常格式覆盖率、基础编辑完成度、体系化管理闭环”，不能只报告技术子模块数量。

## 1. 原始目标

LongEdit 的首要目标不是复刻一整套 Office，也不是只做 Markdown 知识库，而是在同一个本地文件管理器中完成：

1. 识别、分类、搜索和管理常见文档及开发文件。
2. 在软件内直接阅读 PDF、文本、数据、图表、思维导图和 WPS/Office 常用格式。
3. 对适合本地可靠写回的格式提供编辑能力。
4. 对暂时不能安全编辑的格式提供只读预览、批注、转换或调用外部程序的清晰降级方案。
5. 所有能力必须明确区分“能识别、能预览、能编辑、能可靠保存”，不得把“可以打开”宣传为“完整支持”。

## 2. 产品定位

> LongEdit 是以本地文件为事实源的专业多格式资料管理器，提供统一文件浏览、全文搜索、格式化预览、基础到专业编辑、批注、关系组织和安全保存能力。

知识图谱、Canvas 和工作台是文件管理的增强能力，不应挤占基础格式覆盖的优先级。Excel 高级兼容继续迭代，但在 PDF 页面操作、DOCX/PPTX 基础支持和开发文件工作面形成闭环前，不继续把高级 Pivot 等能力作为唯一开发主线。

## 3. 能力等级定义

每种格式在统一注册表中必须分别声明以下能力：

| 能力 | 定义 |
|---|---|
| 识别 | 能根据扩展名、MIME 和必要的文件签名识别，显示正确图标、类型和打开入口 |
| 预览 | 不依赖外部软件即可查看主要内容；不支持的对象必须明确提示 |
| 搜索 | 文件名、正文或结构化字段能够进入本地索引，并可从结果定位到文件或内部对象 |
| 编辑 | 用户能够修改受支持的内容，界面明确显示不可编辑的高级对象 |
| 保存 | 可靠写回原格式或另存为目标格式；保存失败不得破坏原文件 |
| 批注 | 在不修改原始内容时，以可迁移 sidecar 或格式原生批注保存评论、标记和引用 |
| 创建 | 能从软件内创建合法的新文件，并可被通用第三方软件读取 |

界面统一使用以下状态：

- `完整编辑`：主要对象可编辑，支持可靠往返保存。
- `基础编辑`：只开放已验证子集，高级对象只读保真。
- `阅读/批注`：原文件内容只读，可以搜索、复制或添加批注。
- `仅预览`：只能查看，不能保存修改。
- `外部打开`：应用内尚无安全适配器，提供系统默认程序入口。
- `不支持`：明确说明原因，不以空白页或通用文本错误打开。

## 4. 格式需求矩阵

### 4.1 文本、JSON 与开发常用格式

#### P1：首批必须形成完整闭环

| 格式 | 扩展名 | 目标能力 | 当前状态 |
|---|---|---|---|
| 纯文本 | `.txt` | 识别、预览、编辑、创建、全文搜索、可靠保存 | A2 代码级范围已具备独立编辑、最近文件、系统外部打开、自动保存和跨工作面统一标签；桌面验收归 A5 |
| JSON | `.json`、`.jsonc` | 源码/树形双视图、折叠、搜索、校验、格式化、压缩、JSON Path、编辑与可靠保存 | A3 第六批第五段已交付源码工具、树形预览、原始节点复制、受门禁标量替换、对象键重命名、对象/数组追加和对象属性/数组项删除；代码级基础结构编辑闭环完成，创建和索引待后续批次 |
| 日志 | `.log` | 大文件渐进读取、行号、筛选、搜索、高亮、自动刷新；默认只读，可显式开启编辑 | A4 第一批第一段已完成注册、有界索引、独立只读工作面、筛选/高亮、末尾范围、自动刷新和有界显示缓冲；显式编辑与桌面证据待后续 |
| YAML | `.yaml`、`.yml` | 语法高亮、结构大纲、校验、编辑、搜索与保存 | 实现未开始；解析器、高亮依赖和保存门禁方向已完成调研，恢复入口见暂停点审计 |
| XML | `.xml` | 源码/树形视图、折叠、校验、格式化、搜索与保存 | 未开始 |
| 配置文件 | `.toml`、`.ini`、`.conf`、`.properties` | 语法高亮、键值导航、搜索、编辑与保存 | 未开始 |

TXT 与开发文本工作面必须满足：

- 支持 UTF-8、UTF-8 BOM，并检测常见本地编码；无法可靠判断时要求用户选择，不静默转码。
- 保留原始换行符 `LF/CRLF`、末尾换行和 BOM 策略。
- 显示行号、当前行列、编码、换行符和文件大小。
- 支持查找替换、大小写/整词/正则匹配、跳转到行、撤销重做、自动保存开关和外部冲突提示。
- 大文件进入渐进只读模式，不把完整文件一次性装入编辑器；用户明确确认后才进入高成本编辑。
- 二进制文件、包含 NUL 的文件或超出限制的文件不得当作普通文本保存。

JSON 工作面必须满足：

- 普通 `.json` 与 `.table.json`、`.canvas` 分开路由，复合扩展名采用最长匹配。
- 源码视图和树形视图使用同一内容模型；切换视图不得丢失字段顺序、数值精度或未知字段。
- 提供语法错误位置、重复键提示、格式化、压缩、节点复制、JSON Path 复制和局部搜索。
- 支持数组、对象、字符串、数字、布尔和 null 的结构化增删改。
- 保存前校验；格式错误时允许保留草稿，但不得覆盖最后一个合法文件，除非用户明确选择按纯文本保存。
- `.jsonc` 保留注释；不得使用不保留注释的结构化编辑器静默覆写。

A3 采用源码事实源：CodeMirror 负责编辑，Rust `jsonc-parser` 负责权威诊断和树形元数据。格式化只重建 token 间空白；树节点复制和标量修改使用精确源码范围，不经过普通对象序列化。重复键、精度敏感数字、容器替换和陈旧范围会阻止树形修改；保存继续复用签名冲突与可靠替换。详细边界见 `docs/JSON_Editor_Architecture_Decision.md`。

#### P2：通用代码阅读与轻量编辑

首批识别以下扩展名：

- Web：`.html`、`.htm`、`.css`、`.scss`、`.less`、`.js`、`.jsx`、`.ts`、`.tsx`、`.vue`、`.svelte`
- 脚本：`.py`、`.sh`、`.ps1`、`.bat`、`.cmd`
- 后端与系统：`.rs`、`.go`、`.java`、`.c`、`.cc`、`.cpp`、`.h`、`.hpp`、`.cs`、`.php`、`.rb`
- 数据与查询：`.sql`、`.graphql`、`.gql`
- 其他常用工程文件：`.env`、`.gitignore`、`.editorconfig`

本阶段定位为“代码阅读与轻量文本编辑”，不承诺替代 IDE。要求包括语法高亮、符号大纲（可解析语言）、括号匹配、搜索替换、差异/外部冲突提示和可靠保存。不得在未审计前加入代码执行、终端执行或自动安装依赖。

`.env`、凭据文件及疑似密钥内容默认遮罩敏感值，不进入全文索引、日志、知识图谱或遥测；用户可对单个文件显式解除遮罩。

## 5. 统一管理器需求

### 5.1 文件识别与打开

- 文件树、最近文件、收藏、搜索结果和系统打开事件统一消费格式注册表。
- 使用扩展名、MIME、文件签名和文本/二进制嗅探组合识别；扩展名与内容冲突时显示风险提示。
- 未支持格式仍在文件树中可见，不得被扫描器静默隐藏。
- 对未知文本提供“按纯文本打开”，对未知二进制提供元数据和十六进制只读预览的后续扩展入口。
- 支持“应用内打开”“使用系统默认程序打开”“打开所在文件夹”和“复制完整路径”。

### 5.2 统一工作面

- 标签页支持混合打开 PDF、文本、JSON、表格、脑图和 Office 文档。
- 每个标签页显示文件类型、只读/可编辑状态、未保存状态、外部冲突和当前保存目标。
- 工具栏根据格式能力切换，不显示无效保存按钮。
- 对部分编辑格式显示“本次保存会修改什么、会保留什么、哪些对象只读”的能力说明。
- 保存、另存为、导出和转换必须是不同命令，避免误覆盖源文件。

### 5.3 搜索、索引和知识关联

- TXT、JSON、YAML、XML、配置文件、日志和代码文本进入可重建全文索引。
- JSON/YAML/XML 搜索结果尽可能定位到字段路径；代码和日志至少定位到行号。
- PDF 定位到页码或批注；Office 文档定位到段落、工作表/单元格或幻灯片。
- 敏感格式和用户排除目录不得索引。
- 知识图谱只作为关系入口；基础阅读和编辑不能依赖用户先建立图谱。

### 5.4 安全保存

- 所有可编辑格式使用临时文件、完整校验和可靠替换，失败时保留原文件。
- 保存前比较内容签名，发现外部修改时提供比较、重新加载或另存，不静默覆盖。
- OOXML、PDF 和其他复合格式写回必须有真实 fixture、包完整性校验和语义重读门禁。
- 未知字段、高级对象或扩展节点不能保真时，默认只读或阻断保存。
- 日志和错误提示不得包含正文、密钥、密码或未脱敏路径信息。

## 6. 重新排序后的开发路线

### 阶段 A：开发文本与 JSON 闭环（P1）

1. 注册普通 `.json/.jsonc`、`.log`、YAML、XML、TOML 和配置格式。
2. 建设统一文本编辑内核：编码、换行符、行号、搜索替换、大文件和冲突处理。
3. 建设 JSON 源码/树形双视图及可靠保存。
4. 将新格式接入文件树、标签页、搜索、最近记录和外部打开。

退出条件：TXT/JSON/YAML/XML/LOG 可被正确识别；TXT/JSON 主流程可阅读、编辑、搜索、保存和重开，且不会破坏编码、换行符或合法结构。

### 阶段 B：PDF 实用编辑（P1）

1. 页面旋转、排序、删除和提取。
2. 合并、拆分、插入页面和另存。
3. 加密、签名、表单和元数据安全边界审计。

退出条件：页面级操作经真实 PDF 重开验证；失败不破坏源文件；界面明确区分批注和内容编辑。

### 阶段 C：DOCX/PPTX 基础工作面（P1）

1. DOCX 阅读、目录、搜索和基础结构编辑。
2. PPTX 缩略图、放映、搜索和基础对象编辑。
3. 建立 WPS、Office 和 LibreOffice 三类生产者兼容矩阵。

退出条件：常用 DOCX/PPTX 能在应用内阅读；已开放编辑子集可以可靠保存，高级对象不丢失。

### 阶段 D：格式广度与专业化（P2）

1. SVG 和 Draw.io。
2. `.ods/.odt/.odp`。
3. `.wps/.et/.dps` 和旧版 Office 的转换或预览方案。
4. 通用代码阅读与轻量编辑。

### 阶段 E：高级等价能力（长期）

- PDF 正文与排版编辑。
- Excel 高级 Pivot、外部数据连接和更完整图表对象。
- DOCX/PPTX 高级排版、动画、母版、修订和协作对象。

## 7. 当前能力结论

当前产品已经具备 PDF 阅读批注、Mermaid、JSON Canvas、OPML、CSV/TSV、Open Table 和渐进式 XLSX 编辑能力。TXT、JSON/JSONC、YAML、XML、TOML、常见配置和代表性代码文本已进入统一可靠工作面；A5 使用真实 Tauri 进程验证了保存重开、外部冲突、敏感遮罩、大文件、日志轮转和进程重启恢复。

当前主要缺口是：

1. 知识图谱日常存在感阶段已收口：工作台、搜索和文件上下文均可见，支持同标签、智能集合、跨格式证据和对象定位；代码语义与脑图协同保留为增强项。
2. 日志保持有界只读策略，尚未开放显式编辑。
3. PDF 只能阅读和批注，尚无页面级编辑，是当前最高优先级缺口。
4. DOCX、PPTX、WPS 原生格式、旧版 Office 和 OpenDocument 尚未支持。
5. 安装包、文件关联、升级/卸载和多机器矩阵仍属于发布专项。

2026-07-26 冻结后的权威主线为：**PDF 页面级编辑 → DOCX → PPTX → WPS/OpenDocument/旧版 Office → 统一发布矩阵**。知识图谱增强不得再次挤占这些基础格式需求；完整状态见 `docs/G8_2B_Relation_Context_Closure_Audit_2026-07-26.md`。

后续验收不以“某个高级内核完成”为产品整体完成依据。只有当用户可以在统一管理器中完成常用文件的发现、阅读、基础修改、安全保存、再次查找和关系组织，才视为基础需求闭环。
