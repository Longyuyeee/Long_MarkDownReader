# 1.1.29 计划：PDF 批注与阅读笔记接续

状态：已完成并正式发布。实际范围见 [发布记录](V1_1_29_Unsigned_Community_Release_Audit_2026-10-21.md)；以下保留原计划。

用户要完成的事：“读完一段后继续整理批注；之前生成的阅读笔记能接着更新，我自己补写的内容不能丢。”

## 先复用已有能力

`PdfView.vue` 已有批注文字搜索、页码/类型/颜色筛选、分页、多选、阅读笔记按页或颜色分组，以及插入当前草稿、新建笔记和复制。`pdfReadingNote.ts` 已生成包含文件摘要、页码和批注身份的来源链接。这些属于已交付能力，不重复作为新增功能。

## 按顺序深化

1. **连续整理批注。** 核对编辑评论、切换筛选、保存和返回阅读时，选中批注、所在页及列表位置是否稳定。用户从批注菜单修改和定位，避免每次重新寻找。优先修复可复现的接续中断。
2. **阅读笔记更新预览。** 从 PDF 或已有阅读笔记的具名菜单打开按需弹窗，识别仍有可靠来源身份的已生成片段，预览新增、变化、失效及无法确定的批注。先明确管理片段的边界；不得把无法识别的用户正文当作生成内容替换。
3. **保留用户补写和未保存内容。** 更新当前草稿时保留生成区之外的文字；取消、来源变化和笔记切换不写入。变化需要重新核对。无法可靠合并时提供保留原文、插入新片段或新建笔记的实际退路，可一次撤销后手动保存，包含等待编辑器历史队列后再撤销的情况。
4. **安装包验证后发布。** 使用临时资料验证批注评论修改、筛选返回、生成后补写、重复更新、来源变化、取消与撤销。沿用来源核对和已有历史，不增加常驻解释区或额外确认步骤。

## 范围和完成标准

以现有 PDF 阅读、批注与 Markdown 阅读笔记为范围；不扩展 PDF 任意版式编辑，不将已有搜索换名作为新功能。无法识别旧版生成内容时保持原文，不能宣称已自动接续。实现前先明确片段身份和已有笔记兼容方式，再完成首条用户流程。入口在右键、批注菜单、文档操作和按需弹窗内，保留六种风格及现有全部功能。

完成标准：修改批注后能回到原阅读位置；已生成笔记可预览合理更新；补写文字与其他草稿不丢失；重复操作不产生意外重复内容；取消、撤销、失效来源均有可理解的处理方式。
