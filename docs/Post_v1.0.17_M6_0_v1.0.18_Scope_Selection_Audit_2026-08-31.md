# v1.0.17 后 M6-0：v1.0.18 范围选择审计

发布候选：否

## 1. 结论

本阶段只审计真实代码、既有真实 Tauri 图谱证据和剩余风险，不修改产品运行代码。v1.0.18 的唯一最小接续点冻结为 **M6-1 图谱有界全屏生命周期与真实桌面审计**。

M6-1 只给 `GraphView` 增加显式全屏入口、状态同步和退出清理，继续复用现有容器、相机、缩略图与 `ResizeObserver`。它不改变节点、边、社区、路径、证据、选择历史、导出或资料库文件，也不提升二进制版本。

## 2. 真实代码盘点与候选比较

| 候选 | 当前真实基础 | 尚缺合同 | 决策 |
| --- | --- | --- | --- |
| 图谱有界全屏 | 图谱已有相机、语义缩放、缩略图、三档响应式证据和 ResizeObserver；历史真实 WebView 记录 Fullscreen API 可用 | 显式入口、`fullscreenchange` 真值同步、Escape/浏览器退出、路由卸载清理、全屏后重算与覆盖层保持 | **选择 M6-1** |
| 社区折叠/展开 | 当前是 Louvain 社区的过滤子图进入/返回 | 代理节点身份、聚合边、选择/历史、路径/证据、缩略图、导出和相机恢复 | 延后 |
| YAML/XML/TOML Schema | 三类编辑器已有有界源码分析、目录、诊断和安全编辑 | provider 信任、工作区映射、解析/缓存、离线与隐私、诊断来源和失败降级 | 延后 |
| ODP 备注编辑 | 备注已解析、索引和只读展示 | LibreOffice 与 PowerPoint 的真实备注保留不对称，正文事务明确排除备注 | 延后 |

现有 F11“专注模式”不是本候选的重复实现：代码只切换 Pinia 的 `isZen` 并隐藏应用栏/侧栏，没有调用 Fullscreen API，也没有图谱自己的全屏状态。M6-1 保持 F11 语义不变，新增图谱工具栏显式入口，避免两个概念互相覆盖。

## 3. 真实证据与预期差异

M6-0 没有制造新的 UI 能力，也没有把历史截图当成新功能验收；它复核了当前源文件摘要，并把仍适用的真实桌面证据作为选择基线：

- M3B-8 暗色/reduced Tauri 在 `1280×800`、`1000×700`、`720×680` 均无页面溢出，Canvas 分别为 `1280×710`、`1000×610`、`720×590`。
- 三档 WebView 均实测 Fullscreen API 可用，但产品全屏入口为 false；运行时错误 0，源目录摘要不变并成功返回资料库。
- 社区交互实测是 17 节点全图 → 4 节点过滤子图 → 17 节点全图，不是代理集群折叠。
- M3B-12 组合图谱证据继续证明全屏、社区代理折叠和治理环均未实现，运行时错误 0、源文件不变。

| 预期 | 当前实际 | 本阶段修正 |
| --- | --- | --- |
| F11 可能已是真全屏 | 只切换 `isZen`，没有 Fullscreen API | M6-1 增加图谱专属显式入口，不改 F11 |
| 社区过滤可直接扩成折叠 | 当前只改变可见子图，没有代理身份或聚合边 | 不混入 M6-1，另立语义审计后再做 |
| 三个结构化编辑器让 Schema 成为同等小切片 | provider、映射、信任、离线/隐私和诊断来源均为空 | 暂不进入实现 |
| ODP 正文副本完成后可顺带开放备注 | 真实生产者备注保留不对称，正文事务刻意排除 notes | 备注继续只读 |

## 4. M6-1 冻结合同

M6-1 必须使用浏览器/WebView 标准 Fullscreen API，以 `fullscreenchange` 作为状态真值；提供图谱工具栏入口及可理解的进入/退出提示；支持 Escape 或浏览器退出；路由卸载时不得留下全屏；全屏变化后通过现有 ResizeObserver 重算画布，并验证相机、选择、详情/路径/社区面板、缩略图仍保持。

真实测试至少覆盖暗色、浅色、reduced motion 与 `1280×800`、`1000×700`、`720×680` 三档 Tauri 窗口，记录进入前、进入后、退出后的 DOM/尺寸/状态差异、截图、运行时错误、资料库前后摘要和返回资料库结果。首次实际与预期不符时必须记录差异并修正，不得只修改断言放行。

M6-1 不包含原生窗口全屏 API、F11 改义、集群代理、治理环、Schema、ODP 备注、图谱数据写回、版本提升、打包或发布。
