# P1-B3C PDF 永久脱敏右侧工作区审计

审计日期：2026-08-15
阶段结论：**原 PDF 右侧工作区接入完成，用户能力已形成；P1-B3D 真实桌面与独立渲染证据待补。**

## 1. 需求对齐与结论

本阶段严格对齐“日常管理和基础编辑必须发生在原左侧资料库 + 右侧编辑区”这一初始目标，没有新增路由、独立窗口或另一套 PDF 界面。资料库内 PDF 的工具栏和侧栏新增“永久脱敏”，外部 PDF 继续只读。用户可以直接在右侧页面框选黑色或白色区域，预验证通过后只能另存同目录新文件。

这不是视觉覆盖能力。最终副本由全部页面的离线栅格重新构建，源 PDF 的文字、图片、矢量、隐藏内容、表单、链接、批注、附件、图层、书签、标签和元数据均不会复制到输出对象图。

## 2. 原工作区交互

- `src/views/PdfView.vue`：沿用现有 `WorkspaceToolbar`、侧栏、页面滚动区、字号、间距和状态组件；新增框选草稿、区域列表、撤销、清空、预验证、风险确认与可靠另存。
- `src/components/PdfPage.vue`：在既有 PDF.js 画布上增加仅供草稿预览的黑/白区域层和规范坐标框选层；不改变阅读、搜索、批注和页面整理结构。
- 离开存在框选草稿的 PDF 时进入统一未保存确认；切换侧栏或按 Esc 会退出框选模式。
- 明确提示图片型副本将失去文字搜索、选择、表单、链接、批注、书签与无障碍结构，用户必须勾选确认后才能落盘。

## 3. 全页可信栅格与 IPC 边界

`src/utils/pdfRedaction.ts` 直接使用当前 `PDFDocumentProxy`，按源页顺序获取全部页面，先计算 64 页、4096 单边和 1.2 亿像素预算，再使用 `alpha: false` 白底画布逐页渲染。框选坐标转换使用与 Rust 后端相同的 `ceil` 起点和 `floor` 终点，黑/白矩形在 PNG 编码前以整数像素烧入。

源摘要从 PDF.js 当前完整字节计算 SHA-256。页面 PNG 以严格 Base64 传入 Tauri，避免 JSON 数字数组造成数倍内存膨胀；Rust 在进入隔离构建前拒绝数据 URL、无效 Base64、单页异常长度和累计超过 256 MB 的输入。前端预算只是快速失败，最终页序、几何、不透明度、烧录像素和资源上限仍由 P1-B3B Rust 后端独立复核。

## 4. 可靠另存与安全状态

预验证返回输出 SHA-256 后，前端保留同一组栅格字节；保存必须同时提交源摘要和预验证输出摘要。后端重新构建并比对输出，禁止覆盖源文件和已有目标，落盘后重新验证对象白名单、文字提取为空、源对象隔离和源摘要不变。保存结果任何复读标志缺失，工作区都不会把操作报告为成功。

本阶段开放的只是资料库内“另存永久脱敏图片型副本”，没有开放外部 PDF 写回、源文件覆盖、加密 PDF、签名 PDF、增量更新、局部页面复制或 OCR 文本复用。

## 5. 验证与下一步

自动验证范围：

- 前端类型检查与生产构建；
- Rust 永久脱敏后端、Base64 IPC、可靠另存和攻击面测试；
- P1-B3C 门禁核对原工作区入口、全部页面渲染、整数像素烧录、摘要锁定、风险确认、外部只读和契约状态；
- 当前开发审计链与历史 P1 阶段血缘回归。
