# B1A PDF 隔离写入引擎与保真门禁审计

更新日期：2026-07-27

开发分支：`codex/a4-format-closure`

对应 Draft PR：#6

审计结论：**B1A 已完成。页面草稿现在可以在内存隔离副本中执行旋转、改序和排除，并通过结构、页序、旋转、文本和源字节复核；仍未开放文件另存或覆盖。下一步进入 B1B“可靠另存为新 PDF”。**

## 1. 目的对齐

本步骤直接服务于用户最初的基础需求：在统一管理器内阅读和基础编辑 PDF，并与日常文件形成体系化管理。B0 已解决页面操作模型和右侧工作面预览；B1A 解决“计划是否真的能生成可复读 PDF”以及“什么情况下必须拒绝生成”。

本步骤不扩展 PDF 正文排版编辑、表单填写、签名、擦除、合并或拆分，也不以隔离内存验证冒充用户文件已经保存。

## 2. 引擎候选审计与决策

| 候选 | 许可证与能力事实 | 工程影响 | 本阶段决策 |
|---|---|---|---|
| `lopdf` | 官方 crate 文档声明 MIT，提供 PDF `Document` 的加载、页面访问、对象操作和保存接口；当前文档最新系列为 0.44 | 纯 Rust；项目已通过 `pdf-extract` 间接使用 0.42，可避免本阶段引入第二套 PDF 对象模型 | **选作 B1A 隔离原型，显式锁定 0.42.0** |
| QPDF | 官方仓库为 Apache-2.0；CLI 文档提供页面选择和相对旋转，适合作为成熟页面操作参考 | 引入 C++ 原生二进制、Windows 打包和额外供应链；当前开发机未安装 | 保留为 B1B/B1C 独立预言机或生产引擎候选 |
| PDFium | 官方许可证为 BSD-3-Clause，并包含其分发依赖的附加许可 | 强项是 PDF 渲染；本阶段需要可控对象树重建和保存，引入体量较大 | 继续由 PDF.js 承担前端渲染，不作为 B1A 写入引擎 |

来源：

- [`lopdf` crate 文档](https://docs.rs/lopdf/latest/lopdf/)及其 [`Document` API](https://docs.rs/lopdf/latest/lopdf/struct.Document.html)
- [QPDF 官方仓库与 Apache-2.0 许可证](https://github.com/qpdf/qpdf)

## 3. 已实现的隔离生成链路

调用链为：

1. `WorkspaceGuard` 限制路径必须位于当前知识库且扩展名为 `.pdf`；
2. 校验打开时文件签名，拒绝外部修改后的陈旧页面计划；
3. 限制输入不超过 128 MiB、计划不超过 20,000 页、输出不超过 256 MiB；
4. 要求每个源页面精确出现一次，旋转只能为 0/90/180/270，至少保留一页；
5. 在内存中物化页面继承的 `Resources`、`MediaBox`、`CropBox` 和 `Rotate`；
6. 建立新的扁平 `Pages` 树，保留原页面对象并应用相对旋转；
7. 只把结果保存到内存字节，不创建文件；
8. 对输出重新解析，核对页数、每页源映射和最终旋转；
9. 分页提取源/输出文本，核对文本页序；
10. 重新读取源文件并比对完整字节、SHA-256 摘要和签名，任何变化均失败。

前端入口仍位于原 PDF 工作面的右侧“页面”栏。用户调整草稿后点击“验证隔离副本”，成功时显示输出页数、临时字节大小和“源文件未修改”；计划发生任何变化后，旧验证结果立即失效。

## 4. 风险阻断矩阵

| PDF 特性 | 当前处理 |
|---|---|
| 加密 | 始终阻断 |
| 数字签名或权限字典 | 始终阻断 |
| AcroForm 交互表单 | 始终阻断 |
| PDF Portfolio / Collection | 始终阻断 |
| 嵌入附件 | 始终阻断 |
| 目录/书签 | 发生改序或排除时阻断 |
| Page Labels | 发生改序或排除时阻断 |
| Tagged PDF 结构树 | 发生改序或排除时阻断 |
| Named Destinations | 发生改序或排除时阻断 |

这些阻断是保真门禁，不是格式识别失败。界面会把稳定阻断码翻译成用户可读原因，且不会生成输出或修改源文件。

## 7. 下一步：B1B 可靠另存

B1B 按以下顺序实施：

1. 仅开放“另存为新 PDF”，默认建议原文件名加副本后缀，禁止选择源路径；
2. 保存前再次校验源签名和页面计划验证摘要；
3. 复用可靠写入服务，以同目录临时文件、落盘复读、原子提交生成目标；
4. 目标已存在时必须显式确认，不做静默覆盖；
5. 保存后由应用重新打开目标并核对页数、方向、文本页序和文件签名；
6. 增加 QPDF 或另一独立解析器/桌面阅读器的交叉重开证据；
7. 保持本审计列出的所有高风险对象阻断；
8. 完成真实桌面“另存—重开—源文件不变—目标可搜索”闭环后，B1 才能收口。

B1B 不顺带加入合并、拆分、插页或正文排版，避免扩大写入风险面。
