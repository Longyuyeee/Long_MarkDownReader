# v1.1.16 XLSX 高频操作深化

当前公开版本仍为 v1.1.15；本页记录 v1.1.16 的开发过程，不代表已封板或已发布。继续沿既定路线深化工作簿，不新增高级透视平台，不删减原功能，不更改显式保存原则。

## 实际页面基线

使用实际 `WorkbookView.vue`、隔离 Chromium 的真实剪贴板和键盘，原生 IPC 使用已有模拟接口；不接管用户桌面，不使用用户文件。结果和截图位于 [基线目录](evidence/v1116-workbook-baseline-observed/results.json)：

- 带引号的换行字段被按两行拆开，影响目标行；应保留字段边界。
- 粘贴 `00124` 后，保存请求的类型为 number。原生写入器保留原始 XML 文本，但数字类型不能保证其他生产者保留编号前导零，因此必须修正分类，不能声称已经发生原生磁盘精度损坏。
- 复制含换行的单元格未引用，存在再次粘贴的范围歧义。
- 19 位整数排序通过 Number 比较后发生精度合并，`9007199254740993124` 被排在 `9007199254740993123` 前。

第一轮驱动失败另存于 `evidence/v1116-workbook-baseline/`。原因是模拟接口直接 structuredClone Vue 代理，而真实桥先进行 JSON 序列化；仅修正夹具边界后在新目录重跑，未修改产品或弱化断言。组件证据不是原生保存、安装态或其他生产者验收。

## 实施约束

修改前的[界面示意](design/v1116-workbook-editing.png)已经渲染并实际查看。保留当前网格坐标、全部工作表、工具、菜单和保存入口；只在数据面板增加明确的结果复制入口及范围提示。Ctrl+C 仍复制当前选区；复制筛选结果不混入其他行，不重排原网格，不修改草稿。

优先处理受限 TSV 往返、编号/公式/文本语义、精确整数排序和填充类型。保留每批 10,000 格、工作面 256 列、原生文件 128 MiB 等原有边界；先验证整批再提交，支持一次撤销。异步剪贴板、筛选加载、公式平移期间文档或选区变化均拒绝旧结果。未加载的原有行不得当作空白覆盖。

实现后需逐层补齐纯函数、实际页面、原生磁盘、独立生产者、固定安装包及同包复核。只有固定源码和同一安装包的全部门禁通过，才能封板、发布和更新 README 末尾更新记录。后续仍按 v1.1.17—v1.1.20 顺序，不将计划计为已完成。

## 实现与组件审查

`workbookClipboard.ts` 复用轻量表格的有界 TSV 解析器，并传入工作簿自己的预算，不缩小原工作簿容量或更改 Table 默认值。应用内剪贴板以标准 text/plain 配合受限 HTML 类型记录；不携带文件路径，不把 HTML 插入页面，不解析外部 HTML 的功能内容。文本与类型记录逐格核对，只有真实公式做原生相对引用平移；普通文本等号和编号保留类型。外部纯文本仍按现有公式输入语义解释。元数据和文本各受 10 MiB 预算约束。

区域输入先验证整批原生字符限制、坐标、只读类型及加载状态，再提交一个撤销事务。粘贴读取和平移等待期间还检查草稿是否变化，防止旧内容覆盖后续编辑。结果复制先完整载入受限范围、核对筛选/排序/文档/草稿状态，再按结果顺序包含表头复制；任何失败不写剪贴板、不更改原网格。整数比较不经过浮点；数字填充使用有界十进制定点运算，文本种子不当数字，超出可靠精度拒绝。

实际组件证据最终位于 `evidence/v1116-workbook-browser-final/`：7 组操作、六风格浅深两色和 760/480/360 三种窄窗口，正常动效，截图已实看；旧保存/失败重试/切表/过期剪贴板回归单列。第一次新驱动用了不存在的 `.save-button`，原失败保留在 `v1116-workbook-browser/`；改为实际按钮后新目录重跑，不改产品或放宽断言。定向回归增加原子拒绝和不完整结果复制后共 41 项，另有 3 项合成发布协议防伪检查，不当作安装态验收。

原生验收新增 11 项实际键鼠/剪贴板场景，仍要求前版本 186 项全部重跑；独立生产者为[官方 openpyxl 3.1.5](https://pypi.org/project/openpyxl/3.1.5/)，及 et-xmlfile/defusedxml 的锁定 wheel 哈希，仅在一次性 GitHub Windows 虚拟环境安装。它检查原生文件类型、公式、五个未触及包部件，再另存并由软件重开；不是 Excel/LibreOffice 视觉验收，不声称计算公式。未接管本机桌面。
