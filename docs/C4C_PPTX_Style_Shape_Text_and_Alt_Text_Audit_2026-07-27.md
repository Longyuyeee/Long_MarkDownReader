# LongEdit C4C PPTX 字符样式、形状文本与替代文本隔离编辑审计

审计日期：2026-07-27

阶段结论：**C4C 已完成；下一开发入口为 C4D 冲突检测、可靠无覆盖另存与写后语义复读**

## 1. 目的与用户需求对齐

C4C 在 C4A 原件保护基线和 C4B 单文本补丁之上，补齐日常演示文稿基础编辑中的两个高频能力：

1. 对安全的单运行、单段落文本设置字号、字体、RGB 颜色、粗体、斜体、下划线和段落对齐；
2. 明确区分普通文本框和几何形状中的形状文本；
3. 为安全内嵌图片添加、修改或清除替代文本；
4. 所有结果仍只存在于内存和临时副本，不写入用户源 PPTX；
5. UI 继续位于 Library 原有右侧 PPTX 详情面板，不创建新窗口、独立编辑页或不一致的视觉体系。

本阶段把 PPTX 从“只能替换一段文字”推进到“可预览常用文字格式与图片无障碍元数据修改”，但尚未向用户承诺保存。

## 2. 安全目标规则

### 2.1 单运行字符样式

字符样式目标必须同时满足：

- 位于普通 `p:sp` 文本形状；
- 具有稳定 `p:cNvPr@id`；
- 只有一个段落、一个 `a:r` 运行和一个 `a:t` 文本事件；
- 不含字段、显式换行、制表符、超链接、外部内容或复杂文本载体；
- `a:rPr` 只使用保守属性集合：语言、字号、粗体、斜体、下划线和删除线状态；
- 字体只接受 `a:latin@typeface`；
- 颜色只接受直接 `a:srgbClr`，主题色和复杂颜色变换保持只读；
- 段落属性不存在，或只含基础 `algn` 对齐属性；
- 不增加或删除运行、段落及文本节点。

可写入范围：

| 能力 | 安全范围 |
|---|---|
| 字号 | 1～4000 pt；UI 使用百分之一磅传输 |
| 字体 | 1～100 个安全字符 |
| 颜色 | 6 位 RGB 十六进制 |
| 粗体/斜体 | 显式布尔值 |
| 下划线 | `sng` 或 `none` |
| 对齐 | 左、居中、右、两端对齐 |

### 2.2 形状文本

C4B 已经允许安全 `p:sp` 文本替换，但没有把普通文本框与几何形状明确区分。C4C 根据 `p:cNvSpPr@txBox` 返回：

- `text-box-style`：普通文本框；
- `shape-text-style`：矩形、圆角矩形等普通形状内部的安全文本。

该分类只开放文本格式，不开放形状几何、填充、线条、位置、旋转、组合或连接关系。

### 2.3 图片替代文本

图片目标必须满足：

- 位于普通 `p:pic`；
- 具有唯一稳定 `p:cNvPr@id`；
- 恰好包含一个内嵌 `a:blip@r:embed`；
- 不包含外链 `r:link`，不接受关系不明确或多媒体载体；
- 只修改 `p:cNvPr@descr`；
- 替代文本不超过 1024 个 Unicode 字符且不包含控制字符；
- 空文本表示移除 `descr`。

图片二进制、关系、裁剪、尺寸、位置、旋转、透明度和名称全部保持不变。

## 3. 隔离事务与摘要保护

C4C 新增：

- `PptxEditableStyleTarget`；
- `PptxEditableAltTextTarget`；
- `PptxIsolatedMetadataPatchReport`；
- `build_pptx_style_patch_isolated`；
- `build_pptx_alt_text_patch_isolated`；
- `preview_pptx_style_patch_isolated_copy`；
- `preview_pptx_alt_text_patch_isolated_copy`。

每个目标同时返回：

- 稳定目标 ID；
- 幻灯片、对象和目标 OOXML 部件；
- 当前语义状态；
- 目标语义摘要；
- 目标部件摘要。

补丁提交时必须重新枚举安全目标并比对摘要。过期目标、过期部件、未知目标、无变化请求和不安全输入均被拒绝。

## 4. 包级保护

样式和替代文本事务共同复用以下门禁：

1. 只重建目标 slide XML；
2. 其他 ZIP 条目全部通过 `raw_copy_file` 原样复制；
3. 输入和输出 OOXML 部件名称必须完全一致；
4. `changedParts` 必须严格等于一个目标 slide 部件；
5. 输出必须通过完整 PPTX 结构重解析；
6. 输出必须重新枚举同一稳定目标并核验样式或替代文本；
7. 输出必须写入真实临时文件、同步、复读并重新解析；
8. 操作后再次读取源文件，验证字节、SHA-256 和文件签名均未变化；
9. 报告固定返回 `writesUserFile=false`。

前端不接收、缓存或保存任意 OOXML 输出字节。

## 5. 原界面工作流

C4C 控件位于原 PPTX 右侧详情面板的“C4C 样式与无障碍预览”区域。

字符样式流程：

1. 点击原工具栏“编辑准备”；
2. 选择安全文本框或形状文本；
3. 设置字号、字体、颜色、粗斜体、下划线和对齐；
4. 点击“验证样式补丁”；
5. 查看目标类型、变化部件、语义复读和源文件写入状态。

图片替代文本流程：

1. 选择安全内嵌图片；
2. 输入或清除替代文本；
3. 点击“验证替代文本”；
4. 查看单部件差异、其余部件保全、语义复读和源文件写入状态。

底部状态栏明确显示“C4C 隔离补丁已验证 · 原文件未修改”。

## 8. 下一步：C4D

C4D 进入可靠保存前的事务收口：

1. 为所有 PPTX 编辑操作统一请求模型和冲突检测；
2. 在保存前重新核对源文件签名、源包摘要、目标摘要和目标部件摘要；
3. 只允许原子创建新的 `.pptx` 副本，禁止覆盖源文件和已存在目标；
4. 写后重新打开输出副本并执行结构、部件差异和语义复读；
5. 对文本、备注、字符样式和图片替代文本建立一致的保存报告；
6. UI 只有在全部可靠保存门禁通过后才显示“另存副本”，并继续保留清晰的非覆盖提示。

C4D 完成前，PPTX 继续保持预览-only，不得提前开放保存入口。
