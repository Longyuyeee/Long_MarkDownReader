## 4. 风险与边界

1. YAML 不是 JSON 子集替换问题。锚点、别名、标签、多文档、块标量和复杂键必须由 YAML 1.2 解析器处理，不能用正则或 JavaScript 普通对象往返覆盖源码。
2. YAML 保存必须复用 A1 可靠文本写入，并在默认路径下阻断无效语法覆盖；是否允许“按原始无效源码保存”需要单独、明确且可恢复的用户选择。
3. YAML 结构大纲只能消费带源码位置的后端分析结果；路径数量、深度和预览长度必须有界，避免别名或超大文档拖垮 IPC 与前端。
4. `.env`、疑似凭据文件和敏感值遮罩必须在扩展代码/配置格式前完成，且解除遮罩与允许索引必须分开授权。
5. A1～A4 当前主要是代码级证据；没有真实 Tauri 证据的能力不得在发布说明中宣称完成桌面验收。

## 5. 后续开发步骤

### A4 第二批：YAML 源码编辑与校验

1. 固定并提交直接依赖：候选为 Rust `saphyr 0.0.11` 与 CodeMirror `@codemirror/lang-yaml 6.1.3`；依赖必须与实现同批提交，不单独落锁文件。
2. 注册 `.yaml/.yml`：独立 `YamlEditor` 路由，读取、基础编辑和有界索引为 `supported`，创建先保持 `planned`。
3. 新增 Rust YAML 分析内核：返回有效性、多文档数、节点统计、带源码位置的诊断和有界结构大纲。
4. 新增 YAML 工作面：源码高亮、查找、折叠、诊断定位、结构大纲、草稿恢复和可靠保存。
5. 保存门禁：默认只允许有效 YAML 覆盖源文件，继续使用内容签名、工作区守卫、编码与换行保真。
6. fixture 与回归覆盖：映射、序列、多文档、注释、锚点/别名、标签、块标量、复杂键、Unicode、损坏输入和超限大纲。

退出条件：`.yaml/.yml` 正确路由；有效文档可编辑保存并重读；无效文档可继续修复但默认不能覆盖；结构大纲和诊断均来自 Rust 权威分析；格式契约、生产构建和全量 Rust 回归通过。

### A4 第三批：XML

- 注册 `.xml` 独立工作面，提供源码编辑、折叠、校验、格式化和只读树形预览。
- 明确实体、DOCTYPE、外部资源和超深结构安全边界；默认禁止外部实体解析。
- 使用真实 fixture 验证命名空间、CDATA、注释、处理指令和损坏 XML。

### A4 第四批：TOML 与常见配置

- 按 `.toml`、`.ini/.conf/.properties` 分组注册，不用一个宽松解析器伪装全部格式。
- 提供语法高亮、键值导航、搜索、轻量编辑和可靠保存。
- 保留注释、顺序、重复段落和原始格式；不能保真时只开放源码编辑。

### A4 第五批：代码文本与敏感配置
