# G8-1 关系摘要产品化审计

审计日期：2026-07-26

开发分支：`codex/a4-format-closure`

对应目标：让知识图谱从独立可视化页面进入日常文件管理流程

## 1. 目标对齐

G8-1 不增加新的事实源，也不把全量图谱画布复制到每个页面。它解决的是“用户必须主动打开知识图谱，才能知道文件存在关系”的产品问题。

本批退出条件：

1. 默认工作台的最近文件和收藏文件能看到关系数量或孤立风险；
2. 资料库当前文件能在不切换侧栏的情况下看到关系摘要；
3. 全文搜索结果能同时显示命中内容和关系摘要；
4. 点击摘要后，独立图谱以对应文件为中心打开；
5. 摘要请求有资源上限，不读取或修改图谱之外的用户文件；
6. Windows 内部规范路径不会泄漏到界面或制造重复最近文件。

## 2. 已实现能力

### 2.1 有界关系摘要命令

新增 `summarize_graph_relations`：

- 单次最多接受 100 个文件路径；
- 路径先经过 `WorkspaceGuard` 规范化和工作区包含性校验；
- 仅返回已进入图谱的文件，不把“未索引”误报为“孤立”；
- 返回关系总数、入链数、出链数、无向关系数、关系类型和孤立状态；
- 响应路径映射回调用方原始身份，图谱节点 ID 保留权威规范身份；
- 不写入任何用户文件。

### 2.2 三类默认入口

- 工作台：最近文件和收藏文件显示紧凑关系摘要；
- 当前文件：Library 顶部标签工作区直接显示关系摘要，Markdown 与嵌入式日常编辑器共用；
- 搜索结果：正文命中信息旁显示关系摘要，不遮蔽原搜索上下文。

统一组件 `RelationSummaryBadge.vue` 负责视觉和交互，避免三个入口各自形成不同语义。

### 2.3 居中导航与图谱可读性

- 摘要点击后使用图谱节点 ID 写入 `root` 查询参数；
- 图谱加载后选择并居中目标节点，同时展示关系证据；
- Windows `\\?\` 内部路径前缀在展示和再次打开文件前被移除；
- 工作台按规范路径身份去重，避免同一文件出现两次；
- 力导向连边使用 120px 期望距离，避免小型局部图谱的节点标签重叠。

## 3. 审计中发现并修复的问题

真实 Tauri 审计不是一次通过，本批通过失败证据发现了三个代码级测试未覆盖的问题：

1. Windows `WorkspaceGuard` 规范路径带有内部前缀，最初与界面路径无法匹配，导致摘要命令返回空数组；
2. 路由首次打开文件发生在部分侦听器注册前，当前文件摘要没有触发刷新；
3. 规范路径和普通路径同时进入最近文件后会形成重复项，图谱详情也会暴露内部路径。

以上问题均已修复，并增加路径规范化 Rust 回归、前端机器契约和真实桌面证据。失败过程没有被算作验收通过。

## 5. 能力边界

本批完成“可见与可导航”，尚未完成：

- PDF、OPML、Canvas、Table 和开发文本工作面的统一关系上下文侧栏；
- 搜索结果中的相邻对象、关系依据解释和动态关系集合；
- import、相对路径、配置键和数据文件引用提取；
- 从关系选择生成 OPML/Canvas 规划视图；
- 图谱增量索引与超大知识库的摘要缓存。

孤立状态仅对已经进入图谱的对象显示；未进入图谱的格式不显示徽标，不伪造为零关系。

## 6. 下一步

下一开发入口为 **G8-2 文件上下文侧栏**。应先抽取统一的“关系上下文”组件和定位合同，再按 Markdown/开发文本、PDF、OPML、Canvas、Table 的顺序接入。上下文必须区分事实关系、结构关系和规划层级，并保留来源证据。
