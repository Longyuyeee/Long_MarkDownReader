# P2-D 全格式能力事实巡检（2026-08-21）

## 目标

对齐格式实现、共享注册表、公开格式能力页、发布能力矩阵、保存边界和安全降级通道，避免实现前进而公开说明滞后。

## 修正前差异

- 43 类格式注册表、发布矩阵和安全通道本身均完整。
- 扩展 `check:format-contract` 先后在 R4、R5 活策略身份处失败：当前包、Tauri 和 Windows 生命周期为 `1.0.12`，仍由当前门禁读取的发布策略与预检身份停留在 `1.0.0`。
- 历史 Release 回执、截图和旧产物摘要没有漂移，也不应被改写。

## 修正

- 只把当前 R4/R5 策略与预检清单的版本身份对齐到 `1.0.12`；签名、VM 矩阵和企业 RC 仍保持 fail-closed，不改运行状态、产物哈希或历史回执，也不把无签名社区版误写成企业候选。
- 新增 `check:p2d-format-facts`，逐格式核对路由、能力层级、保存模式、writer、发布 profile、验证状态、外部依赖和唯一安全通道。
- 每条安全通道继续检查代码证据文件和关键实现标记，格式能力页必须直接渲染同一审计数据源。

## 结果

- 43 类格式、91 个扩展名全部且仅一次进入发布映射与 7 条安全通道。
- 发布验证分布：30 个已验证、7 个受限验证、6 个外部依赖。
- 直接编辑、可靠副本、受限写回、只读预览和外部交接边界没有扩大。
- 当前格式、R4 和 R5 活策略版本事实均为 `1.0.12`；P2-D 机器审计通过。
- 完整发布链真实推进到 R5I 后确认：本机 `1.0.12` MSI/NSIS 哈希与未签名状态已重采集，但上一版本安装包和隔离 Windows 运行器在当前主机不可用，因此安装变更继续 fail-closed。
- R5D-R5G、R5J-R5M 与 U1/U2 的历史运行证据没有改写；下一阶段使用官方 `v1.0.11`、`v1.0.12` Release 资产重新执行托管更新生命周期。

机器证据：`docs/evidence/p2d-format-fact-audit/format-fact-audit.json`。

结论：P2-D 通过，可以进入官方 `v1.0.11 -> v1.0.12` 更新观察；外部 Office 生产者证据仍按现状阻断。
