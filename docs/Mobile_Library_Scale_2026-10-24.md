# 第九批：大资料库列表与查找

本批继续完成 M2 的规模与响应边界，移动里程碑仍为 `0.1.0-dev`。代码在独立移动 worktree；桌面界面和原目录没有改动。没有将本批标记为全功能迁移完成。

## 先回答用户的问题

| 用户此时的想法 | 本批行为 |
| --- | --- |
| 文件很多，先让我看到和找到资料 | 列表首批显示 80 项，按需再显示；名称筛选覆盖本次已读取的全部目录条目 |
| 我记得文件名，不想等待所有正文读取 | “名称与路径”独立读取目录快照，不逐份打开正文；明确显示“未读取文稿正文” |
| 查询不对，让我停下来或换一个词 | 匹配分批让出执行时间；可停止、重试或更换关键词；迟到结果不会覆盖新查询 |
| 刚才打开的文件在哪？ | 返回保留已展开批次、滚动和文件焦点；新建靠后的文件、返回靠后的上级文件夹也先展开对应条目 |

竞品依据为官方资料分析，没有安装竞品或测量竞品速度。[Obsidian Search](https://obsidian.md/help/plugins/search)区分文件 / 路径与内容范围，也明确部分需要解析内容的查询更慢；[Joplin 搜索说明](https://joplinapp.org/help/apps/search/)说明中文等自定义搜索模式在大库中可能较慢；[Joplin 附件说明](https://joplinapp.org/help/apps/attachments/)提供手动或按需读取选项。由此采用按当前任务读取所需数据、解释范围、允许停止的设计。没有把竞品功能声明当作本项目性能结论。

## 实现与边界

- 列表保留原来最多 1,000 条目录元数据的读取限制，首批只创建 80 行。继续按钮显示剩余数量，追加后焦点落到新增批次的可操作条目；名称查找不局限于可见的 80 行。
- 搜索快照增加 `paths` / `content` 范围。路径模式只列目录、处理身份与目录预算，不调用正文 `read`。正文不可读或超过正文上限的 Markdown / TXT 仍可先找到位置，打开时按真实读取结果处理。
- 原生 SAF 列表一次查询名称、类型、大小和修改时间，在内存中排序；读取、保存和附件目录的按名定位也改为读取同一次游标中的 ID / 名称，避免在排序比较器或定位循环中反复调用 `DocumentFile` 元数据 getter。同名的多个文档 ID 拒绝定位，未知大小 / 时间保留为 0，界面显示“时间未提供”；提供器异常仍显示读取失败，不能变成空目录。
- 切换到全文范围重新读取正文；全文读取不完整后切回路径范围时，重新准备目录快照，不将缺失的正文等同于文件不存在。目录快照的来源签名为空，不显示“原文发生外部变化”的假提示。
- 匹配保留中文 / 符号原样搜索、路径优先、稳定排序、总数统计和最多 100 行结果。排序快照复用，每扫描 64 项或一个批次已超过 8 毫秒时让出执行时间；停止、换词、切库、撤权或离开页面取消旧任务。单份文档的正则匹配仍是一个不可抢占操作，8 毫秒是让出检查阈值，不能视为所有设备上的单帧保证。
- “停止读取”保留已读取文稿并标记部分范围；“停止查找”取消当前匹配，不把部分结果当成完整结果，也不显示假的“没有匹配”。重试复用已准备的快照。

保持既有边界：最多 1,000 份文档位置、200 个目录、16 层目录；全文最多 24 MiB，单文件最多 4 MiB；本批没有持久化倒排索引、分页原生目录访问或扩大可读取规模。

新增 `npm run test:mobile-library-scale-browser` 的 7 组任务通过，覆盖 1,000 文件、按需展开、焦点与位置恢复、路径读取、匹配停止 / 重试、新建文件和上级目录定位、路径到正文升级以及换词竞争。

## Android 任务与复现

使用专用 Android 10 / API 29 AVD `LongEdit_Compat_API29`、WebView 124。夹具为真实 Documents 目录中的 1,000 份合成 Markdown、合计 1,661,890 字节，文件名为 `Note-0000.md` 至 `Note-0999.md`。通过系统 SAF 选择器授权目录，没有扩大应用的存储权限。

```powershell
node scripts/create-mobile-scale-fixture.mjs
E:/Android/Sdk/platform-tools/adb.exe -s emulator-5558 push E:/Android/BuildCache/mobile-scale-fixture/library/. /sdcard/Documents/LongEdit-Scale-20261024/

./scripts/build-mobile-debug.ps1 -Target x86_64
./scripts/build-mobile-debug.ps1 -Target aarch64

node scripts/verify-mobile-scale-native.mjs --serial emulator-5558 --output docs/evidence/mobile-0.1.0/library-scale-native-2026-10-24 --stage before
# 编辑后、保存前使用 --stage pending；等待保存回执后使用 --stage saved 核对文件字节。
# 只有 saved 通过后才强制停止并重开，最后使用 --stage final。
```

原生结果以 `evidence/mobile-0.1.0/library-scale-native-2026-10-24/final.json` 和同目录截图 / XML 为准。Android 升级序号递增为 `1002013`，两个 ABI 一致；versionName 继续为共享基线的 `1.2.11`。安装包摘要、实际版本、ABI、ELF 和签名由各包的构建记录保留。

首次原生规模任务暴露了单纯减少网页行数不能解决的瓶颈：旧原生目录排序和定位仍反复查询元数据，路径读取长时间保持 0 份。此状态及初轮包记录以 `before-native-batch-*` 保留；改为批量元数据游标后重新构建验证。一次自动定位用过宽的文字匹配误点了“停止访问”的确认入口，随后通过“继续访问”取消；没有撤销授权或删除文件，XML 保留为 `first-navigation-attempt.xml`，后续改为精确选择资料库按钮。

第一次保存复核还发现写入前的目标定位仍沿用逐条名称查询，自动任务在保存回执完成前强制停止，故源文件仍是原始内容；保护的候选仍在，重启可恢复。此过程以 `before-write-fix-*` 保留，没有记为成功保存。补齐写入和附件目录定位后，增加独立 `saved` 文件核对阶段，再验收重启；实际读取的字节和草稿代次清理均须通过。

一轮基础浏览器回归与 `dist` 重建重叠而发生临时 404；失败报告 `browser-1792793171224` 保留，并在构建结束后重新执行受影响任务。它属于本地测试调度问题，未记为应用保存失败。
