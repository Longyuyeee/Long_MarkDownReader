# 1.2.17—1.2.18：准确保存状态与 XML 元素日常编辑

状态：1.2.17 已发布；1.2.18 XML 子元素创建与元素重命名已接入，正在候选收尾，尚未发布。

## 代码依据与用户需要

`src/views/JsonEditorView.vue`、`YamlEditorView.vue`、`TomlEditorView.vue`、`XmlEditorView.vue` 此前在源码发生变更时直接标记未保存，撤销恢复原文后仍可能要求额外保存或确认。1.2.17 已通过 `src/composables/useStructuredSession.ts` 的可信读取/保存基线解决这项问题，继续保护保存和切换读取期间的后续输入；只读分段保持清洁，未知草稿保守保留。

XML 元素提纲已有属性和文字编辑、元素复制、移动、删除及统一差异预览；用户仍需要手动同时修改成对标签名称，或输入完整新元素。因此后续把元素创建与重命名放在同一版完成，复用准确标签范围与草稿保护。

| 版本 | 用户要做的事 | 入口与交付范围 |
| --- | --- | --- |
| 1.2.17 | 撤销或改回已保存内容后，正确知道是否还有未保存内容 | 沿现有状态栏、保存按钮和关闭确认改进判断；先覆盖 JSON、YAML、TOML、XML，以及 XML/SVG 共用源码视图，不增加新页面或设置 |
| 1.2.18 | 创建 XML 子元素，或修改当前元素名称 | 元素右键“添加子元素…”及“重命名元素…”，弹窗输入，差异预览后应用到草稿；两项复用准确标签范围与既有保存接续 |

## 1.2.17：准确保存状态

为当前文件保留经过真实读取或保存回执确认的基线，区分文档文本、文件身份与必要编码信息。撤销、重做、手动恢复原文及结构化操作恢复基线后，统一更新状态栏、标签、保存按钮和关闭确认；不因曾经发生过一次编辑就一直标记未保存，也不能仅用一个未经校验的摘要就判断内容相同。

继续保护保存过程中产生的后续输入：成功回执只确认本次实际写入的内容，不能把后来输入误标为已保存。写入尚未完成时仍保留关闭与跨窗口草稿保护。恢复草稿、切换文件/资料库、改名移动、重新读取、外部修改或冲突处理后，必须确认基线所属的文件与会话；无法确认时保留草稿，不猜测清洁状态。

核对输入后撤销到读取基线、保存后继续输入再撤销/重做、连续属性与节点操作回到原文、切换标签接续、保存中继续输入、失败重试、外部冲突副本、关闭提示和重开。保留用户输入的空白、数字、BOM/换行和原有排版；使用源码编辑器实际展示的文本与可信文件元数据判断，不序列化结构来猜等价，也不在每次按键时重复读取磁盘。

## 1.2.18：XML 元素创建与重命名

实现前补齐开始标签名称、对应结束标签名称及父元素内容的准确原文范围；不全文替换名称，不根据搜索结果猜闭合标签，不整体序列化文件。

重命名弹窗预填当前本地名称，支持根元素、同名兄弟、自闭合与成对元素。仅修改选中元素的开始/结束标签名称，保留原前缀绑定、属性、内部文字、注释、CDATA、BOM 和换行；名称按 XML 规则校验，同名兄弟允许，提纲路径刷新且定位跟随原元素。有前缀的元素保留原前缀，只编辑本地名称，不借改名猜测或变更命名空间绑定。

添加子元素先支持子元素加明确空白的容器，以及没有内容的成对/自闭合容器。名称和可选普通文字在弹窗输入，文字转义，沿明确的缩进与换行新增；自闭合父元素仅在范围明确时展开。说明新元素继承默认命名空间的实际语义，不猜前缀绑定。混合正文、注释/处理指令归属不明确、位置不足或超出预算时，局部解释并定位源码，保留当前输入和草稿。

预览本身完成确认，不叠加无必要的二次弹窗；创建后选中并定位新元素，连续操作沿当前草稿重新分析，其他原文保持不变。与 1.2.17 的准确保存状态一起核对撤销、重做、保存失败、冲突副本及重开。
