## 已具备的能力

`NoteTemplateManager.vue` 已支持模板编辑、内置另存、自定义、导入/导出、库默认值，以及 `title/date/time` 填充预览。`noteTemplates.ts` 与原生 `commands/note_templates.rs` 已有非递归变量替换，未知变量保留原文，创建使用库边界和无覆盖新写入，不能把这些再宣称为首次实现。

`QuickNote.vue` 已在保存时确定资料库和位置，应用模板前保护已有正文；主编辑区沿所选目录新建，保留显式保存和内联改名。不能重新引入“快速保存后再归档”步骤，也不能把现有顶部一行拆成多行常驻配置。

本地图片由 `useImageFix.ts` / `localImagePath.ts` 在库权限内解析，显示用临时 `srcset`，保留 Markdown 原 `src`，不把预览偷偷写成 base64 正文。共享图片不能随单篇文档移动或导出而被搬走。

## 实际缺口与先后顺序

1. 优先复现现有导出路径。`LibraryMode.vue::handleExport` 以 `any` 调用实例 `exportPDF()`；当前锁定 Vditor 的公开实例声明没有该方法，PDF 导出实现位于内部 toolbar 模块。正式开发先实际点击并保留失败、打印窗口和错误信息，再选受支持、可审计的本地打印/导出路径，不能仅删掉报错提示。
2. HTML 当前取 `getHTML()`，原生 `export_to_html` 在 Markdown 旁同名 `.html` 可靠写入，但没有独立位置/同名确认流程；还需核对已修复的本地图片显示与导出 HTML 中资源路径、临时 `srcset`、字体/分页的关系。先对比导出原字节与离开应用后打开结果，不凭预览显示正常宣称已可交付。
3. Markdown 导出原生返回 `Option` 区分取消与失败；界面却把所有异常都按取消吞掉。应保留真正取消的安静行为，并明确告知权限/磁盘/写入失败、位置及可重试方式，不代存草稿。
4. 在已有模板上深化实际创建前的文章标题/参数与预览，解释真正目标目录及库默认继承。保留旧变量和未知文本，不用新增复杂配置替代简单写作；先给受影响界面示意，再改真实页面。
5. 统一选择/粘贴/拖入本地图片的保存位置和相对引用；按实际交付痛点评估受限的正文+本地资源包。只复制所选文档依赖的授权资源，避免复制整库、跟随外部链接、搬走共享图片或自动下载网络资源。

以上是代码观察，除已有测试外尚未进行 1.1.14 的真实导出复现，不把可能风险写成已确认的数据丢失。当前仍专注完成 1.1.13 安装、封板及公开发布。

## 1.1.14 封板样例

使用中文/空格路径、多图、共享图、长文、标题分页与不同字体，实际执行模板创建、未保存草稿写作、导出取消/同名/失败和移动到另一目录后重开。检查导出的文字、图片和实际打印/文件输出；原正文、资源和其他文档摘要不变。六风格/深浅/宽窄实际页面与固定安装器同包历版回归继续保留。不能将源码、打印预览或模拟响应当作真实 PDF/HTML 交付通过。
