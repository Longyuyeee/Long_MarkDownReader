# v1.0.15 后 M0 真实测试基线审计

日期：2026-08-25  
基线：`main` / `v1.0.15`  
阶段：M0 事实冻结与测试基线  
结论：通过，可以进入 M1A XLSX 日常编辑增强

## 1. 开发目标

M0 不增加或扩大用户能力，只解决后续开发缺少统一事实、固定资料库和规模基线的问题。本阶段目标为：

1. 固定 43 类格式、91 个扩展名和 30/7/6 发布状态分布。
2. 为 13 类有界或外部依赖格式绑定至少三项现有真实文件或历史真实证据。
3. 建立可重复扫描的工作台资料库，稳定产生待办、Canvas、重复文件、未引用批注、断链和歧义链接。
4. 使用当前 Rust 产品后端实际构建 100、1,000、5,000 节点知识图谱并记录耗时。
5. 建立所有后续阶段共用的“修正前实际、目标、修正后实际、证据”模板。

## 4. 修正前、目标与实际结果

### 4.1 格式事实与样本

修正前实际结果：格式事实分散在注册表、发布矩阵、生产者样本和阶段证据中，尚无面向下一周期的统一薄弱格式清单。

目标结果：机器应确认 43 类格式、91 个扩展名、30 个已验证、7 个有界验证和 6 个外部依赖；13 类薄弱格式均应绑定三个可复核证据入口。

修正后实际结果：

- 数量实际为 43 类格式、91 个扩展名。
- 发布状态实际为 30 个已验证、7 个有界验证、6 个外部依赖。
- 13 类目标全部存在于当前发布矩阵，并绑定至少三项真实文件、生产者回执或真实桌面证据。
- 每项证据在执行时检查存在性、字节数和 SHA-256；缺失会使 M0 失败。
- 当前能力声明没有改变，PDF、ODF、旧式 Office 和 WPS 边界保持原状。

差异结论：原先缺少统一账本的问题已解决，产品能力本身没有被规划文档提前扩大。

### 4.2 工作台固定资料库

修正前实际结果：已有零散单元测试，但没有可由后续工作台 UI 审计反复使用的固定资料库。

目标结果：当前产品后端应从固定资料库得到 11 个注册文件、2 个未完成任务、1 个 Canvas、1 组精确重复文件、1 条未引用批注、1 条断链和 1 条歧义链接。

修正后实际结果：

| 指标 | 预期 | 实际 |
| --- | ---: | ---: |
| 注册文件 | 11 | 11 |
| 未完成任务 | 2 | 2 |
| Canvas | 1 | 1 |
| 重复文件组 | 1 | 1 |
| 未引用批注 | 1 | 1 |
| 断链 | 1 | 1 |
| 歧义链接 | 1 | 1 |
| 后端扫描耗时 | 记录基线 | 22 ms |

差异结论：预期与实际一致。资料库由项目自建内容组成，可提交、可重复扫描，不读取用户真实资料。

### 4.3 知识图谱规模基线

修正前实际结果：已有图谱正确性测试和真实桌面交互证据，但没有 100/1,000/5,000 节点的统一构建基线。

目标结果：为每档实际生成 Markdown 文件和有向 WikiLink 链，当前 `build_link_graph` 应返回 N 个节点和 N-1 条边，并记录纯构建耗时。

修正后实际结果：

| 档位 | 预期节点/边 | 实际节点/边 | 实际构建耗时 |
| ---: | ---: | ---: | ---: |
| 100 | 100 / 99 | 100 / 99 | 105 ms |
| 1,000 | 1,000 / 999 | 1,000 / 999 | 773 ms |
| 5,000 | 5,000 / 4,999 | 5,000 / 4,999 | 4,853 ms |

差异结论：数量完全一致；5,000 节点后端构建约 4.9 秒，已成为 M3 的明确优化基线。该结果只测后端构建，不代表 Canvas 布局、绘制和交互帧率已经通过。

### 4.4 审计器自身差异

首次真实运行时，两项 Rust 后端测试均通过，但机器汇总错误地用 JSON 键顺序比较发布状态对象，将实际 `6/30/7` 的不同输出顺序误判为失败。

目标结果：状态计数应按键逐项比较，不受 JSON 对象键顺序影响。

修正后实际结果：比较方式已改为逐状态数值核对；第二次完整执行 2/2 Rust 测试和 M0 汇总全部通过。首次失败被保留在本审计中，没有通过修改预期掩盖问题。

## 6. 边界与下一步

- M0 不是格式编辑增强，不改变任何保存策略或用户可见能力。
- 5,000 节点的约 4.9 秒是后端冷数据基线；M3 还需单独测布局、首帧、缩放、框选、内存和重复进出。
- 视频当前样本由既有真实 Tauri MediaRecorder 审计提供，后续 M1D 增加播放能力时需重新生成视频并验证时间戳和导出结果。
- Office/ODF 新增写回能力仍需独立生产者复开，缺少外部环境时必须保持阻断。

下一步进入 **M1A：XLSX 日常编辑增强**。先基于三个已冻结工作簿样本审计公式、数据验证、条件格式、表格、图表和高级对象的当前实际结果，再选择首个能形成完整用户价值且可独立复开的对象子集。
