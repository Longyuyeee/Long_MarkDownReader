# DOCX 界面接续

基线 e9af0b44，分支 codex/v110-editor-shell，2026-10-12。遵循已批准 R2 阅读/Office 方案；不升版、不宣布封板。

## 本步实现

- 顶部提供有名称的“目录与详情”“页面编辑”“保存”。原有撤销、重做、搜索/前后结果、重读保留，窄窗横向工具行不删入口。
- 大窗口目录可收起；1180px 以下通过相同入口打开目录浮层，定位标题后关闭浮层，编辑草稿不丢失。原来窄窗目录直接隐藏且无法打开的问题已修复。
- 兼容画像、页面布局和包特征完整保存在“文档详情与兼容画像”展开区；脚注/附属内容与原始定位仍保留。
- 保留文本、字符、段落样式、图片说明、修改清单、验证、保存原文件和另存副本的原有面板及处理逻辑。未扩大可编辑对象范围。
- 发现并修复首笔输入发生在页面启动后 650ms 内可能无法撤销的问题：输入合并节流只在已有撤销快照时生效，不跳过第一次快照。
- 窄窗状态栏改为单行可滚动，不再将说明挤成纵向碎片；只读/草稿保存说明不再在窄窗隐藏。

## 实际验证

`test-docx-redesign-browser.mjs` 使用真实 DocxReaderView 和模拟原生解析报告。打开实际页面并查看阅读、编辑和480px目录浮层截图；通过目录/详情、搜索、草稿关闭重开/撤销重做、900/480px目录定位和不丢草稿检查。确认未触发原生保存，未经验证保存仍禁用。截图位于 `evidence/v110-docx-redesign/`。

类型检查和生产构建通过，UX-38D2 历史合同通过。`check-docx-batch-patch-contract.mjs` 失败在旧审计文档必须写“UX-33 进行中”的断言，不是本次代码断言；未为通过测试倒改历史状态。该门禁与现有多目标实现状态的对齐仍待单独审计。

本轮不等于原生 DOCX 解析/可靠保存验收；测试模型只有正文与脚注，复杂图片、字符格式和多生产者输出仍需原生回归。PDF 专用面板及原生输出验收仍待办，不能用本轮替代。
