# v1.0.15 后开发版本身份对齐审计

日期：2026-08-27  
开发目标：`1.0.16`  
运行时与当前公开版本：`1.0.15`  
结论：已对齐，下一步进入 M1D 媒体与结构化文本对象选择审计。

## 1. 修正前实际结果

- `main` 已比公开标签 `v1.0.15` 领先 29 个提交，但 package、Cargo、Tauri、能力矩阵和主界面仍统一显示 `1.0.15`。
- 公开制品版本本身正确，问题是开发代码没有独立、可见且可机器验证的开发线身份。
- 若直接修改所有二进制版本，会破坏既有 Release、更新链和安装包哈希证据；若保持原状，又会让领先代码看起来仍是公开版能力。

## 2. 目标结果

- 开发目标固定为下一个补丁版本 `1.0.16`，主界面显示 `v1.0.16 dev`。
- 运行时、公开 Release 与安装制品继续保持 `1.0.15`，直到 M4 发布冻结。
- Git 必须证明 `v1.0.15` 是当前 HEAD 的祖先且主分支至少领先一个提交。
- 格式能力页必须同时说明开发线和运行时基线，`releaseCandidate` 保持 `false`。

## 3. 修正后实际结果

- 新增 `shared/development-version-policy.json`，独立约束开发目标、公开标签、标签提交、运行时基线和版本提升时点。
- 主界面版本徽标和格式能力页消费同一开发策略；公开发布策略及历史制品事实未被改写。
- `check:development-version-identity` 使用真实 Git 标签、HEAD、祖先关系和提交计数验证版本身份，不使用模拟仓库。
- `audit:main-version-indicator` 使用真实 Tauri WebView 检查宽屏、压缩侧栏和窄窗口中的版本显示、容器边界、更新入口与运行时错误。
- 首轮真实桌面测试实际进入 `ERR_CONNECTION_REFUSED`：已有调试壳内嵌地址与当前 9000 端口不一致。重新执行 `cargo build --locked --manifest-path src-tauri/Cargo.toml` 后，测试进入真实资料库页面。
- 第二轮实际发现 260 px 侧栏的“当前资料库”被徽标挤成两行，且全局工具提示治理会移除原生 `title`。现已把标签固定为单行省略，并改用真实保留的 `aria-label` 验收。
- 最终真实 Tauri 结果：1280×800 / 260 px、1280×800 / 220 px、900×720 / 200 px 三种侧栏状态页面横向溢出均为 0；底部卡片高度为 61.6 / 60.0 / 60.0 px，徽标全部位于容器内，运行时错误 0。
- 实际点击徽标进入 `#/settings?category=system&focus=software-update`，“系统与更新”及更新区可见，页面横向溢出 0。
- `npm run build`、`npm run check:current-development-audit` 与 `npm run check:v1-community-release` 全部通过；公开 `v1.0.15` 标签、附件和更新事实保持有效。

## 4. 需求对齐

- 没有扩张任何格式能力声明，也没有提前发布 `1.0.16`。
- 保持“完成一个可验收阶段再提升 0.01 版本”的原始约束。
- 下一步只进入 M1D 对象选择审计，先记录真实格式现状、预期差异和安全编辑边界，再选择实现对象。
