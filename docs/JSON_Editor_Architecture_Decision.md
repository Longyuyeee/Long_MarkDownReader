# JSON/JSONC 工作面架构决策

更新日期：2026-07-24  
状态：A3 第六批第一段已实现，对象与数组成员增删继续受门禁约束

## 1. 决策摘要

- 源文件文本是 JSON/JSONC 的唯一事实源。不得把 JavaScript 普通对象重新序列化后静默覆盖用户文件。
- 前端采用 CodeMirror 6 与 `@codemirror/lang-json 6.0.2` 提供源码呈现；Rust 采用固定版本 `jsonc-parser 0.33.0` 执行权威解析和诊断。
- 普通 `.json` 使用严格 JSON 规则；`.jsonc` 第一阶段只额外允许行/块注释和尾随逗号，不接受松散键名、缺失逗号、单引号、十六进制数字或一元正号。
- `.table.json` 继续由最长扩展名规则进入 Table，`.canvas` 继续进入 Canvas；通用 `.json` 不得抢占专业格式。
- A3 第五批已在树形视图开放受门禁的标量替换；第六批第一段进一步开放对象键重命名。键目标必须精确匹配当前 Rust AST 的属性名范围，新键由 Rust JSON 序列化器编码，变换前后都必须通过结构候选门禁。对象属性/数组项增删和索引仍未开放。

## 2. 数据保真边界

Rust 分析器直接检查 AST 中的原始数字字面量，不把数字转换为 JavaScript `number`。以下情况会发出警告并阻止进入结构编辑候选：

- 同一对象内出现重复键。
- 整数字面量超出 JavaScript 安全整数范围。
- 数字包含超过 15 位有效数字。

JSONC 注释由解析器单独收集并计数。源码保存只写回用户编辑后的原始文本，不执行解析后序列化，因此未编辑的注释、空白、字段顺序、重复键和数字原始表示不会被自动改变。

保存前必须再次执行 Rust 权威分析。非法源码默认阻止覆盖最后磁盘版本；只有用户在独立警告中明确选择“按源码保存”时才允许写入。无论源码是否合法，保存仍执行工作区边界、读取签名、可靠替换和写后重读验证。通用文本写入 IPC 明确拒绝 JSON/JSONC，防止绕过专用语法门禁。

格式化与压缩不把 AST 转换为普通对象。Rust 解析器收集包含注释的 token 流，输出时使用每个 token 的原始源码切片，只重建 token 之间的空白；重复键、字段顺序、数字字面量、字符串转义、JSONC 注释和尾随逗号均保持。变换只进入 CodeMirror 撤销栈，用户仍需通过现有保存命令落盘。

标量替换同样以源码为事实源。Rust 只替换已验证节点的字节范围，不重建父对象或数组；JSONC 节点外部的注释、逗号和空白保持原样。重复键、已有或新引入的精度敏感数字、容器替换、非法字面量及过期范围稳定拒绝。结果作为单次 CodeMirror 事务进入草稿和撤销栈，不直接写磁盘。

## 3. 规模与错误模型

- 单文档完整分析上限：16 MiB。
- AST 节点分析上限：200,000。
- JSON Path 返回上限：20,000 个节点；界面单次最多呈现 200 个筛选结果。
- 树形视图单次最多渲染 2,000 个可见节点；超限后要求折叠节点或使用 JSON Path 筛选。
- 语法错误返回 UTF-8 字节范围、行列位置和稳定错误码。
- 重复键和精度敏感数字为警告：文档语法仍有效，但 `structureEditCandidate` 为 false。
- 前端把 Rust 字节偏移转换为 CodeMirror 的 UTF-16 位置后再执行定位，避免 Unicode 内容导致跳转错位。

## 6. A3 退出条件

- JSON/JSONC 能从文件树正确进入专用工作面，专业复合扩展名不被抢占。
- 合法、非法、重复键、高精度数字、Unicode 和 JSONC 注释均有稳定行为。
- 源码编辑、草稿恢复、冲突保护、可靠保存和重新打开通过自动化与真实 Tauri 验收。
- JSONC 未验证的结构化写回保持禁用，任何格式化或树形编辑都不得静默丢注释或改变数字语义。
