# M5-9 v1.0.16 → v1.0.17 官方应用内更新观察

日期：2026-08-31

状态：**真实托管执行待运行**

## 开发目标与需求对齐

本阶段只验证两个已公开官方 Release 之间的真实应用内更新，不构建安装包、不修改产品功能，也不把 M5-6 的直接安装覆盖升级冒充应用内更新结果。验收预期固定为：已安装 v1.0.16 发现 latest v1.0.17；用户确认前不下载或启动安装器；确认后下载并以 SHA-256 校验官方 NSIS；同目录静默覆盖；自动重启到 v1.0.17；首次启动显示最新版；合成资料库与配置在覆盖、卸载后保留。

执行只允许在 GitHub 托管的一次性 Windows 环境进行，不触碰用户主机或真实用户资料。

## 预期与实际差异

预期是 v1.0.16 完成发现、用户确认、下载校验、覆盖安装、自动重启和资料保留。当前实际只完成了官方 Release、Tag、NSIS 大小/SHA-256 以及 v1.0.17 安装态主程序身份冻结，尚无应用内更新运行证据。因此当前不能宣称更新链收口；修正动作是先提交并推送一次性托管工作流，再以真实运行结果逐项对照。

入口复核还发现 README 正文已经记录 v1.0.17 发布，但顶部 Stable 徽章、下载表和 SHA-256 仍指向 v1.0.16。预期是所有用户下载入口与当前公开版本一致；实际为发布正文与入口分裂。本阶段已把顶部下载入口、文件名和摘要修正为 v1.0.17，并在审计检查中锁定这些事实。

工作流复用此前多版本通过的参数化 runner/probe，并继续显式解引用 annotated Tag，Release API 的 `target_commitish` 只记录为观察字段。托管产物必须包含机器生命周期结果及三张 UI 截图，完成后逐文件核验大小和 SHA-256，再导入不含真实用户内容的证据目录。

## 当前审计结论

M5-9 的执行入口和验收边界已形成。当前唯一下一动作是推送入口提交并触发 `.github/workflows/v117-managed-updater-lifecycle.yml`；只有真实运行 12/12 通过、截图人工复核和证据导入完成后，才能把 v1.0.17 发布后更新链标记为完整收口。
