# F1 窗口确认登记与生命周期审计

2026-10-11，接续 `02c30e97`。本轮后端生命周期接入，无前端/UI 修改。

## 本轮实现

新增 WindowRegistry 并通过 Tauri managed state 管理。set_window_dirty 使用原生窗口标签登记并推进 revision；即使相同布尔值重复上报也使既有确认失效。窗口首次发现时分配 generation，Destroyed 删除登记并使确认永久失效；同标签重新登记会获得新 generation。

现有归档预检的窗口枚举同时 reconcile 登记集合，新发现但尚未上报的窗口保持 unknown，不假设干净。内部 begin 拒绝未知/有草稿状态，沿用核心的窗口数量和超时限制；每个登记器最多保留一个请求，正常待确认请求不被后续 begin 静默替换，过期/失效请求可以重建。

## 验证

新增 2 项登记器测试：未知窗口阻止开始，同标签销毁重建 generation 改变；重复开始被拒绝、重复干净上报推进版本并失效请求、新增/销毁窗口和重试使用新请求编号。

命令：`cargo test --locked --manifest-path src-tauri/Cargo.toml --lib archive -- --nocapture`。88 passed / 0 failed（新增 2 项，总数含既有压缩包测试）；`git diff --check` 通过。原生生命周期连线通过编译校验；本轮没有运行真实多窗口交互验收。

## 尚未完成及边界

这是生命周期登记接入，不是已经可用的跨窗口确认功能。尚无请求派发、回执命令、前端监听及用户确认 UI，内部 begin 未开放。现有 App.vue 仅在汇总 dirty 布尔值变化时上报，不覆盖已有草稿后继续输入、保存开始/结束；revision 目前只是后端收到上报的版本，不是完整编辑版本。

窗口清单只在预检时同步，新窗口尚未上报/尚未重新枚举的间隔、同标签重载而未销毁、迟到的旧窗口上报等仍须在协议接入时处理。锁异常使调用失败；关闭路径已有清理行为不变。不得依赖本登记打开 canExecute。

下一步先检查实际主编辑区和快速笔记页面，设计前端会话身份、编辑/保存版本上报及请求回执，再实际验收双窗口、保存中、迟到回执和重载场景。新增可见状态按原约定先示意审批；UI 修改前后实际查看页面。
