# A0H Markdown 所见即所得默认与迁移审计

日期：2026-08-04
对应需求：UX-19
结论：代码与配置合同已完成，等待下一安装包复测。

## 根因与修复

- 原配置只有 `editorMode`，历史 `sv/ir` 会在启动时直接恢复；编辑器初始化和输入事件还可能把运行时模式隐式写回。
- 新增 `editorModeExplicit`。旧配置缺少该标记时统一迁移为 `wysiwyg`，后端立即可靠写回；非法模式同样回退。
- 资料库和外部 Markdown 编辑器只在用户点击模式切换时写入显式标记。初始化、加载文件和普通输入不再改变模式偏好。
- 管理备份保留该标记；旧备份缺少标记时继续执行相同迁移。

## 需求对齐

- 新安装和首次打开默认所见即所得。
- 旧配置即使记录源码或即时渲染，也先迁移为所见即所得。
- 用户之后主动选择所见、IR 或源码时，选择会跨启动保留。
- 本阶段只调整 Markdown 打开模式，不改变正文保存、自动保存或格式能力边界。

## 自动验证

- `npm run build`：通过，TypeScript 与生产构建完成。
- Rust 定向测试：旧配置迁移、显式源码保留、非法值回退通过。
- Rust 备份测试：隐私脱敏备份结构回归通过。
- `check:markdown-default-mode` 已加入 `ci:patch-release`，锁定迁移、用户动作与备份合同。

## 安装包复测

1. 使用没有 LongEdit 配置的新账户首次打开 Markdown，应进入“所见”。
2. 用旧版 `editorMode=sv` 且无显式标记的配置升级，应进入“所见”。
3. 主动切到“源码”，重启后应保持源码；切回“所见”后再次重启应保持所见。
4. 分别在资料库 Markdown、外部 Markdown 和管理备份恢复后重复检查。
