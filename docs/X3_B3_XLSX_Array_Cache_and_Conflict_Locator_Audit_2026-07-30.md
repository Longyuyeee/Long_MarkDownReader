# X3-B3 XLSX 数组缓存与冲突定位审计

更新日期：2026-07-30
阶段状态：**代码与真实桌面证据完成；生产者矩阵仍为 `partial 1/3`**

## 1. 目标对齐

本阶段继续服务于“在统一管理器内安全阅读和基础处理日常工作文件”的初始需求。它不尝试实现完整 Excel，而是让包含数组公式的 XLSX 在原有右侧工作面中更容易理解和排障：

- 解释数组声明范围内实际保存了哪些类型的缓存值；
- 报告错误缓存的具体单元格地址；
- 报告可能占用 spill 范围的外来公式地址；
- 从诊断提示直接定位到相关单元格；
- 保持数组计算、内容写回和结构迁移的安全阻断。

## 2. 已交付能力

### 2.1 后端语义模型

`WorkbookArrayFormula` 新增：

- `cachedValueTypes`：按 `number/text/boolean/error/date/other` 汇总缓存类型；
- `errorCacheCount` 与 `errorCacheCells`：错误缓存总数及有界地址列表；
- `conflictCells`：非锚点外来公式的有界地址列表；
- `diagnosticCellsTruncated`：地址超过上限时明确提示截断。

每个数组声明最多返回 256 个错误/冲突诊断地址，避免异常工作簿造成无界内存和界面负担。总数始终保留，因此截断不会被误解为“只有这些问题”。

### 2.2 OOXML 只读诊断

工作表读取器在既有 `<f t="array" ref="…">` 识别基础上，读取声明范围内序列化单元格的 `t` 与 `<v>`：

- 数字、文本、布尔、错误、日期和其他缓存分别计数；
- `t="e"` 缓存记录 A1 地址；
- 非锚点公式记录为具体冲突地址；
- 继续计算声明单元格数、占用数、缓存缺失数和潜在冲突状态。

该过程只观察 XLSX 包内已经序列化的事实，不运行动态数组函数，也不推导期望 spill 范围。

### 2.3 原有右侧 XLSX 工作面

没有新增路由或独立窗口。诊断增强仍位于 `WorkbookView`：

- 数组提示条显示缓存类型摘要；
- 错误缓存与冲突地址提供定位按钮；
- 相关单元格悬浮说明包含缓存类型与诊断地址；
- 冲突单元格使用与现有主题一致的警示纹理；
- 点击诊断地址会选择目标单元格并滚动到可视区域；
- 数组范围内编辑、重算和高风险结构操作继续禁用。

Rust 测试覆盖：

- WPS 真实往返 fixture 的数值缓存分布；

机器契约同时检查模型字段、256 地址上限、UI 定位入口、桌面 manifest、源字节不变以及计算/写回边界。

## 5. 能力边界

- 当前生产者证据仍只有 WPS Spreadsheets，矩阵为 `1/3 partial`；正版 Microsoft Excel 和 LibreOffice Calc 仍缺环境。
- `potential_conflict` 是 OOXML 序列化结构信号，不等于执行 Excel 计算后得到的 `#SPILL!`。
- 当前真实桌面 fixture 没有冲突，因此本阶段桌面证据验证正常缓存与布局；错误/冲突地址由 Rust 合成测试验证。
- 期望 spill 计算、数组公式编辑/写回、缓存写回、数组范围内结构迁移继续阻断。
- 能力公开状态保持“受限”，不能宣传为 Excel 完整动态数组支持。
