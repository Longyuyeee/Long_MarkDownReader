# Long编辑 v1.0.1 全局 UI 一致性审计

审计日期：2026-08-02

审计范围：`src/App.vue`、全局主题与设计令牌、49 个 Vue/SCSS/CSS 界面文件、文件格式路由、资料库嵌入工作区、品牌图标以及浏览器预览状态。

> 2026-08-02 发布后复审更正：初次审计遗漏了根路由在 `725e655` 中由 `/library` 改为 `/workspace` 的结构漂移。虽然文件编辑器已重新嵌入资料库，软件启动首屏仍然进入独立工作台，因此“主结构 P0 已全部处理”的原结论不完整。该问题已在后续 UI 治理阶段修复，并加入自动化门禁。

## 1. 结论

系统已经具备主题变量、间距变量和资料库嵌入编辑器的基础，但视觉体系仍处于“统一框架与各功能页面并存”的过渡状态。用户感受到的混乱不是单一页面缺陷，核心原因有三类：

1. 文件打开结构不一致：Markdown 与部分文本格式进入资料库右侧，PDF、表格、工作簿、图表、思维导图和 Canvas 曾默认切换到顶层页面。
2. 设计令牌落地不完整：49 个样式文件中仍有 727 处独立像素字号、280 处 7–9px 微字号和 571 处直接十六进制颜色。
3. 后开发工作区各自形成局部视觉语言：Workbook、PDF、WorkspaceHome 和 DiagramStudio 的工具栏、信息密度、色彩与字号差异最明显。

因此，v1.0.1 可以收口结构与品牌，但不能把全量 UI 治理描述成已经完成。后续需要在不破坏复杂格式能力的前提下，按组件层级逐步替换硬编码样式。

## 2. 本次已修复

### 2.1 统一文件打开结构

- 将 PDF、CSV/TSV、XLSX、Mermaid、OPML 思维导图和 JSON Canvas 加入资料库嵌入工作区。
- 文件从树、工作台、标签页、命令面板或 Canvas 节点打开时，优先保留左侧管理上下文和顶部标签。
- 修复 `OdfReader` 已声明为嵌入格式但遗漏异步组件映射的问题。
- 为新增嵌入页面统一 `width/height: 100%`、最小尺寸和溢出边界，移除文件页面对 `100vh/100vw` 的结构依赖。

### 2.2 统一工作区视觉基线

- 增加 48px 工作区工具栏、32px 控件和 28px 状态栏令牌。
- 嵌入状态下移除文件页面额外阴影，使用资料库统一边界和圆角。
- PDF、表格、工作簿和 Mermaid 工作室背景改为主题令牌混合色，降低深浅主题切换时的突兀感。
- 扩展文件关系上下文覆盖 DOCX、ODT/ODF、PPTX、XLSX 和图表类页面。

### 2.3 统一品牌入口

- 使用用户选定的 `L + 金色钢笔轮廓` 图标作为 v1.0.1 品牌图。
- 更新根目录 README 图、应用标题栏、工作台页头和空状态品牌图。
- 通过 Tauri 图标生成器更新 Windows ICO/PNG、macOS ICNS、Android、iOS 和 Windows Store 全尺寸资产。

## 3. 风险分级

### P0：发布阻断

- 不允许文件编辑器再次绕过资料库右侧工作区形成第二套主框架。
- 不允许应用图标、README 图、标题栏图标和安装包图标使用不同品牌资产。
- 不允许深色主题下出现固定浅色页面背景遮挡内容。

v1.0.1 标签内处理了文件编辑器嵌入、品牌资源和主题背景，但启动根路由问题在发布后复审才被发现。后续主分支已恢复 `/library` 为启动页，并为主壳层区域增加稳定标识与合同检查。

### P1：高优先级体验问题

- Workbook 仍有 68 处 7–9px 字号和 123 处直接颜色值。
- PDF 仍有 53 处 7–9px 字号，页面组织、OCR、批注等功能区信息密度过高。
- WorkspaceHome 的辅助文字偏小，主导航与内容区的信息层级不够稳定。
- Graph、Settings 和发布能力页仍保留独立页面布局，需要共享统一的管理页壳层。

这些问题不适合在发布前机械批量替换。应通过共享组件和视觉回归逐个迁移。

### P2：持续治理问题

- 571 处直接颜色中，一部分属于文档内容、图表数据和状态语义，不能简单全部替换为主题色。
- 多个复杂工作区将整段 CSS 压缩在单行，降低审查和维护效率。
- 按钮、输入框、分段控制器和空状态尚未完全抽象为共享工作区组件。
- 仅有静态合同检查，缺少覆盖所有主路由的截图差异门禁。

## 4. 后续收口步骤

### 阶段 UI-1：字号和控件统一

1. 建立 `WorkspaceToolbar`、`WorkspaceIdentity`、`WorkspaceStatusBar` 和 `CompactField` 组件。
2. 把 7–9px 功能文字迁移到 10/11/12/13px 四级界面字号；数据网格允许保留受控的紧凑模式。
3. 优先迁移 Workbook、PDF、DiagramStudio 和 WorkspaceHome。
4. 为 100%、125%、150% Windows 缩放分别检查截断、重叠和点击区域。

### 阶段 UI-2：颜色与状态语义统一

1. 将界面 chrome 的直接颜色迁移到 surface、border、text、primary、success、warning、danger 令牌。
2. 保留文档内容、图表系列和用户选择颜色，不把内容颜色错误地主题化。
3. 为浅色、深色和高对比主题增加视觉回归截图。

### 阶段 UI-3：管理页壳层统一

1. 为工作台、知识图谱、设置和发布能力页建立共享管理导航。
2. 保留知识图谱的沉浸画布，但统一页头、返回路径、筛选控件和检查器宽度。
3. 统一空状态、错误状态、加载状态和保存结果回执。

### 阶段 UI-4：自动化门禁

1. 建立主路由截图矩阵：工作台、资料库、Markdown、PDF、DOCX、PPTX、表格、工作簿、图表、思维导图、Canvas、图谱和设置。
2. 检查最小字号、主题令牌使用、全屏单位和嵌入根节点尺寸。
3. 在 PR/Release Gate 中阻止新增 `100vh/100vw` 文件编辑器和未经登记的微字号。

## 5. v1.0.1 发布边界

v1.0.1 是品牌与工作区结构补丁版本：完成新图标、文件右侧嵌入主结构和明显主题冲突修复。它不会宣称 727 处历史字号或 571 处历史颜色已经全部迁移。README 和发布说明必须继续公开这一边界，后续 UI 阶段按本文件顺序推进。
