# F1 归档新鲜窗口确认接入

日期：2026-10-12。基线 cf1375c9。实际开发，不改布局、不开放移动、不发版。

## 已接通

归档预检完成磁盘扫描后，启动有 5 秒期限的新一轮窗口核对，回执新增 `windowConfirmationRequestId` / `windowConfirmationError`。失败保留其余预检证据，不伪装成已确认。后端从原生窗口清单获取接收方；App 各窗口订阅请求，读取当前 session、sequence、就绪与草稿状态，通过命令回报。发送方身份取自原生 Window，不接受前端传入窗口标签。

新增 begin/reply/status 三个命令。状态查询再次核对原生窗口清单；必须每个窗口回复才 ready。窗口新建、关闭、重载、状态报告或超时使旧请求失效。事件发送失败取消本次请求。ready 仍明确带 `canExecute: false`，不是执行租约，也不消费内部执行凭证。

前端在途保存已计入 `hasUnsavedChanges`。本轮以保守的 dirty/saving 合并值阻止确认，不区分两者的用户提示。未确认的在途状态报告可能导致新鲜回复序号不匹配，拒绝并要求重新预检，不以缓存值放行。监听器按既有生命周期清理；不自动保存、丢弃、导航或聚焦窗口。
