# LongEdit 当前开发情况与后续路线审计（2026-07-24）

## 1. 审计结论

LongEdit 当前已经从 Markdown 阅读器演进为本地优先的专业知识管理工作区。产品主干已经具备 Markdown、知识图谱、OPML 思维导图、JSON Canvas、Mermaid、开放表格/图表、PDF 阅读批注与 OCR、本地索引、专业工作台，以及渐进式 XLSX 编辑能力。

本次候选交付完成到：

- 公式语义 **S8-6E**：十个函数族、37 个 verified 函数、56 个真实场景；
- 高级数据对象 **S8-7E2E**：七类 Pivot 聚合包级隔离重建，以及单轴/多度量输出语义验证；
- 场景主题 **T8-1B**：七套正式预设和四套场景主题的真实 Tauri 视觉矩阵；
- 图谱紧凑体验：窄宽度页头、工具栏、筛选区与初始详情遮挡问题完成修复。

当前候选具备继续开发和内部试用条件，但仍不能宣传为完整 Excel、完整 Office 或任意 PivotTable 等价实现。Pivot 用户文件刷新/替换、单轴和多度量完整包重写、外部数据访问、复杂图表、动态数组、PDF 原始内容重排等能力仍处于明确边界之外。

## 3. 当前已完成能力

### 3.1 知识管理与图谱

- 文件、外部授权、索引和格式入口由共享格式能力注册表驱动，用户文件始终是事实源。
- 全局/局部知识图谱支持关系筛选、健康检查、七类语义关系创建和删除，以及图谱到 Canvas 的投影。
- OPML 节点、Canvas 节点、PDF 批注和 Table/图表已经成为可寻址的跨格式知识对象。
- OPML 提供树形与思维导图双视图、层级拖拽、折叠、搜索、撤销重做、可靠往返和 Canvas 投影。
- T8-1B 修复了紧凑图谱场景的标题竖排、工具栏溢出、筛选条错位和初始详情遮挡，并形成四套场景主题、三种尺寸、共 12 张真实 Tauri 视觉证据。

当前图谱的主要差距已经不是“能否显示关系”，而是关系上下文尚未持续进入编辑器、阅读器、搜索结果和工作台决策流程；G8 应聚焦存在感、解释性与行动闭环。

### 3.2 专业格式工作面

- Markdown、JSON Canvas、Mermaid、CSV/TSV、开放 Table、OPML 和 PDF 均有独立工作面或明确适配边界。
- Table 支持网格、看板、图表和仪表盘视图，Markdown/Canvas 可引用可编辑图表配置。
- PDF 支持大文件范围读取、文本层、搜索、sidecar 批注、OCR sidecar、索引和图谱关系；不修改原 PDF 内容流。
- 主题系统由唯一注册表驱动，七套正式主题通过结构和正文 WCAG AA 对比度门禁。

### 3.3 XLSX 渐进式编辑

- S8-1～S8-5 已覆盖行列结构、Excel Table、筛选排序、命名区域、数据验证、受限条件格式、标准图表生命周期、页面布局、页眉页脚和打印选项。
- S8-6 已覆盖十个函数族、37 个函数和 56 个真实场景；标量 `XLOOKUP`、六种受限易失函数和错误分类已进入命令回归，动态数组和真实外部工作簿引用在计算前安全拒绝。
- S8-7A～S8-7D 已完成高级对象机器合同、脱敏审计、离线策略、Pivot 内存预览和写回结构就绪度审计。
- S8-7E1～S8-7E2D 已完成真实 producer fixture、四部件影响清单、Cache Definition/Records 重建、Pivot items/输出联合重建、sharedItems 增删、`location` 扩缩容、旧输出清理和样式延伸。
- S8-7E2E 让 `sum/count/average/max/min/product/countNums` 七类聚合分别生成临时 Pivot 包并完成包校验、对象语义、输出值和未触及部件保真复读。
- 合并真实来源分组的回归证明平均值、计数和乘积从原始记录独立计算，避免对中间聚合结果再次求和。

## 5. 当前明确边界与风险

### P0：数据正确性与兼容风险

- 单轴和多度量目前只完成输出语义验证，尚未重建完整 `rowFields/colFields`、数据字段伪轴、标题和总计 OOXML。
- Pivot 原子替换和用户文件写回仍禁用；没有真实 Excel/LibreOffice 往返证据前不应解除。
- 多层轴、页面字段、切片器、连接型 Pivot 和未知扩展仍必须稳定拒绝。
- 数组公式、动态数组、溢出结果、`XMATCH` 和完整 Excel 易失重算时机未覆盖。

### P1：产品闭环风险

- 图谱入口仍偏“独立页面”，编辑器、阅读器、搜索和工作台中的关系上下文不够持续。
- 思维导图与图谱虽然共享可寻址对象，但缺少清晰的双向增量同步、冲突提示和关系影响预览。
- 下一种专业格式编辑器尚未确定；SVG/Draw.io 必须先完成许可、往返保真和可编辑事实源审计。

### P2：发布与工程风险

- 大型前端分包需要按工作面继续懒加载，避免 Mermaid、PDF 和图谱依赖共同抬高首屏成本。
- 真实桌面 E2E 仍以受控脚本、命令往返和视觉证据为主，跨平台自动点击覆盖不足。
- `v0.7.0` 尚未进入 S8-8 最终等价发布审计，公开文案必须继续使用“渐进式编辑”和分维度兼容矩阵。

## 6. 后续开发顺序

2026-07-24 后续合并的统一文件管理基线已经重新校准产品主线：在阶段 A～C 完成前，Excel Pivot、高级图表对象和其他单格式深层能力只处理缺陷、数据安全和兼容边界，不继续作为唯一开发主线。S8-7E2F～S8-8 保留为 XLSX 专项收尾队列，但当前实际开发入口切换为 **A0：格式契约和能力展示升级**。

### 第一阶段：A0 格式契约和能力展示升级（P0/P1）

目标：

- 让共享格式注册表准确表达识别、预览、基础编辑、批注、安全保存、外部打开和不支持等能力等级。
- 前后端文件匹配统一改为最长扩展名优先，确保 `.table.json`、`.canvas` 与普通 `.json/.jsonc` 正确分流。
- 文件树、标签页、工作面状态栏和保存入口消费同一能力模型，避免把“能打开”误导为“能可靠编辑”。
- `planned`、`unsupported` 和高风险只读格式不得出现覆盖保存入口。

当前实现记录（2026-07-24 A0 第一批）：

- `shared/file-formats.json` 已升级为 schema v2，并为 8 个既有格式写入用户可见能力等级、保存模式和说明。
- 前端 `src/config/fileFormats.ts` 与 Rust `src-tauri/src/formats/file_registry.rs` 已共同消费 `userCapability`，并统一改为最长扩展名优先匹配，避免 `.table.json` 被普通 `.json` 抢占。
- Library 工作面状态栏、文件树提示和保存入口已开始消费同一能力模型；只读/批注类与未来不支持格式不会再获得覆盖保存入口。
- `scripts/check-format-contract.mjs` 已把 schema v2、能力等级、保存模式、最长扩展名路由和 Library 消费点纳入契约门禁。

退出条件：A0 第一批已满足“契约、路由、基础展示和保存入口阻断”的核心门禁。剩余收尾是把同一能力说明继续传播到专用工作面页签、最近文件和未来普通 `.json/.jsonc` 注册入口；这些可在 A1 前的小批次完成，或随 A1/A3 接入时补齐。

### 第二阶段：A1 可靠文本读取与保存内核（P0/P1）

目标：

- 建立可复用文本快照模型，记录路径、内容签名、编码、BOM、换行符、末尾换行、大小、只读原因和修改时间。
- 保存默认保留原编码、BOM、换行符和末尾换行；转换编码必须是显式命令。
- 写入必须携带读取签名并拒绝静默覆盖外部修改，最终字节使用可靠写入并在写后重读验证。
- NUL、损坏编码、超限文件、只读权限和大文件降级返回结构化错误。

当前实现记录（2026-07-24 A1 第一批）：

- 新增 `src-tauri/src/formats/text.rs`，建立 `TextDocumentSnapshot`，记录内容签名、编码、BOM、主换行符、末尾换行、大小、修改时间和只读原因。
- `read_text_document` 已改为读取文本快照；NUL 字节和不可可靠解码内容会拒绝进入通用文本编辑路径。
- `write_text_document` 已接收读取签名和保存策略，默认保留原编码、BOM、换行符和末尾换行，并通过 `reliable_write::write_bytes` 写入最终字节。
- 保存前会重新计算当前文件签名，外部程序改动后拒绝静默覆盖；保存成功后返回新快照，前端继续持有最新签名。
- Library 状态栏已显示文本快照的编码/BOM/换行信息，自动保存和手动保存都会传回读取签名。
- 格式契约脚本已检查 A1 文本内核、签名保存、换行/BOM 逻辑和前端快照展示消费点。

当前实现记录（2026-07-24 A1 第二批）：

- `TextReadOptions` 和 `read_text_snapshot_with_options` 已允许后端按显式编码读取文本；用户指定编码时快照置信度标记为 `user-selected`。
- 保存内核现在返回最终写入编码和规范化内容，命令写入后会使用同一编码重读并比较语义内容，失败时拒绝报告为成功。
- `write_text_document` 在覆盖写入前检查 `read_only_reason`，只读文件会在可靠写入前被阻断。
- 新增 GBK 中文 fixture，验证显式 GBK 读取、默认保留 GBK 编码和 CRLF 换行；新增 UTF-8 无 BOM 显式转换测试，验证编码、BOM、换行和末尾换行策略可被显式覆盖。
- 格式契约脚本已把显式读取选项、用户选择置信度、只读拦截和写后重读校验纳入门禁。

退出条件：A1 第二批已完成编码选择/转换的后端基础、GBK fixture、只读覆盖阻断和写后语义重读。完整 A1 仍需继续补前端编码选择/转换入口、GB18030 更广 fixture、只读/编码失败的结构化错误类型、大文件范围读取与超阈值只读降级，以及用户可见的写后验证失败处理。

当前实现记录（2026-07-24 A1 收口批第一段）：

- Library 文本工作面新增编码菜单，支持按 `UTF-8`、`UTF-8 BOM`、`GBK`、`GB18030` 重新读取，或者显式转换保存为这些安全子集。
- 前端读取调用已传入 `readOptions`，保存调用已传入 `savePolicy`；转换保存仍携带读取签名，继续由后端阻断外部冲突。
- Tab 状态新增 `textReadEncoding`，切换标签后仍能保留用户选择的读取编码；输入、自动保存和手动保存现在会维护可见的未保存状态。
- 格式契约脚本已把编码菜单、显式读取参数、显式保存策略和每标签读取编码记忆纳入门禁。

退出条件：A1 收口批第一段已完成用户可见的编码重读/转换保存入口。完整 A1 仍需继续补 GB18030 更广 fixture、结构化错误返回、大文件范围读取、超阈值只读降级和写后验证失败的更细粒度用户提示。
