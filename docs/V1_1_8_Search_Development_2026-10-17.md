## A/B1：已复现的问题与修正

1. `search_literal_segments`、`search_complex_segments` 和无索引递归扫描都在原始结果满 200 时停止，之后才排序。真实 **243 文件**夹具中，后扫描的“项目预算”文件名强命中完全丢失；磁盘索引和增量覆盖也复现。
2. 旧排序只有分数、标题和页码，同名同分文件的选择受扫描顺序影响；反转扫描顺序，在 200 条边界出现不同结果。
3. 保留原分数规则及 **最多 200 条原始匹配**的旧 API；改为检查后续候选、用最大堆只保留当前最好的 200 条匹配载荷，堆顶为最差项，候选更好时替换。不是收集全部匹配后无限排序，也不是调大上限。
4. 统一总顺序为相关性、标题、精确路径、页码、格式/匹配类别、批注/内部对象身份、位置标签、上下文和提取状态。路径不转小写，保留大小写敏感卷上的不同文件。缓存、增量和无索引使用同一排序，跨库旧合并也复用它。

原生修改前回归：**6 个功能用例全部失败，1 个基线采样通过**，见 [native-before.log](evidence/v118-search-ranking/native-before.log)。不是编译错误，也没有跳过故障。修正后原七项全部通过；又补充 20,000 候选的堆长度/容量逐次检查、局部 Top-K 与跨库合并一致性、大小写/批注/定位/上下文并列顺序，**新十项均通过（含一项基线采样）**。

相关原生搜索 **27 项**通过，完整原生功能 **909 通过 / 0 失败 / 5 既有 ignored**，性能回归独立执行、不混入此计数；包括旧 PDF/DOCX/PPTX、智能集合、隐私过滤与历史/保存测试。搜索查询、分组、路径、定位、返回和恢复 **50 项**通过，完整开发合同通过。前端最初组合执行少传 Node 的既有 `--experimental-strip-types` 参数，导致 `.ts` 模块无法载入（37 通过/1 文件失败），仅纠正执行方式后通过；原失败日志保留，没有修改产品或断言来迁就命令。

最终 `npm run ci:patch-release` 通过，包含类型/生产构建、发布事实/当前开发合同、Rust locked check 与生产依赖 **0 漏洞**。独立工作簿性能回归 1 项通过（本机 total **4374ms**），不据此宣称搜索或 UI 性能改善。未运行新安装器或将 1.1.7 的安装证据当作本版通过。

## 本批明确没有完成的部分（1.1.8 发版阻断）

- 旧命令仍以原始匹配计数，最多 200，尚无用户文件分组分页或第 201 个普通文件的续载。每类最多五个定位匹配的旧规则仍在，不宣称组内全部命中已返回。
- 堆只约束**保留的结果载荷**，不代表索引、去重表、扫描元数据或总内存都只有 200 条。为正确排序会检查更多候选，冷扫描 I/O 和大库时延必须继续治理；不能把修正直接称作性能提升。
- 尚须补单次扫描/读取预算、可验证的查询/快照身份、续载与过期处理、排序和修改时间、索引新鲜度及部分扫描反馈，防止大库无界重读正文或把未完成当成查全。
- 跨库仍串行；需有界并发、失效/离线/权限失败与全失败区分、窗口/查询所有者隔离和取消治理。
- 正式 UI 尚未改动；随后先示意，再接续载/排序/完整性反馈并实际验证。当前原生函数测试不是安装态、真实 IPC 或 UI 验收。
