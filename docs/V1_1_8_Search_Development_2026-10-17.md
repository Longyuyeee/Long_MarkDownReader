### 实际修正

1. 新增查询级 `SearchBudget`：默认每次最多 **20,000 次目录迭代步骤（含结束探测）/10,000 个来源元数据/64MiB 来源读取预留/100,000 个索引段/64MiB 索引正文处理**，协作时间预算 **2 秒**，目录栈最多 **64 层**。计数发生在继续枚举、取出来源、打开正文或处理索引段之前，不等于把结果上限调大。
2. 新增 `SourceScan`，以受限目录栈替代搜索内的递归和整库并行来源收集。暂停时保留目录迭代器及尚未交付的来源，下次预算继续同一位置，不从根目录重来、不跳过预算边界上的文件。隐藏/敏感路径、资源目录、符号链接及未注册格式仍排除；PDF 伴随元数据仍进入索引新鲜度比较。
3. 磁盘索引新鲜度检查也改用受限来源收集，不先调用无界的 `read_ready_snapshot/collect_index_sources`。后者读取就绪快照的旧辅助函数现仅供原生缓存一致性回归使用；建库的既有来源收集不在本批重构范围。
4. 冷复杂条件查询逐文件建段并匹配，不再把全部文件正文段集中到一个新向量中；同一文件内的多词、跨段和整文件排除规则保持。最终仍用上批的共享 Top-K 排序，不能提前拿前 200 个文件当全部候选。
5. 内存缓存和增量覆盖也使用索引段/正文/时间预算。增量只允许既有单文件快路径；删除、非快路径格式及关系变化回到受限扫描，不因旧路径不存在直接阻止剩余文件搜索。已核对旧增量函数会先读一次正文做关系安全检查、再由建段器读一次，因此预留两次读取，并在调用前检查单文件大小。
6. 冷扫描在读取前检查资料库范围和文件类型；PDF 主文件、批注、OCR 共用来源读取预算。共用一次资料库路径守卫，避免对每份文件重新解析根目录；目录读取失败或预算结束不再通过目录迭代器 `flatten()` 伪装成成功空结果。格式解析器原有的失败/提取状态语义未在本批全部重做，不宣称任何损坏文件都已逐项反馈。
7. 旧单库数组返回形状无法表达“部分查完”，因此本批返回明确的“搜索尚未完成”错误；跨库沿用现有每库警告通道。不能让不完整 Top-K 冒充已查全，也没有静默抛弃后面的强命中。正式分页合同接入后再提供保留结果和继续查看，而不是以当前保护性错误作为最终体验。

### 明确边界及下一步

- **这是协作预算，不是硬实时截止**：阻塞文件系统调用、单文件格式解码、缓存 JSON 反序列化不能中途强杀；各自原有单文件/缓存/解压大小保护仍生效。来源读取计数是根据读取前元数据做的保守预留（PDF 缓存命中也预留），不是系统实际物理 I/O 字节仪表；极端并发修改文件的大小竞态不在本批声称解决的范围。
- 索引正文预算不包括索引对象/元数据、去重结构、关系摘要及磁盘快照自身的既有内存上限；不声称整个进程只用 64MiB。普通冷格式仍受其现有读取与解析边界，不能把某一段数上限说成覆盖一切解析开销。
- 当前预算单位是**一个资料库的一次交互式关键词任务**，不是整个跨库操作的总时限；旧跨库仍逐库执行。智能集合的内部匹配器、后台建库、全局并发/取消不在本批声称已全面受此预算控制的范围，后续 C 和集合版本继续接续。
- **只完成元数据遍历的底层暂停能力**，尚未把它保存为窗口所有的用户搜索会话；没有文件分组页、可点击第 201 个文件、查询/排序/快照绑定的游标、过期拒绝或取消。目录在暂停期间变化也未当作稳定快照承诺。
- 保护性限制可能使大库旧入口报“尚未完成”。因此仍只推开发分支，**不合 main、不发布**；下一批 B2b 必须用可续接会话与文件分组页接住此状态，而不是为了通过质量门放宽/删除预算。
- B2b 后依次做 C 有界跨库与任务隔离、D 原入口内的正式分页/排序/完整性反馈。D 仍须先出示意并取得确认，再修改与实看页面；默认主区打开、显式参考、草稿保护和六风格保留。

## 本批明确没有完成的部分（1.1.8 发版阻断）

- 旧命令仍以原始匹配计数，最多 200，尚无用户文件分组分页或第 201 个普通文件的续载。每类最多五个定位匹配的旧规则仍在，不宣称组内全部命中已返回。
- 堆只约束**保留的结果载荷**，不代表索引、去重表、扫描元数据或总内存都只有 200 条。为正确排序会检查更多候选，冷扫描 I/O 和大库时延必须继续治理；不能把修正直接称作性能提升。
- 尚须补单次扫描/读取预算、可验证的查询/快照身份、续载与过期处理、排序和修改时间、索引新鲜度及部分扫描反馈，防止大库无界重读正文或把未完成当成查全。
- 跨库仍串行；需有界并发、失效/离线/权限失败与全失败区分、窗口/查询所有者隔离和取消治理。
- 正式 UI 尚未改动；随后先示意，再接续载/排序/完整性反馈并实际验证。当前原生函数测试不是安装态、真实 IPC 或 UI 验收。
