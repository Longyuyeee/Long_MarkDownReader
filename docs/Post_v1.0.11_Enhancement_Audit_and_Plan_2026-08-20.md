# v1.0.11 之后的增强审计与执行计划

审计日期：2026-08-20

## 1. 当前阶段

最领先代码在 `main`。v1.0.11 的发布、远端附件和 `1.0.10 -> 1.0.11` 官方应用内更新链已完全收口；当前进入不绑定新版本号的独立增强迭代。

本轮已完成三项：P2-A 修正 PDF 实现与格式能力声明漂移；P2-B 为图片基础编辑增加亮度、对比度和饱和度，并完成真实文件、真实桌面和独立像素验证；P2-C 为图片查看增加光标锚定滚轮缩放、双轴拖拽平移和双击 100%/适应窗口切换，并完成真实鼠标输入和宽窄窗口验证。

## 2. 与原始需求对齐

- 多格式资料库、左侧管理与右侧编辑、显式保存、撤销/返回、横向滚轮、主题与专业工作区仍保持已收口状态。
- PDF、DOCX、PPTX、XLSX、图片等复杂格式继续使用有界编辑或可靠副本，不能宣传为完全等价专业编辑器。
- 当前 43 类格式能力分层不变；新增功能必须同步注册表、发布矩阵、用户界面和测试证据。

## 3. 后续开发顺序

1. **P2-D 全格式能力事实巡检：** 把本轮发现的“实现前进、能力页滞后”扩展为 43 格式的证据引用检查，优先检查 Office、表格和图形格式。
2. **P3 外部生产者证据：** 在确有 Excel/WPS/LibreOffice 环境时补动态数组、透视表和 Office 三生产者复开；没有环境时保持阻断，不用合成文件冒充。
3. **P4 真实资料库观察：** 仅在用户明确同意的资料库上评估知识图谱推荐与孤立对象提示是否易懂，证据必须脱敏。
4. **下一版本发布：** P2-A 至 P2-C 已形成一组可独立说明、可重复验证的 PDF 声明纠偏与图片体验增强包；完成当前开发提交和综合门禁后审计是否进入 `1.0.12` 候选，不因单项测试通过而跳过安装与更新生命周期。

## 4. 每步验收规则

每项功能先写可观察预期，再记录修正前实际差异；实现后至少验证真实输入输出、失败边界和源文件安全。涉及 UI 的项目必须跑真实 Tauri 宽窄屏并人工查看截图；涉及 Office/PDF/图片结构的项目还要用独立解析器复核。每个可独立收口阶段单独更新文档、提交并推送。
