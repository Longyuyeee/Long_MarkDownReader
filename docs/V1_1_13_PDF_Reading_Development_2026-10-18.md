# v1.1.13 PDF 阅读笔记开发审计

当前目标 1.1.13，公开与运行时仍为 1.1.12。已有 PDF 阅读、搜索、表单、OCR、脱敏、水印、属性和页面整理全部保留。本版深化“批注整理—笔记—准确返回来源”，不再新增阅读器，也不改变原 PDF。

## 已复现的问题

基线为 main `7bb913ea9d066d8051edce27d164a561fb034bd6`。实际 PdfView、PDF.js 和 Pinia 配合明确标注的模拟 IPC，分别操作未保存草稿、生成中继续输入、磁盘外部改写、活动目标改变四种场景。四次均观察到 `write_markdown_file`：插入代替用户保存正文，外部改写会被旧草稿覆盖；继续输入场景没有复现丢字，不能把风险猜测写成已发生。正常 PDF 标签激活还会隐藏旧的“插入到当前 Markdown”入口，基线测试明确切回活动 Markdown 状态才检查这条旧路径。

[原始结果与截图](evidence/v1113-baseline/results.json)保留该问题，属于组件行为证据，不冒充原生磁盘验证。最初复现脚本的等待条件曾把“目标切走后的空白组件”当作必须可见，已改成等待路由组件挂载，写盘次数断言未减。该脚本仅针对旧基线，不作为修复后测试反复执行。

## 首批实现

- 原批注面板增加页码、颜色、类型、摘录/评论筛选；每组显示 50 条，保留原有单条选中、评论、颜色、复制和删除。全选明确针对筛选结果，隐藏选择计数可见；超过 200 条要求先缩小范围，不静默截断。
- 整理后按需预览，按页码/颜色组织，可选择包含评论，保留实际原页、完整摘录/评论和相对来源链接。每次上限 200 条，原生所选文本超过 4 MiB 则分批，笔记保存上限 8 MiB。
- 插入已有 Markdown 只追加当前最新草稿，保留原保存身份和 dirty 状态，不写盘。目标关闭、知识库/文件切换、异步晚回复、来源失败时不错误插入；未加载目标先受控读取并保留保存身份。新笔记由用户选择库内新名称并显式保存，原生禁止覆盖已有文件。
- 新引用携带原生流式 SHA-256。打开时核对内容，不把同名替换后的文件当作原来源；移动后可显式验证新相对路径、只重关联草稿。旧链接兼容但提示缺少摘要，批注已删除或页码失效给出提示。
- 原生生成使用库边界、主窗口限制、PDF/sidecar 双重核对、批注 ID 精确白名单；JSON 损坏、越界、重复选择和读中变化拒绝。未修改原 PDF 或未选记录。

实施前已展示并实看[面板示意](evidence/v1113-proposal/annotations.png)和[预览示意](evidence/v1113-proposal/note-preview.png)。正式[组件结果](evidence/v1113-formal-ui/results.json)覆盖 11 个场景、六风格深浅及 760×620、480×800、360×620。独立样例最初缺少正式应用的定高父容器，截图暴露整体滚动；已补齐与应用相符的容器后重跑。这是测试环境修正，不宣称修复产品中不存在的容器问题。

## 当前验证和剩余封板门禁

原生专项 6 项通过；前端纯逻辑 4 项通过；正式 Vue/PDF.js 组件 11 场景通过，IPC 为模拟，不算安装态磁盘证明。完整质量门禁与原生回归继续执行，既有 `scan_visible` dead-code 警告保留。

接下来审计细节与长文档响应，固定 1.1.13 产品源码并构建安装包，在一次性 Windows 环境中完成“批注→草稿→显式保存→点击来源→正确原页原批注”、失效/移动/恢复、原文件摘要不变、真实原生选择器与历版功能同包验证；再独立复核同一安装器。通过后才封板、原包发布、公开回下载，更新 README 下载身份和末尾摘要、Release 与交接。不能用单测/模拟 IPC 取代这些门禁。

内容摘要校验需要读取整个 PDF，2 GiB 仍是原阅读器上限，不宣称超大文档零等待；不自动扫描整个资料库猜测同名来源，不自动迁移、代存或覆盖草稿。OCR 本版沿用既有离线能力，不宣称识别质量有新的提升。尚未公开发布 1.1.13。
