日期：2026-10-21（Asia/Hong_Kong）。审计基线：`eb13b3fcd22f6439bbc08e8aced48f4379f907ae`，已拉取 main，与远端一致。

## 结论

最近 20 个正式版本为 **1.1.10—1.1.29**，已交付内容有实质增量：文件整理、持续编辑、阅读成果、保存与恢复逐步形成完整工作流程。后续继续深化已有功能的方向正确，不需要为了发版重新做 UI、增加格式或另起一套工作台。

现有十二版路线已完成 9/12，**1.1.30 → 1.1.31 → 1.1.32 的顺序保留**。范围应进一步具体化：Table 补真实录入规则；XLSX 补不同写入入口的校验一致性与筛选范围；内容恢复衔接现有工作现场。已存在的列表下拉、规则编辑、现场导入等不再计作新功能。

发现一处应优先小修的前端行为差异：XLSX 列表校验会阻止单格输入相同非法值，批量粘贴却未执行相同规则。另有命令入口覆盖、自动更新观察、交接指向和版本维护成本等问题。没有足够依据把这些扩大为整个软件不可用或源文件已损坏。

## 核对方法与发布事实

- GitHub 当前公开、非预发行的最近 20 条记录均有 NSIS、MSI 和 SHA256SUMS，共 **60 个公开附件**。API 提供的大小与 SHA-256 均与仓库固定清单一致，标签解引用后的源码一致，发布说明与归档正文一致。带注释标签和轻量标签分别处理。
- 对 20 份安装运行清单调用现有验证器，复核来源、包身份、原始报告及相应数据输出；按导入清单重新计算 **4054 份归档输出**的字节数/摘要，20/20 通过。4054 是按版本累计的文件份数，包含各版保留的历代输出，不是 4054 个独立功能或新测试。
- 实际安装功能任务累计从 122 增至 336；不能把任务数量当作用户功能数量或无缺陷证明。当前仍找到了校验入口差异。

- 本次复核已有资料并审读实际代码，没有重装 20 个版本、重新下载全部安装包或重跑完整构建。公开附件比较的是 GitHub 当前摘要元数据与原有清单；不是本次重新下载 60 个二进制。工作簿问题另用实际前端函数隔离复现，未读写真实 XLSX，未操作日常应用。

## 当前问题与优先级

### F1：XLSX 校验在单格与批量输入之间不一致（优先小修）

证据：[单格提交](../src/views/WorkbookView.vue#L2526) 读取 `validationAt` 并对显式列表阻止非法值；[批量输入](../src/views/WorkbookView.vue#L3555) 检查坐标、已加载范围、只读区域及数据类型，却没有调用相同的数据校验。实际函数的隔离执行结果：规则允许“是、否”时，“不在列表”在单格输入被拒绝，批量路径则进入模拟草稿。

[诊断原始结果](evidence/recent-20-versions-audit-2026-10-21/workbook-input-diagnostic.json)。这是前端入口差异的复现，不是原生安装态或文件损坏证明。[规则表单](../src/components/WorkbookValidationForm.vue#L16) 的提示也没有充分区分哪些规则仅被保存、哪些会在当前编辑器执行。

处理建议：开下一版时先把这一差异作为小修处理，不必等待整个 1.1.31。共享一次输入核对，覆盖手输、下拉、粘贴和填充；不能执行的公式规则诚实提示，不假称通过。取消和整批失败保留现有草稿，不靠每格弹窗解决。

### F2：新增能力可发现性落后于菜单能力（与功能一起改善）

[命令列表](../src/components/CommandPalette.vue#L209) 仍主要是打开文件、专注、导出、保存、刷新、主题和今日笔记，近期附件管理、来源核对、阅读笔记更新等尚未进入该列表。低频功能放到右键是正确的，但用户不知道功能存在时，命令搜索应该能提供入口。

处理建议：复用现有命令窗口，在当前文档支持时呈现相关动作或可理解的不可用原因；菜单保持具名、按上下文安排。不要新增介绍卡片或常驻功能区，也不要把全部命令常驻到页面上。

### F3：自动更新的实际升级观察持续待补（单独补当前路径）

[发布策略](../shared/v1-community-release-policy.json) 中 1.1.9→1.1.10 至 1.1.28→1.1.29 的真实应用内更新观察仍标为 pending。现有证据支持下载安装和相应安装生命周期，**没有证据据此认定自动更新失败，也不能当作自动更新已通过**。

处理建议：补最近一条有代表性的真实升级路径，核对用户草稿、下载失败重试与重开结果；发现问题就修当前流程。不要为了补账重演全部 20 条历史路径，不单开庞大验收项目。

### F4：交接信息存在过期指向（文档收口时校正）

[开发版本配置](../shared/development-version-policy.json#L17) 的 activeSlice 已是 1.1.29，但 document 仍指向 1.1.28 发布审计。原十二版路线尾部仍写“下一次从 1.1.21 接续”，与当前 9/12 状态矛盾；本次文档复核已修正路线尾部并添加本报告入口。activeSlice 指向仍列为待校正，没有在审计中修改产品配置。

建议后续当前状态只维护一处清楚的摘要，交接保留到历史区；减少多个“最新”段落叠加。文档错误不等于用户功能故障，但会导致下一轮重复开发。

### F5：功能与版本维护都开始集中到少数大文件（随功能小幅拆分）

LibraryMode 6144 行、WorkbookView 5479 行、PdfView 3084 行。最近二十版在 src / src-tauri/src 修改 135 个文件，而 scripts / shared / 工作流修改 402 个文件；数字描述改动范围，不能直接换算成本或缺陷率。[运行证据校验器](../scripts/lib/installed-release-runtime.mjs#L32) 仍有逐版叠加的版本数组与分支。

建议只在受影响流程中提取共用的编辑上下文、校验和操作描述，逐步让版本信息驱动现有发布流程。保留历史校验，减少每版机械修改；不为了重构暂停功能，也不另开平台化大工程。性能继续每版解决实际瓶颈，保留正常动效。

## 后续三版：审计后的具体开发范围

### 1.1.30：Table 录入与纠错——优先按原顺序推进

用户任务：“我持续填写项目表格，能看懂哪里填错，并只修正这些记录。”

已有：稳定行列身份、推断类型、行编辑、筛选、四视图、可见行粘贴、数据撤销和导出。代码：[TableDocument](../src/views/TableView.vue#L247)、[推断类型](../src/views/TableView.vue#L363)、[原生文档模型](../src-tauri/src/commands/table.rs#L30)。**推断成日期/数字不等于已设置合法性约束**，目前模型没有独立的录入规则。

建议首批只做：必填、文本长度、固定选项、常量数值范围与真实合法日期。列头右键打开“录入规则…”，错误位置按稳定行列 ID 定位；单元格显示简短原因，具名菜单按需打开异常清单，并回到已有行编辑弹窗。批量修正先看原值/新值及影响范围，一次应用/撤销，不静默更改隐藏行、前导零、长编号或空值。

必须先明确规则保存位置：原生 Table 可以携带版本化规则；CSV/TSV 本身不能携带规则。对后者应说明当前检查范围，需要长期规则时沿用已有“创建 Table 副本”能力，不静默改写 CSV 或暗中制造一套额外配置。原 CSV/TSV 编码、BOM、换行及值继续保留。

本版不做任意公式规则、跨表约束或完整电子表格引擎。同步处理 F1 的小修，并按需把新动作接入已有命令入口。

### 1.1.31：XLSX 连续录入——收窄为校验一致性与准确范围

用户任务：“手输、下拉或粘贴都遵守同一条规则，只修改我选中的记录。”

已有：[字面量列表下拉](../src/views/WorkbookView.vue#L1515)、[规则编辑表单](../src/components/WorkbookValidationForm.vue#L1)、规则复制/删除、剪贴板元数据、公式平移及整批撤销。原路线中“将已有校验规则接到实际选择”有部分已经实现，不再重做。

真实增量：统一可执行规则的输入行为，先覆盖字面量列表、常量整数/小数范围及文本长度；区域来源和公式只有能准确计算时接入，否则明确保留。一次批量预览显示不合规位置、原因及实际范围，不能静默跳过若干单元格。数据面板的筛选结果、视口虚拟行和真实工作表坐标必须区分，不能把 `visibleRows` 当作筛选后的目标行。

保留规则、公式、未触及对象和其他工作表；选中、输入、保存及其他草稿继续接续。取消、一次撤销和保存重开以本版用户任务核对，不用复制一套剪贴板实现，不扩为完整 Excel 计算器。

### 1.1.32：恢复后继续工作——连接已有两个流程

用户任务：“资料恢复到新目录后，能接着打开原来的文件和视图，不逐个重新找。”

已有：内容恢复到新目录后可添加资料库；工作现场能导入/导出、保留可用文件、逐文件重新定位，并保护当前脏标签。[内容恢复完成动作](../src/components/ContentBackupDialog.vue#L43)、[现场重新定位](../src/components/WorkSessionTransferDialog.vue#L60)、[草稿保留计划](../src/services/workSessionTransfer.ts#L39)。

真实增量：恢复完成后按需“接续工作现场…”，复用已经保存的现场或用户选定的现场文件，沿用新库根；先预览命中项，缺失目录一次映射多个子项，保留逐文件修正。只有明确选择继续才切库或打开，旧工作区未保存内容不被替换。

原内容包不含正文草稿，也不保证带现场记录；没有现场时完成内容恢复即可。是否在未来内容包增加可选现场区段，需要兼容决策，不作为首批必须重做备份格式的理由。保留旧包和既有单独现场文件。

## 后续候选与每版收口

1. 三版完成后，优先考虑“带阅读成果复制项目资料”：现有跨库复制明确不携带 PDF 批注、关系和历史，章节链接仍是本机路径。应先定义用户选了什么、会带走什么，沿既有复制预览与来源映射补足依赖，避免仅复制可见文件后成果断开。暂不新增版本号或另一条平行路线。
2. 每版同时提升一两个现有功能的可发现性，复用右键、具名菜单、命令窗口；不靠页面增加大量说明、按钮和面板。
3. 验证围绕实际变化和必要回归，复用原包与现有工具；发布前保留必要安装检查和真实失败记录，避免同一固定产品在多个阶段重复无关的全量工作。指标用于发现缺口，不作为产品目标。
4. 数据丢失、保存失败和错误遮挡继续即时优先；性能针对输入、切换、滚动的真实瓶颈逐版处理。没有新的实测，不把当前软件概括为普遍卡顿，也不以关闭全部动效作为默认优化。
