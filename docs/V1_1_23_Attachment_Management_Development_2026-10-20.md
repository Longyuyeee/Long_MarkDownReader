# 1.1.23 附件管理：开发与发布接续

当前开发目标：`1.1.23`；当前运行时版本：`1.1.23`；当前公开版本：`1.1.22`。当前阶段：**v1.1.23 附件管理候选**。

已实现：普通 `images`、`assets`、`img`、`public`、`static`、`*.assets` 及本软件插图使用的 `.assets` 目录可达，真正内部目录与排序文件仍隐藏。文件树、搜索源枚举、搜索失效判断、集合、工作台及移动引用检查采用同一规则，不只修改文件树的外观。

文件右键“更多操作 → 管理附件…”及文档操作菜单打开按需弹窗：显示当前 Markdown 草稿的本地引用、可用情况、路径、行号，支持查找、打开、查看位置及更换引用。任意文件可查找引用它的已保存 Markdown 笔记；结果不表示整库、全部格式或其他窗口草稿已经完整扫描，也不作为删除许可。

更换引用复用既有 Markdown 源码范围与 URL 解析，保留标题、片段、引用式语法和其他正文。库内文件直接关联；系统选择的库外文件保留原件，经已有防覆盖导入复制到当前笔记 `.assets` 中。只将新引用应用到当前草稿，可撤销，仍需保存；没有覆盖或删除共享附件的操作。取消后已复制附件保留并可从文件栏查到。

弹窗结果绑定资料库、文件、编辑器实例、读取代次和当前正文；切换文档、继续输入、保存中、重载中或整理文件时，保留当前草稿并拒绝迟到替换。读取或预览失败局限于弹窗，可关闭继续工作。移动与还原沿用已有事务及 1.1.22 整理记录，不另写一套文件操作。

开发观测：首批 4 项原生针对检查通过（尚未固定最终源码）；新增目录可见、索引及失效判断的联合检查待最终执行。8 项实际组件检查通过，明确 `nativeBridgeMocked=true`，覆盖取消、新输入保护、局部错误及六风格明暗宽窄窗口，不能替代原生安装证明。早期搜索框标签与重复名称的组件失败保留，已修正。

本机首次原生编译因 E 盘无剩余空间失败，原始日志保留；使用 Cargo 的包级清理回收可再生成的 tauri-app 调试产物（约 147 GiB），未删除源码、证据、用户未跟踪文件或资料库。后续本轮原生检查关闭增量缓存。TypeScript 首轮发现声明顺序及空值收窄问题，修正后通过。
