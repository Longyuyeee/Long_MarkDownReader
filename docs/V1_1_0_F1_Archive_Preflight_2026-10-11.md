# F1 归档结构预检：第一步实现

日期：2026-10-11。基线：`bff56090`。本次为后端只读预检，不是归档功能闭环；不发版，不改变现有 UI 或拖动行为。

## 对齐需求与审计

沿用已确认的 UI-F1-02 / UI-F1-03：显式移动、同名不覆盖、未保存正文不自动代存、错误逐项解释。实际阅读 `files.rs`、`history.rs`、`workspace_guard.rs` 和标签状态代码后，确认不能直接用现有 `move_items` 包装归档：该命令首错退出，先前文件可能已移动；历史迁移错误被忽略。历史目录使用路径字符串的 MD5，而保存历史先规范化路径，因此后续迁移还须统一路径身份，不能直接散用显示路径。

## 本步实现

新增 Tauri 命令 `preflight_archive(libraryRoot, targetDir, items)`。每项必须提供 `sourcePath`、`targetName`、`hasUnsavedChanges`；后者不能省略后默认为“没有草稿”。这是调用者报告的状态，不冒充后端已读取所有窗口草稿。

- 只检查已有库内目录和普通文件，不创建目录、不移动或保存正文。
- 逐项报告源失效/越界、目录/符号链接、非法文件名、同名目标、重复来源、重复目标、原地移动、扩展名变更和未保存状态。
- 一项错误不阻止报告其余项；重复冲突标记全部相关项，而非只标记后一个。
- Windows 目标名称进行不区分大小写的保守比较；目标检查包含悬空链接，不能把链接误判为可覆盖的空位。
- 根目录/目标目录无效、空批次或超过 500 项为整体错误。上限是本次接口保护，不是资料库文件数量限制。

结果包含 `items[{sourcePath,targetPath,issues[{code,message}]}]`、`structuralChecksPassed`、`canExecute` 和 `pendingChecks`。**当前 `canExecute` 始终为 false**；路径检查通过不代表依赖、历史、权限或并发安全已经通过。不允许界面据此调用旧移动命令执行归档。

## 验证范围

使用独立临时目录验证，不操作真实资料库。自动测试覆盖只读性及源/目标正文保留、多项问题、重复项、非法名称、扩展名、库边界、批次限制、必填草稿状态、原地移动、预检后新增冲突、Windows 大小写和序列化字段合同。运行命令：

```text
cargo test --locked --manifest-path src-tauri/Cargo.toml commands::archive::tests -- --nocapture
git diff --check
```

本步没有 UI 改动，没有新增页面截图，也不把单元测试写成实际界面验收。符号链接/不可读目录的操作系统故障注入、跨窗口草稿核对及命令的 WebView 调用仍须后续验证。

最终结果：归档模块 **9 passed / 0 failed**；既有 WorkspaceGuard 回归 **4 passed / 0 failed**；`git diff --check` 通过。既有符号链接测试在创建链接失败时会跳过断言，因此其通过不单独作为本轮符号链接故障注入证据。最终测试使用新增两项用例后的源码，不沿用首轮 7 项结果。
