## 1. 用户任务与现有能力

目标：“我想找到那份资料，知道结果是不是全的；改词、切范围和继续查看时不要乱。”

保留已有关键词/短语/排除词、文件分组、多位置命中、默认主区打开、显式参考、搜索定位与返回、跨库草稿保护。已有前端请求代次保护，不能重新立项成从零实现。

## 2. 实际调用链及缺口

| 位置 | 当前代码事实 | 对后续实现的影响 |
| --- | --- | --- |
| `src/views/LibraryMode.vue::scheduleKnowledgeSearch` | 常规查询调用 `search_knowledge`，得到结果数组；单标签查询走 `search_by_tag`；已有 300ms 防抖与库/请求代次判断 | 不能只改命令面板；普通搜索和标签快捷路径要明确各自范围与完整性语义 |
| `src/components/CommandPalette.vue::scheduleSearch` | 调用 `search_knowledge_libraries`，接收 `results/warnings/limitReached`；200ms 防抖，按路径去重为文件列表 | 其条目单位是文件，不是裸命中；分页不能把同一文件多个位置算成多个可见文件，也不能跨页不断重复同一文件 |
| `src-tauri/src/commands/index.rs` | `MAX_SEARCH_RESULTS=200`；`search_literal_segments` 扫描达到上限就提前退出，再按分数、标题、页码排序并截取 | 只对最后数组加游标仍看不到未扫描部分；扫描顺序可能先排除后面的强命中，需要先复现并修正收集/排序边界 |
| `index.rs::search_knowledge_libraries` | 配置范围先去重，资料库逐个 await；合并各库已限额结果后再全局排序/截断 | 续载及全局排序必须跨库一致；单库先截断可能影响全局结果，慢库也影响总体延迟；保留原警告与全失败报错 |
| `KnowledgeSearchResult` | 有路径、分数、类型、命中类别和 locator，没有修改时间字段 | 修改时间排序不能仅改前端比较器，须明确元数据来源、缺失值和成本 |
| `src/utils/searchResultGroups.ts` | 按精确路径分组，`searchMatchKey` 保留页/批注/对象及上下文身份 | 不把合法多个位置删掉，也不能把不同文件或路径别名处理错误；排序需要确定的最后身份键 |
| `services/knowledge_index.rs` | 已有缓存快照、`Arc`、source digest、builtAt、changed paths 与增量覆盖路径 | 不重做索引；游标/查询现场要绑定实际可验证的快照身份，并处理监视器变化，不能只绑定建库时间 |

这些是源码观察与风险推断，不是新故障已经完成真实磁盘复现的声明。尤其要先验证超过 200 条时的强命中排序及多位置去重问题，再确定最小修正。

## 3. 建议实施批次

### A：先确定可分页的结果与完整性合同

1. 生成授权范围内的固定大库，至少包含超过 200 个匹配文件、同名不同目录、同文件多位置、晚扫描但高分命中、中文及特殊路径。
2. 记录现有首屏、扫描/取消成本及结果缺口；分别验证缓存、增量覆盖和回退扫描路径，不只改其中一条。
3. 明确分页单位：面向用户的文件组与组内合法匹配位置；给同分、同名、多库等情况确定稳定总顺序。
4. 定义页大小、还有结果、实际扫描未完成、警告、索引状态及续载身份；数量未知就明确未知，不伪造精确总数。

### B：单库正确收集、排序和续载

1. 先修正“提前截取后再排序”的边界，再实现稳定续载；不能无限提高结果上限，不能每点一页都无界重新读取全部正文。
2. 续载身份绑定查询、排序、范围和快照；切词、切排序、切库、索引/源文件变化时，拒绝或明确重建过期查询，不静默混页。
3. 保留安全回退及部分扫描说明；时间/内存/结果预算按基线确定，触及预算不能谎称已经查全。
4. 修改时间使用已核实的元数据；统一缺失值、并列顺序，避免为排序反复打开所有正文。

### C：有界跨库与过期任务治理

1. 将逐库串行改为有界并发，固定并发/内存预算后测量，不无限启动任务。
2. 保留每库失败和不完整状态；部分成功可继续操作，全失败仍是错误，不是“无结果”。
3. 复用前端已有代次保护。若增加原生取消，需协作式停止阻塞工作，并区分窗口/查询所有者，不能让一个窗口取消另一个窗口任务。
4. 与单库共用稳定排序和续载语义，保留命令面板文件条目及资料库组内多位置的不同展示意图。

### D：沿原搜索界面接入并验证

1. 在正式 UI 修改前展示现有布局上的续载、排序及完整性反馈示意；保留紧凑布局，不新增常驻搜索管理页。
2. 两个原入口均接入；搜索默认主区打开、参考显式选择和跨库草稿保护不改。
3. 翻页失败保留已加载结果并允许重试；切词后的旧响应不追加，Esc/关闭/返回焦点和阅读位置继续有效。
4. 实看宽窄窗口、六风格及正常动效，用真实点击/键盘走完“搜索→继续查看→打开→返回”，再做固定安装器验证。

## 4. 必须有的回归场景

- 第 201 个及后续目标可达；晚扫描的高分命中不会被首批截断永远排除。
- 同分同名、多库和多个合法位置下，续载无重复文件、无漏项，组内位置仍可访问。
- 连续输入、切库/排序、翻页中的索引变化、改名/删除，不允许旧结果覆盖或混入新查询。
- 一库慢/离线/失效时，有界执行、其他库结果可用，明确不完整；全失败不返回成功空列表。
- 当前草稿、已有参考和搜索返回现场保持；不为打开搜索结果自动代存。
- 使用固定数据记录首屏、续载、取消和资源开销。未测指标不写成性能提升成果。
