# v1.0.15 后续 M3-0 知识图谱真实基线审计（2026-08-27）

## 1. 结论

M3-0 已完成。审计使用真实 Tauri/WebView2、真实临时 Markdown 文件和 100/1000/5000 节点固定有向链，不修改用户资料，也不先修改图谱产品代码。

现有图谱在三档规模下都能构建、选择中心节点、缩放并返回资料库，1000 节点连续进入退出 20 次仍可导航且运行时错误为 0；但 1000 节点已出现明显主线程长任务，5000 节点首次可见和布局稳定时间不可接受，画面标签严重重叠。现状证明 M3 的语义与性能工作均有真实必要性，不能把 M0 后端构图通过解释为大图 UI 已完成。

## 2. 原始需求对齐

- 用户文件继续是事实源；图谱负责发现，Canvas 负责表达和整理。
- 图谱是体系化管理增强能力，不成为打开、编辑和保存基础文件的前置条件。
- `FR-GRAPH-004` 的关系方向、类型、上下文和证据仍为本阶段最直接的未完整闭环需求。
- M3 路线要求先建立语义、算法和性能基线，再进入视觉系统；本审计没有先增加光效、社区轮廓或动画。
- 运行时与公开版本保持 `1.0.15`，开发目标保持 `1.0.16`，`releaseCandidate=false`。

## 3. 修正前真实结果

| 节点/边 | 首次可见 | 布局稳定 | 长任务 | 最长任务 | 结果 |
| --- | ---: | ---: | ---: | ---: | --- |
| 100 / 99 | 231 ms | 2,931 ms | 2 | 73 ms | 可操作，中心选择、缩放和返回通过 |
| 1,000 / 999 | 638 ms | 11,654 ms | 84 | 491 ms | 可操作但稳定慢；20 次进入退出通过 |
| 5,000 / 4,999 | 19,378 ms | 115,802 ms | 91 | 9,334 ms | 最终可返回，但首次等待、布局和可读性不合格 |

三档均满足：源文件目录 SHA-256 前后逐字节一致、中心节点选择成功、滚轮缩放成功、返回资料库成功、运行时错误为 0。

视觉复核确认：1000 和 5000 节点下所有标签同时绘制，产生密集覆盖；5000 节点虽然没有空白或彻底失去返回能力，但不构成可用的全局阅读体验。当前也没有用户可见的对象/关系统一图例、最短路径流程或社区流程。

## 4. 差异与选择

当前最先需要解决的不是社区动画或背景视觉，而是稳定、统一、可验证的对象/关系语义：

1. `GraphView` 与 `LocalGraph` 分别维护关系中文名称，节点颜色又在画布绘制逻辑中硬编码，存在漂移风险。
2. 后端当前生成 11 类对象以及引用、包含、依赖、嵌入、批注、派生等关系，但用户无法在一个稳定图例中理解这些编码。
3. 最短路径、社区发现和语义缩放都依赖同一类型身份；若先做视觉，后续会重复迁移颜色、形状和方向合同。

因此下一阶段固定为 **M3A-1：稳定对象/关系语义注册表 + 用户可见图例**。首个实现必须提供未知类型安全降级、固定排序、前端统一消费和独立合同检查；不得把它扩张成社区发现或大图性能收口。
