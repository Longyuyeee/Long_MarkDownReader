# 移动端：重命名一个 JSON 字段

2026-10-27。阶段 3C2，起点 `81dafb889`，在独立移动分支 `codex/mobile-0.1.0-foundation` 推进。本轮沿用[每次一个用户任务](Development_User_Task_Plan_2026-09-22.md)与[移动端交互重设计](design/mobile-interaction-v2/interaction-spec.md)规则，完成“找到字段 → 修改名称 → 核对 → 应用到草稿 → 保存”。桌面工作目录未修改。

旧页面实际观察：展开操作后，重命名表单与核对结果继续堆在字段详情中，底部还保留修改字段值动作；返回会取消整份名称输入。[改造前原图](evidence/mobile-json-rename-2026-10-27/before-review.png)留作依据。本轮将短选择放入操作弹层，将名称输入与核对分别做成整页。

“短操作菜单 → 名称输入整页 → 核对整页”以及逐层返回是本项目的设计决定。已有原文范围补丁保持不变，没有重新序列化 JSON。

## 页面与返回契约

[四屏冻结设计](design/mobile-json-rename-v1/index.html)覆盖操作菜单、名称输入、核对、同层名称冲突；[冻结回执](evidence/mobile-json-rename-2026-10-27/design-freeze.json)记录时间 `2026-10-27T03:57:28.547Z`，早于运行时代码修改。设计源 SHA-256：`e63ea00735e628decbd53e2a43dd6b56e641d8d9f4f4aa93ecf44c4b5413adf3`。

- “更多结构操作”打开短弹层，只列当前节点可用动作；背景不可操作，关闭、背景点击、Escape 或返回都恢复触发按钮焦点。
- 重命名页只包含文件与字段位置、名称输入和当前步骤动作；说明放入独立 `?`。不再同时显示字段值修改底栏。
- 核对页只展示原键名与新键名，使用 JSON 原文写法，区分空名称和转义字符。“继续修改”或返回恢复输入、选区和输入框横向滚动。
- 从名称输入返回操作菜单会保留该字段的临时名称；“取消重命名”才丢弃。不同字段的临时输入独立，返回菜单后焦点落在重命名动作，再返回才回字段详情。
- 冲突与工作线程失败留在输入页，可改名或重试。停止核对、核对中返回会终止线程；旧结果不能发布候选。原名未变时保留其原始转义写法并禁用应用；空键名仍合法。
- “应用到草稿”沿用原源码编辑器和单次历史事务。失败时保留源码输入与焦点；只有显式保存才写文件。源码版本或文稿身份变化清除过期输入与候选。

重命名输入是本次文稿中的临时状态，尚未应用的名称不承诺在进程结束后恢复。本轮仍保留新增、删除、移动的原有表单，只把它们的入口收入短菜单；这些表单的整页迁移、JSON 诊断入口，以及其他格式的结构任务将按顺序继续。阶段 3 整体未完成。

## 实页核对与验证

[四屏并排对照](evidence/mobile-json-rename-2026-10-27/comparison.html)保留冻结设计、实际页面及七张适配原图。标准浏览器视口为 390×872，只裁去 28px 预览提示条，得到 390×844；大字体截图按实际提示条高度裁切，未重绘或移动页面元素。逐图检查了菜单、编辑、核对、冲突、320px/200%字体、暗色和短视口；另用滚动区内的真实滚轮输入确认大字体与短视口都能完整查看新名称后再应用。

[量测记录](evidence/mobile-json-rename-2026-10-27/comparison.json)共核对 88 项坐标，均在 0.5px 容差内；126 项字体、字重、行高、字距与颜色属性一致。实际输入焦点框和按压状态保留，是静态设计以外的真实交互差别；这些量测不等同整屏逐像素一致。

实际补测发现并修复两处问题：[原生弹层 Shift+Tab 焦点离开](evidence/mobile-json-rename-2026-10-27/failure-focus-cycle-report.json)，以及[长名称失焦后横向位置归零](evidence/mobile-json-rename-2026-10-27/failure-name-scroll-report.json)。前者增加首尾焦点循环，后者在指针/键盘离开前及输入框选择、滚动时记录位置；返回再恢复。两个失败报告和原始截图都保留，没有改写为成功。
