# LongEdit C3C4 PPTX 索引与桌面综合收口审计

审计日期：2026-07-27

阶段：C3C4

阶段目标：验证 PPTX 在本地知识索引完整生命周期中的一致性、降级与资源边界，并用真实桌面链路完成 C3C 搜索和知识管理阶段收口。

## 1. 阶段结论

C3C4 已完成，C3C1～C3C4 至此整体收口。PPTX 已具备统一文件管理系统内的只读搜索、精确定位、知识对象和可重建索引闭环：

1. 索引缺失时，PPTX 搜索安全回退到实时扫描。
2. 索引重建后，文件、幻灯片对象及 `contains` 关系进入持久化快照。
3. 源文件变化后，界面可见“索引已过期”，搜索不消费过期快照，继续实时扫描。
4. 源文件删除并重建后，旧 PPTX 对象和关系被清理；手动删除索引后状态回到“未构建”。
5. 搜索结果可定位到幻灯片、对象或备注，关系侧栏和知识图谱复用同一对象定位器，并能返回原有 Library 右侧 PPTX 工作区。
6. PPTX 解析与索引均具有明确资源上限，超限文件被稳定拒绝，不会无限占用内存。
7. 全链路仍严格只读；审计前后 fixture 源字节不变。

本阶段不包含 PPTX 对象编辑、保存或原件覆盖，也不把当前能力描述为 PowerPoint/WPS 完整等价。

## 2. 实施审计

### 2.1 PPTX 专项索引生命周期

Rust 回归覆盖真实 PowerPoint 与 LibreOffice fixture：

- `missing → ready → stale → ready → stale → ready(empty) → missing` 全状态转换；
- 有效快照包含 3 个幻灯片对象和 3 条文件到幻灯片的 `contains` 关系；
- 过期快照被拒绝，实时扫描可发现替换后的 LibreOffice 内容；
- 删除源文件后实时扫描不再返回 PPTX，重建会移除陈旧对象和关系；
- 删除索引后状态恢复为 `missing`。

索引仍是可删除、可重建的派生数据，不是事实源。

### 2.2 可见状态与安全降级

Library 在窗口重新获得焦点和完成知识搜索后刷新索引状态。因此外部程序修改 PPTX 后，用户无需离开阅读工作区即可看到“索引已过期”；搜索同时使用实时扫描，不会因状态提示而中断。

该改动复用现有 Library 搜索、状态提示和右侧格式工作区，没有引入新的独立 PPTX 页面。

### 2.3 资源和拒绝边界

PPTX 解析器当前执行以下主要上限：

- 单文件 96 MiB；
- ZIP 条目 12,000；
- 解压总量 384 MiB；
- 单 XML 部件 32 MiB；
- 幻灯片 2,000；
- 对象 100,000；
- 文本字符 2,000,000。

本阶段新增 2,001 张幻灯片的超限回归，确认解析器以明确错误拒绝。知识索引另有限制：快照 128 MiB、来源 100,000、对象 250,000、关系/搜索段各 500,000。两层限制共同防止恶意或异常 Office 包造成无界资源使用。
