# 收集箱用途、空状态与恢复体验

2026-10-14，基于已发布 1.1.0 的主分支提交 `40939ea6`，在 `codex/inbox-experience` 接续用户反馈。当前为开发改动，公开版本和安装包仍为 1.1.0。

## 问题

收集箱默认指向资料库内的 `Inbox`，但该目录此前仅在向其中保存内容时创建。直接打开一个尚未使用的收集箱，原组件调用 `scan_directory`；不存在的路径被当作读取故障，页面显示“暂时不可用”和原生错误文字。用户需要先绕到快速笔记才能创建目录，界面没有直接可用的开始入口。

原页面还同时展示“收集目录”、路径、计数、长错误说明和重复设置按钮，缺少明确用途与视觉层次。截图中的 `os error 2` 能说明路径缺失；未查看用户实际磁盘，不能将每一次缺失都断定为首次未创建。

## 已实施

- 标题改为“收集箱”，用“先放在这里，稍后再整理”说明用途。上方突出新建笔记，刷新/设置采用图标按钮；完整路径、位置设置和使用说明按需展开。
- 未使用且缺失的默认收集箱显示正常空状态。浏览不创建目录；点击新建笔记时创建收集文件夹，再将 Markdown 笔记创建在该位置并打开正文编辑。子文件夹中创建笔记使用当前子目录。
- 原生命令 `read_inbox_directory` 以结构化字段区分收集根目录缺失与真实读盘失败；子目录缺失、权限问题、路径占用和整个资料库失效继续报告失败。`create_inbox_directory` 为用户的创建/写入操作准备目录，保留已有文件。
- 成功访问过的位置记录可用状态，后来缺失时显示恢复卡片；自定义位置缺失始终提供重试、更换文件夹和明确创建空文件夹。整个资料库失效时可以打开资料库设置。旧版本没有记录过的默认位置，单凭目录不存在不能判断是否曾存过资料。
- 保留打开文件、进入子目录、上一级、刷新、错误详情、选择资料库内目录及快速笔记跨窗口位置同步。更换位置不会移动旧资料；没有加入强制归档步骤。
- 新增当前文件夹的文件名筛选及清除入口。Markdown 在列表中显示为“笔记”，取消文件路径悬停浮窗；文件类型图标、密度、平面/卡片行及六类主题令牌接续。
- 读取与创建状态防止重复点击；失败采用局部反馈，技术详情默认收起。独立收集箱页复用同一组件，移除重复的大段说明。

## 已有检查

- `scripts/test-inbox-experience-browser.mjs`：实际 App/LibraryMode/InboxView 的6组流程及六风格×宽/窄12组布局通过，页面异常为零。覆盖默认未创建、曾可用位置消失、创建/打开、筛选、子目录、设置同步、读写失败和恢复。原生 IPC 为隔离模拟。
- `scripts/test-workflow-redesign-browser.mjs`：原8组日常工作流回归通过，包括快速笔记、参考、集合和工作现场；仅迁移本次改变的收集箱标题/按钮选择器，不移除功能断言。
- `scripts/test-inbox-archive-browser.mjs`：直接打开文件、无强制归档及历史结果组件回归通过。
- `scripts/test-capture-destination.mjs`：2项通过，保留快速笔记默认直接保存和原位置记忆，补 Windows 资料库身份的自定义收集位置解析。
- Rust `commands::inbox::tests`：2项真实文件系统测试通过。覆盖首次缺失不创建、子目录失败、同名文件不覆盖、显式创建可重复、已有内容保留及根目录缺失不自动新建。
- debug 原生构建成功，50.39s；最终前端构建成功，含类型检查及生产打包，33.74s。
