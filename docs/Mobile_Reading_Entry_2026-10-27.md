# 手机端阅读与编辑入口

阶段3A只推进“打开文字资料，阅读、查找或记下一段，再回到原任务”。在移动工作目录 `codex/mobile-0.1.0-foundation` 实施，未改桌面目录。源码工具分组、结构和诊断、PDF 的控件整理另行验收。

## 实际观察与竞品依据

[修改前实页](evidence/mobile-reading-entry-2026-10-27/before/reading.png) 中，一条待接收提示占用整行，阅读标题下常驻“已保存到文件”，查找常驻顶栏。编辑菜单还重复列出底部已有的格式工具。普通阅读被接收和编辑工具挤占。

| 官方资料，2026-10-27 核对 | 可确认事实 | 本项目采用的决定 |
| --- | --- | --- |
| [Obsidian Mobile app](https://obsidian.md/help/mobile) | 移动编辑在底部提供可定制工具栏，动作多时横向滑动；非编辑状态有导航，手机没有桌面的 Ribbon，其他动作从菜单进入。 | 保留常用编辑工具及真实撤销历史，工具横向滚动；阅读只留正文任务所需入口。没有照搬其多标签或下拉快捷操作。 |
| [Notion for mobile](https://www.notion.com/help/notion-for-mobile) | 手机没有悬停状态，以可见的更多和加号入口提供操作；桌面多列在手机折为单列。 | 文档操作使用显式更多菜单，查找按需出现；不要求用户发现悬停动作。阅读/编辑分离和返回层级是本项目的设计决定。 |
| [Joplin Mobile app](https://joplinapp.org/help/apps/mobile/) | 当前帮助页确认 Android/iOS 可用，但未提供足以核实工具栏层级和返回细节的文字说明。 | 不据此宣称验证过其编辑切换或系统返回。竞品调查为官方资料核对，没有声称完成安装后的真机走查。 |

## 冻结设计与实现

[四屏设计源文件](design/mobile-reading-entry-v1/index.html) 与 [冻结记录](evidence/mobile-reading-entry-2026-10-27/design/capture.json) 在运行时代码修改前保存。四屏分别为阅读、编辑、文档菜单和文档查找。原始图和源文件均保留摘要，比较脚本拒绝覆盖冻结记录或使用变更后的参考。

- Markdown/TXT 阅读顶栏保留返回、文档名和更多，编辑为底部明确入口。干净文件的保存状态不常驻标题，未保存草稿、来源不可用、内容变化和真正错误继续说明。
- 查找移入文档菜单，打开才占用正文上方空间。顶部返回标为“返回文稿”，与关闭查找、系统返回模拟一样先收起查找，保留当前文档，焦点回更多。源码格式沿用原有查找入口。
- 收到内容时只更新更多按钮的圆点和辅助状态，不移动正文、不自动打开任务、不抢输入。菜单内有稳定收件入口与待核对数量；检查接收记录仍先保护草稿。取消后回发起文档的更多按钮，保留编辑器、输入和撤销历史。
- 普通高度下菜单不重复格式工具，干净文件不显示不可用的保存项；高度不超过200 CSS px、原底栏隐藏时，菜单恢复格式工具。图片、文字导出和附件包继续走已有独立任务。
- 切到编辑前先请求阅读位置快照。正文未变化时回到原位置，正常恢复不再显示常驻成功横条，“从头阅读”移入更多且只在离开顶部后出现。正文变化仍按原指纹保护从头打开并说明，不能把旧段落误当作当前位置。
- 切到阅读先等待草稿保护，失败则保留编辑并恢复输入焦点；不把切换等同于保存文件。编辑器继续保留为同一实例，正文 CRLF、选区及撤销/重做不经由菜单重建。
- 文字顶栏、编辑工具及按需查找的翻页/关闭按钮至少48 CSS px。Android 实际dp、输入法抬升和边到边安全区仍需原生检查。

## 对图与验证

对比包含 [阅读](evidence/mobile-reading-entry-2026-10-27/comparison-reading/comparison.png)、[编辑](evidence/mobile-reading-entry-2026-10-27/comparison-editing/comparison.png)、[菜单](evidence/mobile-reading-entry-2026-10-27/comparison-menu/comparison.png)、[查找](evidence/mobile-reading-entry-2026-10-27/comparison-find/comparison.png)。只裁去浏览器调试横条，没有隐藏产品控件、修改实际截图或重画设计图。

首个候选功能验证通过后，对图仍发现顶栏多1px、菜单多64px、查找区域少10px。保留 [首轮记录](evidence/mobile-reading-entry-2026-10-27/candidates/layout-before/alignment.json)，随后修正实际菜单行高、标题、留白及查找按钮触摸范围。极矮横屏回归又发现64px顶栏覆盖了原有紧凑规则，在127px可用高度与200%字号下只剩40px编辑区；保留 [失败现场](evidence/mobile-reading-entry-2026-10-27/candidates/compact-header-before/report.json)，并恢复高度不超过200px时的49px顶栏，同时保留48px返回/更多目标。最终边框几何见 [alignment.json](evidence/mobile-reading-entry-2026-10-27/alignment.json)。

不是像素完全一致：编辑器保留已验证的16px可缩放正文、原有内边距和 CodeMirror 字体，静态稿用14px等宽字；查找标签在实页保持一行，静态稿出现了换行；实际搜索高亮、输入焦点、图片图标和导出动作的准确文案也保留在截图中。这些差异单列，不用移动截图或修改冻结图掩盖。

生产构建通过，25项针对性逻辑检查、48组浏览器检查和28次命名axe扫描通过；axe未发现违规不代表完成所有人工无障碍检查。未变化正文的切换前后阅读位置同为1300px。构建、用例数量、失败候选和实际产物摘要见 [verification.json](evidence/mobile-reading-entry-2026-10-27/verification.json)。旧编辑测试曾等待已移除的标题保存提示，已改为检查真实文件、草稿清理和“与文件一致”，没有删除 CRLF、输入法组合、选区及撤销断言。另保留草稿尚未落盘就抓取预期值、辅助状态选择器重复，以及收件注入器在菜单阶段过早触发返回的失败记录；分别等待真实保护完成、选中准确状态区，并限定忙碌保护阶段注入返回。原有文字/接收/无障碍测试通过可见菜单进入新入口；脚本不直接修改应用内部状态来跳过返回。

本轮为本地生产构建浏览器验证；Chromium合成输入法、键盘缩小视口、Back桥接和axe检查不能替代 Android 系统输入法、TalkBack、真实 Intent、后台恢复与实体返回键。没有生成或提升新 APK。下一步按用户任务整理源码触摸工具及结构/诊断，再进行原生出口验收。
