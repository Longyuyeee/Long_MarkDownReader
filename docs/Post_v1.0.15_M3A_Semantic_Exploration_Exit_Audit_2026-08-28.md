## 1. 退出范围与原始需求对齐

本次退出审计直接对照 `Post_v1.0.15_Professional_Capability_Enhancement_Roadmap_2026-08-25.md` 的 M3A：稳定对象/关系语义，一至三层邻居聚焦，独立验证的最短路径，双节点比较，邻接固定与选择历史，稳定社区，以及可回到来源位置的关系证据。`Professional_Knowledge_Workspace_Design.md` 进一步约束局部图谱应固定在编辑器右栏并跟随活动标签，算法建议和会话状态不得写回用户数据。

M3A-1 至 M3A-7 均已有独立算法、桌面和安全证据。本阶段不以重新截图代替这些独立审计，而是在同一真实 Tauri 会话中串行组合所有语义探索入口，验证状态互斥、返回路径、宽窄屏与源文件安全。

## 2. 组合审计发现的偏移与修复

代码复核发现，单项入口各自可用，但探索状态没有完全互斥：

- 从社区筛选进入邻居聚焦或最短路径时，活动社区 ID 没有清除，最终节点范围会被两个条件静默相交。
- 打开选择历史时只关闭了社区面板，没有退出已选社区或邻居聚焦；历史快照会被旧范围裁剪，偏离“当前全局图谱会话”的冻结语义。

现已为图谱根容器增加可审计的活动探索范围，并统一入口行为：邻居、路径、社区、比较和历史之间切换时，清除不兼容的旧探索范围；普通搜索和显式筛选仍作为用户选择的数据边界保留。修复后任一时刻最多只有一个活动探索范围。

## 5. 提交前总门禁纠偏

`check:current-development-audit` 首次重跑还暴露两处与产品功能无关、但会破坏持续审计的历史门禁偏移：

- M1 总退出脚本把“当时选中的下一阶段”误写成“当前项目阶段必须永远等于 M3 初始入口”。阶段推进到 M3B 后必然误报；现改为验证 M1 冻结策略本身的历史接续，完整当前阶段链继续由开发版本身份门禁负责。
- M1B2A 的证据清单绑定 Git 中 LF 字节摘要，但 Windows 工作区按文本属性检出为 CRLF，导致同一已提交证据误报摘要变化。仓库 blob 摘要与清单完全一致；现仅在该跨平台校验点规范 CRLF 为 LF 后计算，不修改历史证据或放宽 JSON 内容检查。

修复后 `check:current-development-audit` 从头到尾返回成功，而不是依赖后续命令覆盖中途失败状态。

## 6. 边界与结论

M3A 语义探索能力已经满足本轮路线图退出条件，但这不把整个知识图谱或 `FR-GRAPH-004` 扩大为全部完成：普通节点详情与编辑器局部图谱仍主要展示首条 mention 摘要；社区轮廓、语义缩放、路径方向流动、缩略导航图、聚类镜头、主题/减少动效以及大图性能分别属于 M3B、M3C。

下一接续点为 **M3B-0 专业视觉基线选择审计**。应先用 M3-0 的 100/1000/5000 图谱和当前跨格式图谱记录社区表达、远中近景信息密度、路径可读性、导航能力、主题与减少动效的修正前事实，再选择一个最小 M3B 实现；不得直接堆叠背景光效，也不得提前修改版本或进入发布冻结。
