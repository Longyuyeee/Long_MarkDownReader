# v1.1.8 B2b：文件组续载、查询过期及窗口隔离

## 状态与需求对齐

基于开发分支 `codex/v118-search-completeness` 的 `5a42df0a` 接续。公开/运行时仍 **1.1.7**，不是 1.1.8 候选包。已实现并注册单库原生分页 API，尚未接正式搜索页面或跨库聚合；**保持草稿 PR，不合 main、不发布**。

对齐 [Master PRD](Product_Requirements_and_Development_Roadmap.md) 的“找资料、读资料、写内容”、搜索同名辨识/多位置/默认主区打开及显式保存规则，以及 [统一文件需求 §5.3](Unified_File_Manager_Format_Requirements.md) 的可重建索引与敏感路径排除。本批深化原搜索，不新增页面、格式、AI 或额外资料管理步骤；既有两个数组/跨库入口保持原样，等待 C/D 统一接入后替换适配，不能长期维持两套面向用户的搜索。

用户目标：“前面找到的看完了，我还能继续找后面的文件；翻页别重复读一遍所有正文，也别混进上一次查询。”

## 实际代码与合同

- `commands/index.rs` 保留旧接口和收集/排名算法；抽出可复用的借用迭代匹配器，支持交错存储的索引段按文件引用，无须复制整份索引。新增 `search_knowledge_page` / `close_knowledge_search` 薄命令。
- `commands/index_search_pages.rs` 管理单库查询现场、文件组与游标；`lib.rs` 注册状态/命令，并在窗口销毁时取消该窗口会话。
- `services/search_scan.rs` 的预算增加协作取消标记，逐条目录扫描及索引段处理均可检查。旧接口未被提前切换。
- `KnowledgeIndexRuntime` 增加进程内变化代次及监视健康状态。来源修改、快照替换/失效、建库状态变化推进代次，清除 changed paths 不重置代次；不只使用秒级 `builtAt`。代次在快照/状态更新后推进，变化路径先登记再推进代次，避免新查询认领新代次却读到旧缓存。

| 合同 | 当前实现 |
| --- | --- |
| 请求 | 已配置的单库、关键词/短语/排除条件、相关性或修改时间、页大小 1—100、`library/palette` 入口通道、可选游标；拒绝未知字段 |
| 所有者 | 来自原生命令注入的窗口标签，不接收客户端伪造 owner；一个窗口的两个搜索入口独立 |
| 准备中 | `preparing`、无文件页、总数未知，返回继续工作的游标；不把尚未排序完的前 200 条当最终首屏 |
| 文件页 | 每个精确路径只占一个文件名额，保留组内合法 locator；`pageOffset/sessionId/snapshotId/nextCursor` 可识别页与重试 |
| 排序 | 相关性沿用共享总顺序；修改时间以来源纳秒比较、缺失置后、共享身份打破并列；对外毫秒值避免 JS 纳秒精度损失 |
| 过期 | 查询/范围/排序/页大小不符拒绝混页；变化代次、真实文件大小/mtime/路径、PDF 伴随记录变化、空闲/最长寿命使现场过期 |
| 重试 | 最近一次准备步骤重复请求返回相同响应，不多做下一步；已签发页可重复读取，无重复建段；跳页/旧会话位置不关闭新会话 |
| 不完整 | `limited`、`scanComplete=false`、`totalFiles=null` 与警告，仍可翻已找到的文件；不能把预算或正文失败冒充查全/无结果 |

结果 `coverage=registered-extractable-content` 明确沿用**当前注册格式与提取器的可检索范围**，不是对任意原文件全部字符、所有工作簿行或扫描图像的无限全文承诺。组内仍保留旧约束：有定位类别最多五处、无定位类别最多一处、单文件最多 200 条原始命中；字段和潜在更多位置提示如实说明，不宣称把任意文件所有出现次数都返回。

## 预算、复用与失效处理

1. 来源元数据沿 B2a 的目录迭代器继续，不每次从根目录重来。完成元数据后校验内存/磁盘快照来源摘要和关系摘要；过期、旧路径或缺失段安全回到逐文件提取。不为搜索重建/写回资料库或另一套磁盘索引。
2. 借用现有 `Arc` 快照，以受预算限制的“文件→段下标”表匹配。冷查询逐文件建段，段处理预算结束时保留当前待匹配输出；已经处理的文件不会因翻下一页重新建段。排序完成后释放目录句柄、提取临时段与索引引用，只留有界结果和元数据签名供续页核对。
3. 准备/匹配每步沿用 B2a 协作预算，另限制每步最多处理 256 个来源。单文件任务不适合反复从头重试时明确限量状态，不让用户陷入无限“继续”。同源 PDF 主文件/批注/OCR 共用预留。已完成文件页只核对最多 100 个文件及必要伴随元数据；这类文件系统调用同样没有硬实时截止。
4. 新分页运行时最多四个会话、四个活动任务；满时立即 `busy`，不把无穷工作排到后台。每会话最多 100,000 份来源元数据、10,000 个匹配文件、8MiB 序列化结果载荷；单份保留提取段最多 100,000 段/64MiB 正文。达到上限明确未完成，不静默截断成完整结果。8MiB **不是进程 RSS 上限**，元数据、段下标、现有索引、待匹配单文件和重试响应另有成本。
5. 空闲五分钟、总寿命二十分钟；按下次请求惰性清理、窗口销毁主动清理，不声称定时器到点释放全部资源。新查询替换同入口旧查询并触发取消；旧窗口/旧关闭请求不能清掉新查询或其他窗口/入口。活动旧任务直到协作检查点退出，阻塞文件系统/单文件解析并非硬实时可中断。
6. 查询执行前后检查变化代次和监视健康；返回页面及重试时直接核对本页来源签名和 PDF 伴随记录，捕获部分监视事件尚未递送的改名/删除/新增伴随情况。监视报错拒绝继续，而不是宣称最新。**这不是文件系统原子快照**：通知递送延迟、时间戳被刻意保留的同大小原地修改等仍不能据此声称完全解决。
7. 列表顺序、隐藏历史、资源文件夹等不改变可检索内容，不推进搜索变化代次；资料和关系记录仍推进。已有 changed paths 集合保留原口径，新分页只选择相关变化，不为正常打开/返回反复过期。补审纠正 Windows 大小写边界：旧扫描仅排除精确小写 `.assets`，因此 `资料.Assets/预算.md` 仍是可检索来源，监视过滤也必须保留它；真实磁盘来源与监视谓词的一致性回归已加入。不是为通过测试把扫描范围再缩小。
8. 先从配置中选择目标库，再解析该路径；不每翻一页就访问所有其他配置库，避免离线库影响单库续载。Unix 路径不擅自转小写；Windows 路径分隔符/设备前缀在选择阶段规范化，实际内容读取仍由资料库守卫约束。
9. 不能读取/提取的正文不当作已满足排除条件。简单正向文件名仍可返回，但明确正文失败；有排除条件则不把未知正文文件纳入，整体标为不完整。空库的完成零结果、缺失库错误、预算停止和正文失败分别验证。
