# v1.0.15 后 M3C-0 大图性能基线选择审计

日期：2026-08-28

进入基线：`main` / `785a1b27be947cad34d151943ef41da99ee2d6b9`

阶段：M3C-0

发布候选：否

## 1. 结论

M3C-0 已用 100、1,000、5,000 节点的真实 Markdown 资料库和真实 Tauri/WebView2 完成性能基线选择审计；本阶段没有修改图谱产品运行代码，也不把“页面最终能显示”误报为大图性能完成。

100 和 1,000 节点的首屏、布局和交互达到本阶段预算；5,000 节点虽未卡死、空白或失去返回能力，但布局稳定耗时 `185195ms`，超过 `120000ms` 目标，缩放耗时 `8010ms`，超过 `5000ms` 目标。三个规模在布局稳定后均仍约 `132` 次/秒绘制，显著超过 `<=2` 次的静止预算；代码也确认当前循环无条件执行 `draw()` 和下一次 `requestAnimationFrame()`。失焦和离开资料库后绘制分别降至 `1` 和 `0`，20 次进入退出没有持续堆增长信号。

因此当前接续点固定为 **M3C-1 稳定后脏帧刷新与生命周期循环控制**：先消除稳定图谱的无条件持续绘制，同时保持布局推进、相机、路径动效、指针、尺寸和主题变化能显式唤醒绘制。空间索引、Worker/布局替换、视口裁剪/标签缓存、保存视图恢复继续独立延后，不能一次混入。

## 2. 冻结的真实测试方法

- 数据：每档生成真实 Markdown 文件和真实 `[[链接]]` 有向链，分别形成 100/99、1,000/999、5,000/4,999 节点/边；源文件只读验证。
- 环境：每档使用独立真实 Tauri/WebView2 会话，避免上一档内存和绘制状态污染下一档。
- 路径：首次可见 → 布局稳定 → 缩放 → 全图平移 → Canvas 框选 → 有界搜索聚焦 → 稳定帧活动 → 窗口失焦/恢复 → 返回资料库。
- 生命周期：1,000 节点额外执行 20 次进入/退出并记录最大重新可见时间和前后 JS heap。
- 安全：监听运行时错误，计算资料库前后 SHA-256，并验证实际返回资料库。
- 预算：100 节点 `2000/5000/250ms`，1,000 节点 `5000/20000/1000ms`，5,000 节点 `30000/120000/5000ms`，依次对应首次可见/布局稳定/单项交互上限；稳定和非活动绘制均最多 2 次。

## 3. 预期与最终实际

| 规模 | 首次可见：预期 / 实际 | 布局稳定：预期 / 实际 | 缩放 / 平移 / 框选 / 聚焦 | 稳定绘制：预期 / 实际 | 长任务 | 判断 |
| --- | --- | --- | --- | --- | --- | --- |
| 100 | `<=2000 / 1407ms` | `<=5000 / 3724ms` | `27 / 111 / 92 / 13ms` | `<=2 / 132` | 6 次，最长 `537ms` | 首屏、布局、交互通过；稳定空转失败 |
| 1,000 | `<=5000 / 2189ms` | `<=20000 / 15050ms` | `651 / 140 / 147 / 54ms` | `<=2 / 132` | 136 次，最长 `616ms` | 首屏、布局、交互通过；稳定空转失败 |
| 5,000 | `<=30000 / 24722ms` | `<=120000 / 185195ms` | `8010 / 1486 / 1403 / 233ms` | `<=2 / 132` | 128 次，最长 `17237ms` | 首屏通过；布局、缩放、稳定空转失败 |

补充实际结果：

- 三档平移均确认发生在完整图谱而非社区过滤子图；框选分别真实选中 20、180、924 个节点。
- 三档失焦后的绘制均为 1 次，返回资料库后为 0 次；运行时错误均为 0，源 SHA-256 前后一致。
- 1,000 节点 20 次进入退出全部完成，总计 `24157ms`，单次重新可见最大 `2487ms`；heap 从 `90535140` 降至 `33657276` 字节，差值 `-56877864`，本轮没有持续增长证据。
- 5,000 节点最终截图确认完整图为 5,000 节点、4,999 连接、78 社区且可返回，但全局视图出现大面积社区轮廓和标签重叠；这不是空白或崩溃，却不满足大图可读性，后续应由层级细节/裁剪阶段处理，不能借 M3C-1 偷带视觉重构。

## 4. 测试差异与纠偏记录

| 发现 | 对实际结果的影响 | 修正 |
| --- | --- | --- |
| 初版 Canvas 探针对每条绘制路径持续做图谱身份判断 | 5,000 节点下探针自身放大主线程成本，不能作为产品基线 | 每帧最多抽样 64 次，增加 CDP 请求超时，并废弃受污染结果 |
| 初版等待按轮询次数计时 | WebView 忙时单次求值延迟，名义超时与真实墙钟不一致 | 改用墙钟截止时间，并对超预算保留有界失败证据 |
| 单档失败会迫使全部档位重跑 | 增加无关重复和证据覆盖风险 | 增加 `-Tier` 单档重跑，最终仍执行三档完整重跑形成同批证据 |
| CDP 鼠标事件未带完整按键状态，随后远景社区入口又截获拖动 | 首次平移未发生；后续测试一度落在 64/5,000 节点社区子图 | 补全按键状态和真实 DOM Canvas 事件；每次平移后检测社区入口，若误入则返回全图、重新适配并重试；最终证据强制 `panFullGraph=true` |

以上修正只消除测试工具和测试路径污染，没有调整产品性能预算。纠偏后完整重跑仍如实保留 5,000 节点布局/缩放失败及三个规模的稳定空转失败。

## 5. M3C-1 开发边界

- 将无条件 `simulate → draw → requestAnimationFrame` 改为“布局/动效活跃或状态变脏时调度下一帧”。
- 必须覆盖布局尚未稳定、相机过渡、calm 路径流动、指针/选择/过滤、缩放/平移、尺寸/主题变化和窗口恢复；reduced 静态内容不应依赖连续循环。
- 布局稳定且无相机/路径动效时，1 秒窗口绘制不超过 2 次；失焦、隐藏、返回资料库和卸载后不残留循环。
- 使用同一 100/1,000/5,000 真实资料库复测，明确列出修正前 `132` 与修正后的实际差异；1,000 节点继续执行 20 次生命周期测试。
- 不在 M3C-1 引入空间索引、Worker、布局算法替换、视口裁剪、标签缓存、保存视图或视觉层级重做。

## 6. 阶段目标与需求对齐审计

- 开发目标：建立可信大图现状、识别首个最小性能瓶颈并冻结下一阶段，而不是先写优化再寻找理由。
- 需求对齐：路线图的 100/1,000/5,000 可操作性、连续长任务、稳定 CPU、20 次生命周期和返回能力均有真实数据；导出与保存视图不在本选择阶段伪装完成。
- 差异闭环：产品失败与测试污染分别记录；纠偏后完整重跑，预算未放宽。
- 安全边界：三档均零运行时错误、源资料库摘要不变并实际返回资料库。
- 文档与事实源：政策、当前阶段、状态、交接、路线图和开发版说明同步到 M3C-1。
- 版本：运行时/公开版本仍为 `1.0.15`，开发目标为 `1.0.16`，`releaseCandidate=false`；M3C 尚未完成。
