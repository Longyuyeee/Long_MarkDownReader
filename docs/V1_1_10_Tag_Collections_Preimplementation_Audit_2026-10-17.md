# v1.1.10 标签与集合：接续前代码审计

本文件是已确认十三版路线中下一版本的实施起点，不代表功能已开发或验收。当前先完成 v1.1.9 的安装、封板和发布，不将两个版本混合打包。

## 需求与已有能力

沿用现有侧栏标签、智能集合和保存的集合，不增加第二套文件管理器。用户任务是“持续整理资料，数量可信，刷新后能接着看，批量操作不会悄悄改坏正文”。集合是动态视图，不是文件副本；既有搜索主区打开、显式参考、草稿保护和普通集合编辑必须保留。

实际代码已读：`src-tauri/src/services/smart_collection.rs`、`src/components/SmartCollectionPanel.vue`、`src/components/InlineTagsPanel.vue`、`src/utils/savedCollections.ts`，以及已交付的 1.1.8 搜索分页入口。不要重新立项已有目录/类型/标签/时间组合、集合保存、标签固定或库切换代次保护。

## 已证实的缺口与边界

- 集合服务在过滤后累计结果，超过 200 条即停止并截断。带关键词时会扩展一个文件的多个命中；无关键词时一文件一项。因此前端“匹配资料 N 项”不能直接解释成同一口径的文件总数，前端名称/路径排序也只是已加载部分的排序。
- 集合的 `run()` 先调用 `invalidate()` 清空结果。虽然已经记住排序/滚动和过期响应代次，但刷新失败时不能保留刚才可用的结果；不能把“已有保护”误写成完全没实现。
- 标签 `selectTag()` 也先清空结果；刷新会重新执行它。库切换、卸载和请求代次已有隔离，必须保留。添加标签现有提示明确“保存笔记后生效”，不能为统计立即一致而自动代存用户草稿。
- 改名/删除、批量标签整理的范围及统计语义还需逐调用链复现，暂不凭推测宣称已有错误或已支持安全批量写入。

## 实施顺序与每步完成条件

1. **统一文件与命中口径。** 先建立超过 200 个文件、一文件多命中、同名不同目录、混合格式、损坏/不可读、标签变化等固定样本。明确“已加载文件数 / 命中数 / 是否还有 / 是否未查全”，复用现有分页身份和失效原则，不能只在 UI 加一个假的“加载更多”。原旧命令兼容入口和既有结果定位保留。
2. **续载、排序和刷新连续。** 排序针对完整查询，不只当前数组；条件、根库和索引代次变化不能串页。刷新期间保留旧结果和现场，失败明确旧结果尚未更新；用户新改但未提交的条件不被覆盖。真正切换条件时不混用上一查询的结果。
3. **安全深化标签整理。** 先审计原生读取/写入、统计和现有命令权限。批量操作先预览影响文件和是否修改正文，明确确认后执行，逐项给出完成/失败/未执行；不自动全量重试、不覆盖活动草稿或外部新修改，不因验收方便清空脏状态。
4. **改名/删除后的组织接续。** 核对集合条件、目录路径、标签固定/排序和失效条目；能保持身份则保持，需要用户选择则沿原入口解释，不静默丢集合或增设归档步骤。
5. **封板与发布。** 正式 UI 改动前先展示示意；保留全部现有功能，实看正式页面宽窄/短窗和六风格，模拟真实语气与操作。模型、原生、模拟页面、开发程序、已安装包分层验收；固定包通过全部历版回归、真实退出重启和安装升级后才封板，发布相同字节并核对公开下载，README 更新摘要仍在末尾。

每步完成后审计、记录原始成功/失败证据并推送，再继续下一步；当前版未发布不直接提升运行时。1.1.11 仍是既定图谱深化，不因这份接续审计改变版本顺序。
