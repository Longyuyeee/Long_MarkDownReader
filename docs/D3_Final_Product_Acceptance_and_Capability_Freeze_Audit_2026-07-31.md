# D3 最终产品验收与能力冻结审计

日期：2026-07-31
版本：`v0.7.0`
阶段：D3

## 结论

D3 已完成，本机基础产品能力进入冻结状态。

本阶段没有重复制造新的桌面截图，也没有扩大格式写入能力，而是将现有真实
Tauri 验收、格式合同、生产者复开、Rust 回归、性能基准、恢复与隐私门禁汇总为
`shared/product-acceptance-freeze.json`。新增
`check:d3-product-acceptance-freeze`，并直接接入 `ci:check`。

## 验收范围

统一验收总账覆盖 9 个领域：

1. 日常工作区与文件管理；
2. 格式编辑和安全降级；
3. 知识图谱、关系和知识组织；
4. 可视化创作、主题与关键可访问性；
5. PDF 页面提取、合并和插入；
6. DOCX/PPTX 可靠新副本；
7. XLSX 已验证子集的有界编辑；
8. 索引恢复、管理备份和隐私诊断；
9. 启动/路由/PDF/XLSX 性能及完整 Rust 回归。

检查脚本会从 `ci:check` 递归解析所有 `npm run` 依赖，确保每个验收领域声明的
门禁仍然真正属于共享 CI，而不是只存在于 `package.json` 中但从未执行。

## 冻结基线

- 注册格式：39；
- 发布能力配置：10；
- 安全降级通道：6；
- 产品状态：`accepted-for-capability-freeze`；
- 发布状态：`blocked-external-evidence`；
- `releaseCandidate=false`。

能力冻结意味着基础版后续只接受缺陷、数据安全、性能和兼容性修正。新增大范围
写入能力必须进入新的专项阶段，不得悄悄改变当前格式矩阵。

## 仍未收口

- R5N 正式代码签名和 Windows 10/11 已签名安装生命周期；
- WPS ODF/ODT 生产者证据仍为 2/3；
- XLSX 数组公式生产者证据仍为 1/3；
- 完整 Excel 等价编辑；
- 复杂 Office/ODF 等价编辑和 WPS 原生格式内核级写回。

这些项目不影响本机基础产品能力冻结，但继续阻止 RC 晋级或更高能力承诺。

## 后续入口

下一代码阶段为 E0 高级编辑能力差距与风险矩阵，按以下顺序审计：

1. 完整 Excel 等价编辑缺口；
2. 新格式编辑器候选及安全写入模型；
3. 主题预设覆盖、视觉回归成本和实际用户场景；
4. 复杂 Office/ODF 与 WPS 原生编辑的实现和维护成本。

E0 只确定范围、优先级和退出标准，不自动解锁现有只读/副本/sidecar 边界。
