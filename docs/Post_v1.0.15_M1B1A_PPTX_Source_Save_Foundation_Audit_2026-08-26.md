# v1.0.15 后 M1B1A PPTX 原文件保存基础审计

日期：2026-08-26  
状态：后端基础通过，用户流程尚未开放  
版本：不提升版本

## 1. 本阶段目标

在不改变现有 PPTX 界面与公开能力声明的前提下，为已通过隔离验证的单个 PPTX 操作建立可靠原文件保存基础。现有可靠另存副本继续保留。

## 2. 实现结果

新增 `save_pptx_patch_source` Tauri 命令和独立返回回执。保存链包含：

1. 恢复可能由上次中断留下的可靠写入备份。
2. 校验资料库路径、PPTX 格式、96 MiB 上限、源内容签名和隔离预览输出 SHA-256。
3. 重新构建操作并通过未改部件、结构复读与语义复读门禁。
4. 写入前再次比较源字节、元数据签名和源摘要，阻断验证期间的外部修改。
5. 使用同目录临时文件、备份和原子替换完成可靠写入。
6. 落盘后再次比较完整输出、解析 PPTX 并重放操作；验证失败时恢复原始字节并确认恢复结果。

界面仍显示“源 PPTX 始终只读”和“可靠另存副本”，没有提前接入原文件覆盖按钮。原因是当前 PPTX 仍一次只提交一个操作，也没有统一撤销/重做；直接开放会违反已确认的编辑交互要求。

## 4. 真实测试

使用 Microsoft PowerPoint、WPS Presentation 和 LibreOffice Impress 生成的三份真实 PPTX fixture。每份文件复制到临时目录后执行真实文本操作、隔离输出构建、原文件替换、磁盘复读和语义提取；确认目标文字存在、输出字节与原字节不同、未改部件门禁通过。随后使用旧签名再次保存，三份文件均被拒绝且已验收字节不再变化。测试目录没有残留 `.longedit-tmp` 或 `.longedit-bak` 文件。

第一次阶段审计曾因合同错误而停止：合同误要求私有的副本保存内核出现在 Tauri 注册表。修正为“私有内核存在、公开副本/原文件命令注册”后，完整审计通过。这一修正保留在过程记录中，没有通过降低产品要求绕过失败。

证据：[`docs/evidence/post-v115-m1b1a-pptx-source-save/`](./evidence/post-v115-m1b1a-pptx-source-save/)

## 5. 下一步

进入 **M1B1B：PPTX 多操作事务基础**：把多个经过验证的操作按确定顺序应用到同一内存输出，并在一次源签名校验和一次可靠写入中保存。真实测试至少覆盖文本与一个非文本对象组合、操作冲突阻断、确定性重放、三生产者保存重开和旧签名拒绝。

M1B1B 通过后，再接入前端统一草稿、撤销/重做、脏状态、离开保护、显式“保存到原文件”和保留“另存副本”的完整流程。
