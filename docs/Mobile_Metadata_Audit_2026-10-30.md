# 手机端本机元数据审计

2026-10-30，继续处理 WebView 资料与应用原生资料分离带来的恢复缺口。以 `codex/mobile-0.1.0-foundation` 实际调用为准，不根据某次主页入口消失推断全部浏览器元数据已经丢失，也不声称能恢复此前未备份的旧记录。

| 用户内容或现场 | 当前存储与边界 | 后续顺序 |
| --- | --- | --- |
| 文稿未保存正文、恢复副本 | 原生私有文件，最近入口上轮已迁原生；不依赖 WebView 正文缓存 | 保留现有保护与故障验证 |
| PDF 正式高亮、评论 | 原生批注文件，带来源签名与修订核对 | 保留现有保护 |
| PDF 书签、名称输入、删除撤销 | 本轮接入原生 `pdf-bookmarks-v1.json`；旧 WebView 记录仅在原生缺失时验证迁移，旧数据保留 | 本轮完整验证后收口 |
| PDF 未完成批注输入 | 已迁原生 `pdf-annotation-recovery-v1.json`，旧键仅首次验证迁移；保存与草稿清理分开确认，恢复到页面采用独立副本 | [本轮原生恢复记录](Mobile_Native_Pdf_Recovery_2026-10-30.md)，完整无障碍／实体机仍独立验收 |
| PDF 批注删除日志 | 与草稿在同一原生封套，先确认pending材料再正式删除，重开核对实际ID，撤销合并到最新正式批注 | 已联动实现与验证；不把恢复日志的保存当成正式删除成功 |
| PDF 页码、缩放、方向、连续阅读锚点 | 已迁原生 `pdf-reading-v1.json`，旧键仅缺失时验证迁移；失败可读不默认覆盖，等待确认、双重比较写入，保留未知字段与其他资料 | [本轮记录](Mobile_Native_Pdf_Position_2026-10-30.md)；原生树／完整TalkBack继续独立验收 |
| 普通排版阅读位置 | 已迁原生 `text-reading-v1.json`，块号／比例／进度／横向位置与指纹绑定，旧键仅原生缺失时验证迁移；失败不默认覆盖，队列等确认，阅读框核对操作编号 | [本轮记录](Mobile_Native_Text_Position_2026-10-30.md)；原生延迟取消与完整无障碍继续独立验收 |
| 分段长文现场 | 已迁原生 `source-reading-v1.json`，修复恢复前写段首，保持身份、段号、查询／命中／选区与滚动；按需跳段与逐层返回，隐藏预览不记零布局 | [本轮记录](Mobile_Native_Source_Position_2026-10-30.md)；原生直连大包堆压力与完整无障碍继续专项验收 |
| 外观偏好 | 已迁原生 `preferences-v1.json`，旧键仅缺失时验证迁移；显式选择、系统跟随、保存确认／重试、冲突和迟到回复分开处理，补充原生配置通知及系统栏配色 | [本轮记录](Mobile_Native_Appearance_2026-10-30.md)；原生锁定夜间命令的失败及实际复验单列，完整TalkBack等仍独立验收 |
| 浏览器预览数据与最近列表 | `PreviewStorage` 明确仅用于浏览器开发预览 | 继续使用浏览器适配器；原生错误不得回退到预览数据 |

本轮书签保留原有物理页码、资料库／完整路径／内容指纹隔离、200枚上限、旧版本只读、名称草稿和单次撤销。同步业务变换仍可独立验证；生产页面改用异步仓库，原生串行 IO 以整个原始文件的 SHA-256 做比较后原子写入并读回，页面收到确认后才更新成功状态。迁移并发时只接受重新读到且验证通过的原生记录。损坏记录和显式空字符串不冒充缺失，不以空白数据覆盖。

交互与画面先冻结在[设计规则](design/mobile-native-pdf-bookmarks-v1/Interaction.md)。竞品官方资料支持书签列表与按需操作层：[Adobe Android](https://helpx.adobe.com/acrobat/mobile/view-manage-files/manage-bookmarks.html)、[Xodo 移动端改名流程](https://feedback.xodo.com/support/solutions/articles/35000202866-renaming-a-page-bookmark)。Xodo 文档更新于2022年，未将其写成当前版本实机调查；两者的内部持久化方式均未由这些资料证实。本项目的原生迁移是针对自身审计结果的实现。

2026-10-30原生大包补充：普通／分段／PDF位置、书签与批注恢复共五类改用小块IPC和Rust原子读写。精确旧超限探针返回预算错误，四类5 MiB及512 KiB书签在同一API29环境完整读写，原生冷启动明确恢复原查询、段落与锚点；原175文件／302提供器保护收尾通过。详见[本轮记录](Mobile_Native_Metadata_Memory_2026-10-30.md)。这项进展收口已知元数据整包Java堆故障，整个应用／渲染器内存、正文／附件通道、TalkBack与ARM/OEM继续单列。
