# v1.1.20 结构化文件深化：实际代码预审

这是接续预审，不是已实现或已验收。v1.1.19仍在固定安装器流程，必须完成独立同包和发布闭环后再进入20。沿用十三版路线最后一项“可信地修改结构化文件”，不新增格式、IDE或另一套编辑器。

## 已有能力不能重复立项

- `JsonEditorView.vue`已有源码/虚拟树、路径筛选、错误位置、标量替换、对象键改名、成员增删、数组增删、格式化/压缩、撤销及局部Schema。原生`formats/json.rs`的格式化采用源码token而非`JSON.parse/stringify`，已保留注释和数字原文；局部修改有源码范围校验。不能误称这些功能尚不存在。
- JSON超过4MiB已有分段只读、导航和搜索，不应为了完整树再次读入全文。
- YAML、XML、TOML分别有真实`YamlEditorView.vue`、`XmlEditorView.vue`、`TomlEditorView.vue`和独立原生分析器，不是都复用TextEditor。已有诊断、路径及源码跳转；JSON Schema不能被宣传为四种格式的通用校验。
- `TextEditorView.vue`已有保存时捕获编辑器、路径、读取代数、标签与编码的保护，可借鉴原则但不能直接套用PlainText历史逻辑。

## 优先核实的实际风险

1. JSON `transformSource`和`applyKeyRename`等操作在await原生后直接对当前editor全量dispatch；部分仅在调用前比较源码。应先复现“操作期间继续输入／切换文件／切换外部模式”，核对是否覆盖后续输入或新文件。不能只以按钮disabled推断源码不会变化。
2. 四种格式保存均先await分析，再从当前computed路径/模式/签名组装写请求；对回包也缺少统一文件归属核对。风险是旧源码和新文件身份混用。应捕获root/path/external/editor/代数/源码/签名，任何一步迟到均不能写向另一文件；正常输入仍可继续。
3. 非法源码确认、外部冲突“重新加载”等弹窗回调直接调用当前save/load。应核对弹窗所属文件，防止旧弹窗作用于新上下文；取消、读取失败必须保留草稿和既有分析。
4. JSON实时分析已有代数与源码比对，不能推倒重做；仍需核对Schema轮询、树选中、窗口关闭及标签缓存的组合，避免过期诊断、重复快捷键写入和未完成写入被当作清洁状态。
5. 格式化当前直接更换内存全文，虽然可撤销，不等于已经提供“变更前差异预览”。应在既有工具入口按需给出可取消的原文/候选差异，保留原字面量/注释/成员顺序，不把YAML别名、TOML表结构或XML命名空间强转成JSON树来修改。

以上是代码风险，不把尚未复现的假设写成已确认故障。若复现数据丢失风险，先修安全链路，再做路径体验与差异交互；每批记录原始失败和修正。

## 建议实施顺序和封板条件

1. 建四格式真实Vue页面+受控延迟IPC的失败基线，覆盖未失焦输入、异步局部修改、格式化、切换、重读、弹窗取消和保存中输入。UI修改前先出示意并实际查看；保留全部现有工具、六风格和紧凑布局。
2. 补统一但有边界的文件/快照归属。继承已有签名、防覆盖和原文写入，不另造自动保存；Ctrl+S只触发当前格式，写入参与窗口/移动保护。
3. 深化现有路径/诊断到源码联动，覆盖中文、JSON Pointer转义、数组和重复键；Schema仅按原实际支持范围说明。
4. 在原格式化、压缩和局部修改入口提供适当差异/损失说明、取消和整项撤销；常规保存不要额外多一步“先整理”。原格式不支持的转换不添加伪无损入口。
5. 用四格式原始字节和独立读者核对未修改区域、注释、数字、Unicode、顺序；失败/源变更不覆盖。保留分段与分析预算，固定样例评估大树可见项与连续输入，不用关闭动效冒充优化。
6. 完整发布质量、Rust、实际页面、固定安装器本版+所有历版、独立同包、封板CI、原包公开回下载后才发布；README保留开头，说明在末尾。十三版路线全部实际发布后，再按用户要求规划至少十个后续版本，继续深化现有能力。
