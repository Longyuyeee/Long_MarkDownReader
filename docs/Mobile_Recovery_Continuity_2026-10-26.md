# 手机端恢复核对与原任务返回

本轮推进阶段 1B 的一个用户任务：保存或文字导出异常后，查看已保护的版本，再返回刚才的编辑或导出任务。沿用移动独立分支，不改桌面工作目录。

## 实际问题与设计依据

生产构建的改前操作复现了三处问题：保存恢复入口先关闭文档并切到设置；文字导出入口清空导出快照；刷新详情把已选择的原文切回草稿。原始观察保存在 [基线报告](evidence/mobile-recovery-continuity-2026-10-26/before/report.json)，其中 `passed` 表示采集完成，三个缺陷字段均为 `true`。

本轮继续核对官方资料，未声称安装或录制了竞品 App：

| 来源 | 文档描述 | 本项目采用的交互判断 |
| --- | --- | --- |
| [Notion 移动版本历史](https://www.notion.com/help/duplicate-delete-and-restore-content) | 从页面菜单进入按时间排列的版本，点开一个版本查看，再复制内容或恢复。 | 列表与核对详情分层；切换版本与执行另存分开。 |
| [Obsidian 文件恢复](https://obsidian.md/help/plugins/file-recovery) | 在设置进入文件快照，选择文件与快照后，可复制内容或恢复；快照是本机完整内容。 | 继续保留设置中的历史入口，同时让异常现场直接进入；明确完整版本和独立副本。这份文档没有说明移动端返回细节，不能据此断言竞品实机行为。 |
| [Android 对话目的地](https://developer.android.com/guide/navigation/backstack/dialog) | 临时层位于已有目的地上方；转向普通目的地时清除上层对话目的地。 | 核对时保留原任务；用户明确另存并成功打开副本后，结束这次核对任务。当前实现采用 Vue 任务层，并未迁移为 Android Navigation。 |

## 完成的交互

- 从保存异常进入：先确认私有草稿保护，再显示独立的恢复任务。原编辑器与撤销历史继续存在，底层不能被误操作。
- 从文字导出进入：保留同一个导出组件、内容快照、错误、完成状态与滚动位置；返回后可继续重试。
- 返回顺序：问号说明 → 核对详情 → 恢复列表 → 实际来源任务。设置入口仍返回设置。返回恢复列表时恢复选中行和滚动；同一次核对任务内重开记录保留所选版本。
- 读取、复制或导出处理中消费返回与重复动作。刷新失败继续显示上次读到的完整版本；刷新成功不改变所选原文。
- 另存仍生成独立文件并打开。写入成功但打开失败时保留该文件身份，按钮改为“打开已存副本”；在当前任务内重试不会重复生成文件，原文、草稿与恢复记录继续保留。
- 导出完整恢复记录的结果显示在当前核对页。取消、失败和成功都不清除恢复记录。
- 页面只保留“原文件的写入未确认”等必要状态；版本含义、异常解释和另存行为收进可点击问号。导出详情不显示原文件可能部分写入的警告。

“另存并打开副本”是明确的新文档操作，成功后结束原恢复/导出任务；副本的文档返回沿用已有资料来源规则。本轮没有新增“副本 → 恢复详情 → 原编辑器”的跨文档回退链，不能把它与只读核对后返回原任务混为一谈。

保留的差异：设计使用占位日期、两条列表记录和另一导出文件名；正式页使用真实测试数据、现有图标和字体。两者内容字形、文字行高及操作图标有少量差异，不声明像素完全一致。参考图本身的顶部栏也包含边线，不将其称作精确 64px。

## 验证与边界

具体验证结果、构建资产和源码哈希见 [验证记录](evidence/mobile-recovery-continuity-2026-10-26/verification.json)。新增 `npm run test:mobile-recovery-layers-browser` 覆盖现场进入、版本与帮助、刷新失败、原编辑器与撤销重做、原导出重试、21 条记录滚动、复制繁忙返回、已写入但打开失败与同一副本重试、完整恢复文件下载，以及深色窄屏大字。

`npm run build:mobile` 与 289 项现有逻辑测试通过；本轮相关浏览器验证共 59 组：恢复任务 9、写入恢复 6、文字导出 6、附件包导出 11、导航 8、帮助 14、可访问性 5。最后一轮仅调整恢复列表样式及两个入口的触摸反馈，之后重新构建并重跑恢复任务 9 组、可访问性 5 组；不因样式调整反复重跑全部历史脚本。新增 4 次可访问性扫描无检测到的 A/AA 违规，这不等于完整读屏验收。构建仍有原有分包体积提示。

仍需 Android 原生验证真实 IME、系统保存选择器、预测性返回、后台与进程死亡恢复。副本身份和页面位置仅在当前任务内保留，本轮未新增跨重启的恢复副本回执，也未新增 APK 或改动原生存储格式。阶段 1B 继续处理图片附件和外部来源；完整恢复工作流及原生验收仍在后续阶段。
