# P1-A1 图片变换与可靠另存后端审计

审计日期：2026-08-15

版本基线：`1.0.10` 之后的开发增量

阶段状态：后端切片已实现，等待右侧媒体工作区接入

## 1. 需求对齐

本阶段服务于“覆盖日常管理和基础编辑，并把内容成体系管理”的初始目标。图片编辑继续留在资料库右侧媒体工作区，不创建新的顶层界面；保存策略固定为另存新副本，原图不被覆盖。

首个安全子集为 PNG、JPEG、WebP、BMP 的 90 度旋转、水平/垂直翻转、指定宽高缩放和上述格式间转换。GIF 动画、ICO 多尺寸图标和 AVIF 暂时保持只读预览，避免在没有帧/层级保真证据时把第一帧导出误称为完整编辑。

## 2. 已实现能力

- 新增有界图片处理内核，最长边限制 `16384 px`、像素上限 `50,000,000`、输入与输出上限 `100 MiB`、解码分配预算 `512 MiB`。
- `inspect_image_edit_source` 只对资料库内可编辑图片生成尺寸与 SHA-256 源身份，外部媒体授权仍然只有预览。
- `save_image_transform_copy` 同时校验源路径、目标路径、扩展名、源摘要和处理期间源字节稳定性。
- 输出经隔离编码和结构复读后，使用 `write_new_bytes` 原子创建；目标已存在或等于源文件时拒绝覆盖。
- 落盘后再次复读字节、摘要和尺寸，并复核源文件未变；失败时只清理与预期输出完全一致的本次新建文件。

## 3. 自动化验证

- `cargo test image --lib`：12 项相关测试通过。
- `cargo test saves_verified_copy_without_changing_or_overwriting_source --lib`：真实临时 PNG 到 JPEG 旋转、翻转、缩放、源字节不变、目标拒绝覆盖通过。
- `npm run check:image-transform-copy`：依赖特性、资源预算、格式白名单、冲突检测、原子新建、复读与 Tauri 注册合同通过。
- `cargo check --locked --manifest-path src-tauri/Cargo.toml`：通过后方可提交。

## 4. 当前边界与下一步

此提交只建立后端安全内核，不把公开格式能力提前改为“可编辑”。下一步 P1-A2 在现有 `MediaViewerView` 中加入编辑模式、尺寸约束、变换预览和另存对话框；完成桌面运行证据后，再同步更新共享格式注册表、能力矩阵、README 与发布说明。

裁剪、压缩质量、EXIF/隐私元数据清理属于后续 P1-A3，不与首个后端原子切片混在一次变更中。
