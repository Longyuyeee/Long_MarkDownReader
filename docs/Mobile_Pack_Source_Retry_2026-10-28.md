# 移动端：导出前检查附件与原地重试

2026-10-28，阶段5E1，起点 `7d9363e31`，沿用 `codex/mobile-0.1.0-foundation`。按[一次推进一个用户任务的规则](Development_User_Task_Plan_2026-09-22.md)，本轮处理“导出前有附件暂时读不到，确认是哪份笔记并继续检查”。仅修改移动工作树，仅本地提交。

## 实测与竞品

[改前正式App报告](evidence/mobile-pack-source-retry-2026-10-28/before/report.json)确认：缺失路径会准确报出，失败不生成残缺包；已有完整包在来源附件消失后仍可下载，同编号包不会重复生成。这些是已有保护，继续复用。实际断点是重试放在正文中；320×346、200%文字滚到重试后，失败原因已滚走，底部历史入口超出视口。原返回页头已有吸顶保护，未将其误报为缺失。

本轮查阅[Acrobat手机保存副本](https://helpx.adobe.com/acrobat/mobile/view-manage-files/save-copy.html)：从文件及位置进入操作，再决定副本位置和名称；参考明确对象后继续当前任务的顺序。[Obsidian手机版](https://obsidian.md/help/mobile)提供返回／前进和按需菜单，不把桌面Ribbon全部展开；参考当前层只保留必要动作。[Obsidian附件说明](https://obsidian.md/help/attachments)指出附件是普通文件，可位于资料库或笔记邻近目录，因而保留准确相对路径帮助定位来源。[Joplin导出说明](https://joplinapp.org/help/apps/import_export/)只用于核对完整归档的目标，不把它描述为手机端取消／重试界面。未安装或录制竞品；固定重试、快照与返回保持是项目设计和本地验证结果，见[调研记录](evidence/mobile-pack-source-retry-2026-10-28/research-sources.json)。

## 用户操作

| 当前情况 | 页面与动作 | 保留内容 |
| --- | --- | --- |
| 附件暂时不可读 | “检查附件”显示源笔记名和准确错误路径，底部固定“重新检查附件” | 不写原笔记或草稿，不生成缺附件的包 |
| 等待检查 | 固定动作显示正在检查并禁重复，返回也等待本次回复 | 同一份捕获正文、来源、revision和快照编号 |
| 查看历史或问号 | 按需进入；一般说明仍放问号，历史入口不占固定底栏 | 返回原错误、真实入口焦点及非零滚动位置 |
| 来源恢复 | 显式重试完整检查，通过后回已有导出核对及附件清单 | 原捕获正文和原笔记身份，复用既有附件处理 |
| 下载失败／取消 | 保留已有导出状态与记录，继续原任务重试 | 已准备附件不再次依赖源文件；同一完整包继续使用 |
| 短屏与200%文字 | 固定返回和当前重试；正文单独滚动，也可键盘滚动 | 不靠整页滚动寻找主要动作，历史返回恢复滚动和焦点 |

只在检查阶段启用新的固定布局；准备好的清单、历史详情、移除确认与下载协议继续复用。源笔记名比尚未生成的包名更便于辨认，检查阶段使用现有文件图标，减少大字下PACK徽标挤占。保留“包含未保存内容；原笔记仍需保存”的提醒，并统一该流程的提醒／错误文字色；删除解释性常驻文案不是隐藏真实风险。

## 设计冻结与修正

先冻结Vue／HTML／PNG设计，后修改生产。v1九状态完整审图；v2改为紧凑源笔记身份。实际浅色检查发现旧未保存提醒对比度不足，保留[失败报告](evidence/mobile-pack-source-retry-2026-10-28/first-failure-light-warning-contrast.json)与原图，v3先冻结颜色修正。实际历史返回发现入口被卸载，保留[失败报告](evidence/mobile-pack-source-retry-2026-10-28/first-failure-history-trigger-unmounted.json)与原图，v4保留真实入口，全部九张PNG与v3字节相同。随后检查准备完成和下载失败页，v5将同一套可读文字色用于这些步骤，并加入下载失败参考。

[最终设计／实页对照](evidence/mobile-pack-source-retry-2026-10-28/comparison.html)包含10状态参考与12张实际截图。逐项核对名称、坐标、尺寸、字号、行高、颜色，差异0，见[几何记录](evidence/mobile-pack-source-retry-2026-10-28/visual-comparison.json)。实际截图均已审阅，其中四张最终图与前一已查看运行字节相同，另外八张直接查看；全部改前图已查看。原图和焦点保留，未加工图片或替换字体，不声明整图像素相同。

测试脚本也保留三类原始失败：把CodeMirror当textarea使用、在键盘滚动生效前断言，以及向axe的沙箱子frame写入localStorage。分别改为核对真实编辑器／草稿、等待真实非零滚动、只向顶层测试页注入数据；没有过滤或吞掉页面错误。它们是测试假设问题，不记为产品缺陷。

## 最终验证

`npm run build:mobile`通过，随后同一候选执行23组浏览器检查：新来源重试6组、导出分层11组、附件包原回归6组；另有4组注入延迟回复组件检查。报告无页面错误或外部请求；底层引擎未变，未重复全量历史测试。新专项四次axe扫描无违规；检查失败和下载失败各有一处背景重叠未决，保留原报告，原图及计算样式人工补查为11.244:1、10.824:1，见[补查记录](evidence/mobile-pack-source-retry-2026-10-28/contrast-review.json)，不称为axe自动解决。

覆盖首次源缺失、完整检查失败不产生部分包、等待防重复与返回保护、显式重试、历史和帮助的逐层返回、短屏大字／暗色／真实键盘滚动、完整原文与草稿签名／revision保护、来源恢复后准备、下载失败后来源再次消失、同包精确重试。注入原生分支验证取消／失败／成功均复用同快照，卸载后不接纳迟到回复。

三份真实下载原样保存并独立通过Python ZIP／CRC检查；新专项核对整个改写后的草稿与二进制字节、重试下载与保留包字节相同。原附件包专项继续验证干净原文的BOM和混合CRLF／CR／LF，见[归档内容证据](evidence/mobile-pack-source-retry-2026-10-28/archive-content-review.json)。没有将“下载开始”写成外部保存已核对。

生产仅改 `PortableExport.vue`、父任务的检查阶段样式／返回名称接线及对应CSS。`storage.ts`、TextPack打包／路径／预算、编辑器、恢复和Android插件均与起点一致；父组件接线和CSS增量也经逐字校验，见[源码与服务身份](evidence/mobile-pack-source-retry-2026-10-28/provenance.json)。设计组件仅适配导入路径后与生产组件匹配。

本地复现：构建完成后使用已有移动预览，设置 `LONGEDIT_PLAYWRIGHT_MODULE`，运行 `node scripts/test-mobile-pack-source-retry-browser.mjs`、`node scripts/test-mobile-pack-source-replies-browser.mjs` 及两个原有附件包专项。截图和报告自动使用新目录；冻结目录和最终证据拒绝覆盖。
