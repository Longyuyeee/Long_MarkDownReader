# UX-52 应用内默认打开管理审计

状态：**源码与合同验收通过，安装态复测留待下一补丁候选**

## 用户问题

原“格式能力”页面只能把 Long编辑注册为候选后跳转 Windows 默认应用首页，无法在当前页面关闭候选，也看不到真实默认状态。入口名称与实际能力不一致，用户需要离开当前上下文才能管理。

## 本次实现

- 37 类允许外部编辑或预览的格式继续按格式逐项管理，不批量接管全部扩展名。
- 展开格式后直接显示未启用、已启用、当前系统默认或部分扩展名默认状态。
- “启用 Long编辑打开”只为当前格式写入当前用户的 `OpenWithProgids` 与 Long编辑能力映射，不改变其他格式。
- “关闭 Long编辑打开”直接从当前页面移除当前格式映射；注册表项不存在时视为已关闭，权限或写入错误会明确反馈。
- 页面恢复焦点时自动刷新已展开格式的状态，用户完成系统确认后无需重新进入页面。
- 设置页只保留“管理打开方式”入口，不再并列提供笼统的“打开系统设置”。

## Windows 边界

Windows 10/11 保护每个扩展名的 `UserChoice`。Long编辑只读取该值用于显示状态，不直接写入、破解哈希或调用 `reg.exe`。因此启用和关闭候选可在应用内完成；“设为系统默认”仍必须由用户主动点击，并由 Windows 显示一次系统确认。这个确认是操作系统安全边界，不是产品页面缺失。
