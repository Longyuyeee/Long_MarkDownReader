# v1.1.0 / F1 快速笔记首批实现

日期：2026-10-11。用户已明确批准 UI-F1-01 R2。运行/公开版本仍为 1.0.26；本提交不是发版，不代表 F1 或全界面重构完成。

后续进展：[保存重试与窗口收尾](V1_1_0_F1_QuickNote_Reliability_2026-10-11.md) 已实现稳定操作标识与真实字节对账；以下列表保留首批实现当时的状态，最新验证范围以上述记录为准。

## 已实现

- 原生快速笔记窗口调整至 560×460，保留置顶、拖动、关闭和显式保存；资料库、保存到、模板保持单行，窄于 450px 才换行，编辑区占剩余空间。
- 保存目标明确显示：默认当前库的 Inbox，可选库根目录或用原生选择器选择目录；后端执行资料库边界校验。成功后按库记忆目标目录，不更改主窗口活跃库。
- 提取已有 Markdown 模板为共享模块；资料库模板内容不变。快速笔记应用模板前若已有正文，需确认替换。
- 用已有 `create_format_file` / `write_new_bytes` 写入完整正文，替代先建空文件、再写内容。显式保存、空输入校验和忙碌保护保留；失败不清空正文。
- 支持保存后关闭、继续记录、请求主窗口打开。持久化成功后，即使刷新/打开/关闭失败，也显示“文件已保存，无需重存”及真实路径，不误报正文保存失败。
- 主窗口打开只处理同一活跃库，并重新调用受限 Markdown 读取后导航；跨库时保留主窗口状态并提示先切库，不静默清空其标签与草稿。

## 审计后必须继续的工作（不得宣称闭环）

1. 独立 quick-note 窗口：主区打开的成功/拒绝/超时、关闭确认、中文输入法、原生目录选择和深色主题专项验证。目前打开交接已实现，但未进行双窗口端到端验收。
2. 强幂等边界：当前真实“写入前失败 → 修复 → 重试”已验证；`write_new_bytes` 在落盘后清理 sidecar 仍可能报错，回执丢失也未覆盖。需要稳定操作标识及重试对账，不能把随机文件名和按钮防连点当作全场景幂等。F1 完成前必须解决。
3. 目标库记忆、失效目录提示及设置入口完善；保存到另一库后，目前不自动切主窗口，而是明确提示先切库。这是草稿保护边界，不代表跨库交接闭环。
4. 收集箱资料库视图与归档弹窗仍须单独示意审批，再完成归档、防覆盖和复开流程。当前仅完成快速笔记的首批操作。
