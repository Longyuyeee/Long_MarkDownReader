# F1 历史副本内部发布步骤

2026-10-11，接续 `b7cb4a33`。仅内部后端服务，无 UI 修改、无执行命令、无升版。

## 已实现

`archive_history::publish` 在历史 lease 内复查来源预检清单和暂存副本，在暂存目录写入并同步独立 publish-intent.json；构建只包含快照的 publish-payload 目录，逐文件限长读取、摘要验证、新建写入、同步和回读；再次复查来源后，以既有 Windows 无覆盖重命名原语发布目标历史目录。目标路径由当前调用的 document target 重新计算，不使用日志指示路径执行。

原历史和原始暂存副本均不删除。目标目录不混入日志文件。既有目标冲突拒绝、不合并；无历史副本返回无需发布错误，不造空历史。非 Windows 仍不支持无覆盖发布。

发布意图文件使用 create_new，失败/中断后的再次调用不会盲目续作，必须交由未来恢复协调器核对。发布成功后记录 published 标记；标记写入失败时返回 PublishedHistory，附 marker_error，不能报成“没有发布”，避免调用方错误重试。

## 审计边界

本步骤仅发布历史副本，不移动正文、不删除源历史、不更新标签/索引，也不是完整事务。上层必须完成来源身份、草稿和依赖协调才能接入。无用户入口，preflight canExecute 仍为 false。

已有 inspect_staging 的 Prepared 只表示原始暂存副本有效，**不代表发布状态或归档成功**；发布恢复必须额外读取意图、核对实际目标，不能仅信任 published 标记。当前尚无这一自动恢复流程。外部进程修改、父目录替换、断电和跨文件系统持久性仍未解决；同进程 lease 不能代替系统文件锁。

逐文件限长回读，最多单快照 64 MiB；写入/回读期间可同时持有两份字节缓冲，批次性能与更低内存流式发布仍待验收。此次不宣称性能收口。

新增三个真实临时目录测试：发布成功且保留源历史、目标只含快照、再次调用拒绝；发布后标记被目录占用导致写入失败，回执仍准确标明目标已经存在且正文正确；来源历史变化导致拒绝并不创建目标。
