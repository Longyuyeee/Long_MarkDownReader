# A0M JSON 工作区体验审计

日期：2026-08-04

对应需求：UX-25、UX-26、UX-28

结论：代码侧已完成，等待下一安装包复测。

## 本步完成

- JSON 源码继续使用 A0L 的九主题 CodeMirror 配色；结构树按对象、数组、字符串、数字等类型显示语义色，指标、兼容状态和路径区域形成清晰层级。
- 次要源码工具和“结构与诊断”均可独立收起；窄屏默认隐藏诊断侧栏，避免长期挤压源码和树形正文。
- “JSON Path”改为“字段路径与快速定位”，说明可按字段、路径或值检索，并提供 `$.items[0].name` 示例。
- 路径结果点击后切回源码并定位；复制反馈包含实际字段路径；语法错误、无字段、无匹配和超过首批展示数量均有明确说明。
- Rust 继续承担 JSON 解析与路径分析，保留 16 MB 源码、20 万节点和 2 万路径的安全上限。
- 前端只在分析结果变化时建立父子索引；折叠/展开按父子关系遍历，不再为每个节点反复扫描全部祖先。
- 树行使用固定 44 px 高度和带缓冲的虚拟窗口，只挂载可视区域附近的 DOM。超过 500 个路径的大文档首次仅展开根层，下级按需展开。
- 所有结构编辑仍只修改内存草稿，只有用户点击“保存”才写入源文件。

## 自动门禁

- `check:json-workspace-experience` 检查字段路径说明、源码定位、复制反馈、侧栏收起、父子索引、按展开节点遍历、虚拟窗口和 Rust 安全预算。
- 专项门禁已接入 `ci:patch-release`，并明确禁止旧的 2,000 行 DOM 截断逻辑回归。

## 安装包复测

1. 在浅色、深色和高对比主题打开普通 JSON/JSONC，检查源码、结构树、指标、兼容状态、字段路径和诊断的层级与文字对比度。
2. 收起和展开“结构与诊断”，并在 100%、150%、200% 缩放及窄窗口检查正文不被挤压。
3. 使用至少 20,000 个已分析路径的大 JSON，切换树形、滚动、折叠和展开节点，确认界面持续响应且 DOM 不随总节点数线性增长。
4. 搜索字段名、完整路径和值片段；确认点击结果切回源码精确定位，复制反馈包含所复制路径。
5. 在树中修改标量或结构，确认未点击保存前磁盘文件不变，撤销有效，点击保存后才写入。
