# v1.0.22 保存后切换文件：生命周期修复

日期：2026-09-12。前置 `93635366`；对应主 PRD 1.1 的安全保存。旧候选 `ada0cd60` 仍被拒绝，未改其原始截图或报告。

用户场景：“会议纪要写好了，按保存，马上去看预算；回来为什么显示保存失败和未保存？”

## 原因验证与修复

测试从 Git 读取固定旧候选真实 save 函数，用可控异步写入回执执行“开始保存 → 编辑器卸载 → 回执返回”，稳定复现 `reading 'state'` 的错误反馈。这里的时间顺序是受控代码级复现，不是本机手动操作或完整 Tauri 验收。

修复捕获原文件、编辑器及加载代次；旧回执不再访问销毁的编辑器或写入后来选中的文件。已离开的文件只更新原标签的磁盘签名；正文和保存格式均未再变化时才清除脏状态，有新编辑则保留草稿。再次进入同一文件时等待正在进行的保存结束，再判断恢复草稿或读磁盘。卸载使旧加载失效。真实保存失败仍显示文件名和错误，不伪装成成功；旧冲突对话框也不能重新加载后来打开的文件。

这不是简单屏蔽 null 错误：还处理旧草稿与磁盘签名不一致，避免下一次保存误冲突或丢失继续编辑的内容。

## 验证及不放宽标准

- 8 项生产函数回归通过：旧版复现、卸载后回执、立即返回等待、切文件隔离、新编辑保留、保存策略变化、真实失败仍报错及加载顺序契约。
- 类型检查/生产构建通过，6,280 模块；当前开发总审计通过。未重复 Rust 编译，因为本轮仅改前端及验收代码。
- 安装脚本保留原“磁盘落盘后立即切走再返回”动作顺序，不新增延迟；原截图先保存，再要求界面无“保存失败”且文件标记为“已同步”。有错误仍保留截图并失败，不只依赖磁盘内容。
- 本机安装授权尚未明确，未覆盖用户安装、未操作真实资料库。因此真人语气/场景仅用于设计操作，本轮不声称已完成真实 UI 复验。
