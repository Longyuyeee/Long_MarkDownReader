## 环境与操作

Windows 真实 Tauri debug 应用，运行版本 1.0.22，约 1000×700 暗色窗口；Vite 本地服务和独立 WebView 用户目录。仅使用临时资料库中的合成文件，不覆盖用户已安装版本、不操作真实资料。通过 computer-use 的原生鼠标、键盘输入并逐步查看截图，没有直接调用保存函数或修改页面状态。

1. 打开 `客户会议纪要.txt`（原文“客户会议纪要 / 交付日期待确认。”），在正文输入“客户说周五前给确认版，我下午再跟进一次。”，界面显示未保存。
2. 按 Ctrl+S，看到已同步；打开 `项目预算.txt`，实际加载“软件服务：3000 元。”，再返回纪要。新正文保留，状态为已同步，没有看到保存失败反馈。
3. 继续输入“预算我还没核对，先别发给客户。”，不保存。直接检查磁盘，仍只有步骤 1 保存的正文，未包含新备注。
4. 切换预算再返回，备注仍在，状态仍为未保存。随后点击保存按钮，变为已同步；磁盘包含完整两次新增内容。

本次 UI 保存已在切换前完成，不能声称原生操作复现了“回执晚于卸载”的竞争时间顺序；该顺序仍由既有 8 项受控生产函数回归覆盖。测试过程有一次截图 ID 失效，刷新观察后重试点击；窗口曾被其他应用遮挡，重新激活目标，不操作或保存无关界面。这些情况不计为产品测试通过或失败。
