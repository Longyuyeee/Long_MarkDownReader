# v1.0.13 发布后侧栏信息架构审计

日期：2026-08-21  
状态：已验收，尚未进入新安装包

## 审计结论

| 入口 | 结论 | 当前用途与处理 |
| --- | --- | --- |
| 文件 | 保留 | 浏览、搜索和管理资料库文件，是主入口。 |
| 搜索 | 保留并改名 | 原“保存”实际保存的是关键词与格式筛选，并非保存文件；改为“搜索”，面板说明不会复制或修改文件。 |
| 目录 | 保留 | 展示当前文档标题大纲，支持快速定位。 |
| 标签 | 保留并解释 | 标签来自 Markdown 正文中的 `#标签名`；保存文档后自动汇总，非 Markdown 文件不显示添加控件。 |
| 关系 | 保留核心能力并收缩 | 原“引用”在窄栏嵌入局部图谱，和完整知识图谱重复且容易变形；现只显示当前 Markdown 的链出、链入和清晰数量，需要图形浏览时进入知识图谱。 |
| 最近 | 保留 | 汇总收藏与最近打开，属于高频回访入口。 |
| 备份 | 保留 | 展示和恢复当前文件的本地历史快照。 |

七个入口均补充了完整用途提示和 tab/tabpanel 可访问性关联。侧栏不再让“搜索条件”冒充“文件保存”，也不再把完整关系画布压进约 200 px 的区域。

## 真实验收

使用隔离 Tauri 实例和临时真实资料库执行审计。资料库包含两个 Markdown 文件、一个 `#product` 标签，以及一条正向和一条反向 `[[笔记名]]` 关系。

预期：显示“文件、搜索、目录、标签、关系、最近、备份”；关系面板为 1 条链出、1 条链入；移除嵌入图谱；侧栏宽度不超过 262 px；页面和面板无横向溢出。

实际：全部七个入口名称和用途提示正确；关系计数为 1/1；未挂载局部图谱；200 px 侧栏下页面与各面板横向溢出均为 0；运行时错误 0。结果为 `accepted`。

证据位于 [`docs/evidence/post-v1013-sidebar-information-architecture/`](./evidence/post-v1013-sidebar-information-architecture/)，可使用 `npm run audit:sidebar-information-architecture` 重放。

## 后续边界

本轮只调整侧栏入口的命名、说明、关系面板密度和响应式表现，没有删除搜索、标签、关系、最近或备份的数据能力，也没有提升版本。后续发布前继续保留本审计与小窗口 UI 审计作为门禁。
