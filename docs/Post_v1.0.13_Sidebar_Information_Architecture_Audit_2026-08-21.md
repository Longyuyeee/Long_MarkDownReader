# v1.0.13 发布后侧栏信息架构审计

日期：2026-08-21  
状态：已验收，尚未进入新安装包

## 审计结论

| 入口 | 结论 | 当前用途与处理 |
| --- | --- | --- |
| 文件 | 保留 | 浏览、搜索和管理资料库文件，是主入口。 |
| 常用搜索 | 保留并解释 | 原“保存”实际记录文件页当前的关键词与格式条件，并非保存文件；点击条目会回到文件列表并重新执行该搜索。 |
| 目录 | 保留 | 展示当前文档标题大纲，支持快速定位。 |
| 标签 | 保留、后移并优化 | 标签来自 Markdown 正文中的 `#标签名`；作为 Markdown 专属工具移动到末位，面板增加格式徽标、当前笔记添加区和清晰的标签结果列表。 |
| 关系 | 保留核心能力并收缩 | 原“引用”在窄栏嵌入局部图谱，和完整知识图谱重复且容易变形；现只显示当前 Markdown 的链出、链入和清晰数量，需要图形浏览时进入知识图谱。 |
| 最近 | 保留 | 汇总收藏与最近打开，属于高频回访入口。 |
| 备份 | 保留 | 展示和恢复当前文件的本地历史快照。 |

最终顺序按通用性和使用频率调整为“文件、目录、最近、备份、常用搜索、关系、标签”。七个入口均补充了完整用途提示和 tab/tabpanel 可访问性关联。侧栏不再让“搜索条件”冒充“文件保存”，也不再把完整关系画布压进约 200 px 的区域。

## 真实验收

使用隔离 Tauri 实例和临时真实资料库执行审计。资料库包含两个 Markdown 文件、一个 `#product` 标签，以及一条正向和一条反向 `[[笔记名]]` 关系。

预期：按顺序显示“文件、目录、最近、备份、常用搜索、关系、标签”；常用搜索直接说明记录与重放行为；标签明确标记“仅 Markdown”，且句末标点不进入标签名；关系面板为 1 条链出、1 条链入；移除嵌入图谱；侧栏宽度不超过 262 px；页面和面板无横向溢出。

实际：全部七个入口顺序、名称和用途提示正确；`#product.` 正确汇总为 `#product`；关系计数为 1/1；未挂载局部图谱；200 px 侧栏下页面与各面板横向溢出均为 0；运行时错误 0。结果为 `accepted`。

证据位于 [`docs/evidence/post-v1013-sidebar-information-architecture/`](./evidence/post-v1013-sidebar-information-architecture/)，可使用 `npm run audit:sidebar-information-architecture` 重放。

## 后续边界

本轮只调整侧栏入口的命名、说明、关系面板密度和响应式表现，没有删除搜索、标签、关系、最近或备份的数据能力，也没有提升版本。后续发布前继续保留本审计与小窗口 UI 审计作为门禁。
