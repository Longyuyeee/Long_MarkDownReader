# M8-3 知识图谱性能与视觉收口审计

日期：2026-09-01

阶段结论：**通过；用户截图暴露的图谱可用性偏差已完成真实 Windows/Tauri 纠偏，可进入 v1.0.20 版本迁移与发布门。**

## 与最初路线的对齐

本轮没有新增知识图谱语义，也没有改变源文件写回边界。修复直接回到 M3B“专业视觉系统”和 M3C“稳定交互/大图性能”的原始要求：大量内容下先看清结构，再按需查看标签与详情；拖动、滚轮、单击选择、双击打开保持分离；视觉效果服务于悬停、选择和路径，不引入持续重绘动画。

## 实际代码修复

- 画布只绘制视口及安全边界内节点，并跳过视口同侧以外的关系；选中集合由逐节点线性查找改为 `Set`。
- 普通网络进入时不再自动选择“最强节点”，因此不会无缘无故弹出详情面板。
- 180 节点以上的状态环固定最多 24 个，并按关系强度、度数和新近性稳定排序；修正此前计算了受限集合却仍绘制全部状态环的偏差。
- 移除重复的 `M` 字母徽标和塑料感白色高光；节点使用克制的语义色与方向性微光，近景尺寸按缩放平方根增长，避免 300% 时变成巨型圆泡。
- 标签保持屏幕恒定字号、执行碰撞规避，并在 120 个以上节点时把近景标签限制为 28 个、中景限制为关键节点。
- 顶部高频区只保留视图、搜索、帮助和“图谱工具”；最短路径、节点比较、知识治理、SVG/PNG、重排、撤销/重做、缩放、适配和全屏统一进入原生弹层。弹层不再依赖 WebView2 传送布局。

## 真实 Tauri 对照

环境：Windows、Tauri/WebView2、1440×900、DPR 1.25、暗色主题、180 个合成 Markdown 节点、540 条连接、6 个社区。合成资料仅存在临时目录，仓库未包含用户内容。

| 指标 | 修复前 | 修复后 |
| --- | ---: | ---: |
| Canvas draw 峰值 | 7.1 ms | 5.1 ms |
| 超过 50 ms 的绘制 | 0 | 0 |
| 进入图谱自动选择 | 1 个节点 | 0 个节点 |
| 新近/强关系状态环 | 180 个资格节点均参与视觉竞争 | 最多 24 个 |
| 工具菜单 | 顶部多项并排、信息过载 | 1 个入口、13 个单行命令 |
| 运行时错误 | 0 | 0 |

峰值下降约 28%；多次复跑观察到 4.4～5.1 ms，均低于同一基线的 7.1 ms。工具弹层实测宽 248 px、高约 253 px，最大按钮高度 32 px，13 个标签全部保持单行。最终截图人工复核确认入口可见、弹层不遮挡默认画布、全图可适配视口、300% 近景仍可辨认节点与标签。
