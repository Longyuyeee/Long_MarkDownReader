# C0/C1 DOCX 结构化阅读首批审计与设计

更新日期：2026-07-27

开发分支：`codex/a4-format-closure`

对应需求：`FR-OFFICE-001`

## 1. 结论

DOCX 已从“未识别、无应用内工作面”推进到 **C0/C1 首批可用状态**：知识库中的 `.docx` 会在原 Library 右侧工作区打开，可阅读标题、段落、列表、表格和可见文本，使用目录与正文搜索定位，并查看生产者与高级对象兼容画像。

本批不宣称 C0 或 C1 全部完成，更不宣称 DOCX 可编辑。当前缺口是三类真实生产者 fixture、高保真样式/分页、真实图片渲染、页眉页脚/批注内容展示、全局索引和可靠写回。原文件始终只读。

## 2. 与基础需求的对齐

用户基础目标是“覆盖日常管理和基础编辑，并把内容成体系管理”。本批只解决其中 DOCX 的第一层：

| 目标 | 本批结果 | 判定 |
|---|---|---|
| 在管理器内打开 | 保留文件树、统一标签和关系入口，在 Library 右侧嵌入 | 已交付 |
| 日常阅读 | 标题、段落、列表、表格、换行与可见修订文本结构化展示 | 首批已交付 |
| 查找定位 | 标题目录、正文搜索、上一项/下一项和命中高亮 | 已交付 |
| 能力边界可见 | 明示“结构化阅读、原文件只读”；高级对象集中警告 | 已交付 |
| 体系化管理 | 格式注册、路由、最近标签链路已接入；全局正文索引未接入 | 部分完成 |
| 基础编辑 | 未开放，等待局部 OOXML 写回与保真矩阵 | 未开始 |

## 3. 架构与安全边界

```mermaid
flowchart LR
  A["Library 选择 .docx"] --> B["共享格式注册表"]
  B --> C["WorkspaceGuard 路径、扩展名与大小校验"]
  C --> D["有界 ZIP/OOXML 解析器"]
  D --> E["结构块 + 目录 + 兼容画像 + 警告"]
  E --> F["Library 右侧 DOCX 工作面"]
  F --> G["目录定位 / 正文搜索 / 只读阅读"]
```

后端固定边界：

- 原始 DOCX 最大 64 MiB；
- ZIP 项最大 10,000 个；
- 解压后总量最大 256 MiB；
- 单 XML 部件最大 32 MiB；
- 可见结构块最大 50,000 个；
- 可见文本最大 2,000,000 字符；
- 表格单元格最大 100,000 个；
- 拒绝路径穿越、重复 ZIP 项、缺少 `[Content_Types].xml` 或 `word/document.xml` 的包；
- 拒绝 OOXML 中的 `DOCTYPE`，不解析外部实体；
- 命令只允许当前知识库内已存在的 `.docx`，不信任前端路径。

解析器复用项目已锁定的 `zip` 与 `quick-xml`，没有为首批阅读引入新的 Office 写入依赖。

## 4. 结构模型与兼容画像

首批结构模型输出：

- 标题：识别直接声明的 Heading/Title/标题样式 ID，生成 H1～H6 目录；
- 普通段落与显式换行、制表符；
- 有序/无序列表的层级信息；
- 表格的行、单元格和检索文本；
- Drawing/Pict 图片对象数量与占位提示；
- 可用于当前文档搜索的纯文本与稳定块 ID。

兼容画像输出：

- Core Properties Creator 与 Application；
- 段落、标题、列表、表格、媒体、页眉和页脚数量；
- 脚注、尾注、批注、修订、域、内容控件、公式、嵌入对象和 AltChunk；
- 未知 `word/` 部件清单；
- 对当前未建模对象生成显式只读警告。

可见修订文本不会因检测到高级对象而消失，但修订语义、作者、接受/拒绝状态尚未建模。

## 5. 右侧工作面设计

工作面沿用项目原有紧凑字号、颜色变量和空间层级：

- 顶部：文件身份、能力标签、正文搜索与重读；
- 左栏：标题目录与兼容画像；
- 中央：纸张式结构化正文；
- 顶部警告条：高级对象及当前降级原因；
- 底部状态：大小、结构块、字符数与“不写回 DOCX”承诺。

真实桌面证据：

- `docs/evidence/a5-stage-a/c1-docx-structured-reading.jpg`
- `docs/evidence/a5-stage-a/audit-manifest.json`

证据同时断言 Library 外壳存在、左侧栏宽度有效、DOCX 工作面嵌入右侧、目录/正文/表格可见、搜索命中和高级对象警告有效。当前总门禁为 33 项真实 Tauri 检查和 25 张机器校验截图。

## 6. 自动化验证

本批新增三组 Rust 回归：

1. 标题、段落、列表、表格、图片对象与换行解析；
2. 修订、域、内容控件、公式、嵌入对象、AltChunk 等高级对象画像，且可见文本不丢失；
3. 非 ZIP、缺少关键部件、DOCTYPE 与不安全包形状拒绝。

格式合同校验 30 类格式、62 个扩展名，并锁定 DOCX 的大小、能力等级、适配器、路由、解析预算、只读文字和 Library 右侧嵌入。

最终 `npm run ci:check` 全量通过：Rust 功能测试 292/292、性能测试 1/1、真实桌面检查 33/33、25 张截图、生产依赖 0 个漏洞；100 MiB PDF 范围基准仍只请求约 255.9 KiB，本机 58 ms。Vite 仅保留既有大分包非阻断警告，Windows Rust 增量目录偶发“拒绝访问”收尾警告不影响编译与测试结果。

## 7. 当前不能宣称的能力

- 不能还原 Word/WPS 的分页、字体度量、浮动布局、主题和复杂样式；
- 图片当前只显示对象占位，不解包渲染真实媒体；
- 页眉、页脚、批注、脚注和尾注当前只进入兼容画像，不展示内容；
- 标题识别尚未解析 `styles.xml` 的继承和本地化样式映射；
- 当前搜索只覆盖已打开文档，不等于全局知识索引；
- 不能创建、修改、覆盖或另存 DOCX；
- 当前自动 fixture 是合成 OOXML 合同样本，不等于 Microsoft Word、WPS、LibreOffice 三类真实生产者矩阵。

## 8. 后续收口顺序

### C0-2：真实生产者兼容矩阵

1. 收集可再分发的 Microsoft Word、WPS Office、LibreOffice DOCX；
2. 每类覆盖标题继承、列表编号、表格合并、内嵌/浮动图片、分页、页眉页脚、批注、修订和未知扩展；
3. 记录来源、生成步骤、许可证、预期结构和原程序截图；
4. 以真实解析差异补齐 `styles.xml`、`numbering.xml`、关系和媒体读取；
5. 失败样本必须返回稳定阻断/降级原因。

### C1-2：只读工作面收口

1. 渲染真实内嵌图片并限制单图/总媒体预算；
2. 解析样式继承、编号定义、合并单元格和分页标记；
3. 展示页眉页脚、脚注/尾注和批注只读内容；
4. 接入可重建全文索引，搜索结果定位到块或表格；
5. 三类生产者完成打开、搜索、定位和桌面视觉矩阵。

### C2：安全基础编辑

只有 C0/C1 证据完成后才开放：

1. 普通段落和标题文本；
2. 经验证的基础字符样式；
3. 简单列表与表格文本；
4. 目标 OOXML 部件局部修改；
5. 未触及 ZIP 部件逐字节保留、签名冲突、临时副本、语义复读、原程序复开与失败不损坏门禁。

包含修订、域、内容控件、复杂绘图或未知扩展的目标对象默认只读；不得以重建整份 DOCX 冒充保真编辑。
