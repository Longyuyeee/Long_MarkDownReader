## 2. 真实代码事实

### 2.1 对象定位当前分散在三个入口

- `src/views/LibraryMode.vue` 的 `openKnowledgeSearchResult` 按格式解释搜索定位器。
- `src/components/GraphView.vue` 的 `openNode` 独立解释图谱定位器。
- `src/components/FileRelationContext.vue` 的 `openNode` 再维护一套关系上下文分派。
- `src/services/fileNavigation.ts` 目前只负责 `{ path, query }` 路由，没有统一的定位器类型、格式到查询参数映射或返回来源合同。

这意味着 DOCX、ODS、ODP、PPTX 等格式虽然已有可用定位数据，但每个入口仍可能发生语义漂移。M4 首个实现不应继续在三个调用点分别追加分支。

### 2.2 搜索、图谱和工作台覆盖不一致

真实跨格式资料库核对结果：Markdown、OPML、DOCX、ODS、ODP、PPTX 的内容可被找到，`Roadmap.table.json` 内部行文本没有被当前知识索引命中，即 **预期 7/7，实际 6/7**。

内部定位方面：

| 格式 | 预期 | 当前实际 |
| --- | --- | --- |
| DOCX | 命中并定位内部段落 | 已返回 `docx-block/docx-block-6`，真实打开后定位到目标块 |
| ODS | 命中并定位单元格 | 已返回 `ods-cell/ods-sheet-1:A1` |
| ODP | 命中并定位幻灯片 | 已返回 `odp-slide/odp-slide-1` |
| PPTX | 命中并定位幻灯片 | 已返回 `pptx-slide/256` |
| OPML | 命中并定位内部节点 | 能搜索到文件，但没有内部节点定位器 |
| Table | 命中并定位行/视图 | 内部行文本未命中，因此也没有定位器 |

图谱当前可见对象族包括 Markdown、Table、OPML/OPML 节点、PPTX/PPTX 幻灯片；M1 已有的 DOCX、ODS、ODP、Workbook 对象尚未进入同等图谱覆盖。工作台的对象级行动主要仍是 Markdown 待办和 PDF 批注，不能宣称已覆盖全部 M1 对象。

### 2.3 返回上下文与现有转换

- 从资料库搜索打开 DOCX 内部结果后返回，搜索词和结果仍保留。最初对返回上下文的静态疑虑经真实界面核对后不成立。
- DOCX 精确定位需要等待目标块渲染；早期“未定位”是测试时序问题，不是产品缺陷。
- CSV/TSV → Table 已展示目标名称、源文件不变和同名时使用新序号，并允许打开新文件。
- OPML → Canvas 会创建目标并自动打开，源 OPML 不变，但转换前没有来源、目标、覆盖策略和损失说明。
- 结构化文本 → Table 尚未实现；图谱已有到 Canvas/项目笔记的输出，但尚未形成统一的转换披露合同。

## 4. 恢复开发时的唯一接续点：M4A-1

阶段名称：**统一对象定位合同与 Table/OPML 搜索闭环**。

范围只包括：

1. 在 `src/services/fileNavigation.ts` 定义规范化对象定位结构，以及定位器到路由查询参数的唯一映射。
2. 让资料库搜索、图谱和关系上下文消费同一映射，移除三处格式语义复制；保留各入口自己的交互外壳。
3. 为 `.table.json` 建立可复核的行或视图索引段，并让结果打开对应内部对象。
4. 为 OPML 节点建立稳定定位器，并让搜索结果打开对应节点。
5. 固化 DOCX、ODS、ODP、PPTX 现有精确定位和搜索返回上下文，防止统一过程造成回归。

明确不包含：DOCX/ODS/ODP/Workbook 图谱扩面、工作台全对象行动、新转换类型、转换 UI 重做、版本提升和 release candidate。

## 5. M4A-1 恢复后的真实验收方法

恢复开发时先冻结一套真实资料库，至少包含 Markdown、`.table.json`、OPML、DOCX、ODS、ODP、PPTX。对每种格式记录“预期命中的内部对象”和“当前实际打开对象”，不只检查搜索结果数量。

M4A-1 的退出条件：

- Table 与 OPML 的真实内容搜索均命中，并打开指定行/视图或节点。
- DOCX、ODS、ODP、PPTX 继续打开既有精确对象。
- 从对象返回后，原搜索词、过滤条件和结果保持。
- 三个入口的路由由同一规范化定位合同生成。
- 测试记录明确列出预期、第一次实际、修正内容和修正后实际；源夹具摘要保持不变，运行时错误为 0。
- 完成阶段审计、需求对齐、必要文档更新后，才允许提交和推送并选择 M4A-2。
