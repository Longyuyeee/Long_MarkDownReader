## 原始需求与范围判断

原始 M4 路线要求清理本周期产生的临时脚本、候选输出和重复证据，只保留可重复生成或发布需要的文件；清理完成后，才允许汇总能力事实、真实测试、残余风险和用户可见变化并决定是否进入版本提升。

M4D-0 已证明本周期脚本是可重跑审计入口，历史证据和 8 组相同 Git blob 各有行为、基线、夹具或阶段语义。M4D-1 因此只删除四个已有完整结构化替代指标的 M3C-4 原生导出负载。本退出阶段不重新解释原始需求，也不以“目录较大”作为扩大删除范围的理由。

## 删除后独立事实

审计以 M4D-1 实现前提交 `9319ecb25918c03877c73001f8f89d141c1d367d` 和清理完成提交 `fb34c527595164387e19ef684fd5c5a728296260` 做 Git 树对照：

- 实际删除路径为 4 个，与 M4D-0 冻结选择逐项相同；意外删除为 0。
- 实际删除总量为 13,883,957 bytes。
- `v1.0.15..20ab256` 冻结周期的 931 个新增路径中，排除四个授权负载后的 927 个路径在清理提交中全部存在，缺失为 0。
- 当前 `docs/evidence/post-v115-*` 下遗留的 SVG/PNG 原生导出负载为 0；其他 PNG 属于更早版本的界面、PDF 独立渲染或安装证据，不属于本周期冻结范围。
- 四个已删除文件的字节数和 SHA-256 继续与 `tier-5000.json#actual.exports` 一致。

## 遗漏候选复核

M4D-0 的 931 路径分类仍可从冻结 Git 提交重建：179 个 capture/check/run/invoke/verify 脚本、573 个历史证据文件、79 个文档和 69 个策略文件均承担可重跑、验收或交接职责。8 组完全相同内容仍全部受保护，Git 本身已对相同 blob 去重；删除这些路径不会减少仓库对象存储，只会破坏证据语义。

当前脚本扫描仅发现另一类 `.png` 生成目标：M1D-B 视频帧输出到真实审计临时资料库，由 runner 的临时根目录生命周期清理，并未提交到 `docs/evidence/post-v115-*`。因此没有满足“本周期跟踪负载、可重建、已有等价结构化指标、无 checker 或发布依赖”全部条件的遗漏候选，遗漏数为 0。

## 未来清理合同

M3C-4 只有在完整三档或明确 5000 档运行、结构化指标落盘且原性能 checker 通过后，才调用 M4D-1 清理器。清理器先对四个精确路径完成全量大小和 SHA-256 预检，再开始删除；100/1000 单档、M3C-0 至 M3C-3、指标不符或 checker 失败均不会触发删除。
