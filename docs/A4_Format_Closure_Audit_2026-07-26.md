# A4 统一格式阶段收口审计

更新日期：2026-07-26

开发分支：`codex/a4-format-closure`

对应 Draft PR：#6

审计结论：**A4 代码级范围达到收口条件；A5 真实桌面验收仍是独立下一阶段。**

## 1. 与最初目标的对齐

本项目的基础目标不是把每一种格式都做成完整 Office 或 IDE，而是：

1. 覆盖日常文件管理、阅读和经验证的基础编辑；
2. 把 Markdown、PDF、图表、思维导图、表格、配置和开发文本放进同一套文件树、标签、搜索、最近记录与知识关系体系；
3. 以开放格式或原文件为事实源，保存失败可恢复，不用私有数据库锁定用户内容；
4. 每种格式明确区分“完整编辑、基础编辑、阅读/批注、只读预览、外部打开和不支持”，不把局部能力宣传成格式等价；
5. 敏感配置默认不进入全文索引、知识图谱、日志或遥测。

A4 的职责是补齐“常用文本和配置格式”这一层。PDF 页面重写、DOCX/PPTX 基础工作面、WPS 私有格式转换和真实桌面故障证据不属于 A4，不应混入本阶段完成声明。

## 2. 当前能力矩阵

| 类别 | 当前能力 | 管理/搜索 | 真实边界 |
|---|---|---|---|
| Markdown | 完整编辑 | 文件树、标签、全文搜索、双链、图谱 | 已是主要知识事实源 |
| TXT | 完整文本编辑 | 文件树、统一标签、搜索、最近记录 | 支持编码/BOM/换行、冲突保护和大文件只读范围 |
| JSON/JSONC | 受保护基础结构编辑 | 文件树、统一标签 | 创建和全文索引仍为计划能力 |
| YAML/XML/TOML | 完整源码编辑闭环 | 可创建、全文索引、统一标签 | XML 禁止 DOCTYPE；不虚报可视化语义往返 |
| INI/CONF/CFG、Properties | 完整文本编辑 | 可创建、全文索引、统一标签 | 不使用宽松解析器伪装语义校验 |
| `.editorconfig`、`.gitignore` | 完整文本编辑 | 文件树可见，可创建 | 点配置文件不进入全文索引或图谱 |
| `.env` 系列 | 受保护基础编辑 | 文件树可见，可创建 | 默认遮罩；当前文件显式确认后才能显示/编辑；不索引 |
| 常见代码文本 | 轻量编辑 | 文件树、语法高亮、全文搜索 | 不执行代码，不提供编译、调试或语言服务 |
| LOG | 有界只读工作面 | 级别/内容筛选、全文搜索 | 显式编辑未开放 |
| PDF | 阅读、批注、OCR | 页级搜索、引用和图谱关系 | 原 PDF 不重写，批注/OCR 使用 sidecar |
| Mermaid | 完整源码图表编辑 | 可创建、预览、导出、搜索 | Mermaid 源码是事实源 |
| OPML 思维导图 | 完整树形/导图编辑 | 可创建、搜索、图谱对象 | 可投影为 Canvas；不是任意脑图私有格式等价 |
| JSON Canvas | 完整开放画布编辑 | 可创建、搜索、图谱转换 | 使用开放 JSON Canvas 事实源 |
| CSV/TSV/开放表格 | 完整基础表格与图表编辑 | 可创建、搜索、嵌入 | 复杂 Office 对象不在开放表格合同内 |
| XLSX | 有边界的基础编辑 | 文件树、统一工作面 | 只开放兼容矩阵验证过的渐进子集，不宣称 Excel 等价 |
| DOCX/PPTX、`.wps/.et/.dps` | 尚未支持内置编辑 | 可作为后续专业格式线 | 必须先审计规范、许可、转换保真和安全写回 |

## 3. 本次收口新增

### 3.1 敏感配置保护

- 注册 `.env`、`.env.local`、`.env.development`、`.env.production` 和 `.env.test`。
- `.env` 默认显示遮罩值并处于只读状态；只有在当前文件工作面明确确认后才加载为可编辑显示。
- 后端统一识别 `.env`、SSH 私钥常用名、`credentials.*`、`secrets.*` 及以独立词命名的 credential/secret 文件。
- 实时搜索、持久化索引和由索引派生的知识对象均在后端再次拒绝敏感路径，而不是只依赖前端隐藏。
- `.env` 的“显示值”和“允许索引”没有合并授权；本阶段根本不开放 `.env` 索引。

### 3.2 常见配置

- INI/CONF/CFG 与 Properties 进入可靠文本工作面，支持创建、查找替换、行跳转、编码/换行控制、签名冲突保护、可靠保存和全文检索。
- `.editorconfig` 与 `.gitignore` 可在文件树识别和编辑。
- 应用内创建点配置文件会生成精确规范文件名；已存在时明确拒绝，不生成 `.editorconfig.editorconfig` 一类伪文件。

### 3.3 常见代码文本

第一阶段覆盖：

- JavaScript/TypeScript；
- Python、Rust、Go；
- Java/Kotlin；
- C/C++/C#；
- Shell/PowerShell；
- SQL；
- HTML/CSS/SCSS/Less/Vue。

共同能力为语法高亮、查找替换、跳行、撤销重做、编码/BOM/换行控制、外部修改冲突保护、可靠保存和全文索引。共同排除项为代码执行、依赖安装、编译、调试、补全、重构和语言服务器。

## 4. 知识图谱与思维导图的真实状态

- OPML 已提供真正的树形与思维导图双视图，节点可编辑并以 OPML 为开放事实源；“思维导图效果”在开放格式范围内已经形成闭环。
- Markdown、Canvas、OPML、PDF 批注和开放表格对象已进入统一知识对象/关系合同。
- 本次新增的普通配置和代码文件可作为可搜索的文件级知识对象出现，但尚未解析 import、调用、配置引用或数据血缘，因此不能宣称已经形成代码语义图谱。
- 知识图谱“存在感”仍需下一条产品化专项：默认工作台关系摘要、上下文侧栏、搜索结果关系预览、对象级入口统一，以及代码/配置关系提取器。该专项应建立在 A5 桌面验收之后，不能用增加更多扩展名代替。

## 6. A4 退出判定

A4 的代码级退出条件已经满足：

- 新格式均由共享注册表驱动文件树、路由、能力展示、创建和索引分派；
- 普通配置和代码文本复用 A1 可靠文本内核，没有复制不一致的保存实现；
- 敏感配置先于代码扩展完成默认遮罩和后端索引隔离；
- 功能说明与真实能力边界一致；
- 完整 CI 通过；
- 功能按独立提交推送，可审计、可回退。

本结论不等于 A5 完成，也不等于整个产品路线完成。

## 7. 后续开发顺序

### 下一阶段：A5 真实桌面验收

1. 使用真实 Tauri 进程覆盖 TXT、JSON/JSONC、LOG、YAML、XML、TOML、INI、Properties、`.env` 和代表性代码文件。
2. 验证打开、编辑/只读策略、保存重开、外部冲突、关闭/重启、最近文件、日志追加/轮转、大文件范围和中断写入恢复。
3. 验证 `.env` 首次打开遮罩、确认显示、重新遮罩，以及搜索/图谱中不可检索。
4. 形成 fixture、操作步骤、截图或日志摘要；只有 A5 通过后，阶段 A 才能声明桌面级完成。

### A5 之后

1. 图谱产品化专项：增强默认入口、关系上下文和代码/配置关系提取，直接回应“知识图谱存在感弱”。
2. PDF 页面编辑专项：旋转、排序、删除、提取、合并、拆分和安全另存。
3. DOCX/PPTX 基础工作面：先读后编，按公开 OOXML 兼容矩阵逐项开放。
4. WPS 私有格式审计：确认公开规范、许可和可靠转换路径；无法证明保真时只提供外部打开或受控副本转换。
5. 统一管理增强：跨格式集合、批处理、元数据、关系摘要和工作区健康治理。
