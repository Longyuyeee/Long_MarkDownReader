# F1 归档历史一致性：只读迁移清单

日期：2026-10-11。接续 `331b5130`。本次仅实现历史预检，不移动文件，不改 UI，不发版。

## 实际代码审计

- `save_history_version`、`list_history` 使用 WorkspaceGuard 规范化路径，再按路径字符串 MD5 定位 `history_v2` 子目录。原有移动代码直接使用传入路径查历史，并忽略历史目录移动失败，不能作为新归档的可靠实现。
- 新归档预检与既有历史命令共用历史目录计算函数；历史键算法保持不变，不迁移旧数据。归档检查传入规范化源路径和规范化目标父目录下的目标路径。
- 图谱的 `resolve_wikilink` 在同名候选下存在取首项/当前目录优先逻辑；直接复用来自动改写链接可能误改。已有解析还分别处理 Wiki 链接和 PDF 引用，不等于完整 Markdown/HTML/附件入链分析。本次没有实现链接重写，也没有宣布依赖安全检查完成。

## 已实现

`preflight_archive` 对结构检查通过的项追加 `history` 清单。源历史不存在返回 `strategy: none`；存在则列出按名称排序的快照、字节数和 SHA-256，返回计划 `copy_verify_then_retire_source`。该字符串是待实现策略，不表示已执行复制或删除。

目标路径即使还没有文件，也可能保留以前文件的历史；只要目标历史目录存在，便返回逐项 `history_conflict`，不混合、清空或覆盖目标历史。单项异常不会隐藏其余项的结果。

源历史/缓存目录类型异常、快照不是普通文件、未知快照名称、读取异常均明确失败，不以 `flatten` 静默丢弃条目。每项最多读取 1000 份快照、64 MiB，总量超限不视为检查成功；流式计算摘要，避免一次加载全部历史。没有历史时不创建目录。

`structuralChecksPassed` 仍只描述路径结构检查；历史是否通过须看逐项 issues/history。`canExecute` 仍为 false，待完成项仍保留历史执行/身份一致性和链接依赖，不将有摘要等同于支持安全归档。

## 验证与边界

新增测试使用独立临时目录：无历史不创建、原字节保留、稳定排序/已知 SHA-256、同长度内容变化后摘要改变、无源历史时目标残留仍阻止、未知/超大快照、伪装成快照的目录、异常缓存路径、实际规范化历史身份、逐项失败不短路。临时测试文件由用例自行清理，未操作真实资料库或用户历史。

运行：`cargo test --locked --manifest-path src-tauri/Cargo.toml archive -- --nocapture`，并回归历史模块和 `git diff --check`。没有 UI 修改，没有新页面截图；这不是界面操作验收。

最终结果：`archive` 名称筛选 **18 passed / 0 failed**（其中归档命令 11 项、历史清单 5 项，另匹配到既有压缩包相关 2 项）；既有历史模块 **1 passed / 0 failed**；`git diff --check` 通过。新增测试共 7 项。

仍待实现：执行前对清单重校验、迁移复制及摘要核验、故障恢复和执行回执；扫描过程不是文件系统原子快照，不能抵御并发同长度改写或链接置换。跨窗口草稿、标签/索引、链接/附件入链一致性仍未完成。任何未来删除旧历史步骤必须在新历史与新文件确认成功后执行，失败保留可恢复来源。

性能边界：当前限制按文件计算；接 UI 前需补批次总预算、后台阻塞任务调度和取消/过期处理，不能把最多 500 项的摘要读取直接当成已验证的大库交互性能。
