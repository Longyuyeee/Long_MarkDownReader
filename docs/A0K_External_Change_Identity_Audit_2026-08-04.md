# A0K 外部修改检测审计

日期：2026-08-04
对应需求：UX-23
结论：焦点恢复检测已改用真实文件身份，等待下一安装包复测。

## 根因与修复

- 旧实现只比较秒级修改时间，并在应用内保存后用 `Date.now()` 猜测文件基线；写盘时间、文件系统精度和焦点事件重入都可能造成误报。
- Rust 新增文本身份接口，统一返回内容摘要、精确纳秒修改时间、尺寸和保存签名。前端以内容摘要判断真实变化，不再用墙上时钟猜测。
- 应用内手动保存、自动保存、编码重读和文件加载都消费真实读写回执，立即更新标签页身份基线。
- 检测过程与弹窗状态均有互斥保护；同一磁盘签名只提示一次，弹窗自身导致的焦点变化不会再次弹窗。
- 仅修改时间变化而内容未变时静默刷新签名，不提示用户；内容确实变化时显示检测时间，并提供比较、保留当前、重新加载三个动作。

## 自动验证

- `check:external-change-identity`：校验 Rust 身份内核、命令注册、保存回执、内容摘要比较、焦点互斥、签名去重和三个用户动作。
- 专项门禁已加入 `ci:patch-release`。
- `npm run build`、Rust 测试、对话框 ACL 与当前阶段审计必须继续通过。

## 安装包复测

1. 未修改文件时连续切换窗口焦点至少十次，不得出现外部修改提示。
2. 应用内保存后立即切换焦点，不得误报；外部工具只触碰时间戳但不改变内容也不得提示。
3. 外部真实修改内容后只提示一次；分别验证比较、保留当前和重新加载，并确认同一磁盘版本不会反复提示。
4. 外部再次写入不同内容后应产生新的单次提示；保存时仍必须保留过期签名保护，禁止静默覆盖外部版本。
