# P1-B3A PDF 永久脱敏安全审计

日期：2026-08-15
状态：安全审计与实现合同已完成；尚未开放写入，下一入口为 P1-B3B 全量栅格可靠副本后端

## 1. 需求对齐与审计结论

本阶段继续对齐最初目标：LongEdit 首先是统一的日常资料管理器，其次提供边界清楚、结果可验证的基础编辑。永久脱敏属于高风险编辑；如果实现只是画黑框，用户可能在外观上误以为内容已删除，但复制文本、搜索、解析内容流、查看旧增量版本或移除批注后仍能恢复秘密。这比明确不支持更危险。

审计结论是：当前 `lopdf` 结构编辑能力足以重建 PDF，但不包含完整绘制布局与相交检测引擎，不能可靠判断任意文本、图片、矢量、裁剪、透明组和嵌套 XObject 是否落入用户矩形。P1-B3 不采用“按绘制操作猜测并删除”路线，也不采用遮罩批注或增量保存。

批准的安全路线是“整份文档逐页栅格化 + 像素烧入 + 全新白名单 PDF”：用已有 PDF.js 在本机把每一页渲染为不透明位图，在图片编码前把脱敏矩形烧入像素，然后由 Rust 从空文档创建只包含页面、内容流和图片 XObject 的新 PDF。任何源对象都不复制。这个输出才可以称为永久脱敏副本。

当前阶段只冻结合同，不增加按钮、命令或写入能力，避免审计尚未形成桌面证据时提前暴露入口。

## 2. 威胁模型

| 攻击面 | 仅遮罩的风险 | 本合同的处理 |
| --- | --- | --- |
| 页面文本 | 黑框下文字仍可复制、搜索或提取 | 源文本流不进入输出；输出逐页提取必须为空 |
| 图片与扫描件 | 覆盖对象可被隐藏或移除 | 在渲染后的像素上烧入矩形，原图片不复制 |
| 矢量与嵌套 XObject | 变换、裁剪和透明组使边界推断不可靠 | 不分析相交关系；整页渲染后重建 |
| 批注、表单和图层 | 可以关闭遮罩、切换图层或读取字段值 | 新文档不复制 Annots、AcroForm、OCProperties 或动作 |
| 附件、标签、书签和元数据 | 机密可能存在非页面对象中 | 新 Catalog 只保留 Pages；Names、Outlines、StructTreeRoot、Info/XMP 均不复制 |
| 增量更新历史 | 旧对象仍留在文件尾部 | 从空文档完整写出，不做增量更新 |
| OCR sidecar | 旧识别文本可能继续暴露秘密 | 不复用源 OCR；需要搜索时只能对脱敏副本重新 OCR |
| 共享页面资源 | 只重建受影响页仍可能保留共享机密对象 | 每一页都栅格化，任何源页面或共享资源都不复制 |

数字签名和加密 PDF 继续阻断。签名文档的任何重建都会破坏签名语义；加密文档在没有独立权限与解密审计前不能进入脱敏流程。

## 3. 方案比较与决定

| 方案 | 保密性 | 保真性 | 可验证性 | 决定 |
| --- | --- | --- | --- | --- |
| 黑框批注/内容覆盖 | 低 | 高 | 低 | 拒绝 |
| 解析操作符并按矩形删除 | 对简单样本有效，复杂 PDF 不可靠 | 中 | 低 | 拒绝 |
| 只栅格化含脱敏框的页面 | 中；共享对象和文档级对象仍需复杂清理 | 高 | 中 | 拒绝 |
| 整份文档栅格化后从空 PDF 重建 | 高 | 视觉保真、语义降级 | 高 | 批准 |

批准方案有明确代价：输出变成图片型 PDF，文本选择、全文搜索、无障碍结构、链接、表单、批注、书签和元数据都会移除，文件也可能变大。这不是后台静默降级；后续 UI 必须在验证和保存前明确展示，并建议保留源文件。若用户需要对输出继续搜索，应在脱敏完成后重新运行 OCR，使新的 sidecar 只基于已经遮挡的像素。

## 4. 冻结的安全合同

机器事实源为 `shared/pdf-redaction-safety-contract.json`，核心约束如下：

- 仅资料库内 PDF；外部 PDF 继续预览只读；只创建同目录新文件，不覆盖源文件或已有目标。
- 输入上限 128 MB、64 页、单边最多 4096 像素、总计最多 1.2 亿像素、最多 256 个脱敏矩形。
- 至少存在一个有限、规范化、页内有效的矩形；遮挡颜色只允许完全不透明的黑或白。
- 必须渲染全部页；任何页面缺失、渲染失败、透明画布或预算超限都整体阻断。
- 新 PDF 从空对象图构建，不复制源对象 ID、内容流、字体、图片、XObject、表单、批注、动作、图层、附件、书签、标签、Info 或 XMP。
- 输出对象图只允许 Catalog、Pages、Page、页面内容流和 Image XObject；保存后重新打开重复检查。
- 当前 `currentWriteCapability=false`；在 P1-B3B/B3C/B3D 全部通过前，能力登记和产品 UI 不得宣称已支持永久脱敏。

## 5. 验证计划

后续 fixture 必须同时包含可提取秘密文本、扫描图片秘密、矢量内容、隐藏文本、批注、表单值、元数据标记和共享 XObject，不能只验证一行普通文本。

自动验证至少包括：源 SHA-256 前后相同；页数和页面几何一致；每页恰好一个图片 XObject 且没有批注；Catalog 不含 AcroForm、Names、Outlines、OCProperties、StructTreeRoot 和 Metadata；逐页文本提取为空；所有 fixture 秘密标记既不出现在输出字节也不出现在提取结果中；保存目标重开重复结构检查。

独立视觉验证使用 Poppler 对比源和目标：脱敏区域必须完全不透明，非脱敏区域仍可阅读；真实 Tauri 在宽屏和窄屏都必须保持初版“左侧资料库 + 右侧 PDF 工作区”，矩形工具、风险说明、验证状态和可靠另存按钮可达，运行时错误为零。

## 6. 后续实施顺序

1. P1-B3B：实现 Rust 图片型 PDF 白名单构建器和结构/文本缺失复读，不接 UI。
2. P1-B3C：在原 PDF 右侧工作区增加矩形草稿、黑/白选择、全量栅格降级说明、验证与可靠另存；外部 PDF 无入口。
3. P1-B3D：生成综合攻击面 fixture，完成 Tauri 宽窄屏、保存重开、秘密标记扫描和 Poppler 独立渲染证据。
4. 只有 B3B～B3D 全部通过后，才把 `permanent-redaction-copy` 加入当前能力；随后进入 P1-B4 水印可靠副本。
