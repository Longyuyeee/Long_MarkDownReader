# v1.0.15 后 M3C-2 大图主线程阶段剖析选择审计

日期：2026-08-28

进入基线：`main` / `5f9f0da185f22a9bbc4232a707ca55b19ec8f267`

阶段：M3C-2

发布候选：否

## 1. 结论

M3C-2 已通过真实 100/1,000/5,000 节点 Tauri/WebView2 阶段剖析确认：当前大图首要瓶颈是前端力布局模拟，不是 Canvas 绘制、语义派生或后端图构建。

5,000 节点在产品总预算到点时仍未稳定。由于一个不可中断的同步布局任务延迟了观察，最终记录点为 `140049ms`；其中布局模拟累计 `133038ms`，最大单次 `29481ms`。同期 Canvas 原始绘制累计 `948ms`、最大 `123ms`，社区检测/概览、路由、状态等语义派生合计约 `1269ms`，后端 `build_link_graph` 为 `7403ms`。布局约占已归因主线程阶段成本的 99%。

因此当前接续点固定为 **M3C-3 Worker 承载的有界力布局内核**：把力计算移出 UI 主线程，并为密集网格单元中的斥力候选建立确定性工作上限。必须保持图谱事实、相机、选择/平移/缩放、布局持久化、M3C-1 脏帧生命周期和 reduced 行为。视口裁剪/标签缓存、保存视图和视觉层级继续延后。

## 2. 冻结的测量与选择规则

- 真实资料库：100/99、1,000/999、5,000/4,999 节点/边 Markdown 有向链，源只读。
- 阶段：后端图构建、Louvain 社区、边路由、节点状态、语义关键节点、社区轮廓/概览、布局模拟、Canvas 绘制。
- 计时：只在测试设置 `window.__m3c2Profiler.enabled` 时记录；正常运行不保存样本。
- 扰动：不修改 Canvas prototype；在同一 WebView 内用 100,000 次记账微校准测量探针成本。
- 重复性：每档注入固定 LCG 随机种子，避免 `Math.random` 初始布局差异被误认为探针开销。
- 选择：以主线程累计总量和最大单次耗时共同判断，只选一个最小后继。

补充事实：

- 5,000 节点社区检测累计 `668ms`、边路由 `108ms`、节点状态 `35ms`、社区概览 `458ms`；所有语义派生约 `1269ms`。
- 三档探针记账成本分别为 `0.484/0.516/0.519µs` 每次，均远低于 `10µs` 上限。
- 5,000 节点预算截断后的取证需要等待当前 `29481ms` 同步任务释放主线程，因此观察点晚于 120 秒；产品判定仍为预算失败。
- 100/1,000 节点完整返回；5,000 节点有界失败后也实际返回资料库。三档均运行时错误 0、源 SHA-256 前后一致。
- 5,000 截图仍是完整图而非社区子图，视觉拥挤继续存在，但绘制成本不是当前第一瓶颈。

## 5. M3C-3 开发边界

- Worker 接收纯图结构和确定性布局参数，不读取文件、不调用治理后端、不改变关系事实。
- 密集网格单元不能继续无界两两比较；每 tick 的候选或时间工作量必须有确定性上限。
- UI 主线程单次布局任务目标 `<=50ms`，5,000 节点不再出现秒级主线程布局任务；布局总稳定目标仍为 `<=120000ms`。
- Worker 结果按有界批次应用并触发 M3C-1 脏帧；失焦、离开、重置和卸载能取消或忽略陈旧任务。
- 真实 100/1,000/5,000 节点复测，明确比较本阶段 `29481ms` 最大单次布局和修正后实际。
- 不并入视口裁剪、标签缓存、保存视图或大图视觉重做。

## 6. 阶段目标与需求对齐审计

- 开发目标：用真实分段数据选择首个大图主线程优化，而不是凭总耗时猜测，已完成。
- 需求对齐：布局、语义、绘制、后端、长任务、探针扰动、源安全和返回能力均有真实数据。
- 差异闭环：随机布局对照、错误函数闭合、过长等待窗口、聚焦窗口和 middle 覆盖五项均按实际修正，产品预算未放宽。
- 选择边界：只选择 M3C-3 Worker 有界力布局；绘制裁剪虽仍有视觉价值，但不是当前第一性能增量。
- 文档与事实源：政策、当前阶段、状态、路线图、交接和开发版说明同步。
- 版本：公开/运行时仍为 `1.0.15`，开发目标 `1.0.16`，`releaseCandidate=false`；M3C 尚未完成。
