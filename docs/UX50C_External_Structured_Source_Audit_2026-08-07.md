# UX-50C / EA-2B 外部结构化源码工作区审计

## 结论

EA-2B 已把 JSON、JSONC、YAML、XML、SVG 与 TOML 接入受控外部编辑。外部可编辑注册项由 17 个增加到 23 个；新增格式继续进入原有专用编辑器，不降级为通用文本页面。

## 已完成

- 系统启动参数和“打开外部文件”选择器可临时授权上述 6 个格式，进程重启后授权失效。
- JSON/JSONC 保留源码与虚拟树视图、局部结构编辑、撤销重做、非法源码确认和冲突保护。
- YAML、XML、TOML 保留实时诊断、结构提纲、撤销重做、非法源码确认和冲突保护。
- SVG 保留安全净化预览；脚本、事件属性、外部引用和其他受阻结构不能通过外部保存写回。
- 每个工作区明确显示“外部文件”和“仅点击保存写回”，标签页保存外部身份，所有编辑坚持显式保存，返回动作回到资料库。
- 通用外部文本写入明确拒绝这 6 个格式，必须经过对应专用外部保存命令，不能绕过语法与安全门禁。

## 默认应用边界

本阶段没有扩大 Tauri/NSIS 文件关联。安装器仍只登记 `.md` 与 `.markdown` 的 OpenWith 候选；其他格式是否使用 Long编辑打开，继续由用户在 Windows 默认应用界面逐项确认。

## 验证

- 前端 TypeScript 检查与生产构建通过。
- Rust `cargo check --locked` 通过。
- 外部授权测试覆盖 6 个新增格式，并确认 CSV 等仅导入格式不能获得编辑授权。
- 机器合同锁定 23 个外部可编辑注册项、专用路由、专用保存命令、通用写入阻断和不变的 Windows 关联边界。
- 本轮内置浏览器未能附着本地预览页，因此没有新增视觉截图；四个工作区沿用已验收的响应式布局，仍需在下一安装包中复测真实外部启动和窄窗口交互。
