# v1.0.15 M2A1 工作台待办行动闭环审计

日期：2026-08-26
阶段：M2A1
结论：通过，不提升版本

## 开发目标

把工作台中的 Markdown 待办从只读入口推进为可完成的日常动作，同时保持本地优先、用户确认、签名冲突保护、可靠写入和可撤销边界。本阶段只关闭待办行动闭环，不宣称 M2 工作台 2.0 已完成。

## 修正前差异

| 用户任务 | 预期 | 修正前实际 | 差异 |
| --- | --- | --- | --- |
| 在工作台完成待办 | 工作台直接完成 | 待办整行只调用 `openPath`，只能打开原文 | 没有工作台内完成动作 |
| 控制写盘 | 用户确认后才修改原文 | 工作台没有写回能力 | 无确认、无签名保护闭环 |
| 误操作恢复 | 工作台内撤销 | 必须进入编辑器手工改回 | 无单步恢复 |
| 首页信息层级 | 行动优先 | 顶部展示文件、Markdown、Canvas 等格式计数 | 格式统计挤占行动首屏 |

修正前从工作台无法形成直接完成路径；用户至少需要打开文件、进入编辑状态、定位任务、修改复选框并保存。修正后完成路径为点击任务复选框并确认两步，撤销为一步。

## 实现结果

- `get_workspace_overview` 为每个待办返回扫描时的文本文件签名。
- 新增 `set_workspace_markdown_task_state`，只接受资料库内 `.md/.markdown` 文件和明确的行号、文本、目标状态及预期签名。
- 写入前同时核对文件签名、行号、复选框状态和任务文本；冲突时拒绝覆盖。
- 写入沿用文本编码、BOM、换行符和末尾换行策略，并通过可靠同目录临时文件写入；写后重新读取核对内容。
- 工作台将“打开原文”和“完成待办”拆成两个动作；完成前使用应用内确认，完成后显示撤销入口。
- 撤销使用完成后的新签名再次写回，外部修改后不会被旧撤销覆盖。
- 删除首页顶部格式数量条；格式统计继续由格式能力页和资料库筛选承载。

## 需求对齐

- 对齐“工作台回答今天要处理什么”的目标。
- 对齐“所有编辑只有明确保存或确认后写回”的统一原则。
- 对齐签名冲突、可靠写入、失败不覆盖和可撤销要求。
- 未改变 Markdown 编辑器及其他格式保存边界。
- 未完成同一治理问题只出现一次、慢任务不阻塞首屏、全部目标尺寸和任务筛选，因此 M2 仍在进行中。
