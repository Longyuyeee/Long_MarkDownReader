## 1. 产品结构基线

初版提交 `cc114dc` 的根路由为 `/library`。其核心结构是：

- 顶部保留轻量应用标题栏；
- 左侧是资料库导航和文件管理 Tab；
- 右侧是统一标签页、编辑器或格式阅读区；
- 没有打开文件时，右侧显示空状态，但左侧管理上下文始终存在。

提交 `725e655` 新增独立工作台后，把根路由从 `/library` 改为 `/workspace`。工作台本身有价值，但它取代了主编辑框架，造成启动体验、文件管理路径和后续格式页面在视觉结构上的分裂。

治理原则：`LibraryMode` 是产品主壳层；`WorkspaceHome`、知识图谱、设置和发布能力是管理级功能，不能取代默认的文件管理与编辑结构。

## 3. 本阶段实际修复（UI-0）

1. 根路由恢复为 `/library`，独立工作台保留为可选入口。
2. 主壳层增加 `library-editor` 身份标记，并登记 `navigation`、`sidebar-tabs`、`editor` 三个稳定区域。
3. 主壳层宽度由 `100vw` 改为容器相对 `100%`，避免标题栏、系统缩放或嵌套环境产生横向溢出。
4. 右侧空状态使用统一品牌图标，并明确提示“从左侧选择文件，在右侧阅读或编辑”。
5. UI 合同新增启动路由、主壳层区域、品牌空状态和容器尺寸检查，防止再次回归为独立工作台首屏。

## 4. 后续逐步执行顺序

### UI-1：主壳层组件与密度

- 抽取共享工具栏、状态栏、字段和空状态组件。
- 先治理 LibraryMode、WorkspaceTabs 和标题栏，再迁移格式编辑器。
- 建立 100%、125%、150% Windows 缩放验证。

### UI-2：高风险格式工作区

- Workbook：优先处理 7–9px 字号、工具栏分组和直接颜色。
- PDF：拆分页面、OCR、批注与页面组织工具，降低持续高密度。
- DiagramStudio：统一工具栏、状态栏和编辑/预览分栏。
- WorkspaceHome：降级为管理概览，不再作为启动框架。

### UI-3：管理页面壳层

- 工作台、知识图谱、设置和发布能力共享返回资料库、页面标题和操作区。
- 保留图谱沉浸画布，但统一返回路径、筛选区和检查器尺寸。

### UI-4：视觉回归门禁

- 覆盖主壳层、Markdown、PDF、DOCX、PPTX、表格、工作簿、图表、脑图、Canvas、图谱和设置。
- 每个页面验证浅色、深色、高对比和三档 Windows 缩放。
- 阻止新增顶层文件编辑器、视口尺寸根节点和未登记的微字号。

## 5. 完成定义

全量 UI 治理只有在主路由矩阵完成视觉回归、所有日常文件保持左侧管理上下文、P1 微字号完成迁移、管理页面共享壳层且自动化门禁持续通过后，才能标记为完成。
