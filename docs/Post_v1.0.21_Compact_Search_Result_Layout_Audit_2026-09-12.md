# v1.0.22 候选：紧凑搜索结果可读性收口

日期：2026-09-12；前置提交 `69e76fc6`。

## 原需求与实际原因

关联主 PRD 1.1 的文件查找/定位闭环，不扩大搜索算法范围。前一轮真实 Tauri 截图显示约 200px 侧栏中标题几乎不可见。代码确认两层横向竞争：卡片是正文 + 关系徽标两列，正文标题行又是标题 + 不可压缩格式标签，导致标题的可用宽度接近零。

## 修复与取舍

- 卡片改为单列，文件打开按钮占整行，关系徽标独占下一行；不改变两个按钮的行为。
- 标题与“格式 · 命中原因”分行。长标题最多两行，可断开无空格长词；完整标题通过 tooltip 和 aria-label 提供。
- 卡片使用 border-box 和主题边框，按钮继承字体并提供键盘焦点轮廓。
- 取舍：单卡高度增加，可同时看到的条目减少，但不再以牺牲文件身份换取密度；本轮所有宽度统一分行，避免新增断点状态和尺寸监听。

- `npm run build`：类型检查与生产构建通过，6,279 modules；当前开发总审计通过（已接入布局检查，搜索恢复 14 项亦通过）。本轮无 Rust 改动，不重复安装/更新链。
