# T8-1B 场景化主题桌面视觉审计

更新日期：2026-07-23
状态：已完成

## 1. 审计范围

本阶段验证 T8-1A 新增的四套正式场景预设：

| 预设 | 场景 | 色调 / 风格 / 动效 |
|---|---|---|
| 云白纸张 `cloud-paper` | 长文阅读 | white / airy / reduced |
| 森林绿柔和 `forest-green` | 护眼研读 | green / soft / calm |
| 暗夜绿光 `dark-neon` | 编码专注 | dark / neo / swift |
| 紫梦幻境 `purple-dream` | 创意图谱 | purple / glass / expressive |

证据来自真实 Tauri Debug WebView2。自动化通过隔离的 `WEBVIEW2_USER_DATA_FOLDER` 和本地调试端口连接 WebView，不操作正式安装版窗口，不把普通浏览器截图当作桌面证据。

## 2. 视觉矩阵

每套场景预设覆盖三个代表工作面和三个窗口尺寸：

| 工作面 | 尺寸 | 验收重点 |
|---|---:|---|
| 设置 / 主题分组 | 1440×900 | 七套发布预设、十二套兼容组合、当前预设、场景标签、正文与卡片层级 |
| 专业工作台 | 1024×768 | 指标带、最近文件、知识库健康、导航、深浅表面和横向溢出 |
| 图谱思维导图 | 760×900 | 标题、视图切换、搜索、治理、导出、筛选条、画布和窄宽度默认状态 |

共生成 12 张 JPG 截图和一份机器清单，位于 `docs/evidence/t8-1b/`。`audit-manifest.json` 固定每套预设的 `theme/style/motion` 最终语义状态和三张证据文件。

## 3. 审计发现与修复

第一轮真实截图发现 760px 图谱存在一致性问题：

- 标题和视图切换被压缩成竖排；
- 工具栏无可控溢出策略；
- 初始节点详情长期占据右侧约 40% 画布并裁切内容。

修复后：

- 900px 以下图谱标题保持横排，工具栏进入可横向滚动的独立行；
- 筛选条位置随紧凑页头调整，不与画布重叠；
- 窄窗口首次进入图谱时保留思维导图中心，但不自动打开节点详情；用户主动选中节点后详情以底部面板显示；
- `npm run check:theme-contract` 固定紧凑工具栏与初始详情行为，防止回归。

审计还发现 Debug E2E 配置读取与写入不对称：`get_config` 使用隔离环境配置，而 `save_config` 仍可能写入应用配置目录。现在 Debug E2E 模式禁止配置落盘，并允许用独立环境变量指定 theme、style、code theme 和 motion。该修复确保视觉审计不会污染用户配置。

## 4. 可重复执行

Windows 本地执行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/run-theme-visual-audit.ps1
```

脚本会构建当前 Tauri Debug 程序、启动隔离 Vite 和四个独立 WebView2 场景进程、生成证据并清理本次启动的临时进程。端口 9000 或 9333 已被占用时脚本会拒绝运行。

## 5. 结论与边界

T8-1B 退出条件满足：四套新场景预设具备真实 Tauri 代表工作面、三档窗口尺寸、机器语义清单、可重复脚本和持续契约门禁。T8-1 场景化主题扩展至此收尾。

本阶段不是所有页面、所有操作状态和所有平台的像素级截图穷举。七套发布预设的完整候选发布矩阵仍按 `Theme_Preset_Contract_and_Visual_Matrix.md` 在发布审计执行；本阶段证明新增场景预设在关键工作面和最容易出问题的窄宽度下可用。
